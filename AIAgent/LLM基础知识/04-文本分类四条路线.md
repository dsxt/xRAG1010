# 文本分类四条路线

任务是今日头条新闻标题的十分类，分完类再送进对应推荐流。四条路线吃同一份数据，对外是同一个函数。模型内部见 `01` 和 `03`，压缩见 `05`。

## 1. 数据

一行一条，`标题\t类别id`。类别文件一行一个英文名，行号就是 id：

| id | 名称 | 含义 |
|---|---|---|
| 0 | finance | 金融 |
| 1 | realty | 房地产 |
| 2 | stocks | 股票 |
| 3 | education | 教育 |
| 4 | science | 科技 |
| 5 | society | 社会 |
| 6 | politics | 政治 |
| 7 | sports | 体育 |
| 8 | game | 游戏 |
| 9 | entertainment | 娱乐 |

规模：训练集 18 万，验证集 1 万，测试集 1 万。十个类在训练集里各约 1.8 万条。训练集拟合参数，验证集选 checkpoint 和超参，测试集留到最后报一次。

文件在 `阶段6-TMF/02-代码/00-data/data/`。路径集中写在一个 `Config` 里：原始文件、处理后文件、模型文件、类别表、停用词、设备、`batch_size`、`max_length`、学习率。演示代码里的绝对路径和 `192.168.x.x` 换成自己的；本机调试用 `127.0.0.1`。

这批数据是公司内部已经标好的成品。实际项目里数据还会以另外几种形态出现：

| 来源 | 常见形态 |
|---|---|
| 内部数据平台 | 成品；只有路径、要自己洗；平台只有一部分，要补外部数据；或者得自己去各业务库要 |
| 甲方 | 半成品；只埋了点，后面要自己加工；或者量很少 |
| 日志 | 行为、性能、广告、搜索埋点。高频，半结构化，噪声多 |
| 业务库 | 订单、用户、内容元数据。结构化，用 `user_id` 和日志对齐 |
| 第三方 | 外部画像或公开集。格式杂，要清洗，可能要付费 |

### 先做 EDA

用 pandas 按 `\t` 读入，列名 `text`、`label`。看三件事：

- 每个 id 的条数和占比。`Counter` 即可。这批数据接近均匀。
- 标题字符长度的最大、最小、均值、中位数。标题短，所以后面 BERT 的 `max_length` 用 32 就够，不必顶到 512。
- 长度直方图，确认没有大量空标题或异常长文本。

空行丢掉。标签转 int 之前先看是不是数字，脏行跳过并记下原值。

评估用 macro-F1，再报 accuracy、macro 精确率、macro 召回率。macro 是各类先算再平均，类的体量不再加权。这批数据本来就均衡，macro-F1 和准确率会一起走。单标签多分类里，micro 精确率、micro 召回率和准确率是同一个数。

## 2. 四条路线怎么选

| 路线 | 什么时候用 | 课程里看到的效果 |
|---|---|---|
| TF-IDF + 随机森林 | 先要一条当天能看的基线 | 训练和代码都短，准确率有上限 |
| FastText | 要深度学习，又想很快 | 词级自动调参，测试集 1 万条上精确率 0.9143 |
| BERT，冻结主干，只训分类头 | 有时间，要往上抬效果，还要能改结构 | 按验证集 macro-F1 存最好的权重 |
| 大模型接口 + 提示词 | 没有训练预算，先看语义理解够不够 | 不更新权重。延迟和费用按条计 |

FastText 那组测试集数字，单标签下精确率和召回率相同：

| 设置 | 精确率 |
|---|---|
| 字级，手写超参 | 0.8714 |
| 字级，自动调参 | 0.873 |
| 词级，手写超参 | 0.9103 |
| 词级，自动调参 | 0.9143 |

手写超参是 `dim=100`、`epoch=50`、`minn=1`、`maxn=4`。自动调参用验证集，时长 3 分钟，`seed=115`。词级稳定高于字级，上线用词级自动调参的那一个。

## 3. 随机森林

预处理：jieba 分词，取前 30 个词，空格连接，写成 csv。训练集、验证集、测试集各一份。正式训练用全量；调试时切片要在上线前拿掉。

向量化：停用词读成 list，交给 `TfidfVectorizer`，在训练集上 `fit_transform`。向量器和森林一起 `pickle`。验证和线上都用这一个向量器的 `transform`。

森林用 `RandomForestClassifier(n_jobs=-1)`。它是 bagging：每棵树用有放回抽样的数据，树与树并行，预测时平权投票。boosting 是另一类集成：用全量数据、一棵接一棵串行、结果加权。这里没有用 boosting。

划分可以用已经给好的 train/dev；课程脚本也在训练集内部再 `train_test_split(..., test_size=0.2)` 看一眼。两种不要混着报成同一个测试结果。

单条预测：标题同样 jieba、截断 30、向量化，`predict` 得到 id，再用类别表映回英文名。

## 4. FastText

模型本身、`__label__` 格式、n-gram 和自动调参在 `01`。这里只补中文这批数据的差别。

- 字级：` " ".join(list(title)) `
- 词级：` " ".join(jieba.lcut(title)) `
- 标签写成 `__label__{类名}`，类名从 id 查类别表，不要把原始数字 id 直接贴进标签。空行先 `strip` 再判断。

预测前用和训练相同的切分。词级模型的返回形如 `(('__label__science',), array([0.81]))`，去掉前缀得到 `pred_class`。入参里没有标题时，返回里写明缺字段，不让异常直接冒到接口外面。

## 5. BERT

结构、`[CLS]`、冻结方式在 `03`。这里的差别是十分类、短标题、用验证集存最好的模型。

`bert-base-chinese`，`max_length=32`，`batch_size=64`，学习率 `5e-5`，epoch 课程脚本里是 1 到 2。类别数等于类别表行数。有 GPU 用 GPU。

`Dataset` 保存 `(标题, int 标签)`。`collate_fn` 用 `batch_encode_plus`，取出 `input_ids` 和 `attention_mask`。单句分类的 `token_type_ids` 全是 0，可以不传。标签 `dtype=torch.long`。

模型是 BERT 加 `Linear(768, 10)`。主干放在 `torch.no_grad()` 里，分类头接收 `last_hidden_state[:, 0]`。损失 `CrossEntropyLoss`，优化器 AdamW。

每 100 个 batch 和最后一个 batch 在验证集上算 macro-F1。高于历史最好就 `torch.save(model.state_dict(), path)`。评估时 `model.eval()`，算完回到 `model.train()`。预测下标 `argmax(dim=-1)`，搬回 CPU 再进 sklearn，少占显存。

单条预测同样编码成 batch 为 1 的张量，`argmax` 之后用类别表取名字。`load_state_dict` 的返回值不用接。

## 6. 大模型接口

这条路线不训练。标题放进用户消息，系统提示词规定类别和输出格式，模型返回一个英文类名。

课程里的技术定义：参数量到十亿以上、骨架是 Transformer 的语言模型。它能做这件事，靠的是预训练见过的大规模文本、自注意力、以及训练时的算力。DeepSeek-V3 对应接口名 `deepseek-chat`，用来做通用对话；DeepSeek-R1 是强化过推理的模型。这批标题用通用对话模型就够。

调用走 OpenAI 兼容接口。密钥放环境变量，用 `python-dotenv` 的 `load_dotenv` 读，不写进源码，也不抄进这份笔记。

| | 环境变量 | base_url | 课程用过的模型名 |
|---|---|---|---|
| 通义千问 | `QWEN_API_KEY` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| DeepSeek | `DEEPSEEK_API_KEY` | `https://api.deepseek.com` | `deepseek-chat` |

消息三种角色：`system` 定规则，`user` 给标题，`assistant` 是模型上一轮的话。`stream=False` 等整段返回；长文本要边生成边显示时再开 `stream=True`。分类只要 `choices[0].message.content`，再 `strip`。

两份原始提示词合成下面这一份。它同时保住了「只准输出类名」和课件里的消歧规则：

```text
你是新闻分类器。根据标题，把它归入且只归入下面十个类之一：
finance, realty, stocks, education, science, society, politics, sports, game, entertainment

规则：
- 只输出小写英文类名，不加标点、不加解释、不输出数字 id。
- 只根据标题本身判断。
- 实体运动归 sports，电子游戏和网游归 game。
- 同一词看上下文：房地产语境的「金科」归 realty，游戏语境归 game。
- 拿不准时按标题里的核心事物归类。

示例：
国务院：严打拐卖操控未成年人违法犯罪 → politics
《赤壁OL》攻城战诸侯战硝烟又起 → game
同步A股首秀：港股缩量回调 → stocks
状元心经：考前一周重点是回顾和整理 → education
```

返回值要校验：去掉空白和反引号之后，必须落在这十个字符串里。不在里面就当这次调用失败，而不是把解释性句子写进 `pred_class`。

这条路线的特点：没有标注也能开始；一个接口可以换系统提示词去做别的任务；标题里的多义词靠提示词里的例子消歧。费用和延迟按调用计，输出受提示词影响，错了要改提示词再看。想把这 18 万条标注吃进模型，用第 5 节的微调，或者 `05` 的蒸馏，而不是在接口上反复改提示词。

## 7. 统一的预测函数和服务

四条路线对外都是：

```python
def predict(news: dict) -> dict:
    """输入 {"title": "..."} ，返回同一字典并写入 pred_class。"""
```

Flask 只做转发：

```python
@app.route("/predict_api", methods=["POST"])
def predict_api():
    news = request.get_json(force=True)
    return jsonify(predict(news))
```

POST 把标题放在 body 里。GET 把参数放在 URL 上，标题一长就不合适，日志里也容易留下全文。`debug=True` 只用于本机。换模型时只改 `predict` 的导入，路由不变。

Streamlit 页一个输入框、一个按钮。按钮按下后记时，POST 到上面的地址，展示 `pred_class` 和耗时。请求失败时给出固定的失败提示，把异常留在服务端日志里。启动命令是 `streamlit run app_streamlit.py`。

随机森林和 FastText 的进程里要持有向量器或 fastText 模型；BERT 和学生模型要先 `load_state_dict` 再 `eval()`。模型在进程启动时加载一次，不放进请求函数里反复读盘。
