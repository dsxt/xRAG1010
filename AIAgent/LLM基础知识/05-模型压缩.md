# 模型压缩

`04` 的 BERT 分类器效果好，体积和延迟也大。压缩要在指标掉得不多的前提下，减小体积、减少计算、把延迟降下来。大模型放不进内存小的机器，推理更慢，也更耗电。家庭摄像头这类要在设备上实时跑的场景，是课件里举的动机。

四条技术：

| 技术 | 改什么 | 体积和速度 | 课程里的用法 |
|---|---|---|---|
| 剪枝 | 去掉贡献小的权重、神经元或整层 | 非结构化剪枝只是把权重变成 0，没有稀疏内核时体积和延迟几乎不动 | 和量化或蒸馏一起用 |
| 量化 | 把 fp32 权重换成更低位宽 | int8 大约把体积降到 1/4，访存和矩阵乘有数倍空间，具体看硬件 | 希望变小，同时指标不要明显掉 |
| 蒸馏 | 大模型的输出分布交给小模型去学 | 小模型本身又小又快，指标取决于学生容量 | 最在意体积时优先看这条 |
| 低秩分解 | 把一个大矩阵拆成两个瘦矩阵的乘积 | 参数变成 `m×r + r×n`，`r` 远小于 `m` 和 `n` | 这一课没有单独的脚本。ALBERT 的嵌入因式分解是同一件事，见 `03` |

课件给出的搭配：先剪枝或先量化，再蒸馏。剪枝加量化叠在同一个大模型上；剪枝加蒸馏则是用教师去教剪过的学生。先看瓶颈是内存、延迟还是指标，再决定以哪一条为主。

## 1. 量化

权重通常是 fp32。换成更窄的类型，模型变小，整数矩阵乘也更快，只能做整数的设备就能装下。int8 相对 fp32：体积约 1/4，内存带宽大约少 2 到 4 倍，推理大约快 2 到 4 倍。换来的是近似，指标会有一点损失。

常见低精度类型：

| 类型 | 累加时常用的类型 | 大约范围 |
|---|---|---|
| float16 | float16 | ±65504 |
| bfloat16 | float32 | 指数范围接近 fp32，尾数更短 |
| int16 | int32 | -32768 到 32767 |
| int8 | int32 | -128 到 127 |

累加类型比存储类型更宽，是为了多次乘加之后不溢出、也不把小数舍没。

三种做法，目的相同：降位宽，尽量保住指标。

| 名称 | 何时确定量化参数 |
|---|---|
| 动态量化 DQ | 推理时按当前这一批激活的范围来量化。权重量化是提前定的 |
| 训练后量化 PTQ | 训练已经结束，用一小批校准数据定好刻度，再推理 |
| 量化感知训练 QAT | 训练时就模拟低精度，权重在噪声下学 |

这一课实现的是动态量化，在 CPU 上做。GPU 上训好的权重先 `map_location="cpu"` 再量化。

```python
torch.backends.quantized.engine = "onednn"   # 也可让 PyTorch 自己选
model.load_state_dict(torch.load(path, map_location="cpu"))
model.eval()

quantized = torch.quantization.quantize_dynamic(
    model,
    qconfig_spec={torch.nn.Linear},
    dtype=torch.qint8,
)
quantized.eval()
torch.save(quantized, "quantized_model.pt")
```

`qconfig_spec` 指定哪些层被量化，这里是所有 `nn.Linear`，BERT 里的注意力投影和分类头都在内。`supported_engines` 里常见 `none`、`onednn`、`x86`、`fbgemm`。机器是 Intel CPU 时，课程把引擎设成 `onednn`；不设的话 PyTorch 会按环境挑。

量化前后用同一套验证集 macro-F1 对比，见 `04` 的评估函数。动态量化改的是模块类型，保存时存整个模块。普通 BERT 存的是 `state_dict`，两种文件不能用同一个 `load_state_dict` 去读。

## 2. 蒸馏

教师是已经训好的大模型，准、慢、大。学生是另起的小模型，快、小，指标靠模仿教师补回来。

学生要学的东西有三层，课程把它们定义成：

| 信号 | 是什么 | 学生学到什么 |
|---|---|---|
| 硬标签 | 标注 id，交叉熵里相当于 one-hot | 只知道最终类别 |
| 软标签 | 教师在各类上的概率，取值在 0 到 1 | 知道「像体育但也有一点社会」这种关系 |
| 中间层 | 教师某层的隐藏状态 | 思考过程。用 MSE 对齐。本课脚本没有实现这一路 |

硬标签是 one-hot 时，学生分布相对它的 KL 散度等于交叉熵，因为 one-hot 的熵是 0。

KL 散度衡量两个分布差多远。越小越接近，0 表示相同。蒸馏里用教师分布当目标、学生分布当近似：`KL(教师 || 学生)`。

软标签经过温度 `T`：

```text
p = softmax(logits / T)
```

`T = 1` 就是普通 softmax。`T` 趋近 0 时分布趋近 one-hot，又变回硬标签。`T` 很大时分布趋近均匀，类别之间的差别被抹平。课程取 `T = 2`，可用范围大约 2 到 5。

总损失：

```text
L = (1 - α) * CE(学生logits, 标注) + α * T² * KL(教师/T || 学生/T)
```

`α` 趋近 1 时更听教师，趋近 0 时更听标注。课程取 `0.7`，可用范围大约 0.5 到 0.9。乘 `T²` 是因为除以 `T` 之后软标签的梯度大约缩小 `T²` 倍，乘回来才和硬标签在一个量级。

### 教师

`04` 的 BERT 分类器。前向时主干放在 `torch.no_grad()` 里。句向量用 `pooler_output`（对 `[CLS]` 做了线性层和 Tanh），再进 `Linear(768, 10)`。`bert_output[1]` 和 `pooler_output` 是同一个返回值。蒸馏时教师整体 `eval()`，前向再包一层 `no_grad()`，分类头也不更新。

### 学生

BiLSTM，词表大小沿用 BERT 的 tokenizer，这样两边的 `input_ids` 对齐。

| 部件 | 课程取值 |
|---|---|
| 嵌入 | `vocab_size × 128`，128 与教师的 768 无关 |
| LSTM | 输入 128，隐藏 256，3 层，`batch_first=True`，双向 |
| Dropout | 0.3，加在池化之后、线性层之前 |
| 输出 | `Linear(512, 10)`。512 是因为双向把两个方向拼在一起 |

句向量只对真实词做平均。`[CLS]`、`[SEP]` 和补齐位先乘成 0，池化时再排除；LSTM 仍会按时间步走过这些位置。`bert-base-chinese` 里 `[CLS]`、`[SEP]` 的 id 是 101 和 102，代码里写成 `tokenizer.cls_token_id` 和 `sep_token_id`。掩码是：

```python
valid = (input_ids != cls_id) & (input_ids != sep_id) & attention_mask.bool()
emb = embedding(input_ids) * valid.unsqueeze(-1)
output, _ = lstm(emb)                       # [batch, seq, 512]
pooled = output.sum(1) / valid.sum(1, keepdim=True).clamp_min(1e-6)
logits = linear(dropout(pooled))
```

LSTM 不传初始状态时，内部按 0 初始化。除以词数之前加上 `1e-6`，避免一句里有效词被滤光后除以 0。

### 训练循环

数据加载和 `04` 相同，`batch_size=64`，`max_length=32`。只把学生的参数交给 AdamW，学习率 `5e-5`。

```python
T, alpha = 2, 0.7
with torch.no_grad():
    teacher_logits = teacher(input_ids, attention_mask)
student_logits = student(input_ids, attention_mask)

log_p = torch.log_softmax(teacher_logits / T, dim=-1)
log_q = torch.log_softmax(student_logits / T, dim=-1)
kl = F.kl_div(input=log_q, target=log_p, reduction="batchmean", log_target=True)
hard = criterion(student_logits, labels)
loss = (1 - alpha) * hard + alpha * (T ** 2) * kl
```

`kl_div` 在 `log_target=True` 时期待两边都是对数概率。`input` 是学生，`target` 是教师。`reduction="batchmean"` 按 batch 平均，这是 PyTorch 对 KL 建议的归约。硬标签用未除温度的学生 logits。

每 100 个 batch 在验证集上评估学生，macro-F1 变好就保存学生的 `state_dict`。存完回到 `student.train()`。教师保持 `eval()`。

预测只加载学生：同一套 tokenizer 编码标题，`argmax` 映回类名。服务层仍是 `04` 的 `predict`。

## 3. 剪枝

剪枝去掉对输出贡献很小的连接。灵感是生物神经网络里的稀疏连接：稠密矩阵里很多权重可以变成 0，行为仍大致保持。

| | 结构化 | 非结构化 |
|---|---|---|
| 删的单位 | 整行、整列、整个通道或整层 | 单个权重 |
| 删完的矩阵 | 仍然是一块更小的稠密矩阵，普通硬件就能加速 | 零散的 0，要稀疏内核才真正变快变小 |
| 粒度 | 粗 | 细 |

PyTorch 在 `torch.nn.utils.prune`，1.4 及以上才有。它可以剪某一层、同时剪多个参数、全局一起排大小，也可以写自己的打分函数。

本课做的是全局非结构化剪枝：`bert-base-chinese` 的 12 层编码器里，每层自注意力的 Q、K、V 权重放进同一个候选池，按 L1 范数最小的 30% 置零。

```python
from torch.nn.utils import prune

parameters_to_prune = []
for i in range(12):
    # BertClassifierModel 里预训练主干的属性名是 bert_model
    attn = model.bert_model.encoder.layer[i].attention.self
    parameters_to_prune += [
        (attn.query, "weight"),
        (attn.key, "weight"),
        (attn.value, "weight"),
    ]

prune.global_unstructured(
    parameters_to_prune,
    pruning_method=prune.L1Unstructured,
    amount=0.3,          # 0 到 1 是比例；整数则是个数
)
for module, name in parameters_to_prune:
    prune.remove(module, name)
```

`amount` 用比例。全局的意思是 30% 在所有列入的 Q、K、V 上一起排，不是每一层各自恰好 30%。只统计某一层 `query.weight` 的零值比例，会在 30% 附近，不一定正好等于 30%。

`prune` 之后权重由 `weight_orig` 和 `weight_mask` 相乘得到。`prune.remove` 把乘完的结果写回 `weight`，掩码缓冲区去掉，这时再 `state_dict` 才是剪过的模型。剪枝前后用同一套验证集看 macro-F1，并打印第一层 query 权重的左上角，确认出现了 0。

非结构化剪枝本身几乎不减小文件、也不加快普通矩阵乘。它的用途是和量化叠在一起，或者给蒸馏提供一个更瘦的教师。

## 4. 低秩分解

一个 `m × n` 的权重如果近似等于 `m × r` 乘 `r × n`，参数量从 `m·n` 变成 `(m+n)·r`。`r` 比 `m`、`n` 小得多时，冗余就被拆掉了。

ALBERT 把词嵌入从 `词表 × 隐藏维` 拆成 `词表 × 128` 再加 `128 × 隐藏维`，数字和动机在 `03` 第 5 节。那是这一条技术在嵌入矩阵上的一个具体做法。
