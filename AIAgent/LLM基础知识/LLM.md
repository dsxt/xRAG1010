# LLM

> 来源：尚硅谷《大模型技术之 LLM》V1.2。这是阅读稿。架构以 Decoder-only 为主线，微调以手写 SFT / DPO 和 Qwen3 为例，部署以 vLLM 为例。公式按课件口径写。第 18 节是对照面试题补的选型边界，不替代前面的机制。

LLM（Large Language Model）是在海量无标注文本上预训练得到的语言模型。它从语料里学语言规律，从而理解、生成和推理。「大」有三层意思：参数从数十亿到上万亿；预训练语料覆盖多语言、多领域；一个模型能跨任务泛化，做问答、摘要、翻译、编程。典型系列是 GPT、DeepSeek、Qwen。

## 1. GPT 系列把训练范式定下来

ChatGPT 在 2022 年 11 月发布。它不是突然出现的，而是 GPT-1 以来在规模、数据、架构和训练方式上连续迭代的结果。

| 模型 | 时间 / 论文要点 | 参数 | 结构上的变化 | 训练上的变化 | 能力上的变化 |
|---|---|---|---|---|---|
| GPT-1 | 2018.6，《Improving Language Understanding by Generative Pre-Training》 | 1.17 亿。12 层，隐藏维 768，12 头，FFN 3072 | Decoder-only；可学习位置嵌入，不用正弦编码；输入嵌入和输出词表共享权重 | BooksCorpus，约 8000 万词的英文小说。先下一词预测，再在顶上加任务分类层做有监督微调 | 证明「预训练 + 微调」。微调后在蕴含、问答、语义相似度上超过从零训练的模型。意义在范式，不在绝对性能 |
| GPT-2 | 2019，《Language Models are Unsupervised Multitask Learners》 | 最大 15.42 亿，约为 GPT-1 的十倍。48 层，隐藏维 1600，25 头，FFN 6400 | 仍是 Decoder-only。改成 Pre-LayerNorm，缓解大模型梯度不稳 | WebText，约 40GB、800 万篇网页。目标仍是自回归下一词预测。没有下游微调 | 文本生成当时多处 SOTA。只用自然语言提示就能做翻译、问答、摘要，这是早期零样本。复杂推理仍不如专用微调模型。实验显示出规模效应：参数和数据变大，多任务性能持续涨 |
| GPT-3 | 2020.5，《Language Models are Few-Shot Learners》 | 1750 亿，约为 GPT-2 的百倍。96 层，隐藏维 12288，96 头，FFN 49152 | 各层交替使用稠密注意力和局部带状稀疏注意力。后者只在局部窗口里算注意力，降低时间和空间复杂度，稠密层仍保留全局信息 | 约 570GB、3000 亿 token。数千块 V100，训数周 | 正式提出上下文学习：使用时不再训练，提示里放任务说明和少量例子就能做。部分测试接近甚至超过微调过的专用模型 |
| InstructGPT | 2022 初，《Training language models to follow instructions with human feedback》 | 与 GPT-3 相同，1750 亿 | 结构不改 | 在 GPT-3 上加三阶段对齐，见下节 | ChatGPT 的直接前身。更听指令，更有用、真实、礼貌、安全，有害和胡说减少，多任务泛化还在 |
| ChatGPT | 2022.11 | 细节未公开 | 和 InstructGPT 同一条路线 | 同样是 RLHF。差别在数据：标注员模拟用户和助手的多轮对话；旧的指令数据也改成对话格式后混进去 | 能接上下文、承认并改正错误、质疑错误前提、拒绝不当请求 |

GPT-3 的问题不是不会生成，而是训练目标只是「预测互联网文本的下一个词」。模型学到的是统计规律，不是执行人的指令，所以和人的意图没对齐（Alignment）。

InstructGPT 的三阶段：

1. 监督微调 SFT。人工写高质量「指令—回答」，目标仍是下一词预测。模型开始能按指令作答。
2. 奖励模型 RM。SFT 模型对同一条指令生成多个回答，人按质量、相关性、礼貌、有用性排序，用排序训练一个打分模型，让它模仿人的偏好。
3. RLHF。从指令集取指令，SFT 模型生成回答，RM 打分，再用 PPO 更新语言模型，使它更倾向高分回答。

串起来就是现在的主流三阶段：

| 阶段 | 做什么 |
|---|---|
| 预训练 | 超大规模无标注语料上自监督。得到语言建模能力、世界知识和基本推理 |
| SFT | 用指令—回答或高质量对话再训。让输出更听话、更稳、更贴任务 |
| 对齐 | 把人类偏好、安全约束和价值观放进来。做法包括 RLHF（奖励模型 + 强化学习），以及不用强化学习的 DPO、ORPO、KTO |

## 3. Decoder-only 的三层骨架

当前大多数 LLM 是 Transformer 的 Decoder-only。整体仍是输入层、一叠 Transformer Block、输出层。ChatGPT 之后结构没有被换掉，演进发生在块内部：注意力、前馈、归一化、残差和位置编码。

输入层把 token 映成词向量。早期的正余弦位置编码加在这一层；后面的旋转位置编码不加在输入上，而是加在 Block 里的 q、k 上。

每个 Block 做两件事。自注意力让当前 token 看到序列里其他位置，抓住长距离依赖。前馈网络对每个位置单独做非线性变换。残差和归一化让几十到上百层还能把梯度传回去。

输出层用线性层 `lm_head` 把隐向量投到词表，再 Softmax，得到下一个 token 的分布。生成是自回归的：吐出一个 token，再把它当下一步输入。小模型（课件点名 Qwen3-0.6B、Qwen3-1.7B）会让 `token_embedding` 和 `lm_head` 共享权重，省参数。

## 4. 位置编码

自注意力本身没有顺序。不额外给位置，模型分不清 token 谁先谁后。

### 4.1 正余弦

原始 Transformer 用固定的正弦、余弦，不增加可训练参数，也不会在训练中漂：

\[
PE_{(pos,2i)}=\sin\left(pos/10000^{2i/d}\right),\quad
PE_{(pos,2i+1)}=\cos\left(pos/10000^{2i/d}\right)
\]

`pos` 是绝对位置，`i` 是维度对的下标，`d` 是总维度。同一频率的正弦和余弦成对。一对频率上，位置 `m` 和 `n` 的编码内积可以化成只含 `m-n` 的余弦，所以编码向量之间带有相对位置。

这个优点在真正的注意力里站不稳。注意力打分是 \((x_m+p_m)W_Q\) 和 \((x_n+p_n)W_K\) 的内积，展开是四项：内容对内容、内容对位置、位置对内容、位置对位置。只有最后一项直接来自两个位置编码的相互作用。\(W_Q\)、\(W_K\) 在训练中一直变，正余弦原来的几何结构会被搅乱，模型还得重新学回相对位置，外推和训练稳定性都受影响。

### 4.2 可学习位置向量

BERT、GPT-1、GPT-2 给每个绝对位置一个向量，和词向量一样更新。实现简单，能贴合语料，但有两个硬伤：没训练过的位置没有向量，长度外推不了；位置向量数随最大长度线性涨，长上下文的参数开销大。

### 4.3 RoPE

旋转位置编码由苏剑林提出，是现在 LLM 的默认方案。它不加到词向量上，而是直接旋转 q 和 k。目标写成：位置 `m` 的 q 和位置 `n` 的 k 做内积，结果只依赖这两个向量以及相对距离 `m-n`。

做法：把 q、k 按维度两两分组，每一对看成一个二维向量，转一个和位置、维度都有关的角度。第 `i` 对在位置 `m` 的转角是 \(m\theta_i\)，

\[
\theta_i = 10000^{-2i/d}
\]

`d` 是 q、k 这一头的维度。二维旋转矩阵是

\[
\begin{bmatrix}\cos\theta&-\sin\theta\\ \sin\theta&\cos\theta\end{bmatrix}
\]

它有两个会在附录里用到的性质：先转 \(\alpha\) 再转 \(\beta\) 等于转 \(\alpha+\beta\)；转置等于转 \(-\theta\)。因此位置 `m` 的 q 和位置 `n` 的 k 相乘时，两次旋转合成一次相对旋转，角度只剩 \((m-n)\theta_i\)。所有维度对加起来，注意力得分就只依赖相对位置。

和前两种比：显式编码相对位置；没有位置参数，几何结构不被训练改掉；不绑定训练长度，外推更容易。课件的限制也要记住：推理长度和训练长度差得太大时，外推问题还在。

Qwen3 示例里的实现细节：频率先按 `head_dim` 的一半算出来，再复制到后一半。旋转配对不是相邻两维 `(0,1)、(2,3)`，而是前一半对后一半：`head_dim=8` 时配对是 `(0,4)、(1,5)、(2,3 不对)、(3,7)`，也就是 `(0,4)、(1,5)、(2,6)、(3,7)`。公式是

\[
x_{rotated}=x\cos + \mathrm{cat}(-x_2,x_1)\sin
\]

缓存开启后，旋转用 `start_pos` 作偏移，保证新 token 的角度接着上文，而不是从 0 重算。

## 5. 注意力和 KV Cache

注意力决定生成下一个 token 时怎么用上下文。模型变大、序列变长之后，多头注意力的推理成本先爆在显存，而不是算力公式本身。

自回归时，每生成一个 token 都要和全部历史做注意力。如果每步都重算历史的 Key 和 Value，计算是重复的。KV Cache 把历史 token 的 K、V 存下来。下一步只算当前 token 的 Q、K、V，再和缓存里的 K、V 匹配。

缓存省了计算，但 K、V 要一直留着。序列越长、层数越多，缓存越大。多头注意力里每个头各存一套 K、V，缓存再乘一头数。这是 MHA 在大模型推理里的主要问题。

| 结构 | K、V 怎么放 | 取舍 |
|---|---|---|
| MHA | 每个头一套 | 表达力最全。KV Cache 最大 |
| MQA | 所有头共用一套。Google，2019，《Fast Transformer Decoding: One Write-Head is All You Need》 | 缓存和带宽降一个头数的量级，推理快很多。头之间的差异变小，精度略降，通常降得不多 |
| GQA | 头分成若干组，组内共享一套 K、V，组间独立。Google，《GQA: Training Generalized Multi-Query Transformer Layers》 | 站在 MHA 和 MQA 中间。缓存仍远小于 MHA，表达力高于 MQA。主流模型用这个 |

Qwen3 的分组注意力要求头数能被 KV 组数整除，`group_size = num_heads / num_kv_groups`。Query 投影是满的，`num_heads × head_dim`；Key、Value 投影只有 `num_kv_groups × head_dim`。可选地对每个头的 q、k 再做一次 RMSNorm。RoPE 加在 q、k 上，并且发生在写入缓存之前。缓存按序列维拼接旧的 K、V。算注意力前，用 `repeat_interleave` 把每组 K、V 复制 `group_size` 份，让组内每个 Query 头对上同一套 K、V。分数除以 \(\sqrt{head\_dim}\)，因果掩码把未来位置填成 \(-\infty\)，再 Softmax。

`head_dim` 可以单独给定。不给定时用 `emb_dim / n_heads`。

## 6. 前馈网络

FFN 是 Block 里注意力之后的第二块。形状是升维、激活、降维，每个 token 独立做。演进沿着激活函数，后来又走出了 MoE。

| 激活 | 行为 | 在 LLM 里的位置 |
|---|---|---|
| ReLU | 负数直接变 0，正数梯度恒为 1 | 浅层网络里缓解梯度消失。负区间梯度是 0，神经元可能永久失活；非线性也偏硬。大模型里基本退出 |
| GELU | \(\mathrm{GELU}(x)=x\,\Phi(x)\)，\(\Phi\) 是标准正态的累积分布 | BERT、GPT-2、GPT-3 用过。全程可导，没有「死亡神经元」 |
| SiLU | \(x\cdot\sigma(x)\) | 和 GELU 一样平滑。大正数接近恒等，大负数被压向 0 |
| Swish | \(x\cdot\sigma(\beta x)\) | \(\beta=1\) 时就是 SiLU。可学习的 \(\beta\) 收益有限，还可能不稳，工程里通常固定为 1，两个名字混用 |
| GLU 一族 | 主分支乘门控分支 | 现在的默认结构。门控函数不同就是不同变体：GLU 用 Sigmoid，GEGLU 用 GELU，SwiGLU 用 SiLU。SwiGLU 在效果和稳定性上最好，Qwen、DeepSeek 用它 |

Qwen3 的前馈就是 SwiGLU，三个没有 bias 的线性层：

\[
\mathrm{FFN}(x)=W_3\big(\mathrm{SiLU}(W_1 x)\odot W_2 x\big)
\]

`W1`、`W2` 从 `emb_dim` 升到 `hidden_dim`，`W3` 投回去。

### 6.1 MoE

MoE 用多份并行的 FFN 换掉单独一份，Router 按 token 的隐藏表示只挑少数专家来算。步骤：

1. Router 对隐藏表示做线性映射，给每个专家一个分。
2. 取得分最高的 k 个，其余这次不算。
3. 对选中的分数做 Softmax，得到权重。
4. 被选中的专家各自前向。
5. 按权重把输出加起来。

稀疏激活带来三件事：总参数可以很大，但每次前向只算几个专家，算力不按总参数涨；不同 token 被分到不同专家，专家会自己分工；专家之间不共享参数，可以拆到不同设备上。

## 7. 归一化和残差

残差给深层网络留一条不动梯度的直通路径。标准残差 \(y=x+F(x)\) 回传时，梯度是 \(\dfrac{\partial L}{\partial y}\left(1+\dfrac{\partial F}{\partial x}\right)\)。那个 1 不改变方向和大小。

| 放法 | 公式 | 结果 |
|---|---|---|
| Post-Norm | 子层加完残差再归一化。原始 Transformer | 归一化把这条恒等路径也缩放了，1 不再是 1。层数一深，扰动累积，大模型基本不用 |
| Pre-Norm | 先进归一化，再进子层，然后加回没归一化的那份输入 | 恒等路径留在残差外面。现代 LLM 的事实标准 |

RMSNorm 是 LayerNorm 的简化：不去均值，只按均方根缩放。深层 Transformer 里均值项对稳定性帮助有限，去掉之后更便宜，也更稳。现在最常用。

\[
\mathrm{RMSNorm}(x)=\frac{x}{\sqrt{\mathrm{mean}(x^2)+\epsilon}}\odot g
\]

`g` 是可学习缩放，\(\epsilon\) 防止除零。课件代码默认 \(\epsilon=10^{-6}\)，并先把输入转成 float32 再算，算完转回原 dtype。代码里还可以选一个平移项，正文公式本身没有减均值。

Qwen3 的一个 Block 就是两次 Pre-Norm 残差：

```text
x = x + Attention(RMSNorm(x))
x = x + FFN(RMSNorm(x))
```

全部 Block 之后还有一次 RMSNorm，再进 `lm_head`。因果掩码是上三角（对角线以上屏蔽）。开了 KV Cache 时，位置从 `current_pos` 接着长，掩码的列覆盖「已有缓存 + 本步新 token」。`reset_kv_cache` 把位置计数清回 0。

## 8. 微调：先别急着训

微调是在已经有通用能力的模型上，继续用特定数据改参数，让它适应某个任务、风格、领域或偏好。它能做三件事：把特定任务做稳；把语气和格式固定下来；把术语、规则和业务逻辑写进参数。

具体任务先试提示工程和 RAG。这两样达不到，再微调。

流程是四段：选模型、准备数据、训练、验证。验证不能只看训练损失下降，还要看验证集、抽样推理和真实任务，用来发现过拟合、不听指令、回答不稳。

### 8.1 选模型和规模

绝大多数场景从 Instruct 模型开始。它已经做过指令微调和偏好对齐，会对话，数据和训练都更省事，适合客服、内容生成、结构化输出、多轮对话。Base 模型适合任务形式很怪，或者手里有大量高质量领域数据、打算从头做深度适配。

参数越大通常越强，显存、训练和推理也越贵。先用负担得起的中小 Instruct 做基线，评测不够再加大。课件给的起点，最终仍以任务评测为准：

| 任务 | 起点 |
|---|---|
| 意图识别、文本分类 | Instruct，1B–7B |
| 客服 FAQ、工单辅助 | Instruct，7B–14B |
| 企业知识库、RAG | Instruct，7B–14B 起，复杂用 14B–32B |
| NL2SQL | 简单 7B–14B，复杂 14B–32B |
| 端侧、边缘 | Instruct，0.5B–4B |

多数业务可以先拿 7B/8B 或 14B 的 Instruct 做基线。复杂推理、长上下文或结构化输出不稳，再上 32B 或更大。

### 8.2 数据

公共数据从 Hugging Face Hub 和 ModelScope 拿，可按任务、语言、许可证筛。私有数据是手册、制度、工单、订单、病历、日志。它们本来不是训练集，要清洗、结构化、脱敏、标注。可以由内部标注，也可以众包，或用人机协同工具（课件点名 Easy Dataset）把私有知识收成微调样本。

不同训练目标要不同的样本形状，不能一套格式打全部算法。

按目标分：

| 方法 | 数据 | 学什么 |
|---|---|---|
| SFT | 有标准答案：指令—回答、问题—答案 | 把回答的 token 概率往标准答案上拉 |
| 偏好对齐，如 DPO | 同一提示下的更优回答和较差回答 | 学相对偏好，不是背一条标准答案 |
| RLHF | 人工偏好先训奖励模型，再用强化学习优化语言模型 | 对齐行为和交互体验。流程最重、最贵 |

按改多少参数分：全参数微调改全部权重，自由度最高，也最贵；参数高效微调只改很少的参数或加一小块可训练模块。LoRA、QLoRA 是后面的重点。

## 9. 手写 SFT

例子是把 `Qwen3-0.6B-Base` 训成能多轮对话、听指令的模型。数据是 `HuggingFaceH4/ultrachat_200k`，模型和数据都从 ModelScope 下。

### 9.1 对话模板和答案掩码

厂商会定一套 chat template，把带角色的消息列表收成模型真正看到的字符串。训练和推理必须用同一套。训练时 `add_generation_prompt=False`，整段对话都在序列里。推理时对到当前用户消息为止，`add_generation_prompt=True`，模型接着把助手的回复生成出来。

SFT 和预训练的本质差别：损失只落在助手回答上，用户和系统提示的 token 不参与损失。否则模型会去拟合「把问题再抄一遍」。

Qwen 模板用 `<|im_start|>` 和 `<|im_end|>` 包每一轮。课件的掩码找所有 `<|im_end|>`，丢掉第一个（那是 system），然后交错区分用户轮和助手轮。助手正文从用户结束位置再跳过换行、`<|im_start|>` 和 `assistant` 这几个 token 开始，到助手自己的 `<|im_end|>` 之前结束。最后一轮如果被截断、没有结束符，就从助手正文一直掩到序列尾。

### 9.2 损失

给定提示，回答的概率是每个答案 token 条件概率的乘积。训练要让这个概率最大。取对数把乘变加，加负号把最大化变最小，再除以有效 token 数，得到平均负对数似然：

\[
\mathcal{L}=-\frac{1}{N}\sum_{t\in\text{answer}}\log p(y_t\mid y_{<t},x)
\]

实现是：logits 做 log-softmax，`gather` 出标签位置的对数概率，乘上「答案掩码且不是 pad」的掩码，再对 batch 里所有有效 token 求平均。这是 token 级平均，不是先对每条样本平均再对样本平均。某个样本切完后一个答案 token 都没有，整批跳过。

一个 step 的骨架和普通语言模型训练一样：pad 到批内等长；输入是序列去掉最后一个 token，标签是去掉第一个 token，也就是下一词；前向拿 logits；算损失；反传；AdamW 更新。学习率用 `cosine_decay`：按 `warmup_ratio` 升温，再从 `max_lr` 余弦降到 `min_lr`。日志写 TensorBoard。

### 9.3 训完怎么看，以及 SFT 的副作用

推理用同一套 chat template，`model.generate`。课件示例里 `eos_token_id` 用了 Qwen 的 151643 和 151645；若输出里有 `</think>`（token 151668），它前面是思考内容，后面是正式回答。这是这套模板和思考模式的解析方式，不是所有模型通用的 id。

SFT 轮次太多、学习率太高，或数据又少又单一，模型会贴死微调分布，通用知识和通用指令变差。这就是灾难性遗忘的一种表现。对策：

- 小数据先试 1 到 2 个 epoch，用验证集早停，别只靠把 loss 压低。
- 任务数据和高质量通用指令混训，避免分布被单一任务拽走。
- 同时准备任务集和通用能力集，微调后两边都测。

## 10. 手写 DPO

DPO 来自 2023 年论文《Direct Preference Optimization: Your Language Model is Secretly a Reward Model》。它用「优答优于差答」直接训语言模型，不另训奖励模型，也不跑强化学习。课件的案例接在前面的 SFT 模型之后。

一条样本是三块：`prompt`、`chosen`、`rejected`。重要的是相对偏好清不清楚，不是某条回答绝对正确。数据用 `HuggingFaceH4/ultrafeedback_binarized`：原始 UltraFeedback 里每个 prompt 有 4 个模型回答，GPT-4 按帮助性、真实性等打分；这个二元版本取得分最高的当 chosen，再从剩下的里取一条当 rejected。

损失有两层。第一层，当前模型 \(\pi\) 在同一个 \(x\) 下要更偏向 \(y_w\) 而不是 \(y_l\)：

\[
\log\pi(y_w\mid x)-\log\pi(y_l\mid x)
\]

第二层，这个差距要和参考模型 \(\pi_{\mathrm{ref}}\) 比。参考模型是冻结的 SFT（或当前起点）模型，训练中不更新、设成 eval、关掉 dropout。它提供基线：不是仅仅「喜欢 chosen」，而是「比原来更明显地喜欢 chosen」，免得偏好训练把原有语言能力拖垮。

\[
\Delta=\big(\log\pi(y_w\mid x)-\log\pi(y_l\mid x)\big)
-\big(\log\pi_{\mathrm{ref}}(y_w\mid x)-\log\pi_{\mathrm{ref}}(y_l\mid x)\big)
\]

\[
\mathcal{L}=-\log\sigma(\beta\Delta)
\]

\(\beta\) 控制把 chosen 和 rejected 拉开的强度。\(\Delta>0\) 说明相对参考模型，偏好方向是对的。

课件实现有一个和论文求和不一样的口径：chosen、rejected 用的是回答 token 的平均对数概率，不是整段对数概率之和。长短回答不会只因为 token 更多就把差值撑大。参考模型的前向放在 `torch.no_grad()` 里，logits 再 `detach`。chosen 和 rejected 各自 pad、各自做答案掩码；任一侧有效 token 为 0 就跳过这个 batch。优化器只挂在要更新的那个模型上。

## 11. 显存和单卡上的省法

微调慢，常常是因为显存不够：batch 加不大，并行度上不去，只能用很保守的配置。显存主要是五块。

| 占用 | 怎么估 |
|---|---|
| 参数 | 参数量 × 每参数字节。7B 是 \(7\times10^9\)。FP16 是 2 字节，FP32 是 4 字节 |
| 梯度 | 每个可训练参数一份，形状和参数一样，精度通常也一样，体积和参数同级 |
| 优化器状态 | AdamW 为每个参数留一阶矩和二阶矩，通常用 FP32。这是微调显存的大头，往往是参数的数倍 |
| 激活 | 前向的中间结果，反传要用。随 batch、序列长度、隐藏维、层数涨。粗估 \(b\cdot s\cdot h\cdot L\cdot bytes\cdot c\)，`c` 是 10 到 30 的经验系数，FP16 的 bytes 取 2 |
| 运行时 | CUDA 临时内存、分布式通信缓冲 |

AdamW 在时间步 \(t\)、梯度 \(g\) 上做四步：一阶矩 \(m_t=\beta_1 m+(1-\beta_1)g\)；二阶矩 \(v_t=\beta_2 v+(1-\beta_2)g^2\)；对 \(m\)、\(v\) 做偏差修正；再用修正后的矩更新参数。

单卡上的四种换法：

| 办法 | 换什么 |
|---|---|
| 梯度累积 | 显存只够小 batch。每次反传后先不 `step`，累积若干步再更新。`batch_size=4`、累积 3 步，等价于一次看 12 条，避免批太小导致更新不稳 |
| CPU 卸载 | 激活、梯度、优化器状态不必一直待在显存。不用时放到内存，用时再搬回来。用传输时间换显存 |
| 梯度检查点 | 前向不存全部激活，只存少量检查点。反传需要时把那一段前向重算。用时间换激活显存 |
| 混合精度 | 前向、反向的矩阵乘用 FP16 或 BF16，更新仍用高精度 |

混合精度同时留两份权重。主权重是 FP32，负责更新和累积，保证数值稳定。工作权重是 FP16 或 BF16，负责矩阵乘。三种浮点：

| 类型 | 构成 | 范围 | 硬件 |
|---|---|---|---|
| FP16 | 1 符号，5 指数，10 尾数 | 小，容易溢出或下溢 | 常见 GPU 都能算 |
| FP32 | 1 符号，8 指数，23 尾数 | 大 | 都能算 |
| BF16 | 1 符号，8 指数，7 尾数 | 指数和 FP32 一样，几乎不溢出，尾数更短 | Ampere 及更新的架构 |

还有两条不在这四项里：算子上用 FlashAttention、Liger Kernel；训练方式上用参数高效微调代替全参。

## 12. 多卡

数据并行：每张卡一份完整模型，各吃一块数据。每卡自己前向、反传，得到本地梯度；AllReduce 把梯度平均成同一份全局梯度；各卡用这份梯度更新，副本保持一致。模型一大，梯度通信会变成瓶颈。它提高的是吞吐，不是单卡装得下更大的模型。

流水线并行：按层纵向切开，每张卡拿连续的几层，降低单卡显存，用来装下单卡放不下的模型。前向把激活往后传，反传把梯度往前传。上下游互相等，中间会空出「气泡」。把一个 batch 拆成多个微批次，一张卡算完某个微批次就接下一个，气泡变小。

张量并行：一层里面的大矩阵乘拆开。每张卡只拿一部分权重。激活广播到各卡，各卡用本地分片算一部分，再通信拼回完整结果。目标仍是突破单卡的显存和算力。

专家并行：MoE 的专家本来就是互不共享参数的 FFN，直接把不同专家放到不同卡上。

ZeRO（Zero Redundancy Optimizer，微软）是加强版的数据并行。标准数据并行里每张卡都存完整的参数、梯度和优化器状态，冗余限制了能训多大的模型。ZeRO 把这些状态切成分片，分散存放；算某一层时再把需要的分片拉过来，用完释放。

| 阶段 | 分片什么 | 取舍 |
|---|---|---|
| ZeRO-1 | 优化器状态 | 最省事，显存省得有限，通信少 |
| ZeRO-2 | 优化器状态 + 梯度 | 中间档 |
| ZeRO-3 | 再加参数本身 | 单卡显存最低，通信最多 |

阶段越高越省显存，通信越重。按模型大小和机器选，不是一律开到 3。

## 13. LoRA 和 QLoRA

全参微调有效，但显存和速度都差。PEFT 只更新少量参数或加少量可训练模块。2019 年前后 BERT、GPT-2 变大，全参微调开始贵，后面分出 Prompt Tuning、Prefix Tuning、P-Tuning、Adapter、LoRA。现在 SFT 的主流是 LoRA；QLoRA 再把基座量化，消费级显卡也能跑。最好的 PEFT 可以接近全参微调。

### 13.1 LoRA

2021 年微软提出。全参微调把权重 \(W\) 更新成 \(W+\Delta W\)，\(\Delta W\) 又大又满。实践里 \(\Delta W\) 往往是低秩的，有效自由度远小于它的形状。于是把它拆成两个瘦矩阵：

\[
\Delta W=BA,\quad W'=W+BA
\]

秩 \(r\) 远小于原始维度。训练时冻住 \(W\)，只训 \(A\) 和 \(B\)。推理前把 \(BA\) 加回 \(W\)，之后没有额外计算，延迟和原模型一样。

一个 \(4096\times4096\) 的矩阵全参更新约 1600 万参数。\(r=8\) 时参数量是 \(2\times4096\times8=65536\)，大约是原矩阵的 0.4%。因此可以共享一个基座，每个任务只存一份小适配器。

低秩的含义在附录里：秩是线性无关的行或列的最大个数。秩为 \(r\) 的矩阵可以写成一个「高×r」和一个「r×宽」的乘积，大矩阵由两个小矩阵完全表示。

插在哪些线性层上：Decoder-only 里最常见的是注意力的 `q_proj` 和 `v_proj`。Query 和 Value 对任务语义最敏感，只插这两处就接近全参效果，参数和显存也最小。还要更强，再加 `k_proj`、`o_proj` 或 FFN，成本跟着涨。

工程上还有两个旋钮。缩放 \(\alpha\) 让前向变成

\[
W'=W+\frac{\alpha}{r}BA
\]

用来压训练初期增量的影响，也让不同的 \(r\) 数值上更稳。通常 \(\alpha\) 和 \(r\) 取一样；想更激进，可以取到 \(2r\) 这一档。另外对 LoRA 层的输入做 dropout，减轻小数据集过拟合。

### 13.2 QLoRA

2023 年华盛顿大学和微软。先把预训练权重量化到 4 bit，再在上面挂 LoRA。几十亿参数可以在一张 RTX 3090 或 4090 上微调，精度损失很小。三块技术：

4-bit NormalFloat。普通 4 bit 用最大绝对值把权重压到一个区间，再均匀切成 16 个格点。LLM 权重接近标准正态，0 附近密、两端稀。均匀格点在 0 附近不够细，两端又浪费。NF4 按累积概率把标准正态切成 15 个等概率区间，每个区间用中位数当代表值。格点因此在 0 附近更密。

双重量化。通常每 64 个权重共享一个 FP32 的缩放因子，这些因子本身很占地方。再把缩放因子按 256 个一组量化成 8 bit。

分页优化器。Adam 的一阶矩、二阶矩即使在 LoRA 里仍然占显存。把优化器状态拆成页，更新某一层时才把对应页载入显存，更新完写回内存并释放。显存里只留正在用的那一页。

## 14. 用库把流程接起来

| 库 | 谁维护 | 干什么 |
|---|---|---|
| TRL | Hugging Face | `SFTTrainer`、`DPOTrainer`、PPO 等，把后训练包成 Trainer |
| PEFT | Hugging Face | LoRA、P-Tuning、Prefix Tuning。`get_peft_model` 得到 `PeftModel` |
| bitsandbytes | Hugging Face | 量化。和 PEFT 合起来做 QLoRA |
| Unsloth | Unsloth | 把反向和关键模块换成 Triton 内核，同样的训练更快、更省显存。兼容 Hugging Face。Studio 是本地无代码界面，Core 是代码。TRL 管训练范式，Unsloth 管跑得快 |
| Accelerate | Hugging Face | 包住 `torch.distributed`：设备、多卡、混合精度、梯度同步，并可接 DeepSpeed、FSDP |
| LLaMA-Factory | 个人项目 | Web UI 微调上百种模型，多种算法，不用写训练循环 |

TRL 把数据分成格式和类型。格式有纯文本的标准格式，也有带角色的对话格式。类型有 Language Modeling、Prompt-only、Preference 等。`SFTTrainer` 要 Language Modeling 或 Prompt-completion；`DPOTrainer` 要 Preference。

`PeftModel` 做三件事：冻住基座；按配置加上可训练模块（LoRA 就是指定线性层里的 A、B）；`save_pretrained` 默认只存适配器权重和配置，不存整份基座。

课件里的具体配置，可以作为数量级，不是唯一正确答案：

- 全参 SFT，Qwen3-0.6B，关键词抽取数据：batch 4，累积 3 步，1 个 epoch，学习率 `2e-5`，warmup 0.1，`bf16`，按 step 评估并在结束时加载最好的检查点，最多留 2 个检查点。
- LoRA：`r=4`，`lora_alpha=8`，dropout 0.05，`bias="none"`，`target_modules="all-linear"`，`task_type="CAUSAL_LM"`。学习率用 `2e-4`，比全参高一个量级。Trainer 里传入的是包过的 `lora_model`。
- 合并：`PeftModel.from_pretrained` 再 `merge_and_unload()`，把适配器加进基座后存成普通模型，推理不再临时算低秩分支。
- QLoRA：`BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=bfloat16)`，加载后 `prepare_model_for_kbit_training`，后面的 LoRA 步骤不变。示例模型是 Qwen3-8B。
- Unsloth：`FastLanguageModel.from_pretrained(..., load_in_4bit=True)`，`get_peft_model` 的目标层写成 `q/k/v/o_proj` 和 `gate/up/down_proj`，`r=8`。`train_on_responses_only` 用 `<|im_start|>user\n` 和 `<|im_start|>assistant\n` 把损失限制在回答上，和手写答案掩码是同一件事。合并用 `save_pretrained_merged(..., save_method="merged_16bit")`。

Accelerate 不改训练脚本的写法。`accelerate config` 交互生成 yaml，`accelerate launch --config-file xxx.yaml train.py` 拉起多个进程。yaml 里要选的包括：运行环境、`distributed_type`（MultiGPU、DeepSpeed、FSDP）、混合精度、是否只用 CPU、进程数（单机多卡通常等于 GPU 数）、机器数。DeepSpeed 相关还有 ZeRO 级别、梯度累积、梯度裁剪、优化器或参数是否卸载到 CPU、ZeRO-3 初始化，以及 `zero3_save_16bit_model`。最后这项为 false 时，存下来的是分片，还要再手动合成完整的 16 bit 权重。

启动后的分工：`accelerate launch` 设置分布式环境变量并拉起进程；Trainer 建 Accelerator，发现要用 DeepSpeed 就把训练参数和 DeepSpeed 配置对齐；真正开始前，模型、优化器、调度器被 DeepSpeed 包一层。跨卡的参数、梯度、优化器状态由 DeepSpeed 组织，底层通信仍是 PyTorch distributed 和 NCCL。

LLaMA-Factory 支持 Alpaca 和 ShareGPT。自己的数据放进 `data/`，在 `dataset_info.json` 里登记文件名、`formatting: sharegpt`、消息列和 role/content 标签，Web UI 里才能看见。安装是 Python 3.12 的虚拟环境里 `uv pip install -e .`，`llamafactory-cli webui` 默认在 `0.0.0.0:7860`。界面里选本地模型（名称用 Custom）、打开 LoRA、设轮数和每集最多样本数、设输出目录。导出时把适配器和基座合并。

## 15. 用 vLLM 部署

vLLM 是面向高并发的推理框架，底层是 PyTorch。和直接用 Transformers 推理比，吞吐可以高一个数量级。原因是 GPU 利用更充分、用 PagedAttention 管 KV Cache、连续批处理，并且服务兼容 OpenAI API，能直接加载 Hugging Face 模型。

环境：Linux，Python 3.9 到 3.12。

单卡：

```text
vllm serve /path/Qwen3-8B-sft-all --served-model-name Qwen3-8B-sft-all --max-model-len 32K
```

`--max-model-len` 里小写 `k` 是 1000，大写 `K` 是 1024。客户端的 `model` 必须和 `--served-model-name` 一致。服务默认在 `http://localhost:8000/v1`，`api_key` 可以填占位符。

多卡：单机优先张量并行；MoE 再打开专家并行。单靠张量并行仍放不下，才加流水线并行。多机时，张量并行的 AllReduce 跨机器太贵，所以节点内做张量并行，节点之间做流水线并行。

```text
vllm serve .../Qwen3-14B --tensor-parallel-size 2 --max-model-len 32K
vllm serve .../Qwen3-30B-A3B --tensor-parallel-size 2 --enable-expert-parallel --max-model-len 32K
```

调用方式是 OpenAI 的 Chat Completions，也可以用 `langchain_openai.ChatOpenAI` 指到同一个 `base_url`。Qwen3 的思考模式通过请求里的 `extra_body.chat_template_kwargs.enable_thinking` 关。

### 15.1 推理框架在解决什么

三件事：很多请求同时来时怎么调度；长上下文、高并发时 KV Cache 怎么少浪费显存；吞吐、时延和 GPU 利用率怎么一起上去。

PagedAttention 按操作系统的分页来管 KV Cache。先按可用显存划一块池，切成固定大小的 block，例如一块存 16 个 token 的 K、V。Block Manager 管哪些块空闲、哪些被占用。新序列按 prompt 长度领走足够的块，存放 prefill 产生的缓存；decode 变长了再申请；生成结束把块还回池子。逻辑上 token 是连续的，物理上不必连续，序列拿一张 `block_table` 做逻辑块到物理块的映射，attention kernel 按这张表读写。

相同的 token 前缀可以共享块。多个请求用同一段 System Message 时，这段前缀的 KV 只算一次、存一份，用引用计数。全部引用都结束，块才回收。

调度器维护等待队列和运行队列。新请求先等待；prefill 做完、正在逐 token 生成的进入运行队列。每一轮 step 按队列、剩余 KV Cache、batch 上限和 token 预算，决定这一轮跑谁、跑多少 token。等待中的请求要先分配缓存并做 prompt 的 prefill；运行中的请求做 decode，简化实现里一轮通常只为一个请求生成一个新 token。一轮结束：prefill 完成的进运行队列；遇到 EOS、最大长度或其他停止条件的移出并释放缓存。课件把 chunked prefill 标成 vLLM 里更复杂、这里不展开的部分。

这就是连续批处理。静态 batch 从 prefill 绑到 decode，要等这一批全部结束才接下一批。连续批处理里，batch 每轮都在变：新请求可以插入，正在 decode 的留下，完成的退出，长 prompt 也可以拆开逐段调度。prefill 和 decode 可以分轮做，也可以在更完整的实现里同一轮混合。

另外三种执行优化：

| 手段 | 改的是什么 |
|---|---|
| FlashAttention | 不改注意力的数学。少存中间结果，少在显存里来回搬，让 GPU 把整段注意力一次算完 |
| Tensor Parallel | 和训练时一样，把一层里的大矩阵切到多张卡。优化的是单次 forward 的显存和算力，不是请求调度 |
| CUDA Graph | decode 每步都在重复形状稳定的一串 kernel。传统方式由 CPU 逐个 launch。把这串固定形状的操作捕获成图，之后整图重放，去掉重复的 CPU 调度 |

## 16. EvalScope

EvalScope 是魔搭的评测和性能基准框架。它既能压测服务，也能做能力评估，并支持自定义数据集。官方数据集列表在文档的 supported dataset 页。

压测打的是已经起来的 OpenAI 兼容接口：

```text
evalscope perf \
  --url http://127.0.0.1:8000/v1/chat/completions \
  --parallel 5 --number 20 \
  --model Qwen3-8B-sft-all \
  --api openai --dataset openqa --stream
```

`--parallel` 是同时在飞的请求数，`--number` 是总请求数。`--stream` 测的是流式输出，不是一次性把整段返回。

读报告时分成四组：

| 组 | 看什么 |
|---|---|
| 完成情况 | 总耗时、并发数、总请求、成功和失败 |
| 吞吐 | 输出 token/s、输入加输出的总 token/s、请求/s |
| 延迟 | 单次平均耗时、首 token 时间、每个输出 token 的平均时间 |
| 长度 | 每次请求的平均输入 token、平均输出 token，以及流式包的延迟和每请求包数 |

能力评估示例是 AIME-2024：

```text
evalscope eval --model Qwen3-8B \
  --api-url http://127.0.0.1:8000/v1/chat/completions \
  --datasets aime24
```

课件用同一套比较了 Qwen3-8B 和 Qwen3-0.6B，8B 明显高于 0.6B。评估还可以覆盖推理、指令跟随、智能体能力和多语言，不限于这一道数学集。

## 17. 应用岗要会划的边界

课件把结构、损失和并行写完了。面试里这门课要收成几句能拍板的话：知识放哪、行为怎么改、显存报哪几块、对齐失败先查什么。

### 17.1 知识、格式、偏好各走一条路

预训练把语言和通识写进参数，更新一次很贵。SFT 和 LoRA 把格式、术语、步骤和工具习惯拉齐。偏好对齐用 DPO 这一类离线方法。知识经常变、回答还要引用原文，走 RAG。三条经常一起用，但不要互相替代。

两个用错的方向要单独记住。微调不是知识库更新：制度、价格、接口每天在变，写进权重就过时，而且改一次要重新训练和回归。LoRA 也只改行为，底座不会的事实不会因为多训了两个小矩阵就出现。

和传统模型的差别放在任务形态上。传统模型通常为一个任务准备特征、数据和一套权重，换任务就换模型。大语言模型先做下一 token 预测，再用提示、检索、工具或轻量微调接很多任务。生成是按分布采样，不是查表。参数规模不保证事实正确。

幻觉在对话里是错句子。接到工具上会变成错单、错邮、错删。兜底是校验、确认和权限，不是再把提示词写长。

Transformer 成为主流，是因为自注意力替换了 RNN 的逐步递归：训练可以按序列并行，也能直接看到远处的 token。CNN 要堆很多层才有长感受野。代价是标准注意力的计算和显存随序列长度近似平方增长。长上下文靠窗口、缓存和截断，不是把窗口无限拉大。应用岗答到这里即可。

GRPO 是用一组采样里的相对优势做策略优化，奖励可以是规则。被问到再展开，不要放进应用岗的自我介绍。

### 17.2 窗口、预填和解码

上下文变长，主要增加的是预填的计算和 KV Cache 显存。一个个往外生成的 token 数，决定解码延迟和后半段费用。多轮 Agent 里，历史、工具说明书和工具结果都占同一扇窗口，要主动截断和摘要，不能等爆窗再处理。

计费和切分都按 token，不按汉字或单词。同一段中文在不同词表下可以差一截。换模型就要用那一个模型的 tokenizer 重算：上下文够不够、chunk 有没有把实体切开、账单对不对得上。上一家的「500 字一块」不能沿用。工具参数和 JSON Schema 也吃 token，Schema 写得过胖会直接进成本。

### 17.3 量化、蒸馏、LoRA 是三件事

| | 改什么 | 适合 | 不适合 |
|---|---|---|---|
| 量化 | 权重和计算的数值精度。行为目标不变 | 省推理显存和成本 | 量化后不回归函数调用就上线。工具调用会先于开放问答掉稳定 |
| 蒸馏 | 模型大小。学生学教师在各个 token 上的概率，或教师写出的推理过程，而不是只背一个硬标签 | 高并发、边缘、便宜路由 | 把蒸馏当成灌新知识。教师会胡编，学生会把这个习惯一起学走，蒸馏后仍用业务集验收 |
| LoRA | 在冻结权重旁边加一小块增量，改格式和话术 | 领域输出习惯稳定、数据不多 | 用它追每天变化的制度。那种变化进索引 |

一种实用的蒸馏分两段。先让教师在「先想再答」和「直接答」两种模式下写出文本，学生用交叉熵去拟合，教师不参与学生的每一步更新，这是离策略。再让学生对同一问题自己出分布，用和教师分布的 KL 散度继续拉齐，这是同策略。只做第一段，学生背的是教师的句子。

### 17.4 LoRA 的起点、秩和部署形态

原权重冻结。要改的线性层旁边加 \(A\) 和 \(B\)，生效时是原权重加 \(BA\)。\(A\) 用随机正态初始化，不同的行一开始就能收到不同梯度。\(B\) 初始化为 0，训练起点的增量就是 0，输出和原模型一致。

原论文主要加在注意力的 Q、K、V、O 上。实践里常扩到前馈的上投影和下投影；用了门控激活，再加门控那一个矩阵。加得越多越接近全参的成本和过拟合风险。

秩没有万能值，从小往大试，常见起点是 8 或 16。秩小参数少、不容易记住训练集，复杂任务可能不够。秩大更接近全参，也更贵。\(\alpha / r\) 决定增量相对原权重有多大。常见拿 \(\alpha = 2r\) 做起点，再用验证集比较 1 倍、2 倍、4 倍。单独背一个 \(\alpha\) 没有意义。过拟合就减小秩、加数据、加大权重衰减，或在 LoRA 层上加 dropout。

合并是把 \(BA\) 加进原权重，推理不再多一次小矩阵，速度和显存与普通模型一样。代价是不能再热切换任务。一个底座服务多个任务时保留未合并的适配器；确定只部署一个任务时再合并。

全参和 PEFT 的选择看数据和想动多少通用能力。数据少、显存紧、只改格式，用 LoRA。数据多、资源够、要尽量贴近全参效果，再用全参。全参的效果上限更高，数据少时也更容易过拟合，并碰到原来的通用能力。PEFT 依赖底座本身会的东西。

### 17.5 报显存时把五块分开

混合精度、Adam 的口算：参数和梯度各约 2 字节乘参数量，Adam 的一阶矩和二阶矩约 8 字节乘参数量。7B 这三项大约是 14GB、14GB、56GB。激活随批次、序列长度和隐藏维涨，往往比参数更不可控。临时缓冲另计。不要把「7B」说成「14GB」。

对应的省法：混合精度砍参数和梯度；梯度检查点用重算换激活；梯度累积把每步的微批次变小；ZeRO 按阶段拆优化器、梯度和参数；模型并行让每张卡只拿一部分层。显存只差一点点时，先用 ZeRO 和混合精度。Offload 到 CPU 或磁盘能把训练跑起来，搬运会明显变慢，不要作为第一步。

FP16 范围小，梯度一乘就可能下溢成 0。损失缩放先把损失放大再反传，更新前除回去。真正写回参数仍用 FP32 主权重，再同步回半精度的工作权重。BF16 的指数位和 FP32 一样宽，比 FP16 不容易溢出，显存仍是 2 字节。

### 17.6 并行的代价

数据并行里，每张卡先算本地梯度，再合成同一份去更新。所有卡都把梯度发给某一台再广播回来，那一台的带宽会堵死。Ring AllReduce 把卡连成环：先分块传递并累加，再把结果传一圈，每张卡都拿到完整梯度，通信量摊开。计算可以和通信重叠，同步点仍然要等最慢的那张卡。

流水线的代价是气泡：前一段还没算出激活，后一段在等。微批次能把气泡摊薄，段与段的计算量差太多仍会空转。张量并行的代价是每一层都要跨卡通信。机器之间带宽不够时，通信时间会盖过计算收益。三维并行是数据、流水线、张量一起用，配置和排障都更重。先证明单机放不下，再上这套。专家并行只适用于混合专家：专家是独立的前馈，没有共享权重才好切开。

### 17.7 样本、在线离线、DPO 失败和思维链

SFT 常见两种 JSON。Alpaca 是单轮：指令、可选输入、输出。ShareGPT 是多轮：每条只有角色和内容。要函数调用，就在对应轮次写工具调用和工具结果，不能把调用塞进普通助手文本里假装模型会了。公开数据来自 Hugging Face、ModelScope。业务数据来自文档、客服和工单，必须脱敏，评测题不能进训练集。多轮样本要留下真实的失败和追问，只留完美单轮，模型不会处理中断。

RLHF 三步之后还有一项约束：提高奖励的同时，用惩罚把新策略拉在原来的 SFT 模型附近，避免为了刷分把话术训崩。经典算法是 PPO，裁剪范围通常在 0.1 到 0.3，要单独调。PPO 是在线策略：边采样边更新，用的是当前模型刚刚生成的回答。SFT 和 DPO 是离线策略：用事先收集好的数据，训练时不再跟环境交互。应用团队做偏好对齐，优先说明为什么选 DPO：少训一个奖励模型，也少一条不稳定的在线采样。DPO 因此更依赖这对数据的质量，也不能拿奖励模型给没标注过的新回答打分。

DPO 训练时，chosen 和 rejected 的隐式奖励一起掉，多数是偏好对坏了，不是学习率太小。常见三种：标注打环，A 优于 B、B 优于 C、C 又优于 A；正例和负例差别太小；标签反了。模型无法判断该提高谁的概率，更新互相抵消。先查标注是否一致、正负例是否真的不同。

思维链有三种数据形态。提示词要求先写步骤，只改当次推理，不改权重。SFT 是在训练集里放入带步骤的回答，让模型模仿这些文本。强化学习是给「答案正确」和「步骤完整」奖励：PPO 用奖励模型给展示了过程的输出加分；DPO 把带步骤的当正例、不带步骤的当负例；GRPO 用一组采样里的相对优势，奖励可以是规则。规则必须真的检查步骤。只奖励最终答案，模型会学会跳过过程。

### 17.8 上线后先看的两个时间

首 token 时间看的是预填、排队和网络，用户感觉「开始说话了没有」。端到端任务完成时间还包含解码、工具和人工等待。优化其中一个，另一个可以不动。EvalScope 压测里的 Average time to first token 就是前一个。

## 18. 附录里的两块数学

二维旋转：向量 \((r\cos\phi,\ r\sin\phi)\) 逆时针转 \(\theta\)，坐标变成 \((r\cos(\phi+\theta),\ r\sin(\phi+\theta))\)。展开后就是左乘

\[
\begin{bmatrix}\cos\theta&-\sin\theta\\ \sin\theta&\cos\theta\end{bmatrix}
\]

连续旋转的角度相加，所以 \(R(\alpha)R(\beta)=R(\alpha+\beta)\)。转置等于反向旋转：\(R(\theta)^\top=R(-\theta)\)。RoPE 把「绝对位置上的两次旋转」收成「相对位置上的一次旋转」，用的就是这两条。

矩阵的秩是行向量或列向量里线性无关的最大个数，也就是矩阵里独立信息的多少。秩为 \(r\) 时，存在两个更小的矩阵，乘积正好等于它：一个提供 \(r\) 个独立方向，一个提供这些方向的组合系数。LoRA 假设微调产生的 \(\Delta W\) 接近这种低秩矩阵，所以用 \(BA\) 去近似，而不是把整张 \(\Delta W\) 训出来。
