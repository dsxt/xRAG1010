# AI Agent 应用工程师学习规划

> 岗位目标：Agent 高端专家（大模型上层应用、智能体业务系统）。做能规划、调用工具、对外服务的单 Agent，以及一套多智能体集群。不训练底层模型，不碰 CUDA 推理内核。
> 规划由四个项目组成。P1 是知识库（xRAG1010，主体已完成）。P2 是单 Agent 业务系统。P3 是 Agent 集群。P4 是把它们做成可部署的线上服务。仓库分开，简历分开写。
> 下文第二、三节只对照 P1 的代码。第四到十节是四个项目共用的知识点和闸门。
> P1 现在是固定图，还不是 Agent。检索、融合、重排、澄清、拒答由代码决定。简历只写对应仓库里已经存在的东西。
> 验收基准：每个项目的主线停在 L4；少量 L5 用一页方案口述。时间不作为闸门。

## 〇、规划包含四个项目

目标岗位要的是一套能对外服务的智能体业务系统，外加一套多智能体集群。四个项目分开写简历。后一个项目的交付物不要提前写进前一个项目。

| 项目 | 对应岗位能力 | 仓库 | 做到什么算完成 | 明确不做什么 |
|---|---|---|---|---|
| P1 知识库 | RAG、切片、重排、Milvus、评估 | 当前仓库，主体已完成 | 导入到 SSE 已有。收尾：引用或证据级拒答、≥30 题和三项数字、一类检索坏例的前后数字。同一题集上做一次轻量图谱对照、一次 Weaviate 对照 | 不在这里做规划循环和多角色。Pinecone 有账号再导一小批，没有账号就写成选型笔记，不阻塞 |
| P2 单 Agent 业务系统 | 任务分解、决策、记忆、工具调用、业务工作流 | 新仓库 | 三个模块能指出来：任务分解引擎、决策引擎、记忆模块。工具含检索（调用 P1）、校验、联网、确认后登记维修记录。ReAct 与 Plan-and-Execute 都跑通。ToT、ReWOO 用同一小批题做 token 对照，不上生产路径 | 不复制 P1 的导入和切分。不把 Milvus 表达式交给模型。不把 ToT 接到线上 |
| P3 Agent 集群 | 多智能体协作 | 新仓库 | 四个角色：编排者、检索专员、校验专员、工单专员。主实现用 LangGraph。CrewAI 或 AutoGen 再实现同一业务一次，留下完成率、重复调用、token 的对照。LlamaIndex、Swarm、MetaGPT、Camel 各跑通官方最小示例并写一页控制权差别 | 两套集群不同时上线。校验专员不能引入新事实。角色没有的工具调用不到。指标差于 P2 时，默认退回单 Agent |
| P4 线上服务 | FastAPI、Docker、K8s、高并发、可观测、成本、容错 | 新仓库，部署 P1–P3 | 题集可重复跑；Trace 能区分幻觉、工具失败、规划失败；回放；取消；Docker 镜像；K8s 上 Deployment、Service、配置外置、存活/就绪探针、HPA。本地 kind 或 k3s 跑通，并做一轮有限并发（例如 20）看超时和限流 | 不写「K8s 生产调优」。不自研评估平台，用脚本加现成 Trace 字段。不把模型权重打进镜像 |

调用关系：P2 把 P1 的「混合检索 → RRF → 重排」当成检索工具，维修记录写到 P2 自己的业务表。P3 的检索专员只能调这个检索工具，工单专员只能调 P2 已经确认过的写接口。P4 负责部署和观测，不改算法。

顺序：

1. P1 的引用、拒答和三项数字先落地，作为后面的对照基线。
2. P2 在题集冻结之后编码。在此之前只画三个模块和工具边界，不把循环写进 P1。
3. P3 在 P2 单链路已经有成功率和 token 数字之后再拆角色。没有单 Agent 基线，集群的「更好」无法证明。
4. P4 的题集脚本可以和 P1 收尾并行。镜像和 K8s 等 P2 的服务接口稳定后再部署。P3 用同一套部署方式加进去。

和上一版规划的差异（上一版把集群、第二套框架、图谱、K8s 留在口述）：

| 主题 | 上一版 | 本版 | 更好的做法 |
|---|---|---|---|
| 多 Agent | 不立项 | P3 做成四个角色的集群，并和 P2 比数字 | 岗位要求能落地协作，本版对。生产默认可以仍是单 Agent。没有对照数字就上集群，上一版的谨慎更好 |
| ToT、ReWOO | 只读论文 | P2 用小批题测 token 和成功率，不进线上 | 线上用 ReAct 或 Plan-and-Execute 更稳、更省。只阅读过不了岗位里的推理范式。对照实验比两个极端都好 |
| 第二套框架 | 只读 README | LangGraph 做主路径；CrewAI 或 AutoGen 把同一集群再做一次；其余框架跑通最小示例 | 六套都做成业务系统不值得。全部不写又对不上岗位清单。主路径一套做深、协作框架一套对照、其余跑通示例 |
| 知识图谱 | 不编码 | P1 同一题集做轻量图谱对照，主检索仍是混合检索加过滤 | 操作步骤用过滤和父子块更好。配件、错误码、适用型号这类关系题，图谱更好。两条都留数字，不互相替换 |
| 向量库 | 只有 Milvus | Milvus 继续做主库；Weaviate 本地导入同一批切片；Pinecone 写托管差异 | 当前稀疏向量加标量过滤，Milvus 更好，不迁移。岗位点了三家，选型要有一次对照 |
| 写操作 | 单独一个小项目 | 并进 P2，成为业务系统里的一个工具 | 岗位要的是从 0 到 1 的完整系统。确认、幂等、补偿这些约束不放松 |
| K8s | 只口述 | P4 写出能在 kind 或 k3s 跑起来的部署 | 岗位把 K8s 列为必备，本版对。简历停在「能部署、能扩容时状态在外部」，不写生产调优 |

仍不立项的只有：自研评估平台、Computer Use、前沿模型接入、开源贡献当作必做项。开源贡献是加分：P2 跑稳之后，可以向所用框架提一个你已经复现过的小问题，没有合并也不影响主线。多租户口述到「过滤条件和缓存键都带租户字段」。

## 一、P1 现在能证明什么

能指着代码讲完的范围：

- 导入：PDF（MinerU）或 Markdown 进图片摘要、标题切分、商品名抽取、BGE-M3 稠密加稀疏、按 `file_title` 先删后插。
- 查询：商品名对齐决定反问、拒答或检索；三路并行（混合检索、HyDE、MCP 联网）；RRF 只融合前两路；重排把本地和网页放在一起做断崖截断；答案节点生成或透传。
- 服务：导入 `8000`（上传、状态、`import.html`），查询 `8001`（提交、SSE、历史、健康检查、`chat.html`）。
- 会话：Mongo `chat_message`，默认最近 10 条；反问和拒答写入历史后本轮结束。

P1 收尾还要在本仓库证明的，只有忠实度这一块：

- 回答是否忠实于切片（没有题集，没有忠实度数字）。
- 一类检索坏例的修改前后数字。

下面这些不属于 P1，不要再补进这条固定图：

- 任务分解、决策循环、记忆模块、确认后的维修登记：P2。
- 多角色协作：P3。
- Trace、跑分、Docker、K8s：P4。P1 只有文本日志和内存任务表。

一句话讲法：

基于 LangGraph 和 Milvus 的产品手册知识库。导入侧完成 PDF 解析、图片摘要、标题切分和 BGE-M3 混合向量入库。查询侧用商品名对齐决定反问、拒答或检索，并行做混合检索、HyDE 和 MCP 联网，再用 RRF 与重排融合，最后按证据草稿生成回答，并用 SSE 把 token 和图片推到页面。检索决策写死。模型决定「澄清 / 查本地 / 查网页 / 直接答」是 P2，不在本项目里。

简历禁止写：精通全部 Agent 框架、自研本体、自研评估平台、K8s 生产调优、前沿模型接入、未合并的开源贡献。没有量化数字时不写「构建评估集」，也不编造指标。页面能答，只说明 P1 的演示链路闭合。P3 的集群在对照数字出来之前，不写「优于单 Agent」。

### 2.3 现成坏例

原规划写「答案节点为空」时，这条已经过时。下面这些仍是代码里的真实行为。修一条并留下前后数字，就够一面深挖。优先用这里的，不要另造玩具故障。

1. **高置信度过滤过宽。** 说明文字写的是多个分数 > 0.85 时只留精确匹配或最高分。代码把所有 > 0.85 的名字都放进 `item_name in [...]`。多商品同时过滤会把不相关手册带进上下文。说明和代码以代码为准。
2. **无商品名则全库检索。** 提取不到名称时不拦截。闲聊或指代失败会打到整库。若历史里已经确认过型号、这一轮抽取失败，直接拒答会误伤追问，应沿用历史里的确认名，而不是空过滤。
3. **重排失败仍继续。** 异常后分数为 `None`。断崖检测跳过空分数，截断位置不可解释。三路检索失败同样写成空列表，和「真的没召回」分不开。
4. **重导空窗。** 按 `file_title` 先删后插。删除成功、插入失败时，这份手册暂时检索不到。注释里出现过「商品名是幂等依据」，代码按文件标题删。
5. **HyDE 把检索带偏。** 假设答案若编造了手册里没有的步骤，稀疏/稠密向量会去找「像这段编造」的切片。假设原文本身没有进答案提示词，带偏发生在召回，不发生在把虚构段落当证据贴进回答。
6. **网页片段和本地切片在重排里平等竞争。** 已有 `source` 字段，没有来源优先级，提示词也没写操作步骤以本地为准。
7. **历史窗口和字符预算会丢较新的话。** 默认 10 条，没有摘要。答案侧文档和历史共享 12000 字符，先装重排文档，历史从旧到新装，预算不够时丢掉的是较新的轮次。当前问题另有字段，不会被这段历史裁掉。
8. **生成不做引用和证据级拒答。** 无参考内容仍调用模型。提示词是「尽量基于参考内容」。关键结论没有强制带 `chunk_id` 或 URL。商品级拒答（库中无此商品、多个候选要反问）已经有了，和「有商品但片段不够」不是同一件事。
9. **图片提取比提示词松。** 提示词要求图片只来自本地切片正文。提取函数会把任意文档里、后缀像图片的 `url` 放进 `final`，网页结果上的图片地址也能出现在页面上。
10. **阻塞生成失败看起来像正常回答。** 流式出错会推 `error` 并抛出。非流式出错写成「抱歉，生成回答时出现错误。」放进 `answer`，任务仍可能按完成返回。调用方分不清模型拒答和调用失败。
11. **断开页面不会停图。** SSE 发现浏览器断开就结束生成器，后台图和模型调用继续跑。任务表在内存里，也没有取消标记。
12. **健康检查只表示进程活着。** `/health` 返回 `{"ok": true}`，不探 Mongo、Milvus、MinIO、模型接口。

过滤表达式注入的转义已经有了，还缺一条「不转义就会改范围」的对照。检索片段和网页片段的提示注入还没有实验。

### 2.4 服务边界

| 接口 | 作用 |
|---|---|
| `POST /upload`、`GET /status/{task_id}`、`GET /import.html` | 导入。长任务放在 `BackgroundTasks` |
| `POST /query`、`GET /stream/{session_id}` | 查询。流式先建队列再后台跑图；非流式用线程跑完再返回正文 |
| `GET/DELETE /history/{session_id}` | 读最近历史、清空会话 |
| `GET /health` | 进程存活 |

异常原文会进 SSE 的 `error`，非流式失败也会把异常字符串放进 `answer`。跨域是 `allow_origins=["*"]`。这两个都比「异常不进模型上下文」更松，上线前要收紧，演示阶段知道即可。

## 三、规划与代码的差异

原规划写成的时候，答案节点还是空的，也没有页面。下面按现在的代码改口径。<span style="color:#c0392b">【差异】</span> 只标记规划和实现不一致的地方。

| 主题 | 规划当时的要求 | 代码现在的做法 | 更好的做法 |
|---|---|---|---|
| 答案节点 | 按证据引用或拒答，空证据不调用模型 | 能生成、能流式、能透传反问/拒答、能出图 | 保留代码的透传、SSE 和图片通道。忠实度规则用规划：关键句带 `chunk_id` 或 URL，证据为空或无关时拒答，并区分「库中无此商品」和「有商品但片段不够」 |
| 反问怎么结束 | 写入 answer 后结束图 | 条件边进入答案节点，已有 answer 只推送 | 代码更好。空节点结束会让流式协议和写历史分成两套。Checkpointer 解决的是「图停在半路再恢复」，和「本轮已经答完」不是同一问题，规划里的中断仍然要学 |
| 流式 | 图的 `values` 流不算 token 流，SSE 放到服务化闸门 | 图继续用 `values` 驱动节点；答案增量走会话队列 | 代码的双通道更好。`values` 用来跑图，SSE 用来给人看。规划里的取消、超时、任务状态外置仍然更好，当前都在进程内存 |
| 服务接口 | 当时写没有 | 导入和查询拆成两个 FastAPI，各带一个页面 | 有接口比「没有」更好，足够当演示。规划里的取消、Trace、回放、应用镜像仍然缺，那些是上线能力。拆进程有利于导入和查询分开扩，也带来两份内存状态、没有网关、没有鉴权 |
| 上下文预算 | 按 token 分 7 段，先砍 HyDE 原文、网页、低分切片，再砍更早的历史 | 重排文档和历史共享 12000 字符；历史从旧到新截断 | 字符预算适合作为第一道闸，代码这层留下。按 token 记账、并且从最近一轮往前保留，用规划。HyDE 原文不进证据区，代码已经做到 |
| 来源优先级 | 操作步骤以本地手册为准，网页只补充并标明 | 重排文档有 `source`，分数平等；提示词未写冲突规则 | 字段用代码的 `source`。策略用规划 |
| 图片 | 原规划没有单独列 | 提示词限制本地切片；`final.image_urls` 还会收网页上的图片后缀 URL；页面能渲染 | 手册场景用提示词这条更严的规则。网页图不要和面板图混在同一个图片区 |
| 高置信度对齐 | 收窄为单一确认名，并做前后对比 | 说明写单选，代码仍全收 > 0.85 | 规划和说明更好。以代码为准讲现状，改的时候改代码，不要只改注释 |
| 无商品名 | 拦截，避免闲聊打全库 | 过滤条件为 `None` | 闲聊和抽取失败用规划，应停检索或拒答。历史里已有确认型号时，沿用该型号，这是两边合在一起才完整 |
| HyDE | 假设文档不能当证据；要做关闭 HyDE 的对照 | 假设文档只用于检索向量，且拼上了原问题；没有对照实验 | 代码的两点都更好：不把假设段落贴进回答，向量里保留原问题，避免假设文档丢掉型号和否定。带偏风险还在，对照实验仍按规划做 |
| 节点返回值 | 返回局部更新；失败写成 `error`，不要写成空列表 | 三路检索返回局部字典；其后节点返回整份 state；失败多数是空列表 | 三路返回局部字典，这点和规划一致，也是这张图没被并行写坏的原因。失败写成空列表，规划更好。其后串行节点返回整份 state，在字段不冲突时能工作，有共享字段的下一张图再用局部更新 |
| 网页进不进 RRF | 不进，因为没有稳定 `chunk_id` | 代码不进；RRF 的说明文字写了会融合网页 | 代码更好，理由仍是规划那条。讲的时候以代码为准 |
| 重排失败、重导空窗、10 条历史无摘要 | 标成坏例 | 都还在 | 规划更好，还没改 |
| 任务与取消 | 外部存储；取消后不再进入新的检索或写工具 | 内存任务表；浏览器断开后图继续 | 演示用代码足够。要谈恢复和取消，用规划 |
| 评估、ReAct、Checkpoint、Trace、回放 | 主线交付物 | 仓库里没有 | 规划保留。页面能答不能代替这些交付物 |
| 健康检查 | 原规划没有单列 | 只有进程存活 | 补一个就绪检查更好：Mongo、Milvus、MinIO、模型接口各探一次。存活和就绪分开 |
| 导入进度 | 原规划没有写页面进度 | 基类写任务表；服务里另有一段按 `node_` 键解析 `values` 流的循环，对不上状态字段 | 讲进度时讲基类。那段循环不要当成协议 |

注释和代码不一致的地方，面试只讲代码：高置信度全收、RRF 不含网页、导入进度来自基类。

## 四、继续有效的学习原则

原规划的等级、打卡动作、必保能力和「少铺框架」保留。项目边界以第〇节为准。

1. 闸门只看交付物。时间少时，当次只完成「读材料 + 在所属项目里修一个坏例 + 记前后数字」。
2. 四个项目分开做。禁止的是与业务无关、跑完即丢的框架合集。P1 的导入和检索不复制到 P2。P2 调用 P1，并包含确认后的写工具。P3 是集群，调用 P2 的工具。P4 做部署和观测。
3. 顺序：P1 把答案补成「引用或拒答」并做出评估基线；P2 做任务分解、决策、记忆和写工具；P3 在 P2 有数字之后再拆角色；P4 的题集脚本可以和 P1 收尾一起做，K8s 等接口稳定后再上。P1 的答案节点已经能出字，收尾修的是忠实度。
4. 混合检索不要按 BM25 教程重做。主路径是稠密向量 + BGE-M3 稀疏向量 + 同一路内加权。跨查询策略用 RRF。BM25、Weaviate、轻量图谱都只在 P1 题集上做对照。
5. 商品名对齐仍是操作步骤题的主方案。轻量图谱做关系问法的对照，不替换主检索。本体保持一页方案。
6. 人机确认有三种，都要能讲差别。P1：本轮走完答案节点，下一轮靠 Mongo。P2：同一 `session_id` 用 Checkpointer 停在澄清节点；写工具之前另有确认页，展示幂等键和参数。P3：工单专员看不到未经确认的写接口。
7. 幂等分成两层。P1 的文档重导按 `file_title` 先删后插，已有，而且有空窗。P2 的工具幂等键还没有。
8. MCP 先讲 P1 里的客户端。百炼 WebSearch 已接入，失败隔离也有了。自建 MCP Server 放在 P2，用来理解协议，不替换 P1 的联网路径。P3 的角色通过工具列表看到能力，不另造一套传输。
9. Token 台账按项目记。P1 额外贵的是商品名抽取、HyDE、图片摘要、重排和最终回答。P2 额外贵的是循环轮次。P3 额外贵的是每个角色各一份上下文。
10. ToT、ReWOO、第二套协作框架、LlamaIndex 和其余多智能体框架的最小示例、轻量图谱、K8s 部署，都要有代码，分别落在 P2、P3、P1、P4。它们不上生产主路径，也不许只停留在阅读。P2 在 P1 的基线数字落地之前不写进简历。P3 在和 P2 的对照数字出来之前不写「优于单 Agent」。

打卡动作不变，每完成一个知识点：

1. 只读该知识点对应的材料章节。
2. 在第〇节指定的那个项目里做最小改动或最小对照，不新开框架 Demo。
3. 主动构造坏例并复现。P1 优先用 2.3 节。
4. 记 3 道口述题：原理、踩坑、什么场景不用。
5. 笔记格式：现象 → 指标 → 根因 → 代码改动 → 修改前后数字。属于哪个项目写在笔记标题上。

本地基线保持：Ollama（Qwen / Llama）用于可控实验；现有 DashScope 兼容接口、BGE-M3、Milvus、Mongo、MinIO、MinerU 用于业务链路。评估稳定后，才用托管大模型做对照，不把对照模型的结果写成唯一结论。

## 六、知识点清单

材料只读对应章节。代码落在第〇节指定的项目里，P2/P3/P4 的任务不要改回 P1 的固定图。面试题保持「原理、踩坑、什么场景不用」。

### 6.1 固定流程图和 Agent 循环怎么拼

<span style="color:#c0392b">【部分已有】</span> 固定图已经能从上传走到页面上的回答。缺的是决策层。

必须写死在代码里的：权限、写操作确认、最大检索次数、最大重排条数、空召回时禁止编造、过滤表达式的拼装、删除再插入的顺序、来源标记（local / web）、图片是否允许来自网页。

可以交给模型的：当前问题是否还指向上一轮商品、要不要检索、查询怎么改写、证据够不够、要不要再查一次。

推荐形态：Agent 循环在外，现有「混合检索 → RRF → 重排」收成一个检索工具。模型只看到工具描述和截断后的证据，看不到 Milvus 表达式。

口述题：复杂业务为什么不把整张图交给模型规划？把检索收成工具之后，模型还能不能改过滤条件？什么业务继续用纯固定图、不上 Agent？

### 6.2 有依据生成

<span style="color:#c0392b">【差异】</span> 生成通道用代码，验收标准用规划。见第三节第一行。

答案节点要同时做到：

- 只根据本次 `reranked_docs` 回答，每条关键结论带 `chunk_id` 或网页 URL。
- 证据为空、或证据与问题无关时拒答，并说明是「库中无此商品」还是「有商品但片段不够」。
- 本地手册和网页冲突时，产品操作步骤以本地为准；网页只补充本地没有的信息，并标明来源。
- 上下文里的证据包一层不可信数据边界，避免片段里的指令被当成系统指令。
- 图片区只放本地切片里的图片 URL。`final` 事件和提示词用同一条规则。

检索命中了，模型仍可能忽略片段另编步骤。评估要分开报。

口述题：如何证明回答没有使用知识库以外的产品参数？拒答和「检索为空」为什么不是同一个指标？什么问题即使检索到了也不该直接生成操作步骤？

### 6.3 查询变换，以及 HyDE 什么时候帮倒忙

<span style="color:#c0392b">【本项目已有】</span> 指代改写、独立问题改写、HyDE。向量文本拼了原问题，假设原文不进答案。

补认知即可，不必每种都上线：多查询、子问题分解、step-back。对照实验只做一件：同一批评估题，关闭 HyDE 再跑，看召回和错误引用是否变化。

口述题：短问句为什么和长切片不好对齐？HyDE 生成了错误步骤时，检索会往哪偏？什么问题不该先生成假设文档？

### 6.4 稀疏检索的三种东西不要混着讲

| 手段 | 本仓库 |
|---|---|
| 稠密向量 + 余弦 | <span style="color:#c0392b">【本项目已有】</span> BGE-M3 dense，COSINE |
| 学习到的稀疏向量 + 内积 | <span style="color:#c0392b">【本项目已有】</span> BGE-M3 sparse，`SPARSE_INVERTED_INDEX`，IP |
| 经典 BM25 | <span style="color:#c0392b">【规划保留】</span> 只做对照，不替换主路径 |
| 多路排名融合 RRF | <span style="color:#c0392b">【本项目已有】</span> 原始查询路 + HyDE 路，k=60 |
| 加权融合 | <span style="color:#c0392b">【本项目已有】</span> 同一路内 dense 0.8 / sparse 0.2 |
| 交叉编码器重排 | <span style="color:#c0392b">【本项目已有】</span> 断崖截断 |

RRF 融合的是名次，加权融合的是分数。分数不在同一量纲时权重会失效（商品名检索开了 `norm_score`，切片检索没有）。网页不进 RRF，是因为没有稳定的 `chunk_id`。

口述题：纯稠密检索为什么会召回语义近但型号错的片段？稀疏向量和 BM25 差在哪？什么规模下不值得再加一路召回？

### 6.5 LangGraph 并行的真实语义

<span style="color:#c0392b">【本项目已有】</span> 三路 fan-out，多起点边做屏障。若拆成三条普通边，任一路返回就会触发下游。

要能讲的机制：

- 三路已经返回局部更新，这是对的。返回整份状态时，容易用上游快照盖掉并行兄弟刚写的字段。
- 同一字段被多节点写入时需要 reducer。现在三路写的是不同字段，所以暂时没爆。
- 失败要写成明确状态（`error`）。空列表现在既表示「没召回」，也表示「调用抛错后被吃掉」。

口述题：为什么三路检索不能用三条独立边接 RRF？并行节点同时写 `answer` 会怎样？什么流程不该并行？

### 6.6 三套状态，不要都叫记忆

| 存储 | 本仓库 | 解决的问题 |
|---|---|---|
| Mongo 对话 | <span style="color:#c0392b">【本项目已有】</span> | 下一轮看历史、做指代消解 |
| 图 Checkpoint | <span style="color:#c0392b">【规划保留】</span> | 图跑到一半挂起，恢复的是节点位置和当时的 state |

反问目前走第一套：图走完答案节点，澄清句写入 Mongo，用户下一句再开一张新图。Checkpointer 走第二套：图停在确认节点，恢复后继续原来的检索计划。

脏状态要分开举：

- 历史写成功了，图没有把 `item_names` 放进 state。
- 模型以为已经确认型号，Milvus 里其实没有这次对齐结果。
- 重导删除已经提交，插入还没完成。
- 页面已经断开，内存里的图还在跑，重启后两边都没了。

### 6.7 入库质量和索引生命周期

- <span style="color:#c0392b">【本项目已有】</span> 版式解析（MinerU）、图片摘要进正文、标题层级切分、OCR/拼接重复的压缩、VARCHAR 按字节截断、集合字段与代码不一致时按真实 schema 适配。MinIO 上传失败会继续本地导入。
- 要补的认知：表格被打成自然语言后丢行列关系；图片摘要是模型写的，可能和原图不符；先删后插不是事务，空窗期要有指标（该 `file_title` 的条数掉到 0）；改切片结构后旧集合不会自动迁移；`AUTOINDEX` 不等于已经理解 IVF / HNSW 的参数取舍。MinIO 失败后正文里的图片 URL 可能指向一个不存在的对象，页面仍会去渲染。

IVF / HNSW 保持 L2：能讲适用规模和建索引/查询的代价，不在本机数据量上调参当主项目。

父子块：用已有的 `parent_title` / `group_id` / `part` 做「检索小块、回扩同一标题下的相邻 part」。这是这条链路的深挖点，优先于 GraphRAG。

- 异常原文给浏览器：<span style="color:#c0392b">【差异】</span> 代码会把 `str(e)` 推到 SSE 或放进非流式 `answer`。模型上下文和用户界面都不要贴堆栈。返回固定错误码，细节只进日志。

### 6.10 评估怎么设计，才谈得上优化

<span style="color:#c0392b">【规划保留】</span> 原规划的 3 个 Agent 指标要留。这条链路必须先有检索和生成分开的数字。

题集至少 30 条，并事先分层：

- 单商品、步骤明确，手册里有答案
- 指代上一轮商品
- 商品名口语化 / 少一个字符
- 多个候选型号，应该反问
- 库中无此商品，应该拒答
- 有商品但手册没写这个参数，应该拒答，不能用网页或参数记忆补
- 源文件已更新、索引仍是旧版（重导空窗或故意不重导）
- 切片边界把步骤拆开
- 网页和手册冲突
- 片段内带指令的污染文本
- 需要看图才能答的步骤（图片 URL 是否来自本地切片）

指标：

- 检索：Recall@k、过滤后的无关切片比例、空召回是否正确
- 对齐：确认 / 反问 / 拒答是否符合预期
- 生成：关键结论是否能在引用片段中找到（忠实度）、拒答是否正确
- Agent 化之后再加：非法工具调用、超过最大检索次数、写工具是否只在确认后出现

每次改动记录模型名、温度、提示词版本、集合名、题集版本。没有这五项，前后数字不能比较。

人工抽检保留：自动分数判「引用了某 chunk」，人看「这句话是不是真在那个 chunk 里」。

### 6.11 上下文怎么装

<span style="color:#c0392b">【部分已有】</span> 现在实际进模型的是：系统要求、重排文档（带元数据标签）、历史、商品名、当前问题。字符上限 12000。HyDE 原文默认不在其中。没有 tokenizer 记账，也没有「证据不可信」边界。

规划中的 7 段仍用来记账，不要因为已经有字符闸就删掉：

1. 系统提示（角色、拒答规则、引用格式）
2. 工具定义或节点输出格式说明
3. 对话历史
4. 查询改写与 HyDE 假设文档（假设文档默认不进证据区；记账时单列，避免和证据混在一起）
5. 检索片段
6. 网页 / 工具返回
7. 已生成的草稿（若有校验重试）

裁剪顺序：先去掉 HyDE 原文，再截断网页，再按重排分数丢低分片段，再从更早的历史开始丢。已确认商品名、用户原问、系统拒答规则最后动。历史截断方向改成保留最近轮次。当前实现是从旧到新装，预算不够时丢掉较新的话。

Lost-in-the-middle：证据很多时，把最相关的一条放在提示词靠后的位置，看引用是否更稳定。这是一个小对照。

### 6.12 结构化输出失败

<span style="color:#c0392b">【本项目已有】</span> 商品名节点使用 `response_format=json_object`，并处理 \`\`\`json 围栏；失败时退回空商品名 + 原问题。答案节点没有 JSON 模式，走的是普通文本。

要补的口述点：JSON 模式只保证是 JSON，不保证字段齐全；字段缺失和类型错误要有业务默认值；Function Calling / 工具参数和「让模型吐 JSON」不是同一条链路。工具参数解析失败应该返回可重试的错误，而不是猜一个参数去执行。

### 6.13 追踪字段按这条图列

<span style="color:#c0392b">【部分已有】</span> 文本日志能看到节点开始和结束、过滤条件、部分检索结果。还不能按一次请求把下面这些字段调出来。

至少能还原一次请求：`session_id`、`message_id`、节点名、模型名、温度、提示词版本、改写结果、对齐分档（确认 / 反问 / 拒答）、过滤表达式、三路各自条数与耗时、RRF 前若干 `chunk_id`、重排分数、是否触发断崖、最终引用、各段 token、异常是「空结果」还是「调用失败」。

有了这些字段，才能回答：这次失败是检索失败、工具参数错、索引过期，还是模型在有证据时仍编造。

### 6.14 流式协议和页面契约

<span style="color:#c0392b">【本项目已有】</span> 这是原规划写得偏轻、代码已经踩出来的一块。

要能讲清：

- 事件：`ready`、`progress`、`delta`、`final`、`error`。结束事件只生效一次，之后的推送丢掉。
- 图的 `values` 流和给人看的 token 流是两条通道。
- 同一会话再次提问会换一条队列；旧任务仍写自己绑定的那条，靠上下文变量绑到 LangGraph 的工作线程。
- 浏览器会自动重连。队列已经读完时，要把结束事件再发一次并立刻断开。
- 心跳只表示连接还在，不表示模型还在生成。
- 页面现在展示进度、正文、图片。引用片段没有进页面。G1 补了引用之后，页面要能点开 `chunk_id`，否则用户仍无法核对。

口述题：用户刷新页面时，为什么不能只靠浏览器重连把答案接回来？断开连接和取消任务差在哪？什么信息适合放 `final`，什么信息必须进 `delta`？

### 模块六：Agent 集群

落在 P3。P2 还没有单链路的成功率和 token 数字时，本模块不开始编码。开始之后必须和 P2 用同一批题对照。

四个角色：编排者负责拆任务和熔断；检索专员只能调用 P1 检索；校验专员只判断引用是否包含结论，不能引入新事实；工单专员只能调用 P2 已经过确认的写接口。共享 state 传递 `chunk_id`、任务状态和幂等键，不传递未约束的长对话。

### 8.1 P1 知识库问答（当前仓库，收尾）

| 类别 | 还要补 |
|---|---|
| 知识点 | 关键句带 `chunk_id` 或 URL；证据为空或无关时拒答；本地步骤优先于网页；图片区只放本地切片；高置信度只确认一个名字；无商品名时不要全库打；父子块回扩或 BM25 对照二选一；轻量图谱和 Weaviate 各做一次同一题集对照 |
| 工程 | 把 6.10 的题集做成可重复脚本；每次记录模型名、温度、提示词版本、集合名、题集版本；说明和代码不一致处以代码为准并改注释 |
| 运维 | 重导后该 `file_title` 条数掉到 0 要记失败；上传目录和 MinerU 解压目录按天清理；MinIO 失败要留下状态，避免页面去渲染不存在的对象 |

P1 暴露出来、后面三个项目都要能讲的知识点：

1. SSE 是协议：事件种类、结束事件只发一次、心跳、重连补发、队列和线程怎么绑。前端联调按这套事件，不另造协议。
2. 进程内任务表和 SSE 队列会在重启、多进程、浏览器断开时分别失效。这是 P4 上副本之前必须先外置状态的原因。
3. `BackgroundTasks` 负责「请求返回后继续跑」。进程退出、失败重试、同一文件并发上传，它都不负责。
4. 字符闸从旧到新装历史，丢掉的是较新的话。token 分段记账在 P2。
5. 正文、`final.image_urls`、MinIO 对象三者可能不一致。图片摘要是模型写的。
6. 检索失败变空列表、重排失败变空分数、非流式生成失败变一句抱歉。P4 的评估要把这三类算成失败，不能算成「没召回」或「已回答」。

### 8.2 P2 单 Agent 业务系统（新仓库）

这是岗位要的「从 0 到 1」。三个模块都要能在仓库里指到文件。

| 模块 | 职责 | 不能交给模型的部分 |
|---|---|---|
| 任务分解引擎 | Plan-and-Execute。计划过长就只重排剩余步骤，有步骤上限 | 最大步骤数、写操作必须单独成一步并标成副作用 |
| 决策引擎 | 受约束 ReAct：澄清、查本地、查网页、校验、停止、请求人工确认 | 最大轮次、过滤表达式、空证据禁止编造、写工具不可见直到确认 |
| 记忆模块 | 短期窗口加摘要；长期只存已确认商品、用户否定、用户纠正；Checkpoint 存图位置 | 整段对话不进向量库；补偿以业务库和幂等键为准 |

| 类别 | 要补 |
|---|---|
| 知识点 | Function Calling 与「吐 JSON」的差别；CoT 只在校验里先列证据再下结论；ToT、ReWOO 的对照数字；确认页、幂等键、超时后分不清写没写过 |
| 工程 | 工具参数解析失败返回可重试错误；再查必须换查询；只读可并行；异常不进模型上下文，也不进页面；自建一个最小 MCP Server。确认前模型看不到写工具。和前端约定确认页字段，和模型侧约定提示词版本 |
| 运维 | 单次任务记下循环轮次、检索次数、各次模型名。多余检索次数和写工具重复次数是这个项目的成本指标 |

场景里的写操作只有一个：按手册结论登记维修记录。P1 的先删后插只用来对照「删除和插入不是原子写」。

上线前每个项目看自己的三个数：

- P1：拒答正确性、无关切片比例、重导后空索引是否被发现。

- P4：题集是否可重复跑、取消后有没有新的工具调用、副本为 2 时会话是否还能续上。

## 九、模拟面试

开放题按同一顺序答：做法、边界、替代方案、上线看什么。P1 用现在的代码路径，不要背已经过时的「答案节点是空的」。P2、P3 没有仓库之前，只讲设计，不讲成已经落地。

1. **设计这个手册业务系统。** P1 哪些节点已经写死？P2 的任务分解、决策、记忆各管什么？模型只允许决定什么？反问为什么在 P1 里是透传，到 P2 才变成可恢复中断？
2. **一次失败。** 怎样区分：库中无商品、过滤过宽、HyDE 带偏、索引被删空、有证据仍编造、网页污染、工具参数错、规划步骤膨胀、调用失败被写成空列表。这三类岗位关键词要分开：幻觉、工具调用异常、任务规划失败。
3. **Token 上涨。** 先分清是 P1 的抽取、HyDE、重排、回答，还是 P2 的循环轮次，还是 P3 每个角色又带了一份上下文。历史若要砍，砍更早的轮次。
4. **写操作误执行。** 确认节点在工具前；确认内容包含幂等键。P3 的工单专员只能调用这条已经确认过的接口。P1 的先删后插说明删除和插入不是原子操作，不能代替幂等键。
5. **为什么要集群，以及什么时候退回。** 四个角色的工具集如何互斥？对照 P2 的完成率、重复调用、token。变差时退回单 Agent，这个退回本身是设计的一部分。

简历按四个仓库分开写。P1 现在可以写页面、SSE、导入和查询接口。三项数字落地之后才写评估集。P2 写出三个模块和写工具之后才写单 Agent 业务系统。P3 有和 P2 的对照数字之后才写集群，数字更差就写「测量后默认退回单 Agent」。Docker、K8s、Trace、回放只写在 P4 落地之后，并且不写生产调优。
