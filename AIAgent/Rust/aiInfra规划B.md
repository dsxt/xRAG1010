# AI Infra 学习规划

对标大厂底层模型工程岗（训练集群 / 推理引擎）。完成标准只有一条：达到岗位要求，并能用项目和手写代码撑住一面到二面。源码级精通所有框架不是这条标准。

起点：大学 C++ 已遗忘，无 CUDA；有 Python / Vue 全栈、RAG 和 Transformer 论文基础。

和 `agent应用规划.md` 的分界：那份规划练的是 Agent 应用。本份规划练算子、通信和推理引擎。简历上两条线只能有一条写深。

主线：**推理引擎做深，训练通信和并行做到能讲、能跑小实验。** 推理在单卡上可以做深，也接得上已有的 Transformer 经验。若集合通信之后有稳定多卡，收成时把简历上写深的第二项换成训练性能调优。

Rust 不占主干，只做 FFI 加分。图编译做到能看懂一次真实融合，不单独开 TVM。原因和以后怎么捡回来，见第 10 节。

## 1. 等级怎么定

三个词在本文里含义固定。它们描述的是达到岗位要求、能进面试时的位置，不是岗位头衔。一项算完成，是指面试追问时能拿代码和数字撑住，而不是读过名词。

| 级别 | 含义                                               | 达标时落在哪                                                                                                                                                               |
| ---- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 精通 | 闭卷能写核心代码；能用测量指出瓶颈；追问两层仍能讲 | CUDA 内存模型与优化路径、Reduce、分块 GEMM、Softmax、Ring AllReduce 的步骤与通信量、KV Cache / PagedAttention、连续批处理                                                  |
| 熟练 | 能顺着调用链读源码，改一处局部并测出差异           | Triton、PyTorch 自定义算子与 Dispatcher、stride 与迷你张量库、Megatron 张量并行、ZeRO 显存账、vLLM 的调度与块管理、一种量化实现、一次算子融合的前后对比                    |
| 了解 | 能画架构、算复杂度或显存、说出取舍                 | 流水线并行、MoE、RLHF 训练拓扑、Ring Attention、SGLang 前缀缓存、投机解码、LoRA、TensorRT-LLM / LMDeploy 的位置、K8s Device Plugin、PD 分离、NVLink / RDMA / GDR、Rust FFI |

学习顺序按模块闸门走。上一模块的必做没有留下，不把下一模块的加做拿来凑进度。

### 主干里要单列的能力

岗位清单容易被学成名词。下面这些必须变成测量，及格线写在第 6 节对应模块里。面试里被追问时，要能指到笔记中的数字。

1. **Roofline。** 先算算术强度（FLOPs / Bytes），再决定瓶颈在带宽还是计算。
2. **数值格式。** FP32 / FP16 / BF16 / FP8 的范围、Softmax 要减最大值、Tensor Core 的形状对齐。实现停在 Ampere / Hopper 上能跑的 CUDA：合并访问、共享内存、`cp.async`、WMMA 或库调用。TMA、WGMMA、FP8 知道适用条件。Blackwell 的 NVFP4 只记名词。
3. **推理指标。** 至少留下 TTFT（首 token 延迟）和吞吐。TPOT 是平均每个输出 token 的耗时，ITL 是相邻 token 的间隔；有数字就写，没有不编。
4. **推理侧容易漏掉的机制。** Chunked Prefill、CUDA Graph、前缀缓存。推理自定义 AllReduce 和 PD 分离（Prefill / Decode 拆开部署）停在了解。
5. **训练侧容易漏掉的账。** 梯度分桶与计算通信重叠；显存账（参数、梯度、优化器状态、激活、碎片）；序列并行 / 上下文并行和 Ring Attention 的关系。
6. **单卡主路径。** 约八成内容一张 12GB 以上的卡就能做。多卡只出现在集合通信和并行里，2 卡或 4 卡即可。

### 从必做里放下的

- 通读 NCCL、Megatron、vLLM、SGLang 全仓库。
- 用 Rust 重写一个对标 vLLM 的引擎，并把它当成简历及格项目。
- 以 TVM 为主线手写多个 Schedule。
- 把 8 卡集群、完整 RLHF、自研 K8s Operator 写成前置条件。
- 把「Linux 内核」理解成内核开发。这里要的是虚拟内存、锁页、NUMA、cgroup、设备文件。

每项为什么放下、深化时的进入条件，见第 10 节。

## 4. 环境与完成标准

- 系统：Linux 为主。Windows 可以写 C++，性能数字以 Linux 为准。
- GPU：计算能力 8.0 及以上（Ampere 或更新），显存尽量 12GB 起。8GB 能写算子，放不下后面的小模型。
- 软件：CUDA 12.x、CMake、Nsight Systems、Nsight Compute、PyTorch 与本机 CUDA 主版本一致。
- 多卡：集合通信和并行模块里安排一次多卡实验，租 2 卡或 4 卡。2 卡足够验证 AllReduce、数据并行和张量并行。没有卡时，先把算法和通信插入点写对。
- 单卡替代：Ring AllReduce 先在单进程里用内存缓冲把步骤写对，再在云上对一次真实带宽。

三类完成标准，都对着岗位和面试，不按投入长短分：

- **必做**：该模块的交付和及格线。这是投递和一面、二面的及格线。
- **优秀**：同一项上的更高数字。写进笔记，不挡住下一模块。
- **加做**：必做已经完成之后再做。没做不写进主线，也不用来填必做的缺口。

## 6. 分模块内容

优化类的模块都走同一条循环：朴素实现 → 对数值 → 上 Nsight → 只改一个瓶颈 → 再测。

### 能编译、能测量、能从 Python 调到 GPU

**工程与逐元素。** CMake 编 CUDA、RAII、`unique_ptr`、移动语义、内存对齐。跳过语法通读。
必做：多文件工程里，向量加法与 CPU 结果比对通过。

**内存池与 ReLU。** 固定大小内存池（分配、释放、重复申请不崩）。CPU 张量先有 shape、numel、dtype，不做广播。CUDA 逐元素 ReLU。用 `cuda-gdb` 和 `compute-sanitizer` 看一次非法访问。
必做：内存池相对裸 `malloc` 的简单对照；ReLU 测试。

**硬件图与朴素 GEMM。** 选 Ampere 或 Hopper 画一张图：SM、Warp、寄存器、共享内存、L2、全局内存、Tensor Core 在哪一级。索引计算（grid / block）。朴素 GEMM。算术强度 = FLOPs / Bytes。用 Nsight Systems 看一次 kernel 和一次 `cudaMemcpy`。
必做：朴素 GEMM 正确，笔记里写明 HBM 流量、FLOPs、瓶颈在带宽还是启动开销。

**Python 绑定与 Linux 地图。** 流和事件的最小例子：两次 kernel 重叠，或拷贝与计算重叠。用 pybind11 把朴素 GEMM 注册成 PyTorch 算子，和 `torch.matmul` 对数值。
Linux 只建地图：进程地址空间、锁页内存和普通内存的差别、`nvidia-smi` 里的显存与利用率、cgroup 能限制什么。
必做：Python 能调用自己的 CUDA GEMM。

资源：NVIDIA《CUDA C Programming Guide》的编程模型与内存章节；《Effective Modern C++》里智能指针、移动、右值相关条目；PyTorch Custom C++ and CUDA Extensions 官方教程。

### 算子

这是简历筛选的硬门槛。性能百分比只在正确性通过之后写。

**归约。** 用归约求和走完：全局内存合并访问、共享内存、Bank Conflict、Warp 分歧、Warp Shuffle。
及格：大数组达到该卡理论带宽的 50%。优秀：70% 以上。
必做：每一版只改一个问题，笔记按版本分开。

**分块 GEMM。** 共享内存分块 → 寄存器分块 → 双缓冲。形状先用 1024 或 4096 的倍数，边界以后再补。
及格：大矩阵 FP32 达到同形状 cuBLAS 的 40%。优秀：60%。
加做：`cp.async`。Tensor Core 放到数值格式，避免和访存优化缠在一起。

**归一化与分块注意力。** 线上 Softmax、RMSNorm、GELU 或 SiLU 里的一个激活。再实现一版分块注意力：不物化整张注意力矩阵，用重计算换显存和带宽。
及格：分块注意力与 PyTorch 对齐，能讲清 SRAM 里放了什么。不要求超过官方 FlashAttention。

**Triton、FP16 与 CUTLASS。**
必做：用 Triton 写 GEMM 或 Softmax 其中一个，记下实现难度和性能，对照自己的 CUDA 版本。用库或 WMMA 跑通 FP16 GEMM，形状满足对齐，并写一页笔记：FP16 范围窄、BF16 范围接近 FP32、FP8 需要缩放、Softmax 要减最大值。Hopper 上的主路径是 WGMMA / TMA，这里不手写。
必做里的阅读：CUTLASS 官方 GEMM 示例能跑，能讲清线程块、warp、指令三层。
加做：自己写 WMMA kernel，而不是只调用库。

资源：CUDA Guide 的性能章节；Triton 官方教程；CUTLASS 文档的 GEMM 层次；FlashAttention 论文的方法节。

### 张量与 PyTorch 调度

**Dispatcher。** 顺着一次 `torch.matmul` 看 ATen 怎么选到 CUDA 实现，弄清 Dispatcher 在分发什么。不改 PyTorch 本体。
必做：给前面的算子补一个简单反向，或在笔记里写明它只用于推理以及反向会缺什么。

**迷你张量库。** 只做四件事：row-major 与 stride、连续和非连续、view 与 copy；广播；CPU / CUDA 注册与分发；调用前面的逐元素、GEMM、归约。
必做：一个小 Transformer 块或两层 MLP 的前向，FP32 与 PyTorch 对齐到约 1e-4。及格看数值和 stride，不看 API 是否像 PyTorch。
加做：计算图和自动微分。没做就在面试里说明做深的是前向和显存布局。

### 通信、并行、容错

**集合通信语义。** AllReduce、AllGather、ReduceScatter、Broadcast、AllToAll，以及每张卡的数据量。Ring AllReduce 分 reduce-scatter 和 allgather 两段。张量大小为 S、卡数为 N 时，每张卡发送的数据量约为 `S × 2 × (N-1) / N`。
必做：单进程里用内存缓冲把步骤写对，并用上面的公式算一个例子。

**NCCL 与链路。** NCCL API 跑通 AllReduce。读初始化和 Ring 时只追两个问题：环怎么建、kernel 何时启动。
必做：nccl-tests 或云上 2 卡，记下一次总线带宽。没有卡就保持单进程实现，并写明缺哪一次实测。
了解：NVLink、PCIe、RDMA、GDR 各自去掉哪一段拷贝。没有 RDMA 就停在图上。

**数据并行与张量并行。** 数据并行：梯度分桶、桶上的 AllReduce、与反向重叠。张量并行：Megatron 的列并行和行并行，Attention 与 MLP 各在哪一次通信。
必做：把通信插入点画对；有卡则用小模型或单层跑一次，记下并行度变化时的显存和耗时。

**流水线与 ZeRO。** 流水线只算清 1F1B 的气泡从哪来、微批用来填什么。ZeRO 用手算，不改 DeepSpeed 源码。混合精度 Adam 下，每个参数的模型状态大约是 2 字节参数 + 2 字节梯度 + 12 字节优化器状态（FP32 主参数、一阶矩、二阶矩）。ZeRO-1 切优化器状态，ZeRO-2 再切梯度，ZeRO-3 再切参数。激活另算，碎片来自分配器，不进这 16 字节。
必做：按 7B 参数写一份账；写出 1F1B 的气泡率公式并用一个微批数代进去。
加做：用 DeepSpeed 或等价配置跑一次，对照手里的账。只看配置和显存曲线。

**训练地图与 Checkpoint。** 建立地图，不从零训练这些系统。

- 序列并行、上下文并行为什么出现。Ring Attention 切的是序列维。
- MoE：门控、专家并行、AllToAll、负载不均。
- RLHF：策略模型、参考模型、奖励模型同时在，显存和通信压力在哪。

必做：Checkpoint 的全量保存、加载、步数对齐。
加做：增量保存。不实现 RLHF。

**续训、指标与隔离。** 用前面的 Checkpoint 做一次杀进程后续训。列出要看的 GPU 信号：SM 利用率、显存占用、功率、温度、Xid、PCIe 或 NVLink 吞吐。能说明 cgroup 如何做设备隔离，Kubernetes Device Plugin 在调度时做什么。Operator / CRD 是扩展 API，这里不写。显存泄漏按这个顺序看：分配路径、缓存分配器、哪一步之后只增不减。
必做：续训记录 + 一页指标说明。

资源：NCCL 文档与 nccl-tests；Megatron-LM 论文和张量并行相关代码；ZeRO 论文；DeepSpeed 文档里 ZeRO 与激活检查点那几节。

### 编译与融合

目标是回答「这次融合省掉了哪次全局内存读写」。

必做：能区分三层 IR（算子图、循环、硬件指令）。在一个小模型上二选一：打开 `torch.compile`，在 profile 里指出被融合掉的 kernel；或用 TensorRT-LLM 编成 engine，对比融合前后的 kernel 数量和延迟。LMDeploy 只记它也在这条链路上。
加做：改一条融合规则，或一个 TVM Schedule。这一步做不成，就停在看懂这一次。

### 推理引擎

先定指标再写代码。预填吃计算，解码吃带宽和 KV Cache。

**分页 KV Cache。** KV Cache 字节数约为 `2 × 层数 × kv 头数 × head_dim × 序列长度 × batch × 每元素字节`。前面的 2 是 K 和 V。用 kv 头数，不要用查询头数，否则 GQA 会算大。分页：块大小、块表、逻辑页到物理块。
必做：自己的块管理器能分配、释放、处理变长序列。对照 vLLM Block Manager 的对应结构，写下相同点和你简化掉的点。

**连续批处理。** 请求何时进入、何时退出、按迭代调度。Chunked Prefill：长预填切块，和短解码穿插，避免一次预填占满 GPU。CUDA Graph 压的是小 kernel 的启动开销，适合解码阶段形状变化不大的路径。
必做：读 vLLM 调度器主路径，并在自己的块管理上做一版多请求调度，能报 TTFT 和吞吐，说明耗时在预填还是解码。
加做：前缀缓存（vLLM APC 或 SGLang RadixAttention）的命中条件。

**量化，以及停在了解的机制。** 量化：对称与非对称、逐通道、校准集用来估尺度。INT4（AWQ / GPTQ）停在「权重量化、激活尺度从哪来」。
必做：一个 W8A16 或 INT8 小 GEMM，同时写下精度变化和 kernel 耗时。模型用 TinyLlama 或同等大小，加载 Safetensors。
了解，不作为及格实现：投机解码的接受率与加速、LoRA 切换带来的碎片和 kernel 数量、推理张量并行里的自定义 AllReduce、PD 分离适合什么流量。
加做：GGUF；Rust 的所有权、借用、`unsafe` 与 C ABI，把现有 CUDA GEMM 封一层安全接口。简历可以写「能把 CUDA 算子接到 Rust」。不把 `infer/` 改写成 Rust 项目。

及格：多请求下块管理正确，有 TTFT 和吞吐，能说明瓶颈在预填还是解码。
优秀：和同模型 vLLM 处于同一数量级，并能指出差距来自哪一类 kernel。不要求打平。

资源：PagedAttention 论文；vLLM 里调度与块管理的源码路径；SGLang 文档中 RadixAttention 和投机解码的说明；TensorRT-LLM 快速开始。

### 简历与手撕

不新开主题。两份项目都要有架构、你改过的点、笔记里的数字、一个没做成的边界。这一段的完成标准就是能投递、能口述。

1. **算子与张量库。** GEMM 相对 cuBLAS 的比例、归约相对理论带宽的比例、分块注意力做到哪一层、自定义算子如何对数值。
2. **推理或训练，二选一。** 推理写分页 KV、连续批处理、TTFT / 吞吐、读过的 vLLM 路径。训练写显存账、一次通信带宽、一次杀进程后续训。

手撕闭卷：归约、分块 GEMM 的核心循环、Softmax、Ring AllReduce 的两段、PagedAttention 的块表。白板上不准备写完整个 vLLM。

口述按第 7 节的四段准备。

## 7. 面试题怎么留

每完成一个精通或熟练项，在该模块笔记末尾加三题，用口述回答：

1. 原理：它在训练或推理的哪一步起作用。
2. 踩坑：你测到的那个瓶颈，指标怎么变，你改了什么。
3. 取舍：什么条件下不用这个做法。

模拟面试四段，每段都要能指到笔记里的数字：

- 算子慢：算术强度是多少，下一步改访问还是改计算。
- 训练显存不够：账本里哪一项最大；ZeRO、激活检查点、并行各动哪一项。
- 多卡变慢：算力没吃满时，先看通信量和有没有与计算重叠。
- 推理延迟高：TTFT 高看预填和排队；TPOT 高看解码带宽、KV Cache 和 kernel 启动。

四段都能指到自己的笔记，这个规划才算完成。

## 9. 达标后可以怎么描述自己

可以诚实写的能力：

- 能独立写、测、优化 CUDA 算子，并用 Roofline 和 Nsight Systems 解释瓶颈。
- 能把算子接到 PyTorch，理解 stride 和非连续张量。
- 能讲清 Ring AllReduce 的两段和每卡数据量，能讲清张量并行的通信点和 ZeRO 三级差在哪，并有小规模实验或一份算对的账。
- 能讲清 PagedAttention、连续批处理、预填和解码的差异，并有可运行的块管理和一组 TTFT、吞吐。
- 能做 Checkpoint 续训，能看 GPU 侧的基本故障信号。

不要写成已经具备的能力：

- 数千卡集群的负责人经验。
- NCCL 或 vLLM 的全仓库维护者。
- 图编译器专家。
- 生产级故障注入平台。

投递时方向写清楚：推理引擎优化，或训练框架与集群。两个都写「精通」会和仓库里的深度对不上。全栈经验放在项目结尾，用来说明能把内核收成可调用的服务。量化句子必须来自 `notes/`，没有数字就写你建成了哪项测试，不编比例。

## 10. 岗位要求达到之后，怎么往下深化

达标时，算子和一条主线能动手，其余方向能讲到第二层。下一步是选定一个子系统，沿调用链改到能用指标证明，而不是把每个「了解」都升成「精通」。是否继续，仍看它能不能让下一次面试多撑住一层追问。

深化的单位是一个子系统。结束时留下三样：跟过的调用链、改过的那一处、前后数字。论文只读能对上这段代码的方法节。同时只跟一个上游项目的版本说明。

默认继续把推理做深，训练保持能跟进。已经有稳定多机时，把下面两条路线对调。

### 推理引擎：从「能讲 vLLM」到「能改一个后端」

前一层没有数字，不进下一层。

1. **把一条请求走完。** HTTP 入口 → 调度器 → 块管理 → model runner → attention 后端 → 采样。指出一次解码迭代里，耗时在哪个 kernel，显存在 KV 还是权重。
2. **只改一个子系统。** 四选一：attention 后端、调度（Chunked Prefill、抢占）、KV Cache（量化、前缀缓存、换出）、CUDA Graph 在动态形状下的边界。改动小到能说明正确性怎么保证。
3. **再做性能专项。** 推理侧自定义 AllReduce、投机解码的接受率、FP8 或 W4A16 的权重 kernel。TTFT 和 TPOT 分开报。
4. **最后才是编译和部署形态。** TensorRT-LLM 如何选 kernel、Inductor 在动态形状下为什么没融合、PD 分离适合什么流量。这些是第 3 步里已经能量到的瓶颈的下一层。

### 训练与集群：从「能算显存账」到「能解释扩展效率」

1. **把一次迭代拆开。** 前向里的张量并行通信、反向、梯度桶、优化器。先在 2 卡上看通信有没有藏进计算。
2. **显存和重计算。** 激活检查点省下的显存、多出来的计算，以及它和 ZeRO、张量并行叠在一起时谁在传数据。
3. **长序列和 MoE。** 上下文并行切序列维。专家并行用 AllToAll，慢常常来自负载不均。
4. **规模和故障。** 这一层才需要更多卡：层次 AllReduce、跨 NUMA、掉卡后续训、慢节点、异步写 Checkpoint。Kubernetes 只读现成训练 Operator 如何设置可见设备、如何处理失败。

### 两条线共用的下一层

| 顺序 | 主题                                                              | 做到什么程度再停                                       |
| ---- | ----------------------------------------------------------------- | ------------------------------------------------------ |
| 1    | Nsight Compute：达成占用、内存吞吐、Roofline                      | 能对一个自己的 kernel 说出离屋顶还有多远               |
| 2    | CUTLASS 3 的布局，或 FlashAttention / FlashInfer 里的线上 Softmax | 能讲清一个生产 kernel 的分块                           |
| 3    | Hopper 的 TMA、WGMMA                                              | 用库或一份最小样例跑通，并说明相对 WMMA 省了什么       |
| 4    | NCCL 的算法目录和拓扑选择                                         | 能解释一次压测为什么是 Ring 或 Tree                    |
| 5    | 缓存分配器与碎片                                                  | 能区分显存不够，和有空闲但分不出连续块                 |
| 6    | MLIR / TVM                                                        | 只有 Inductor 或 TensorRT-LLM 的融合边界已经碰到时再开 |

第 6 步放在最后：Schedule 和 Dialect 要用来解释一个真实的、没被融合的 kernel。

### 主干阶段先放下的内容

这些内容仍在体系里，只是不进主干的必做。它们会把算子、通信和推理的及格线挤掉。及格线是：能写和测量 CUDA 算子，能把通信和显存算清楚，能沿 vLLM 的一条路径改调度或 KV Cache。条件没满足，就继续改当前子系统。

**通读 NCCL、vLLM 全仓库。** 要看的是一条窄路径。NCCL 里决定带宽的是集合算法、环或树怎么建、kernel 何时启动；其余大量是传输层、引导和兼容分支。vLLM 里决定 TTFT 和 TPOT 的是调度器、块管理、model runner、attention 后端；其余是多硬件适配和模型接口。主干阶段把这条路径走通。深化时，只有已经要改某个目录、并且能说出它的调用方，才读该目录和对应测试。

**用 Rust 重写一个对标 vLLM 的引擎。** 对标意味着分页、连续批处理、CUDA Graph、采样和多种 attention 都要在，这是产品范围。岗位源码是 Python 加 C++/CUDA，面试期望你能改 vLLM、SGLang 或 TensorRT-LLM。Rust 的所有权用在算子和调度已经正确之后，用来去掉 Python 开销或嵌进别的进程。主干阶段只留 FFI。进入条件：算子和调度已经有正确性和性能数字，目标是换运行时。

**以 TVM 为主线。** 岗位要的图编译是：融合省掉了哪次访存、动态形状为什么让编译变难、engine 里的 kernel 怎么选出来。`torch.compile` 和 TensorRT-LLM 就是这条路上的样本，连着算子模块的分块注意力和推理模块的 KV Cache。主干阶段若以 TVM 的 IR 和 Schedule 为主线，手写 CUDA 和推理框架会被挤掉。进入条件：能指出某次融合没发生的原因，需要自己控制循环变换或支持新硬件。对应上面共用下一层的第 6 步。

**8 卡。** 2 卡就能验证 AllReduce 对不对、通信有没有藏进计算、张量并行的通信插在哪。更多卡新增的是拓扑、层次算法和扩展效率。算法还没测清时，分不清是 kernel 慢还是机器慢。进入条件：2 卡上的正确性和重叠已经有数字。对应训练路线的第 4 步。

**自研 K8s Operator。** 它解决任务怎么拉起、GPU 怎么隔离、失败怎么重启，不提供 CUDA 或 NCCL 的新知识。岗位里的 Kubernetes 指 Device Plugin 和失败恢复，所以主干阶段要求能解释，并做一次杀进程后续训。进入条件：工作内容已经是多机交付；那时读现成的训练 Operator，不从零写控制器。
