# Go：从语言到 Agent 网关

> 口径：2026-11-20。  
> 目标：自己做一套生产级 Agent 接入网关、模型网关和长任务入队。会写 goroutine 只是起点。终点是：客户端断开能取消上游，限流在多副本下仍然成立，熔断不会把一次内容拦截当成宕机，写操作不会因为重试做第二次。  
> Go 在这条链路里负责连接、协议和取消。规划、RAG、评测留在 Python。沙箱和热点计算留在 Rust。推理引擎不在本文。  
> 同一知识点只在一处讲透。网关骨架的字段以《Agent 开发语言》第 6 章为准，请求顺序以《Agent 应用开发全流程》为准。

分级贯穿全文：

| 级 | 含义 |
|---|---|
| L1 | 不掌握就写不出正确的单机网关 |
| L2 | 决定多副本、尾延迟和取消能不能守住 |
| L3 | 自研调度器、内核旁路、和推理运行时抢同一件事。单机网关做稳后再碰 |

语言基线按 2026-11 能写进生产的那一档：Go 1.22 起的方法路由和每次迭代独立的循环变量；1.21 的 `context.WithoutCancel`；1.23 起没有引用的 `Timer` 可以被回收。岗位手册里写到的 1.26 Green Tea 仍是并发三色标记和两次短暂停顿，变化是把同一页上的小对象攒在一起扫。网关的正确性不押在某一个小版本的 GC 上。

<a id="0-在造什么"></a>

# 0 在造什么

五层，依赖只能向下。接入层不推进 Agent 状态机，模型网关不决定业务是否允许写操作。

```
浏览器 / CLI / 业务系统
  │  HTTP / SSE
  ▼
1 接入网关        鉴权、身份覆盖、限流、体长、词库、Trace、取消
  ▼
2 策略客户端      调用唯一一份策略。超时失败按副作用关闭或降级
  ▼
3 转发或入队      短请求转发给 Python；长任务写入队列后立刻返回 task_id
  ▼
4 模型网关        协议适配、熔断、按错误类型切换、token 统计
  ▼
5 Python 编排     状态机、RAG、工具、评测。不在本文实现
```

一条短请求：

```
接入 → 验签并覆盖 tenant_id / user_id → 限流 → 词库
→ 策略入口（短超时）→ 带上 traceparent 转发给编排
→ 按块把 SSE 写回并 Flush
→ 客户端断开则取消上游
```

一条长任务在词库和策略通过之后入队，响应里只有 `task_id`。Worker 是 Python。Go 不持有租约。

2026 年这条边界已经比较稳定：MCP 远程传输是 Streamable HTTP（2026-07-28 起核心协议不再依赖粘性会话）；模型网关对外统一成内部补全格式，而不是让编排进程直连各家 SDK；AutoGen 处于维护状态，新的多 Agent 编排不放在 Go 里重写一遍。

<a id="1-语言"></a>

# 1 语言

## 1.1 值、指针、切片（L1）

数组长度是类型的一部分，切片是结构：指针、长度、容量。函数传切片传的是这个结构的副本，底层数组仍共享。append 在容量不够时分配新数组，调用方如果还拿着旧切片，看不到新元素。

扩容不要背一个永远不变的倍数。1.18 起，需要的长度已经超过旧容量两倍时，新容量至少取到这个长度；否则旧容量小于 256 时翻倍，达到 256 后按大约 1.25 倍增长，再向上取整到内存分配器的 size class。面试里先说「可能换底层数组」，再讲这个规则。

从大切片切出小窗口后，小切片仍牵着整块数组。要断开时复制出去：

```go
func clone(src []byte) []byte {
    dst := make([]byte, len(src))
    copy(dst, src)
    return dst
}
```

## 1.2 map（L1）

并发读写 map 会直接崩溃，竞态检测也抓得到。网关里的用户令牌桶如果放在 map 里，用互斥锁把「查找、创建、扣令牌」包在同一次加锁里。读远多于写时再用 `RWMutex`。锁里面不做 RPC、不做 channel 收发。

`sync.Map` 适合键集合稳定、读多写少的场景，例如几乎不变的模型端点表。每个请求都插入新用户的限流表不适合它。

## 1.3 接口与错误（L1）

接口是方法集合。网关依赖 `TaskStore`、`PolicyClient` 这种小接口，测试用假实现，不依赖 Redis 先起来。

错误要能被调用方分支，而不是只剩一段文本。用 `errors.Is` / `errors.As`。对用户只返回稳定错误码（`unauthorized`、`rate_limited`、`policy_unavailable`），日志里再放内部原因。

```go
var ErrPolicyDown = errors.New("policy down")

func failClosed(err error) string {
    if errors.Is(err, ErrPolicyDown) || errors.Is(err, context.DeadlineExceeded) {
        return "policy_unavailable"
    }
    return "policy_denied"
}
```

`defer` 后进先出。用来关响应体、解锁、取消 context。不要在 defer 里悄悄吞掉错误。

## 1.4 泛型用在哪（L2）

令牌桶、熔断器这种状态机用具体类型更清楚。泛型适合真正与元素类型无关的小工具，例如带上限的队列。不要为了「像框架」给每个中间件套一层类型参数。

## 1.5 本章留下的代码

一个能编译的小包：切片复制、带锁的 map、用 `errors.Is` 区分策略宕机和策略拒绝。没有网络。

<a id="2-并发"></a>

# 2 并发

## 2.1 goroutine 是什么（L1）

goroutine 由 Go 运行时调度，初始栈大约 2KB，按需伸缩。操作系统线程的栈通常是 MB 级。同等内存下能挂起的 goroutine 多得多，这也是 SSE 连接适合放在 Go 里的原因。模型那一次推理的耗时在上游，语言改变不了模型速度。

GMP：G 是 goroutine，M 是线程，P 是逻辑处理器。M 必须持有 P 才能执行 Go 代码。P 的数量等于 `GOMAXPROCS`，默认按可用 CPU。容器里这个数可能是宿主机核数，配额更小，要用环境变量或 uber 的 automaxprocs 一类库按 cgroup 设置，否则会过度并行。

## 2.2 共享内存还是 channel（L1）

保护连接表、令牌桶、熔断计数，用互斥锁或原子变量。channel 用来交接所有权和通知「这一批结束了」。在热路径上每个请求都经 channel 过一遍，往往比锁更慢，也更容易把无人接收的发送永久堵死。

无缓冲 channel 的发送要等接收。超时之后如果发送仍堵着，这个 goroutine 就泄漏了。

## 2.3 context（L1）

`context` 传递取消、截止时间和追踪，不传递业务对象。入口用 `r.Context()`。出站 HTTP、Redis、策略调用都带同一个 ctx，或者更短的超时。只在外面 `select`、下游不看 ctx，工作仍会跑完。

父请求结束、审计还要写完时，用 `context.WithoutCancel` 切断取消，再给审计自己的超时。长期存活的对象里不要藏一个请求的 ctx。

客户端断开时，接入网关取消发往编排和模型的请求。这是正确性：人走了还在烧 token。

## 2.4 一组子任务（L2）

并行的只读探测用 `errgroup`，一个失败取消其余。写操作不放进这种组。`Wait` 之前必须有人接收结果，或者用带缓冲的 channel，容量等于任务数。

## 2.5 循环变量（L1）

1.22 起，每次 `for` 迭代有自己的循环变量。更早的版本里，闭包捕获的是同一个变量，启动一串 goroutine 会打到最后一项。看 `go.mod` 里的 Go 版本再决定要不要显式拷贝。

## 2.6 本章留下的代码

十个慢客户端同时连着，服务端每个请求一个 goroutine，断开后 goroutine 数回到基线。用 `pprof` 的 goroutine profile 看，不靠感觉。

<a id="3-内存与-gc"></a>

# 3 内存与 GC

## 3.1 泄漏几乎都是还可达（L1）

Go 有 GC。泄漏是对象从根上仍然可达。网关里常见的根：

- 停不下来的 goroutine
- 按用户 ID 只增不删的限流 map
- 大切片的小窗口
- `time.After` 在旧版本里留到触发才回收的 Timer

用户桶要有过期。进程内桶只保护本实例，过期清理和「全局限流放 Redis」是两件事，都要做。

## 3.2 GC 在排障时怎么看（L2）

标记是并发三色：白没访问过，灰可达但子指针还没扫完，黑的子指针已经扫完。标记结束仍是白色的对象被回收。STW 有两处，都短：标记开始时打开写屏障，标记收尾时确认没有灰色对象。

CPU 火焰图如果集中在 `runtime.gcBgMarkWorker` 和 `mallocgc`，先看分配是不是发生在每个 token、每个 SSE 块上。网关应该复用缓冲，而不是为每个小包 `make` 一次。业务函数占满火焰图时，再去看正则、JSON 和词库扫描。

1.26 的 Green Tea 不改变「两次短停顿、三色、不整理」这个模型。面试被问到，先讲三色，再讲小对象按页扫描是实现上的聚集，不是另一套 GC。

## 3.3 逃逸（L2）

`go build -gcflags=-m` 能看到变量是否逃到堆上。热路径上被接口、闭包或返回指针抓住的对象会逃逸。先把 SSE 的缓冲放到 sync.Pool 或固定数组，再谈逃逸。不要为了少一次分配把代码写成无法审查的样子。

<a id="4-网络"></a>

# 4 网络

## 4.1 网关站在哪（L1）

进程前面可以有 Nginx 或云负载均衡，做 TLS 终结和按连接分发。鉴权、词库、熔断、模型切换留在 Go 进程里。没有用过反代就直接说没有，并说明它该放在多个 Go 进程前面，而不是在业务进程里自己解析证书。

HTTP/2 不会自动带来 WebSocket。浏览器要在 SETTINGS 里看到扩展 CONNECT，才会把 WebSocket 放上 HTTP/2。Agent 的主流下行仍是 SSE：服务端单向推，实现和取消都更简单。需要用户中途打断、双向说话时再上 WebSocket。

## 4.2 HTTP 服务（L1）

1.22 起可以写方法路由：

```go
mux := http.NewServeMux()
mux.HandleFunc("POST /v1/agent/run", gw.RunSync)
mux.HandleFunc("POST /v1/agent/tasks/{task_id}/continue", gw.ContinueTask)
mux.HandleFunc("GET /v1/agent/tasks/{task_id}", gw.GetTask)
```

`ReadHeaderTimeout`、`ReadTimeout`、`IdleTimeout` 要设。只设客户端超时、不设服务端读超时，慢客户端会占住连接。写超时对 SSE 不合适：一条合法的长回答会超过固定写超时。SSE 用请求 context 的截止时间，不用一个很短的 `WriteTimeout` 切断正常流。

请求体用 `http.MaxBytesReader` 或 `io.LimitReader` 卡上限。先 `json.Unmarshal` 再检查长度，大包已经进内存了。

## 4.3 SSE（L1）

响应头 `Content-Type: text/event-stream`，`Cache-Control: no-cache`。每写一块就 `Flush`。前面的 Nginx 要关掉这一段的缓冲，否则 Flush 到不了客户端。

```go
func writeChunk(w http.ResponseWriter, p []byte) error {
    if _, err := w.Write(p); err != nil {
        return err
    }
    if f, ok := w.(http.Flusher); ok {
        f.Flush()
    }
    return nil
}
```

首 token 已经写给客户端之后，模型网关结束这次流，由编排器用新请求决定要不要重试。两家模型的输出不拼进同一条 SSE。

## 4.4 出站与取消（L1）

```go
req, err := http.NewRequestWithContext(ctx, http.MethodPost, url, bytes.NewReader(body))
```

`http.Client` 要复用，设连接池上限和空闲超时。每个请求 `new` 一个 Client，会把端口耗尽。`Transport.MaxIdleConnsPerHost` 按上游数量设，默认的 2 对模型网关常常不够。

策略调用的超时短于网关整次请求的超时。写操作和出网在策略超时时失败关闭，返回 `policy_unavailable`。只读问答返回事先写好的降级说明，同样不再调用模型。

远端 MCP 的响应流中断后，不按 `Last-Event-ID` 续传。客户端用新的请求 ID 重新发起。本系统自己的 SSE 仍按第 7.5 节排空，两套规则不要混用。

## 4.5 TLS 与 HTTP 版本（L2）

对外 TLS 放在负载均衡上时，应用只信任它写入的 `X-Forwarded-Proto`，并且只在确定自己站在那台负载均衡后面时才信。对内服务网格或 mTLS 是另一套身份，不和用户令牌混用。

<a id="5-接入网关"></a>

# 5 接入网关

## 5.1 职责（L1）

接入网关做：验签、用令牌覆盖客户端自填的 `tenant_id` 和 `user_id`、多级限流、体长、轻量词库、生成或透传追踪、维护开关、把取消传下去。

它不做：语义注入分类、工具权限的第二份实现、RAG、状态机推进。策略规则只有一份。网关调用它做入口配额和「这个 Agent 能不能用」。工具放行由编排器调用同一份策略。

## 5.2 身份（L1）

生产用 IdP 公钥验签，核对过期时间、受众和角色。示例里的共享开发令牌只能留在本地。验签失败返回 `unauthorized`，不把校验库的错误文本给浏览器。

覆盖身份发生在把请求转发出去之前。客户端 JSON 里的租户字段一律被令牌替换。

## 5.3 词库（L1）

词库是可热加载的版本化集合，命中即返回 `blocked_lexicon`，请求不进编排。语义分类、上传文件和工具结果里的注入不放在这里。内容安全拒绝之后不换备用模型。

## 5.4 追踪（L1）

同时带 W3C `traceparent` 和 `X-Trace-Id`。只收到其中一个时，网关生成另一个再往下传。错误码字符串以语言文档 6.11 的常量为源，不在网关里新造一套。

<a id="6-模型网关"></a>

# 6 模型网关

## 6.1 和接入网关拆开（L1）

调用方不同：接入网关面向浏览器和业务系统，模型网关面向编排进程。合成一个进程之后，限流维度、失败语义和发布节奏缠在一起。可以两个二进制，也可以一个仓库两个 `main`，不要一个 HTTP 路由表什么都做。

## 6.2 错误分类（L1）

| 结果 | 动作 |
|---|---|
| 2xx | 记成功，关闭熔断 |
| 429、408、5xx、超时 | 记失败，达到阈值则熔断，必要时切备用 |
| 内容安全拦截 | 停止，不切换 |
| 上下文超长 | 把 `context_too_long` 交回编排，由编排压缩后再请求 |
| 400 和 Schema 不兼容 | 不切换 |

熔断窗口内拒绝。冷却结束后只放一个半开探针。内容拦截、参数错误和超窗要放开这只探针，否则一次业务拒绝会把端点永久留在半开失败里。

备用模型上线前用同一套评测验证工具 Schema、JSON、上下文长度和安全策略。接口返回 200 只说明网络通了。

## 6.3 协议（L2）

对内收编排发来的统一请求，对外翻译成各家 HTTP。流式工具参数是分片到达的 JSON，拼完整并且结束原因表明已经结束，才交给编排解析。网关不在半截 JSON 上做业务判断。用量按租户记在网关。配置热更新不得切断已经在写的 SSE。自建推理时才增加第二层实例路由；只调用外部模型时，模型网关做到厂商协议和配额即可。OpenAPI 包成 MCP 可以挂在网关上做审计和限流，允许或拒绝仍调用那一份策略服务。

思考模型若要求把上一轮思考内容原样回传，按该家文档放进请求。网关不要为了「省 token」丢掉这段，否则后续推理和前缀缓存会一起失效。

## 6.4 重试只发生在一层（L1）

接入网关对用户的 POST 不自动重试。模型网关只在还没写出首 token、且错误属于可切换时，才试下一个端点。编排器、网关、工具 SDK 共用一个重试预算。三层各试三次会把供应商打成 429。

<a id="7-队列租约与幂等"></a>

# 7 队列、租约与幂等

## 7.1 谁写入（L1）

长任务由接入网关在鉴权和词库通过后写入队列，立刻返回 `task_id`。Python Worker 消费、续租约、推进状态机。网关不再写一份租约。队列至少一次，所以消费端用 `task_id` 去重。队列不是事实源，任务状态以数据库为准。

## 7.2 稳定的 task_id（L1）

客户端带 `Idempotency-Key`。`task_id` 由这个键稳定生成（例如 UUIDv5）。网关在 `XADD` 成功、响应还没回到客户端时重启，重试仍落在同一条任务上。

插入使用 `INSERT … ON CONFLICT DO NOTHING`，已有行的状态保持不变。只有状态仍是 `queued` 才允许再 `XADD`。其余状态，包括 `failed`、`cancelled`、`timed_out`、`handed_off`，只返回原 `task_id`。先读出 `queued` 再 `SET` 回 `queued` 会把已经变成 `running` 的行打回队列。骨架在《03-语言分工》第 6.1 节。

## 7.3 幂等的最后一道不在 Redis（L1）

锁会过期，持锁进程可能在提交前死掉。写操作的最后一道是业务表的唯一约束。Redis 只用来减少并发冲突。这个判断在 Python 执行侧落地，Go 入队不能替代它。

## 7.4 取消（L1）

用户取消或连接断开：取消 in-flight 的 HTTP，并写入 `task:{id}:cancel`。Worker 每一步先读这个标记。已经成功的幂等写不回滚。崩溃之后的对照表在《01-请求全流程》第 4.6 节。

## 7.5 退出时排空 SSE（L2）

进程收到退出信号后：

1. 先标记不就绪，接入层不再把新请求分过来。
2. 停止接受新连接，也停止新的 `XADD`。已经入队的任务留在队列里，不跟着进程消失。
3. 在途 SSE 继续 `Flush`，直到写完或到达排空截止时间。截止时间短于编排器的任务 deadline。
4. 截止时间到了还在生成的请求，取消发往上游的 `context`，让模型和工具停下来。已经写出的首 token 就地结束，不换一条流拼接。

滚动发布时先做这一步，再杀进程。只发信号不等待，客户端会看到半截 SSE。

## 7.6 pending 消息交给谁（L2）

消费组里，消息被读走之后停在 pending，直到 `XACK`。Worker 在读走之后、确认之前死掉，消息不会自动回到队列头。

另一名 Worker 在空闲时间超过租约之后把这条 pending 领走，再按 `task_id` 读任务表。终态直接 `XACK`。租约仍有效则不执行。租约过期时用 `lease_version` 条件更新接手，写操作先查业务表幂等键。版本不匹配的状态写入作废。

`XACK` 发生在任务状态已经落库之后。先确认、后写状态，进程再死一次，这条消息就从 pending 消失，崩溃表里的收尾人也不见了。

领取和确认在 Python Worker。Go 网关只负责 `XADD` 和退出时停止新的入队。

<a id="8-多副本与限流"></a>

# 8 多副本与限流

## 8.1 令牌桶（L1）

过了多少时间就补多少令牌，桶有上限。进程内桶用互斥锁即可，不必为每个用户起一个补令牌的 goroutine。`golang.org/x/time/rate` 就是这个算法，并提供带 `context` 的 `Wait`。

手写是为了把补令牌讲清楚。生产多副本把同一套 key 放进 Redis，用 Lua 保证扣减原子。单机桶只保护本进程。四个副本各允许 100 QPS，对外就是 400，这不是「限流坏了」，是 key 放错了地方。

请求次数和 token 配额是两本账。QPS 桶挡住突发连接，token 配额挡住一次请求把整天的额度打完。用量按租户记在网关，不靠模型厂商的账单回写。

## 8.2 舱壁（L2）

模型并发、工具并发、检索并发分开计数。检索打满不应该把写操作的额度一起耗尽。队列有上限，满了就 `rate_limited` 或明确失败。没有上限的排队会把延迟拉到无限，客户端重试再把系统打穿。

## 8.3 发布（L2）

网关无状态，可以先于 Python Worker 滚动。优雅停机的顺序见第 7.5 节。长任务已经入队的不跟着进程消失。配置热更新走同一条约束：新配置只影响之后进来的请求，正在写的 SSE 继续用旧配置写完。

<a id="9-观测与排障"></a>

# 9 观测与排障

## 9.1 三条线（L1）

- 日志：结构化，带 trace id、租户、错误码。不打令牌、不打完整提示词。
- 指标：在途请求、限流次数、词库命中、上游取消、熔断打开、队列深度、每个模型的错误率。标签避免把 user id 做成高基数。
- 追踪：`traceparent` 从接入网关传到编排和模型网关。

## 9.2 CPU 打满（L2）

`pprof` 的火焰图按栈宽看 CPU。栈在业务函数里，查词库、JSON、正则。栈在 GC 和分配里，查每块 SSE 的分配。锁竞争看 mutex 和 block profile，这两类要先打开才有样本。栈在 cgo 里时，用系统的 `perf` 补 Go profile 看不到的部分。网关应尽量不进 cgo。

## 9.3 取消没有发生（L1）

现象是客户端已经走了，模型账单还在涨。先看出站请求是否使用了 `r.Context()` 派生的 ctx，再看反向代理或 HTTP 客户端有没有把取消往下传。只在写响应时发现错误，上游已经生成完了。

<a id="10-测试"></a>

# 10 测试

L1 至少留下这些测试，不依赖真实模型：

| 用例 | 断言 |
|---|---|
| 无令牌、过期令牌 | `unauthorized`，请求体里的租户没有生效 |
| 体长超限 | `body_too_large`，编排没有收到请求 |
| 词库命中 | `blocked_lexicon`，没有调用模型 |
| 超 QPS | 本进程桶拒绝；两个进程不共享桶时，用测试说明 Redis key 才是全集群限额 |
| 客户端中途取消 | 上游 `Do` 返回 `context.Canceled`，不再读完上游 body |
| 内容拦截 | 不调用第二个模型 |
| 半开探针遇到内容拦截 | 探针被放开，端点不会永久熔断 |
| 相同 Idempotency-Key | 得到同一个 `task_id`，成功状态不会被打回 `queued` |
| 策略超时且请求是写操作 | `policy_unavailable`，工具没有执行 |

`go test -race` 跑限流 map 和熔断计数。数据竞争在单测里复现，不留到线上。

<a id="11-不该用-go-写的部分"></a>

# 11 不该用 Go 写的部分

| 部分 | 放在哪 | 原因 |
|---|---|---|
| 规划、状态机、Prompt、评测 | Python | 按周变化，并且依赖模型与数据生态 |
| RAG 切片与融合 | Python | 金标集和检索库的迭代在这边 |
| 页面、CLI、本地 MCP 客户端 | TypeScript | 只负责展示和本地进程 |
| 沙箱、向量归一化、边缘单二进制 | Rust | 要的是资源边界和可嵌入的纯计算 |
| 推理调度、KV、kernel | 推理运行时 | 见《Rust 推理运行时》。Go 网关只做准入和转发 |

没有高风险代码执行、也没有实测需要下沉的热点时，不上 Rust。隔离先用独立容器。Go 仍然从预生产就站在入口上：限流、身份覆盖和取消不是「等 QPS 上来再补」的优化。

远程 MCP 若只是高并发 HTTP，可以用 Go 提供 Streamable HTTP。工具里的业务判断仍回到那一份策略和对应的业务服务。

# 12 学习顺序

每一段都要留下能跑的测试，再进入下一段。

| 段 | 做完的标准 |
|---|---|
| 1 语言与错误 | 切片断开底层数组；`errors.Is` 区分两类失败 |
| 2 并发与 context | 十个慢请求，断开后 goroutine 回收；`-race` 通过 |
| 3 HTTP 与 SSE | 方法路由、体长、Flush；取消能传到上游 |
| 4 接入网关 | 身份覆盖、词库、进程内令牌桶、追踪头 |
| 5 模型网关 | 错误分类、熔断、半开探针、内容拦截不切换 |
| 6 入队 | 稳定 `task_id`，成功状态不被重试打回队列 |
| 7 多副本 | Redis 限流把四个进程算成一个总额；pprof 能指出一次分配热点 |

然后对照《Agent 开发语言》第 6 章，把示例收成和 Python 错误码一致的服务。编排仍用现成的 Python。不要在这一步重写 Agent 循环。
