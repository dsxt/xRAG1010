## 怎么更有野心

[How to be more ambitious](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)，2026-10-13。

模型能力不均匀。陶哲轩的说法被他借来用：某些方向惊人，另一些方向不够。多数人还停在「法国首都是哪」「把这封邮件改得不那么冲」。他在 Anthropic 内部把「我们还不够有野心」当成口头禅，这篇文章是可执行版本。

野心分成四种。Speed（同样的活更快）已经是默认用法，文章跳过。剩下三种：

**Altitude：问结果，少派任务。** 你交给模型的往往是你自己对路径的猜测。往上抬一层，问的是「接下来要发生什么」。他去年初还在让 Claude 修单个崩溃，后来改成「让应用保持不崩」。要做到这一步，得先改工作流：崩溃报告能拉取、版本能对上 git commit、Windows / macOS / Linux 机器能独立复现并验证修复。人从循环里退出，靠的是这些接口，靠的是一句更短的指令。

用季度业务复盘（QBR）做梯子，一层比一层高：

1. 把能拿到的数据都给模型：「这季度变了什么、为什么、该怎么办。」模板里的数字更新不算。
2. 会议要落成决定：「面对你刚学到的一切，哪三个决定最急？每个给出可行方向和正反理由。」
3. 连复盘这个形式一起质疑：「复盘存在，是为了让管理层早点发现问题、把钱和人挪到对的地方。设计一个比季度幻灯片更好的办法，用我们自己的历史证明它会更早抓住问题，并和现有流程并行跑一个季度。」

适合 Altitude 的信号：这件事后面本来就要开会讨论。纯创作不太适合。2026 年「去赚钱」这种句子对多数公司仍然无效，但模型能稳住的抽象层在变高。

**Depth：按这个领域最好的人的做法做，做到他们也能从结果里学到新东西。**

- 坚持用业内最好的人用的仪器。模型被要求「表现得专业」时，常常只换词汇。流失分析里，它去写 Markdown 表格时，要求改用数据库和统计模型。你不必事先知道专家用什么，模型通常知道。
- 把不合理的目标说成合理的。网站要从 10 秒到 5 秒，就要求 200 毫秒。模型说不可能时，重复说这件事可解，让它继续。
- 用原始数据对抗你以为知道的事。「我们相信流失是 onboarding 问题。用原始数据试着复现这个结论。」
- 在已经钻进数据之后生产新知识。「用日志做一个能复现过去一年的客户模拟。找出我们还不知道的最早流失信号，并在它没见过的数据上证明这个信号能预测。」
- 用外部裁判。2026 年 10 月，让模型给自己打分仍然不可靠。最好是模型能自己跑的工具，反馈立刻回来。

他常用的一段指令（译意）：

> 我要把这个任务做深，规模保持原样。重写之前先说四件事：（1）这个领域的顶尖专业人士在这里会做、而我没要求的是什么；（2）他们会从哪一份最原始的材料出发，已经被人消化好的摘要不算；（3）他们会用的具体方法和工具；（4）除了你和我，什么能证明结果是对的。然后按这四条重写我的提示。

**Range：把过去不划算同时请的那些学科请进来。** 多线程、编排器、子代理让这变得便宜。同事 Alex Albert 用 Blender 渲室内设计之后，他才想到自己的主页可以用三维，尽管他以前做过游戏。

两个手法：

- 把名词换成动词。来自 Tom Kelley、Jonathan Littman 的 *The Art of Innovation*。季度复盘的名词是「一份 deck」。动词是「让忙的人在 30 分钟内相信一个因果故事，并在不确定下做决定」。有了动词，才看得出哪个学科能补一刀。
- 组队，但要的是那个学科的做法。为了制作质量：分析师、记者、编辑。要上台：动效和声音。要对抗：做空者和法务会计师。容易滑进角色扮演，台词变怪，结果不变。让模型去做空者研究仓位时会做的调查，口吻留在外面。

三种野心都要求模型有一台能装软件的电脑，以及相关数据（MCP 或其他接入）。

文章后半解释为什么需要这些技巧：人被「自己相信什么是可能的」卡住，而且只在很窄的学科里相信自己。心理学里这叫 self-efficacy。Locke 和 Latham 总结 35 年目标研究：具体的硬目标，胜过「尽力而为」。三个有记载的黑客：

- 把难题当成作业。1939 年 George Dantzig 迟到，把黑板上两道未解的统计题抄下来当作业交了。
- 看见别人做成。Roger Bannister 1954 年 5 月打破四分钟一英里，之后 46 天里不再是唯一一个。
- 允许自己失败。*The Inner Game of Tennis*：拼命想打好，往往打不出自己的最好水平。Linux 发布时的句子是 “just a hobby, won't be big and professional like gnu”。

Patrick Collison 维护一份 [Fast 清单](https://patrickcollison.com/fast)，记人类在大胆目标和紧截止日期同时存在时做成的事。

## 机械手段做成的主页

[Made by mechanical means](https://felixrieseberg.com/made-by-mechanical-means/)，2026-09-27。交互版房间就是这篇文章的成品。全文用 Opus 5.5。他没开 GitHub，没提 PR，也没用专门的 Claude Code，用的是通用的 Claude。

**编排。** 建一个 Claude Project。Project 横跨 Chat、Cowork、Code，坐在这些产品形态上面：对一个 Claude 说话，它可以拉起更多会话、共享文件和记忆、监督整队去达成目标。今年早些时候他还开玩笑说自己是「派一堆 Claude 干活」。现在每个项目有一个负责的 Claude，它知道怎么管任务、调查和线程。对话更多在目标上。

每个线程有自己的云端电脑，按需装 Blender、FFmpeg、Playwright，用无头浏览器截图检查，发布一个私有预览页。所有线程共享一个文件夹和一份记忆。负责的 Claude 会把已做的决定写进记忆，新线程不用他重复。大约 60 个线程，很多并行。相当一部分编排在手机上完成：骑车时把想法发出去，下一站咖啡时看结果。重的三维渲染可以把自己的电脑接进线程（`Work Locally`），用本地 GPU。

**方向。** 先把灵感倒在桌上：90 年代锐舞海报、喜欢的电影和广告、反复看的照片、喜欢的概念。十个线程几乎没有指导地并行探索。露营国家公园、80 年代攻壳机动队，他都觉得太像已有的东西。喜欢的方向就要求加倍、再给五个变体。

很快他把 Claude 推向 Blender。Claude 把 Blender 当 Python 模块调用，几何和渲染都走代码。复古设备（Game Boy、唱机、Walkman）加一个作品集画廊，Claude 提议用 VHS 带。他加上自己的画面：一部 90 年代德国电影里会给记者的那种房间，而且能交互。第二稿在第一份 brief 之后 39 分钟到达，已经能认出今天的房间。上线版大约 60 轮迭代。

Claude 自己把代码拆成模块，好让线程并行做房间里的物件。每盒磁带是一个文件，往 2D canvas 上画：`mount({ canvas, ctx, width, height, audio })` 返回 `frame` / `input` / `stop`。

**房间。** 他不会用 Blender。他描述想要的东西，Claude 用代码写几何、渲一张静帧、他给反馈。房间大约 3000 行 Python。例子：一盒 VHS（332 行，187×103×25 mm，空壳、卷轴、磁带、导柱、铰链防尘门）；一张 90 年代记者桌（659 行，电话加微型卡带答录机、Rolodex、软盘、寻呼机、太阳能计算器、Discman、Walkman）；一台假品牌的 80 年代末米色 PC（431 行）；镜头背后那半间房，只在反射和自由视角里出现（290 行）。部分家具来自 Poly Haven（CC0），桌子、电视和录像机、随身听、整台旧 PC、房间几何是代码建的。木、灰泥、塑料、金属的表面是程序化噪声。

浏览器里的实时光做不出他要的软反射。Claude 用 Blender 的路径追踪 Cycles，把光烘进贴图。每个静态表面有第二套 UV，打进图集；每个图集最多四张图：无光的颜色、房间自己的灯（台灯、城市光、月光）、电视单独发出的白光、台灯关掉的房间。着色器再用当前磁带的颜色去染电视那一路光，蓝带子就把房间染蓝。会动的东西（磁带、旋钮、舱门、LED、屏幕）不烘，实时打光。

窗外要照片级、要活、访客机器上又不能吃太多。先试了一张 CC BY 的柏林天际线照片，又试过用 Blender 生成整条天际线，生成的不如照片。Claude 改用 Depth Anything V2，把照片变成约 50 KB 的双通道深度图：软的一张让桅杆、信号和近处建筑在镜头漂移时相对天际线滑动，尖的一张让火车能消失在建筑后面。灯和火车由 GPU 画在照片上。

**企鹅。** 他最喜欢的一段是对 Werner Herzog《Encounters at the End of the World》里那只走向内陆的企鹅的戏仿。先用 SVG 把讽刺的尺度谈清楚，再让 Claude 做贴近原片的 CGI，然后再改。Claude 按镜头边界切成八段，逐帧跟摄像机的摇、推、手持晃动，用 Blender 代码建雪、山、碎石和企鹅，渲了 2787 帧 640×480、23.976 fps，116 秒。改动很小：冰上的办公桌和电脑、企鹅路上一排他待过的公司的旗、一年才更新一次的博客。旁白先用开源语音模型，质量不够，他办了 ElevenLabs Starter，把 API key 交给 Claude。

站上还有三首从零合成的配乐，同样是 Python：先写谱，再写合成器。他给的反馈是 Rick Rubin 式的「我喜欢这个」「别这么兴奋」。他自己复述不出和声进行。

**不读代码。** 几十个线程同时在写，他读不完，也没有去读。他用带团队时的办法建立质量：严格的过程和度量，以及专门负责弄坏东西的对抗线程。多路 QA 在无头浏览器里一轮轮跑站点，往共享文件夹写了大约 3000 行发现。负责的 Claude 判断是哪条线程的问题并转过去。对抗线程抓到过：空白标签的磁带、残留的德文、卡片后面仍可点的链接、快速切带时的竞态。单条线程写不出他能接受的代码；一队互相追责的 Claude 可以。

性能用爬山。给线程明确目标：帧率、draw call、阴影绘制。模型要判断两个版本看起来是否差不多，Claude 的办法是多角度截图、逐像素算差。性能提升要在画面差几乎为零的前提下成立。

文章收在美术史：1859 年巴黎沙龙第一次接受摄影，波德莱尔认为把机械过程算作创作是品味的威胁，摄影是「每一个想当画家、又太没天赋或太懒、完不成学业的人的避难所」。他承认主页里单件道具可以挑出质量差的地方，也承认自己没走过三维的苦功。48 小时前脑子里的画面，就是现在这间房。

## 饥饿胜过资历

[Hunger beats tenure](https://felixrieseberg.com/hunger-beats-tenure-advice-for-junior-engineers/)，2026-10-27。对象是没有社会资本、地位和权力的工程师。「初级」这个词他觉得不准确。

他这个月以 Anthropic 招聘经理的身份停掉了传统编程面试。以前，能快速定义问题并找到干净解法，是弱但有用的预测；真实代码里的小挑战确实能说明一点问题。现在给一道 React 小题，和考汇编一样没有信息量，Claude 两样都更强。他看到的高产出的人，成败和这些测验分数对不上。

他看到的现象：入行不久的人超过了代码更好、待得更久的人。影响不再被「在框架和库里积累了多少年」卡住。

**新鲜眼睛的优势，和没人听你的劣势。** Patrick Collison 在 Stripe 要求新人盯住自己觉得奇怪的地方。James March 1991 年写过，组织靠「持续流入天真和无知」活着。Orson Welles 被问为什么敢用没人试过的镜头：「无知，纯粹的无知。对一门行当有所了解之后，人才会胆怯、才会小心。」

他加入 Notion 时的一场面试是设计离线架构。对方当它是「诡计题」：离线被认为不可能。数据模型太复杂，没法轻松同步整个工作区；按页下载又是 CEO Ivan Zhao 不会接受的体验。数据模型的复杂度是真的，创始人的抵制后来证明是假的。这事被当成常识，久到没人再去核对。

他自己也变成过那个老手。刚进 Notion 时他想给团队装大电视放实时看板，撞上组织的墙，失败了，也懒得再打一架。一年后新人 Ji Pei 提了同一个想法，他劝对方别费劲。电视第二天就到了。

公司结构假定执行很贵：中间层把业务目标翻译成执行，少数人批准或拦住单个想法，你得先磨到一定地位，组织才肯在你的想法上下注。很多相信 AI 的公司仍然只让初级的人把手头任务做快。执行的成本已经掉下来了，动手不必再等地位。

五步：

1. 选业务影响，选待办列表。Patrick McKenzie 2011 年写过：工程师被雇来创造业务价值。先搞清公司（大公司里则是你所在的组）到底要达成什么。合适的高度常常是你经理的经理的目标。
2. 选一个激进的想法。做成了会明显提高组织达成那些目标的概率。
3. 用一个周末做出来。他见过小团队和单人用可运行的原型，飞过写 PRD、求认同、排队等设计和产品经理的流程。
4. 一个原型里只放一个好想法。初级的人常把多个想法塞进同一个原型，三个好想法埋在二十个坏的里面。原型如果同时要新语言、后端和移动端，就失败了。原型的作用是把想法讲清楚，让领导同时看见机会、看见你是能把它做下去的人。
5. 用上你还没被熏过的视角。做面向用户的产品时，你更知道外部用户实际怎么用。Slack 和 Notion 的老人很难回到「第一次用」的感觉。做基础设施和工具时，你还没学会所有「这不可能」的理由。

Anthropic 内部的例子：大家用惯了 Claude Code 的命令行之后，两个相对较新的工程师 Anthony Morris 和 Alice Zhao 用一个周末做出可用原型，大约八天后第一个公开版本发出。Claude Code 的图形界面成了很受欢迎的产品。

编程面试他不指望再回来。他在招的人，是能和 AI 一起把东西做好的人，具体怎么面他还没定下来。他现在扫简历和作品集时找的是小原型，上面能看出品味、同理心和有原则的思考。
