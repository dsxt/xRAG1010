九、文件命名、保存与交付
格式为 UTF-8 编码 Markdown（.md）。
文件名：周一日期_周日日期.md。
例如：2026-11-09_2026-11-15.md。
年份目录按统计周周一所属年份确定。
目标目录：
D:\python\xRAG1010\AIAgent\资讯\<年份>\
完整示例：
D:\python\xRAG1010\AIAgent\资讯\2026\2026-11-09_2026-11-15.md
先在助手电脑生成并校验，再通过受支持的文件传输保存到目标电脑；不存在的年份目录可以创建。
不能在 Linux 上伪造同名 C 盘路径冒充本地保存，不因目录位于项目下而修改仓库代码或执行 Git 操作。
目标已有同名文件时先比较：内容相同则无需重复写入；内容不同须获得我的覆盖确认，不静默覆盖。
用户电脑上的操作遵守实际权限与审批要求。
电脑离线、未获审批或传输失败时，仍先在本聊天交付可下载的 .md 附件，并明确说明本地保存尚未完成。不得把“源文件已生成”说成“已保存到我的电脑”。
后台无法完成传输或附件交付时，把已校验的源文件、准确目标路径、日期范围及实际保存状态交回本聊天继续完成，不把内部交接当成用户已收到。
十、周报交付前校验
确认：
- 文件存在，UTF-8 编码可读。
- 周一至周日日期范围正确，无误收本周一内容。
- 每日所有已发送正文与补充均完整纳入。
- 链接、表格、时间、数据口径和限制均保留。
- 缺失日期、缺失原文和事后更正均准确标注。
- 不将各日 GitHub stars today 累加成周净增。
- 本地保存成功后，确认实际目标文件存在且内容与源文件一致。
最终将 .md 作为可下载附件发送给本聊天中的我，附一句中文说明覆盖日期与实际本地保存状态；存在归档缺口时同时明确说明。不要用 Page、聊天摘要或只有路径的回复代替文件。
