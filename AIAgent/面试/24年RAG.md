# 2024 年的切块问答、近邻索引、Agent 分界、上下文向量

只记晓灰 2024 年 11 月那几篇笔记里的做法和当时的反思：和 PDF 聊天、向量数据库、案件分析 Agent、向量为什么能够表示语义，以及同一时期「要不要做 Agent」的清单。后面的评测、轨迹包、领域微调和发布门禁不在这里。

## 切块问答

直接把整篇 PDF 发给模型就能答，但文章太长，会超出 token 上限。即便不设上限，一个问题也可能要花 10 到 100 美元。所以当时的做法是先缩小再生成。

链路四步：

1. 用库把 PDF 抽成文本。笔记里用的是 PyPDF2，按页 `extract_text` 拼成一整段。
2. 切成小块再嵌入。`CharacterTextSplitter` 的参数是分隔符换行、`chunk_size=1000`、`chunk_overlap=200`、长度按字符数。重叠是为了块和块接得上，相似度检索时多捞到相邻上下文。
3. 用 OpenAI Embeddings 把每个块变成向量，放进 FAISS。本地就有「这段文字 ↔ 一串浮点数」。
4. 用户提问时，问题也做一次嵌入，按相似度取出若干块，交给 `load_qa_chain(..., chain_type="stuff")`，把这些块和问题一起塞进一次生成。

提问「who are the main author of the article?」时，内部是三步：问题向量化，和本地向量比出最相似的几块，再把这几块交给模型归纳。中文提问同样走这三步，模型侧会处理语言。

当时试过的文档是《2023 GPT4All Technical Report》。问训练成本，返回的是文中那几句：大约四天、800 美元 GPU（含失败的训练）、500 美元 API；发布的 gpt4all-lora 在 Lambda Labs 的 DGX A100 上大约八小时、一百美元。

反思写在问答那一节的末尾：问题如果必须结合全文才能概括，这种匹配不够用。它每次送进模型的，总是和问题最像的局部片段。总结里的判断是：向量化负责模糊匹配，生成模型负责把匹配到的片段说成人话。

## 近邻索引

向量被当时的笔记称作 AI 时代的 JSON：文本、图像、音频、商品描述都变成浮点数组之后，才能用距离比较。传统库能存图片的二进制，不能以图搜图；字符串可以模糊匹配，一句话就不行。`king - queen` 与 `man - woman` 被当成同一类差异的示意。GPT 被写成仍是黑盒，不知道涌现从哪来。llama-2-70b 在文件系统上是参数文件加运行它的二进制，大约 140G（700 亿参数，每个参数 2 字节）。

精确 KNN 要和库里每条向量比。数据到千万、亿级时算不动，所以检索降级成 ANN，近似最近邻。

四种索引是当时记下的做法：

| 方法 | 做法 | 当时看到的代价 |
|---|---|---|
| 随机投影 | 造一个目标维度的随机矩阵，输入向量乘上去，只留前几维。查询用同一矩阵投影后再比 | 维度降了，搜索变快；相似性只是被保留，不是被证明不变 |
| 局部敏感哈希 | 哈希要满足「输入像，输出也接近」。相似向量进同一桶，查询只和同桶比较 | 比扫全库快。高维里两个向量可以很像、空间距离却远，线性扫描既慢也常常没必要 |
| 倒排 | 用中心点把空间划成区域。建索引时，向量归到最近的中心点 | 和 LSH 一样靠缩小范围。一个向量只属于一个区域，要提高召回就得搜更大的一片，计算量又上去 |
| HNSW | 在 NSW 上加分层 | 图方法可以只走空间的一部分 |

HNSW 的直觉是「邻居的邻居也可能是邻居」，再加六度分隔：同质性让相似点连在一起，弱连接让少数边跳到远处。NSW 的建图是随机插入顶点，新点和最近的 m 个点连边。问题是不稳定：先插入的点邻居偏远，后插入的点邻居偏近，热点的度会很高。HNSW 把图分层，检索从粗到细。

相似度三条：

- 欧氏距离是直线距离，和向量的大小有关，适合比「买了多少、隔了多久」这种带计量的属性。
- 余弦看夹角，范围从 -1 到 1，不看长度。适合比文本的整体方向。按「温暖」分好类之后，还要用高饱和度的图去找高饱和度的图，余弦不够，因为饱和度在长度里。
- 点积同时受长度和夹角影响。

集合层面另有三条。Jaccard 是交集比并集。两个大集合里混进少量噪声，系数会掉：A 有 1000 个元素且完全包含于有 10000 个元素的 B，系数约 0.0909；再各混 10 个噪声，约 0.0891。Dice 用 `2|A∩B| / (|A|+|B|)`，对这种不均匀没那么敏感，计算更贵，也更怕异常值。F1 兼顾精度和召回，对零值敏感。

每条向量还可以带日期、标签、地理这类元数据。过滤有两种时机，笔记没有选边，只写下两边的开销：

- 预过滤先缩搜索空间，可能把不符合元数据、但向量很近的结果丢掉，筛选一宽还会拖慢查询。
- 后过滤先做完近邻，再扔掉不符合的，相关结果更不容易漏，筛的是已经算过的集合，查询同样变慢。

选型上的判断是：向量对数据库来说就是多了一种类似 JSON 的类型。Elasticsearch、PostgreSQL 的 pgvector、Redis 都能做，Milvus 和 Pinecone 是专门的向量库。

## Agent 和 RPA 的分界

业务是核赔。一个案件人工平均两小时，复杂的要一两天。专家精力之外的大量案件和里面的线索没人消费。第一目标是自动分析案件、判断风险；第二目标是把沉在案件里的知识用起来。

人工流程四步：收医疗报告、事故报告、检方报告；按基本信息再查就医、轨迹、财务、投保，查的过程中会冒出新线索；把线索联起来判断欺诈，必要时查亲友；按保司要求出结构化核赔报告。

笔记里的例子是 2024 年 5 月，赵某在家一氧化碳中毒死亡，家属发现意外险还在保期内来索赔。专家看到的线索是：资金流水里有约 20 笔给某男性的送礼、半月前停止；一个月内买了烤炉和木炭，寒冷天气已经过去；预测月入一万、无逾期、家庭流动资产三万以上；近期无就医；意外险连续四年续保、没有多头，2023 年加保到 100 万。推理是疑似感情破裂、木炭买得不寻常、加保发生在出险前不久，表面上的意外更像自杀。坐实自杀可以拒赔，证据不够也可以少赔。

当时列出的四类技术障碍：

- 私域数据要进提问和推理，公域模型接进来之后，安全不可控。
- 自由生成会幻觉。投保日 2024-04-01、出险日 2024-04-10 这种逆选择，不检查的话，模型判对只是一个概率。
- 推理够不到专家的取证方向。煤炭中毒要去看煤炭的浏览和交易、当地当时是否需要烧煤取暖、生前感情关系。模型未必知道该从这些方向收集。
- 领域黑话对不上：逆选择、道德风险、多头投保、多头借贷、失信被执行、除外责任、风险评估。

和 RPA 的分界写得很死。SOP 里用模型做实体识别、推理和总结，下一步做什么仍由代码预先写好，模型只是流程中的一个角色，这仍然可以叫做 RPA。把模型放进控制流，由它决定采取哪个动作、用哪个工具、怎样解释输入，才是当时定义的 Agent。由此得到的能力是自主、自然语言交互（从菜单表单的 GUI 换成把意图说清楚），以及业务路径变化时不必改死每一步。a16z 的判断被引来支持这一点：上一代 RPA 做不到真正的数字员工，是因为每一步都硬编码；Agent 对着目标自己选工具。

组成沿 Lilian Weng：规划（拆子任务、看进度、改计划）、记忆（Postgres + 向量库或 Chroma，放领域知识和有界上下文）、工具（浏览、代码、鉴权、企业内部 API）。实践里再加一条推理：底座权重里已经有一部分世界模型和基本逻辑，这是对非结构化数据推理的底子。

框架调研名单是 AgentUniverse、AutoGen、LangGraph、TaskWeaver、Swarm、Magentic-One。选了蚂蚁的 AgentUniverse，模式用 PEER：Plan、Execute、Express、Review。启动顺序是读配置、用户密钥、日志、Web、扩展、监控，再扫描注册组件。

一次案件的控制流是：提问进 Facade，NER 抽出参数，Planner 决定调查方向，方向对应的 Agent 已在执行数组里就执行，然后 Express，再 Review。意图和可调用方法一一对应，方法参数来自 NER。Planner 是某一种模式的封装，检测、输入、控制、数据、记忆、模型分成层。

工具上的做法：工具描述要短、要结构化，放进上下文让模型选。场景只查询、不写入，所以中间数据都放进 context，被调到的工具自己取参数，不要求模型把一长串参数填对。每个 Agent 只负责一个调查方向，模型决定方向，不决定方向里面的具体工具。ToolGen 被记下来作为对照：工具太多、描述塞不进窗口时，可以把工具标识和参数知识微调进模型，让它直接输出工具 id。这个案件没有走那条路，因为窗口里要选的是调查方向，不是全部工具。

提示沿用的一般原则是：指示写清楚，复杂任务拆成子任务，指令把模型按在任务上，回答前先解释。

RAG 被指出的缺陷是不懂查询背后的上下文，会召回跑题或事实不够的文档。笔记转述微软亚洲研究院的四层：

1. 显式事实：数据里直接有的事实。
2. 隐式事实：要把数据里的隐含信息拼起来。
3. 可解释推理：要套领域理由和逻辑。
4. 隐式推理：连推理逻辑本身都得从数据里推。

做法是对原始查询生成多种解释，让检索盖住更多潜在含义，再重排。回测看准确率和阳性发现率。

反思是一条实现路径，每一步都靠上一步已经有的东西：完全人工，然后电子表单和在线收集，然后 SOP，然后 RPA 跑重复步骤，最后才把分析和决策交给 Agent。案件分析能做，是因为案例库、就医、轨迹、财务、投保记录和一套 SOP 已经在。

另一条反思是准确率的乘积。从查询理解、知识维护到多路召回，没有单点可以跳过。效果到 70% 之后，剩下的是把每一段再做细。

当时写在展望里、还没落地的三件事：用语言代理树搜索（蒙特卡洛树搜索加反馈和回溯）加强推理；规划用有向无环图，不只有链；人可以干预。界面预期是自然语言加多模态。同一时期的清单用来决定做不做 Agent：

| 问题 | 走工作流 | 走 Agent |
|---|---|---|
| 任务够不够复杂 | 不够就走工作流 | 够复杂才考虑 Agent |
| 一次值多少钱 | 低于 0.1 美元走工作流 | 高于 1 美元才考虑 Agent |
| 子步骤是不是都能做 | 不能就缩小范围 | 都能做才交给 Agent |
| 出错和发现出错的代价 | 高就只读，或人在回路里 | 低才让 Agent 自己做完 |

另外一条和语言有关的观察被记在同一时期：一个较弱的小模型若能被大模型的方案说服，这个方案人也比较容易看懂。语言被当成智能的核心，工具用来补模型不会做的计算，例如多位数乘法。

## 上下文向量

两句都有「苹果」：「苹果公司发布了新手机」「我把苹果削皮以后吃了」。one-hot 给的是同一个固定向量。能看见上下文的模型，会按「公司、手机」或「削皮、吃」算出不同的表示。差别来自训练目标：数出现次数会丢掉词序，预测周围的词留下共现，预测下一个 token 则要求用更长的上下文。损失反复改参数，留下对当前任务有用的信息。

one-hot 只回答「我是谁」。词表四个词时，「苹果」和「香蕉」的距离等于「苹果」和「公司」。五万词就是五万维，只有一位是 1。one-shot 是提示里给一个例子，和独热编码只有拼写接近。

词袋按次数计数，「我喜欢苹果」和「苹果喜欢我」是同一个向量。TF-IDF 压低「的」「是」，仍然只数次数。LSA 把词—文档共现矩阵分解到低维，没有用同样词的两篇文章可以因为主题方向接近而相似，但每个词仍只有一个位置，词序和具体上下文进不去。2003 年的神经概率语言模型把词映射成稠密向量，用前面几个词预测下一个词，嵌入和预测网络一起反向传播。窗口是固定的，对整个词表算概率很贵。

Word2Vec 没有发明词向量。它用浅层网络、负采样或分层 softmax，把训练放到大规模语料上。Skip-gram 用中心词预测周围的词，CBOW 用周围的词预测中心词。中心词「吃」、窗口里的「喜欢」「鱼」是正样本，随机的「火车」「利率」是负样本。正样本把点积拉高，负样本把点积压低。猫和狗共享「喂养、宠物」这类上下文，梯度方向反复重合，于是靠近。没有人给「猫」指定坐标。

`king - man ≈ queen - woman`，`Paris - France ≈ Beijing - China`，来自大量词对里重复出现的用法差异，在梯度里留下近似平行的位移。这不是一根可以命名为「性别」的精确坐标轴，也不是每组类比都成立。语料、词频、训练目标和社会偏见都会改变结果。学到的是用法分布，不是词典定义，也不保证事实。GloVe 同样是一个词一个固定向量。使用时的上下文不再改这个向量，所以两个「苹果」分不开。

RNN 按顺序把当前词和上一步状态合成新状态，「狗咬人」和「人咬狗」因此不同。最后状态可以当句子摘要。LSTM 和 GRU 用门减轻长序列遗忘。限制是：历史都要穿过同一条链，开头容易变淡；第 t 步要等第 t−1 步，难并行。早期 Seq2Seq 把整句压进一个固定向量，句子一长，人物、动作和长距离关系一起丢。

2014 年的注意力让解码器在生成每个词时，对源句每个位置算匹配分，归一化后加权求和。生成 `loan` 时可以回头看「贷款」，不必只靠最后一个摘要。计算仍然挂在 RNN 上，词还是要按顺序读。

Transformer 去掉这条循环。每个 token 先查嵌入表，加上位置：同一个「苹果」的初始向量相同，加上位置之后两个位置的输入已经不同，后面的自注意力再把上下文造成的差异写进隐藏状态。Query 是这一位在找什么，Key 是它能以什么身份被找到，Value 是找到之后取走的内容。这是读公式用的比喻，关系本身由训练出来。多头用多组投影，不同头可以抓住不同关系，但不能指定某一头永远负责某一种人类概念。输出不是一个句子向量，而是每个位置各有一个上下文化向量。

形状沿层保持。7 个 token、隐藏维 4096 时，嵌入之后是 `[7, 4096]`，每一层进出仍是这个形状。生成时最后一层映射到词表，例如 10 万词得到 `[7, 100000]` 的 logits，解码读最后一位。训练把序列右移一位当目标，每个没被掩住的位置算下一个 token 的交叉熵。检索不读 logits：从最后一层的 token 状态做池化，可选投影和归一化，得到固定向量，例如 1024 维。没有人给一句话标一个目标坐标，监督是查询和文档、或句子对谁该更近。底座参与训练时梯度会改 Transformer；冻结底座时只更新池化或投影。

BERT 用编码器，遮住一些 token，靠左右两边补回去。两个「苹果」要补出「吃」和「手机」，表示必须分开。适合分类、抽取、阅读理解。原始 BERT 没有直接要求整句相似时向量也相近。句子检索这条分支是 Sentence-BERT 一类：句对加对比学习，再把整段压成一个可比较的向量。ELMo 更早，用双向 LSTM 让同一个词在不同句子里得到不同向量。

GPT 是只有解码器的 Transformer，因果掩码只看左侧。一段文本提供很多预测题。损失只检查正确答案的概率，不检查事实。GPT-1 是预训练再微调，GPT-2 观察到只靠提示也能做一部分任务，GPT-3 把 zero-shot、one-shot、few-shot 放进输入，参数不更新。它的上下文散在各层、各位置的隐藏状态和下一 token 的分布里，不会自然给出一根用来检索的句子向量。要做相似度，得另用嵌入模型把整句压成固定长度。

从 one-hot 到 GPT，当时整理的界限是：

| 阶段 | 一个词怎么表示 | 当时过不去的地方 |
|---|---|---|
| one-hot | 词表里的唯一位置 | 相似词一样远 |
| 词袋 / TF-IDF | 次数和权重 | 没有词序和上下文 |
| LSA | 低维主题方向 | 一词多义、词序 |
| 神经概率语言模型 | 可训练的稠密向量 | 窗口短，对全词表算概率贵 |
| Word2Vec / GloVe | 一个词一个静态向量 | 使用时的上下文改不了它 |
| RNN / LSTM | 按顺序累积的状态 | 长距离变淡，难并行 |
| 注意力 | 当前步骤去读源序列 | 早期仍绑在循环上 |
| Transformer | 每一层更新每个位置 | 计算随长度涨得快 |
| BERT | 双向，靠补空 | 不直接续写；原始目标不是句子检索 |
| GPT | 只看左侧，预测下一个 token | 流畅不保证事实 |

换语料、目标或负样本，更新方向就变，向量空间也变。向量只忠实于训练数据、训练目标和比较方式。相似度检索再用余弦、点积或欧氏距离去比已经压好的固定向量。训练和最近邻搜索是前后两件事。扩展到图像 patch、语音采样或视频时，序列计算可以复用，预测目标不同：文本的下一词落在有限词表上，视频下一帧有大量不可预测的纹理，直接预测像素会把容量花在那些细节上。JEPA 改成在抽象表示里预测目标，不去复原输入的每一个像素。它可以使用 Transformer，目标表示和损失仍然决定留下什么信息。
