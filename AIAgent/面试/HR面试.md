# HR 面试

用法：面试前把文首「口径卡」填成自己的事实，背到能脱稿。每题先看「她在听什么」，再按结构讲完，控制在 30 到 90 秒。技术面和 HR 面只用这一套事实，时间、职级、离职原因、薪资口径保持一致。

公司公开信息（业务、办公城市、是不是外包或项目制）面试前自己核对，不把传闻说成内部事实。数字只报自己算过、背调也能对上的。

---

## 口径卡

主因只能有一个。离职、看机会、定居若各讲一套，追问两句就会穿。

| 项 | 只留一句 | 填写 |
| --- | --- | --- |
| 离职主因 | 业务结束 / 方向接触不到线上系统 / 组织调整 / 地点，四选一 | |
| 前几家 | 每家一句，和简历时间对齐，不讲薪资和人 | |
| 空窗 | 从哪天到哪天，具体在补什么 | |
| 定居 | 跟对象所在城市，还是保持本地；公司若搬迁怎么说 | |
| 方向 | 先把一条生产链路做深，专家路径 | |
| 到岗 | 最早日期，是否要交接或等年终 | |
| 薪资 | 税前月薪区间，以及对应的年度总包；下限是真实能接的 | |
| Offer | 流程中几家、书面 offer 几家，不捏造 | |
| 转方向 | 哪一段是上班做过的，哪一段是离职后补的 | |
| 选 offer | 工作地和签约主体、三个月要做的事、上级、总包，按这个顺序 | |

现场：语气平，认真，可以停两秒再答。对公司和下一份工作用期待来说。被追问时先复述她的问题，确认听对了再答。

---

## 她其实在听什么

| 她问 | 她在确认 |
| --- | --- |
| 自我介绍、性格、优点缺点 | 表达是否清楚，和岗位是否合拍 |
| 离职原因、前几家、空窗、回老家 | 稳定性，原因是否经得起背调 |
| 定居、线上面试、外包、出差驻场 | 人能不能到这个工位上长期干 |
| 想找什么样的工作、为什么是我们、职业规划 | 动机是否和 HC 一致，会不会很快再走 |
| 挑战、立项步骤、意见不合、领导解决不了 | 协作和推进，会不会只抱怨 |
| 前领导、不能接受的点、几天就离职 | 是否好管理，是否玻璃心 |
| 加班、适应新环境 | 试用期会不会因为节奏或陌生就撤 |
| Offer、薪资、到岗、超预算、怎么选 | 能不能谈拢，压一压你会不会改口 |
| 你是 Java 的，为什么做 Agent；能待几年；上家挽留 | 方向是不是临时的，人会不会马上再走 |
| 你的反问、最后还有什么补充 | 你是来了解岗位，还是只来询价 |

## 1. 开场

### 1.1 自我介绍

**她在听什么**：一分钟里能否听懂你是谁、最近做成过什么、为什么出现在这场面试。

**结构**

1. 姓名、年限、方向。方向用岗位语言：Java 服务端，最近在做可上线的 Agent 应用。
2. 一件听得懂的事：给谁用、你负责哪一段、结果是什么。实现细节留到她追问。
3. 一个性格证据：需求不清楚时先收成可验证的验收；线上出问题先把影响范围和链路说清。
4. 收在这个岗位：想做能进产品和工程约束的 Agent，希望了解团队现在的系统和节奏。

**示例**

> 面试官好，我叫【姓名】，做了【N】年后端，主要是 Java 服务端。最近【一段时间】在做【系统名】，它给【谁】用来【完成什么事】，我负责【检索 / 工具调用 / 服务化】这一段，【一个你能解释的结果】。我习惯先对齐验收再动手，出了问题先把影响和链路说清楚。这次看机会，是想把 Agent 做到能上线、能看效果。也想了解这个岗位入职后主要负责哪条系统。

HR 场控制在 60 到 90 秒。她打断就停，按她的问题往下走。和简历上的时间、职称一致。

### 1.2 你是什么性格的人

**她在听什么**：稳不稳定，好不好协作，会不会和团队现有的人处不来。

**结构**

用两个能被例子证明的特点，各配半句事，讲完就停。

1. 做事收口：拿到需求会先问清谁用、什么叫做完、什么情况算失败。
2. 沟通直接：分歧写成目标和约束，会后按定下来的方案执行。

**示例**

> 我偏稳，事情交给我会追到有结果。需求不清楚时，我会先把验收标准写成几条再开工。和同事意见不同，我会把各自要保住的点摊开，定下来之后按那个方案做。

形容词只留「稳」和「把事情做完」。场面话式的「我很外向 / 我追求完美」没有例子，接不住追问。

### 1.3 优点和缺点

**她在听什么**：优点是否就是这个岗位要的；缺点是否真实，以及你是不是已经在改。

**优点**：选一个和岗位相关的行为。例如把边界问清楚、线上能顺着链路查完、交付前会补验证。用一件事的行动和结果说明。

**缺点**：选一个真实、且不打在岗位核心能力上的习惯，并说出现在的做法。

可用口径（换成你自己的事）：

> 我以前容易方案还没对齐就开始写，返工过一次【什么事】。现在我会先写清假设、接口和验收，对齐后再动代码，周报里也把未决问题单独列出来。

优点、缺点各一个例子。缺点讲完补上你现在的具体动作。

### 1.4 你的优势是什么，相对其他候选人

**她在听什么**：你能不能用一句人话说明自己能马上帮上什么。

**结构**

1. 优势落在「能把原型收成可上线的链路」。
2. Java 侧：并发、状态、幂等、超时、权限。
3. 模型侧：你真实做过的那一段，例如检索、工具、评测。没做过的不说成精通。
4. 补一句边界：哪一侧你还要靠团队，入职后打算怎么补。

## 2. 离职、空窗、地点

### 2.1 上家公司为什么离职

**她在听什么**：原因是否单一、是否体面、会不会入职三个月又以同样理由离开。

**结构**

1. 只留口径卡上的那一个主因。
2. 用事实说：项目结束、组织调整、原岗位接触不到你要做的线上系统、工作地变化。选真实的那个。
3. 向前一句：下一份希望模型相关的改动有验收，写操作有权限边界，人能在这个城市稳定做。
4. 三十秒讲完。薪资、前领导的性格放到专门的题，不放在第一句。

**示例**

> 上家我负责【模块】。离开是因为【主因，例如这块业务收掉了 / 岗位做不到线上 Agent】。我希望下一份能在【城市】把一条真实链路做深，所以开始看机会。

原因和简历上的离职时间、项目结束时间一致。背调若打给前公司，你的说法和前领导的说法要能对上。

### 2.2 前几家公司呢，离职原因分别是什么

**她在听什么**：是不是每家都「发展空间不够」，时间线是否有洞。

**结构**

每家一句，按时间从早到近：

> 【公司或业务类型】我做了【多久】，离开是因为【项目交付完成 / 合同到期 / 技术范围】。

三家以内都准备到。方向保持一致：事情做完或范围到头，人是往同一类工作走。中间有重叠或间隔，主动说清，等她从简历里算出来会更被动。

### 2.3 离职之后在做什么

**她在听什么**：空窗是有安排的，还是随缘休息到现在。

**结构**

1. 先报区间：从上家最后工作日到现在，大约【几个月】。
2. 再说三件具体的事：补一条能讲完整的项目或系统、按目标岗位准备面试、处理交接或个人事务。
3. 若主因是回老家或跟对象聚合，这里用同一句话带过，说明城市已经定了，所以现在可以入职。
4. 有接过短单或帮忙，就说范围和是否结束，方便背调。

**示例**

> 离开到现在大约【N】个月。这段时间我把【项目】补到能独立讲清楚，也在按 Agent 应用岗准备。城市这边已经定在【城市】，所以现在可以安排到岗。

### 2.4 回老家的原因

**她在听什么**：回来是临时过渡，还是能在这里待住。

**结构**

原因和定居用同一套，只强调稳定性。

1. 个人安排已经落地：家人或对象在这里，生活有落点。
2. 工作安排：这个城市有你要做的业务，回来是为了长期做，同时看机会。
3. 若是公司搬迁、项目结束之后才回来，把顺序说清楚，避免听成「那边干不下去了」。

**示例**

> 我对象在【城市】，生活上我会以这里为长期落点。工作上也希望在这边把服务端和 Agent 应用做下去，所以这段时间集中在看本地的机会。

若实际还没决定留不留，就先把口径卡填死再去面，现场临时改口最容易被听出来。

### 2.5 以后考虑定居哪里

**她在听什么**：半年后会不会因为对象、家庭或公司搬迁再走。

按事实二选一，说完补一句对这份工作的态度。

**对象在面试城市**

> 我对象在这边，我考虑在这里定居。这份工作如果匹配，我可以长期做，也接受正常的出差。

**人在本地，担心公司搬到外地**

> 我打算定居在【当前城市】。如果团队主体在这里，我可以稳定到岗。若后续办公城市有调整，我会在变动落实前和公司把工作地谈清楚，再决定是否跟随。

她追问「对象在哪里、什么时候结婚」，用一两句事实回答，然后回到工作地已经定了。家庭细节点到为止。

### 2.6 外地候选人，为什么是线上面试

这题可能是她问你，也可能是你要确认流程。

**她问你时**

> 我人在【城市】。贵司岗位在【城市】，这次先线上把匹配度聊清楚。如果进入下一轮或 offer 阶段，我可以按你们的安排到现场。

**你要确认时**

> 后续是继续线上，还是会安排一次到场？如果需要到场，我提前协调时间。

人在外地、岗位在本地时，主动说出能到岗的时间，减少她对「人根本不过来」的担心。

### 2.7 上家要是加薪挽留，你还走吗

**她在听什么**：离职原因能不能被钱买回去。能买回去，她就默认你在用这家抬价。

主因是地点或业务范围时，加薪改变不了这个事实。

**示例**

> 走之前他们如果谈挽留，我还是会离开。原因是【口径卡上的主因，例如人要落在这个城市 / 原岗位做不到这条链路】，加薪解决不了这件事。交接我会做完，证明人也可以提供。

主因若其实是薪资，这题就改成实话：期望区间是多少、上家差在结构的哪一项。两套说法不能混用。

### 2.8 你跳得比较勤，能在我们这里待几年

**她在听什么**：每段履历是不是都做完了，这次稳住的条件是什么。

**结构**

1. 先报事实：几段工作、每段大概多久。短的那段用第 2.2 节那一句原因带过。
2. 再说这次不同在哪：城市已经定了，要做的系统类型也定了。
3. 给一个你能负责的周期：把一条系统从接手做到稳定上线，按两到三年看。

**示例**

> 前面几段分别是【时长】，离开都是因为【项目结束或范围到头】。这次城市定在【城市】，我想把一条业务链路做完整，按两到三年看。匹配的话，我不会因为外面有个新名词就再动。

年限和简历一致。把「至少三年」说成保证，而实际一年一跳，背调对不上。

## 3. 动机和规划

### 3.1 想找什么样的工作

**她在听什么**：你的筛选条件和她手头的 HC 是否是同一份工作。

**结构**

按这个顺序，每项一句：

1. 内容：业务后端加上可上线的 Agent，有真实用户或内部系统，有验收。
2. 团队：需求、研发、测试的协作是清楚的，线上问题有人负责。
3. 城市：和口径卡里的定居一致。
4. 公司形态：能接受的是自有业务、还是也接受外包驻场，面试前自己定好。

**示例**

> 我想找一份能长期做的后端工作，最好是业务系统里真实在用的 Agent，而不是只做演示。团队最好有明确的需求评审和上线节奏。城市就在【城市】。公司是自己的产品还是项目交付，我都会问清楚再决定。

### 3.2 为什么看我们公司，对我们有什么了解

**她在听什么**：你是海投，还是知道自己来的是哪家。

**结构**

1. 了解到什么：用面试前核对过的两三句，业务、产品、办公城市。只说你能对上的那条业务。
2. 为什么是这里：业务类型和你想做的系统一致；技术栈和你的 Java 经验对得上；城市与定居一致。
3. 你能马上做的：服务化、工具权限、一条链路的上线和排查。

了解不够就少说，把问题换成「想听你介绍这个组具体做哪条业务」。编内部架构或没感受过的文化，追问会接不住。

### 3.3 公司是外包吗，你接不接受

这题两边都会出现：她问你的接受度，你要核实岗位性质。

**她问你接不接受外包或驻场**

先按自己的真实底线答，现场临时放宽，入职后会变成「几天就走」的理由。

能接受时：

> 可以。我在意的是工作内容是不是业务系统开发、驻场是否稳定、汇报和考核在谁那里。这些清楚的话，我可以做。

只接受自有产品时：

> 我更希望做公司自己的业务系统，长期跟一条产品线。如果是短期驻场、项目结束就换场，和我这次想稳定做深的打算不一致。

**你来核实**

一次问清四件事，问完就停：

1. 劳动合同签在哪家公司，是用工主体还是外包供应商。
2. 工作地点是自有办公区还是客户现场，客户和项目周期大概多久。
3. 直属上级是供应商还是甲方，转正和绩效由谁评。
4. 项目结束后是内部调配，还是重新找项目。

问的时候用了解岗位的语气。听到的答案和 JD 不一致，记下来，回去再决定，当场不必表态。

### 3.4 职业规划

**她在听什么**：你的三年目标和这个岗位是一条路，还是来镀金。

**结构**

先定专家路径，再用两年顺序收住。

1. 近一年：独立负责一块系统，把需求、上线和线上问题闭环做熟。岗位含 Agent，就说先把一个功能做进现有系统，并补上验收。
2. 三年：能对一条链路的稳定性、权限和效果负责，可以做方案评审或带新人。带人放在能独立判断之后。
3. 和团队对齐：如果业务更需要把现有系统做稳，你前两年就做这件事。

**示例**

> 我走技术专家这条路。第一年先把负责的系统摸透，能独立交付和值班。三年内希望对一条生产链路负责，包括工具权限、失败时怎么降级、效果怎么验收。管理我可以在这条链路稳定之后再考虑，顺序是先把判断做对。

管理岗只在你确实想做、并且接受少写代码时再当成主路径。和 JD 无关的转行目标放到私人计划里。

### 3.5 如果通过了，前三个月怎么上手

**她在听什么**：试用期你是来改架构的，还是来先把业务接住的。

1. 第一个月：把一条真实请求在本地跑通，搞清发布、回滚、权限和数据不能出哪一层。跟着看线上问题，少改框架。
2. 第二个月：接手一个小需求或一类问题，按团队现有节奏独立做到上线。
3. 第三个月：做一件能用事实说明的改进，例如补一段原来看不见的日志，或收紧一个写操作的权限。
4. 想改的地方先写成问题和证据，跟负责人对齐优先级。

### 3.6 你是做 Java 的，为什么现在看 Agent

**她在听什么**：方向是跟风，还是你已经能把原有手艺用到这个岗位上。技术面会往下挖，这里只证明动机和边界。

**结构**

1. 岗位要的仍是后端：状态、超时、幂等、权限、上线之后怎么查。这些是你上班做过的。
2. 模型相关只讲口径卡里那一句：哪段是公司里的，哪段是离职后自己补的。
3. 你能马上做的是把模型接进现有系统，并让它失败时可以关掉、可以追溯。
4. 还要靠团队的部分说出来，例如评测标准、业务数据从哪来。

**示例**

> 我的本行是 Java 服务端。Agent 岗位里真正容易出事的是工具接到真实数据之后：重复执行、越权、超时没有人知道。这块我和原来做接口、做上下游是同一类问题。模型这一侧，【公司里做过的 / 离职后补的项目】我能讲清楚；业务指标和数据口径，入职后按你们现有的来，我先沿用。

她若问「AI 会不会让开发没工作」，收到同一句：模型要进生产，仍然要有人负责权限、失败和验收，所以你想做的是这一层。

## 4. 协作、压力、管理

### 4.1 过往工作里遇到的挑战

**她在听什么**：有没有扛过事，讲的时候是在甩锅还是在推进。

用 STAR，只准备一件真事，技术面若已经讲过，这里换一件，或把技术收成「人和协作」版本。

1. 背景：当时要交付什么，期限和约束是什么。
2. 卡点：需求变了、依赖方没有负责人、上线后指标不对，三选一。
3. 动作：你怎么确认原因，拉了谁，放弃了哪个方案。
4. 结果：功能上线、范围缩小，或明确延期。用你能解释的变化。
5. 收一句：后来你把什么写成了习惯，例如先定验收、决策记进文档。

两分钟。心情少讲，动作多讲。

### 4.2 一个项目从立项开始有哪些步骤

**她在听什么**：你知不知道软件是怎么交付的，会不会只等着接任务。

按你们真实做过的流程说，下面是一条能讲清楚的顺序：

1. 立项：谁提出、要解决什么问题、不做什么、怎样算成功。
2. 范围：参与角色、依赖系统、里程碑和风险。
3. 方案：接口、数据、权限、失败了怎么办；评审通过再开发。
4. 开发与联调：拆任务，和前端、测试、依赖方对齐联调时间。
5. 测试与发布：用例、灰度、回滚条件、谁值班。
6. 上线后：看指标和反馈，把问题收成下一轮。

HR 听得懂的讲法是「先定成功标准，再写方案，评审后开发，灰度上线，上线后看结果」。她追问你负责哪几步，就落到你真实做过的那几步。

### 4.3 和同事或产品意见不一致怎么办

**结构**

1. 先复述对方的结论和理由，确认没有听错。
2. 把分歧收成同一件事：目标、已有事实、代价、期限。
3. 说出你的方案和你担心的风险。能做小范围验证时，用结果说话。
4. 仍然不一致，交给共同的负责人。对方职责内拍板的，按决定执行。
5. 定了之后按这个方案做。

例子里讲清分歧是什么、最后用了哪个方案、上线后怎样。最后用的是对方的方案，也可以讲你如何把它做完。

### 4.4 前领导是一个什么样的人

**她在听什么**：你如何评价有权力的人。她默认你以后也会这样评价她。

讲工作行为，用一件具体的配合。

**示例**

> 我前领导目标说得比较清楚，排期有冲突时会帮我们砍范围。我跟他配合时，周报里会把进度、风险和需要他拍板的事分开写，这样他能直接决策。

准备两个真实特点就够：怎么定目标、怎么处理延期或线上问题。评价停在工作方式。

### 4.5 她的哪一点是你不能接受的

**她在听什么**：你的底线是否正当，以及你会不会因为看不惯就离职。

选一条工作原则，并说出你当时怎么处理。

**示例**

> 我比较不能接受的是出了问题先找人背，事实还没对齐。遇到这种情况，我会先把时间线、影响范围和可选做法写出来，请能拍板的人定。原则我守，但日常协作里我会先把信息对齐，而不是对着人。

底线可以是：事实不清就追责、承诺了的排期随意加需求却不改范围。讲完补一句，大多数时候你会先沟通和适应。

### 4.6 出现问题，上级也解决不了，怎么办

**她在听什么**：你会不会把问题原样抛回去，然后停工。

**结构**

1. 先止血：能回滚、能降级、能暂时关掉的开关，先做，避免影响继续扩大。
2. 把问题上收成一页：现象、影响、你已经查到的、两个可选方案、各自代价、你建议哪一个、最晚什么时候要决定。
3. 上级的上级或真正能拍板的角色，由上级一起拉，你负责把事实讲清。
4. 在等待决定时，继续做不依赖拍板的部分：补日志、通知受影响的人、准备回滚。
5. 决定之后执行，并把结论记下来。

**示例**

> 我会先把损失停住。然后给领导一页纸：现在影响谁、我查到哪、A 和 B 两个方案差在哪、我建议选哪个。如果这一层定不了，我会请他一起找到能拍板的人。等决定的时候，我把不需要拍板的准备工作做完。

### 4.7 对于加班的看法

**她在听什么**：发布和故障时你在不在；同时她也在听你是否完全没有边界。

**示例**

> 发布窗口、线上故障、关键节点的赶工，我会加班，把事情收完再走。我在意的是加班是否有目标，比如这次要保哪次上线。平时我希望需求在评审时就把工作量谈清楚，尽量把赶工留在真正紧急的事情上。长期每天都很晚、又说不清在赶什么，我会在试用期和负责人把节奏谈开。

她追问「能不能接受 996」，按你的真实底线答。底线用工作能否持续来表达：关键节点可以，长期无目标的高强度你会慎重。

### 4.8 什么情况会让你入职几天就离职

**她在听什么**：你的离职触发器是否任性。她要的是「原则清晰，同时你会先核实」。

只留和 offer、岗位事实相关的三条：

1. 实际工作内容和面试、JD 严重不符，比如约定做业务研发，入职后是长期无关支持。
2. 薪资结构、工作地、签约主体和书面 offer 不一致。
3. 工作方式触及你已经说清的底线，比如要求你做无法对账的数据操作。

**示例**

> 我不会因为不适应或和同事不熟就走。如果入职后发现岗位内容和书面 offer 对不上，比如签约主体、工作地或主要职责变了，我会先和负责人、HR 核对。核对之后仍然和约定不一致，我才会考虑很快离开。所以今天我也想把职责和工作地问清楚。

把「氛围不好」「领导语气」「有更好的就走」留在心里，这句话一出口，稳定性就没了。

### 4.9 到一个新环境，怎么适应

**结构**

1. 第一周搞清三件事：系统和发布怎么走、事情向谁对齐、这个团队怎样同步进度。
2. 术语和历史决策先问，先沿用现有做法交付一个小需求。
3. 主动做一次短同步：每天或隔天告诉导师你做到哪、卡在哪。
4. 两周后再提你看到的问题，附上事实，请负责人排优先级。

**示例**

> 我会先跟着现有流程走通一条需求，搞清找谁评审、怎么发布、出问题找谁。不熟悉的业务词我会记下来问。前两周以交付小需求为主，适应之后再把看到的问题拿出来对齐。

### 4.10 抗压：需求很多、排期很紧，你怎么办

1. 先列清单：哪些必须本期做，哪些可以下一期，各自影响是什么。
2. 和负责人确认砍哪一块，自己保住正确性和可回滚。
3. 做到哪一步同步到哪一步，风险提前说。
4. 准备一件你真实砍过范围或分过期的事。

### 4.11 失败的一次经历

一件真事：哪里判断错了，你怎么补，后来加了什么机制防止再犯。例如一次评审没对齐导致返工，之后你改成先写验收再开发。失败要有补救，讲完收在机制上。

## 5. Offer、薪资、到岗

### 5.1 手里有没有 offer，面试了几家

**她在听什么**：你的紧急程度，以及你会不会拿假 offer 压她。

如实说进度，分成「在流程中」和「已有书面 offer」。

**示例**

> 目前在流程中的大约【N】家，书面 offer【有 / 还没有】。我比较想认真看【业务类型】和城市是否匹配，所以还在比较。贵司这次我意向是明确的，也希望了解你们的定级和大致时间。

有 offer 就说城市和大致方向，薪资数字等她问到薪资再讲。没有 offer 就说没有，同时表明你在认真推进，时间上可以配合。

### 5.2 期望薪资是多少

面试前自己算清三档：不能接受的下限、希望的目标、职责明显更大时可以谈到的上限。下限必须是你真实愿意签的。

**结构**

1. 先定口径：税前月薪，还是含奖金、补贴的年度总包。对方问哪个就答哪个。
2. 报区间，并说明依据是当前总包、岗位职责和你了解的市场水平。
3. 问清结构：月数、绩效、股票或签字费、城市补贴、试用期比例。
4. 对方的级别和你假设的不一致时，先问级别，再调区间。

**示例**

> 按税前月薪，我期望是【A】到【B】，对应年度总包大概【C】到【D】，这里按【14 或 16】薪估算。具体还想了解这个级别的固定、绩效和补贴怎么构成。如果职责包含线上值班或更大的模块，我们可以再谈。

当前收入被追问时，按真实结构说固定和浮动，不夸大。同事的包不拿来比较。还没算清区间，就说想先听级别和薪酬结构，当天给过的数字不要当场改口。

她说「比你现在高很多」：用一句职责差异回答，例如模块更大、要值班、城市不同。说完停住，把区间留在原来的数字上。

她说「超预算」：先问超在哪一项，是月薪、月数还是级别。她给出新数字后，复述一遍，并问固定、绩效、试用期比例。这个数高于或等于你的下限，就说可以按这个结构继续。低于下限，就说这个数你签不了；如果定级或职责有调整，可以再看一版。下限当天不改。

### 5.3 最快什么时候到岗

**示例**

> 如果本周定下来，我最早【日期】到岗。中间需要【交接天数 / 没有交接】。如果涉及年终或未休年假，我会在签 offer 前和你们对齐，避免入职日期来回改。

日期和口径卡一致。已经离职就说现在即可，并留出体检、背调、租房的天数。

### 5.4 出差和驻场

按底线答。能接受偶尔出差：

> 项目上线和客户对接需要出差，我可以接受，希望频率大致可预期。长期驻场我需要知道城市、周期和结束后的安排。

定居城市若和驻场城市不同，在这题一次说清，避免签完才发现人要长期待在另一个城市。

### 5.5 竞业和背调

**竞业**

> 我【有 / 没有】竞业协议。如果有，限制的是【行业或客户】，期限到【日期】。和贵司业务是否冲突，我可以提供条款里能给的范围，签之前双方确认。

有竞业就在谈 offer 前说。瞒到背调，成本更高。

**背调**

> 可以背调。前公司证明人我可以提供【前领导或 HR】的联系方式。离职时间、职级和薪资结构我前面说的就是实际的。

证明人提前打好招呼，口径和你今天说的一致。

### 5.6 家庭情况

被问到婚育、对象，用事实短句，然后回到稳定性。

> 我对象在【城市】，这也是我打算在这里长期工作的原因。家庭安排是稳定的，可以按岗位正常到岗。

愿意说的范围自己事先定好。说完不要展开私人计划。

### 5.7 几个机会你怎么选

**她在听什么**：你的排序和今天说的定居、岗位是不是同一套。

按这个顺序说，和口径卡一致：

1. 工作地、签约主体、是不是长期驻场。
2. 入职三个月实际要做的事，是不是业务系统。
3. 直属上级和团队节奏。
4. 总包结构，最后才是公司名气。

**示例**

> 我先看人能不能在【城市】长期做、合同签在哪。然后看三个月是不是在做业务系统。团队和汇报清楚之后，再比总包。所以今天我也想把这几件事问明白。

现场临时把「谁开得高选谁」说成标准，会和前面的稳定性冲突。

## 6. 你要问的问题

问两个到三个，用来核对岗位，不要问「氛围怎么样」。上一题没问清的薪资结构、轮次和时间，可以补一句。

### 6.1 建议每场都问

1. **为什么招这个人**：这个 HC 是新增还是补缺，前三个月最希望交出来的是什么。
2. **工作内容**：具体做哪条业务，是固定产品还是同时支援多个项目。
3. **流程**：需求从提出到上线经过谁，你在里面负责哪一段。
4. **汇报**：直属上级是谁，技术和管理是否同一个人，和产品、测试怎么配合。

### 6.2 用来判断能不能长期做

5. **晋升**：这个级别往上的标准是什么，最近团队里的例子大概是什么节奏。
6. **考核**：日报、周报、月报分别交给谁，考核看交付、质量还是工时，试用期怎么评。
7. **安排**：工作时间、发布窗口、值班和加班大概是什么节奏。加班是调休、加班费，还是算在绩效里；试用期工资是多少比例。
8. **地点和主体**：办公城市、是否驻场、劳动合同签在哪家。外包题用第 3.3 节那四问。

### 6.3 流程收尾

9. 后面还有几轮，大概什么时候有结果。
10. 若进入 offer，定级和薪资结构由谁沟通。

她答得含糊的地方记下来：签约主体、工作地、三个月目标。这三样和「几天就离职」的底线直接相关，含糊就在下一轮或 offer 前再确认一次。

**示例**

> 我想确认两件事。一是这个岗位入职三个月，最主要要交出来的是什么。二是日常向谁汇报，需求评审和上线分别是什么节奏，考核看哪些指标。

## 7. 现场一张纸

开场 90 秒自我介绍，然后只答她问的。每题四句：事实、你的做法、结果、和这份工作的关系。

| 顺序 | 记住 |
| --- | --- |
| 离职 | 一个主因，向前看一句 |
| 空窗 | 区间 + 三件具体的事 |
| 定居 | 和对象或老家是同一句话 |
| 规划 | 一年做熟一条系统，三年对链路负责 |
| 加班 | 关键节点在，目标要清楚 |
| 几天就走 | 只跟书面约定不符有关 |
| 薪资 | 区间 + 问结构；低于下限当天不改 |
| 转方向 | 后端是上班做的，模型只讲做过的那一段 |
| 挽留 | 主因不是钱，加薪改变不了 |
| 待几年 | 城市已定，按两到三年把一条链路做完 |
| 怎么选 | 工作地、三个月的事、上级、总包 |
| 反问 | 三个月目标、汇报、考核 |
| 收尾 | 匹配点重说一遍，补上还没问到的那一件 |

她问「还有什么要补充的」，用 20 秒收：

> 我补充一句。我人可以定在【城市】，本行是服务端，模型相关的【哪一段】我能独立讲。如果岗位前三个月是把一条现有链路接住，我可以按这个目标来。还想确认的是【三个月目标 / 签约主体，二选一，只留她没答过的】。

讲完停住。最后一分钟不再加新的缺点，也不再改薪资。
