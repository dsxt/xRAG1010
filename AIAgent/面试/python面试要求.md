# Python 后端面试真实强度

别被网上八股大全带偏了，真实战场早就换玩法了。
第一部分，基础核心能力地基必垒
先说硬功夫，这四条你躲不开。
语言核心：别只会 CRUD，Python GIL、内存管理、垃圾回收机制、生成器 / 协程、异步 IO（asyncio）、装饰器、元类、深浅拷贝、线程进程区别、锁机制必须吃透，代码得能讲底层执行机制，还要清楚 CPython 的实现局限。
网络与操作系统：TCP 握手挥手、HTTP/HTTPS、IO 多路复用、零拷贝、进程线程协程，不能只背概念，要能讲清异步框架、WSGI/ASGI 服务吞吐上不去的根源。
数据库：MySQL 索引结构、事务隔离、MVCC、锁机制、慢 SQL 优化、分库分表；SQLAlchemy/ORM 底层、防注入、事务使用坑点，张口要有完整优化方案。
Redis：缓存穿透击穿雪崩、分布式锁、持久化、集群高可用，以及 Python 客户端（redis-py）连接池、管道、lua 脚本使用，别把 Redis 当万能许愿池。

第二部分，主流技术栈深度远大于广度
Web 框架：Django 生命周期、中间件、信号、ORM 原理；FastAPI 请求生命周期、依赖注入、Pydantic 校验、异步特性；Flask 上下文、蓝图、请求钩子，不能只会写接口，要懂源码和底层执行流程。
微服务生态：注册发现、配置中心、网关、熔断限流、链路追踪；消息队列 Kafka/RocketMQ/RabbitMQ，幂等、顺序、延迟、事务消息要能落地；工程化：Poetry/Pipenv、CI/CD、Docker、K8s、日志监控、告警体系都是日常必查。别以为会调 API 就叫 Python 后端，面试官看的是你能不能独立解决依赖冲突、服务启动阻塞、异步链路异常的问题。

第三部分，实战场景才是分水岭
举个例子，如何设计支撑 10 万 QPS 的秒杀系统？不是加个限流就完事，你得聊削峰异步、库存扣减、缓存一致性、分布式事务、降级容灾、压测闭环，白板手写简易限流器、异步任务或者生产者消费者模型，直接检验工程功底。
微服务拆分核心原则是什么？业务域、数据边界、通信开销、版本独立部署，还要结合康威定律讲高可用和可迭代。
另外 Python 后端特有高频场景：同步接口阻塞怎么改造异步？大量任务怎么选型 Celery/RQ/async 任务？大量爬虫任务如何做分布式调度、反爬、限速？
说到这块，我整理了一套大厂 Python 后端高频面试真题，涵盖八股、场景题、AI 融合题和高分简历。只要是我粉丝，评论区甩已关 666，全部打包带走。

第四部分，线上排查和项目经验才是真金不怕火炼
CPU 飙高、内存泄漏、协程阻塞、死锁、慢 SQL、连接池打满、接口雪崩，你能否用 top、py-spy、tracemalloc、gdb、prometheus、链路追踪工具快速定位？要清楚异步场景下的排坑难点（协程卡死、事件循环阻塞）。
项目经历必须有完整闭环：需求评审、技术选型、压测、灰度上线、线上复盘，能讲清架构取舍、Python 选型利弊和踩过的坑（比如 GIL 带来的 CPU 密集瓶颈、异步陷阱、ORM 性能问题）。
