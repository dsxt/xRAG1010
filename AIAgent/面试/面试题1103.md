## 基础概念

先划清 Agent、Workflow、Chatbot 的边界，再谈状态、轨迹和工具调用格式。

#### p1. 用自己的话解释 Agent、Workflow、Chatbot 三者的区别。

**初中级 · Agent 开发岗** · 考察：自主决策、循环调工具、状态机边界

Chatbot 主要是多轮对话、少副作用；Workflow 是预定状态机/DAG，分支固定可审计；Agent 由模型循环选工具，并根据 observation 改计划。面试我先划边界：强合规、零容错走 Workflow；目标开放、需探索才上 Agent。也可以外层 Workflow 控合规，内层 Agent 做局部探索。上海 30k+ 更看你能否讲清何时不该用 Agent，并用前后端经验说明状态、权限与副作用如何落地。

- 先定义再划边界：自主性、副作用、可控性；强合规→Workflow，开放任务→Agent。
- **常见坑**：混用 Workflow/Agent、忽视 observation 闭环。
- **例子**：退款审批走 DAG；排查异常订单走 Agent 调只读工具。

#### p2. 什么是 ReAct？它和 Plan-and-Execute 有什么取舍？

**初中级 · Agent 开发岗** · 考察：延迟、可控性、复杂任务分解

ReAct 边想边做（Thought→Action→Observation），适应变化，但步数与延迟难控；Plan-and-Execute 先规划再执行，可控可并行，计划却容易过时。可分解、工具稳定的任务偏后者，探索性任务偏 ReAct。生产我常混合：短计划 + 执行中局部 ReAct，并加 max_steps、重复调用检测和费用墙。取舍本质是可控性换适应性；答到停止条件与观测指标才像工程岗。

- **常见坑**：无停止条件、只规划不校验工具结果。
- **例子**：max_steps 8–20；同签名重复≤2–3。

#### p3. Function Calling / Tool Use 的典型请求响应格式是什么样的？

**初中级 · Agent 开发岗** · 考察：name、arguments、并行调用、错误回传

Function Calling 里，模型不会直接执行工具，而是在助手消息里返回 `tool_calls`，每项包含 `id`、`name` 和 JSON 格式的 `arguments`。服务端解析并校验后执行工具，再以 `role: tool` 消息把结果回传，并用 `tool_call_id` 对齐。模型可以一次返回多个 `tool_call` 实现并行调用，适合无依赖的读操作；有依赖就必须串行。错误应该结构化回传，包含错误码和可操作提示，让模型决定重试、改参或换工具。工程上我还会强调 Schema 同源校验和 trace 用 call_id 贯穿。

- **常见坑**：只回字符串异常、不定义并行汇合。
- **例子**：Zod+Pydantic 同源校验。

#### p31. 什么是 tool choice / forced function call？什么时候用？

**初中级 · Agent 开发岗** · 考察：强制走某工具、JSON 抽取、降低乱跑

`tool_choice` 用来控制工具选择策略：`auto` 让模型自决，`required/any` 强制至少调用一个工具，指定函数名则强制调用某个工具，`none` 则禁止调用。生产上我通常只在关键节点使用 forced——比如结构化抽取、必须查实时数据的路由——开放对话保持 auto。forced 只管「选不选工具」，不替代 Schema 校验与权限控制；写操作仍要服务端鉴权和 HITL。更稳的是入口先做意图分层：闲聊直出、明确业务进 Workflow、模糊任务再交给 Agent。

- tool_choice 可强制 auto/required/指定函数。适合必须落工具的抽取、路由、禁止纯聊天乱跑；不要在开放对话里永远 forced，否则无法正常回复。
- **常见坑**：全局 forced 导致无法寒暄；以为 forced 可替代鉴权。

#### p32. 解释 observation、action、thought 在轨迹里各自是什么。

**初中级 · Agent 开发岗** · 考察：日志结构与评测对齐

thought 是推理痕迹，action 是工具名与参数，observation 是工具返回，三者构成可评测可复现的轨迹。日志按这三段对齐，才能分别看工具选择准确率与任务成功率。生产可对 thought 采样降本，但 action/observation 关键字段要完整。排障先看 action 是否选错，再看 observation 是否正确写回上下文。

- **常见坑**：只存最终回复，无法复盘工具错选。

#### p33. Agent 的「状态」通常包含哪些字段？

**初中级 · Agent 开发岗** · 考察：messages、scratchpad、tool results、budget

状态常见字段：messages、目标/scratchpad、未完成 tool 结果、步数与 token/费用预算、挂起等待点（补参/人审）。必须可序列化才能 checkpoint/resume，并带图版本。权威状态放服务端，前端只持会话 id。TS 消费状态事件、Python loop 做转移，避免双写。

- **常见坑**：前后端双写状态、恢复不校验版本。

#### p34. CoT、ToT、GoT 对 Agent 工程有什么实际价值？哪些不该上生产？

**中级 · Agent 开发岗** · 考察：成本延迟 vs 收益；生产常只要短推理

短 CoT 对难推理有性价比；ToT/GoT 搜索贵、延迟高，全量生产很少划算。Agent 工程优先工具校验与检索，推理长度设上限。是否加长推理看正确率-成本曲线；多数业务短 CoT + 工具闭环足够。推理预算也要进 Runtime 硬限制。取舍上用「查得准、校验严」替代「想得久」。

- **常见坑**：无推理预算硬限制，只靠提示词「请简短」。

#### p35. 什么是 Computer Use / Browser Agent？和普通 API Tool Agent 风险差在哪？

**中级 · Agent 开发岗** · 考察：非结构化 UI、权限面更大

Computer Use/Browser Agent 操作非结构化 UI，权限面和误操作风险远大于 API Tool Agent。生产默认优先 API；上浏览器必须强沙箱、出站白名单、敏感操作人审，并限制可达域与动作集。观测要能回放关键操作序列，否则事故难追责。

- **常见坑**：无回放、无域名白名单就开放点击。

### 基础应用

#### a29. embedding、chunk、rerank、citation 各解决什么？

**初中级 · 应用开发岗** · 考察：基础概念

embedding 语义向量；chunk 切分单元。rerank 精排；citation 可追溯引用。串起 RAG 链路讲清。

- **常见坑**：概念孤立背、串不起链路。
- **例子**：一句话串完切分→嵌入→检索→重排→带 citation 生成。

#### a91. 解释 reranker 与 embedding 检索为何常常要两段式？

**初中级 · 应用开发岗** · 考察：召回广度 vs 精排精度

embedding 廉价广召回；rerank 交叉编码更准但贵。两段式平衡成本与质量。一阶段向量难又全又准。流程：取 top100→rerank top10→生成。何时可省：语料极小或延迟极敏感。

- 坑：rerank 模型与领域不匹配。

## 编排与 Harness

运行时负责把模型包成可中断、可恢复、有预算的执行过程。先讲终止条件，再讲 checkpoint。

### 编排引擎

#### ★ p4. 设计一个 Agent 运行时：从用户消息到最终回复，画完整数据流。

**中级 · Agent 开发岗** · 考察：prompt、路由、工具、状态、人审

运行时数据流：入口鉴权 → 组 prompt（system/工具/历史/RAG）→ 模型路由 → 解析 tool_calls → 权限校验执行 → 写状态/trace → 循环或人审 → SSE 流式返回；同时画清同步路径与异步 job。机制上要有硬限制、checkpoint、cancel，以及工具副作用标记。人审节点可挂起等待，恢复后继续。结合 TS+Python：BFF 出事件，Python 跑 loop，权威状态在服务端。

#### ★ p5. 如何实现可中断、可恢复的 Agent loop（checkpoint / resume）？

**中级 · Agent 开发岗** · 考察：序列化、幂等、版本兼容

每步后序列化图状态与消息；工具须幂等或记执行凭证。恢复时校验图版本兼容。挂起等待用户用 wait 节点+TTL，取消用 cancel token。

- **常见坑**：无步数/费用上限、resume 双写、取消只停前端。

#### ★ p6. 多轮工具调用时如何防止死循环？你会设哪些硬限制？

**中级 · Agent 开发岗** · 考察：步数、token、重复签名、墙钟、确认

硬限制：最大步数、token/费用墙钟、相同 tool+args 签名重复次数、无进展检测；敏感写操作强制确认。超限转人工或降级固定话术。

- **常见坑**：无步数/费用上限、resume 双写、取消只停前端。
- **例子**：max_steps 8–20；同签名重复≤2–3；费用墙钟按租户配额。

#### p7. 对比 LangGraph / 自研状态机 / Temporal 做 Agent 编排的优劣。

**高级/架构 · Agent 开发岗** · 考察：可控、可观测、成本、上手

LangGraph 上手快生态好但深度定制受限；自研状态机最可控可观测成本高。

- Temporal 擅长长事务与重试，Agent 语义需自建。选看团队与 SLA。

#### p8. 如何做 Multi-Agent：角色拆分、共享内存、冲突解决与汇总？

**高级/架构 · Agent 开发岗** · 考察：supervisor、辩论、流水线

按角色拆（规划/执行/审核），共享内存用受限黑板或消息；冲突用 supervisor 或投票。

- 汇总要摘要降 token。防循环：轮次与重复论点检测。

#### p36. 同步 loop 与事件驱动编排如何选？

**中级 · Agent 开发岗** · 考察：交互延迟 vs 长任务/多等待

低延迟对话用同步 loop；多等待外部系统、长任务用事件驱动/队列。可同步开场+异步收尾，用会话状态衔接。

#### p37. 并行 tool calls 的调度与汇合（join）怎么实现？部分失败策略？

**中级 · Agent 开发岗** · 考察：allSettled、短路、补偿

并发发起后 allSettled 汇合；关键路径可短路失败。

- 部分失败返回成功子集+错误码，必要时补偿或重试独立工具。

#### p38. 如何支持子 Agent 调用（delegation）且控制嵌套深度与成本？

**高级/架构 · Agent 开发岗** · 考察：深度上限、预算下发、结果摘要返回

delegation 下发子预算与深度上限，子 Agent 只回摘要不回全轨迹；父级汇总。超预算强制收束或升级人审。

#### p39. 工作流里「确定性节点」和「LLM 节点」混排，事务边界怎么定？

**高级/架构 · Agent 开发岗** · 考察：LLM 外置、业务写操作可回滚

LLM 节点不做业务事务提交；写库/支付放确定性节点且可回滚或幂等。LLM 输出经校验后再进写路径，失败补偿明确。

#### p40. Agent 中途需要用户补充信息，如何挂起等待又不丢上下文？

**中级 · Agent 开发岗** · 考察：wait 状态、回调、TTL

进入 wait 状态持久化 checkpoint，回调/下轮消息唤醒；设 TTL 与提醒。前端展示待补充槽位，服务端勿丢 messages。

#### p41. 设计支持 A/B 两套编排图同时在线的发布系统。

**高级/架构 · Agent 开发岗** · 考察：图版本、流量比例、指标看板

编排图版本化，流量按租户/用户哈希；看板对比成功率成本延迟。

- 一键回滚图版本。影子流量先比指标再放量。

#### p42. 什么时候该用固定 DAG，什么时候该让模型自由选工具？

**中级 · Agent 开发岗** · 考察：合规流程 vs 开放任务

强合规、固定审批用 DAG；探索性问答/开放工具用自由选择。可「DAG 骨架 + 局部 LLM 选工具」折中。

#### p43. 如何检测并打破 Multi-Agent 互相甩锅或循环讨论？

**高级/架构 · Agent 开发岗** · 考察：轮次、重复论点检测、裁判节点

限制对话轮次；检测重复论点/互相推诿。引入裁判或汇总节点强制结论；超时升 supervisor 或人。

#### p30. 用户说取消就立刻停掉正在跑的工具链，怎么实现？

**高级/架构 · Agent 开发岗** · 考察：cancel token、可中断工具、一致性

请求级 cancel token 下传到工具；工具支持中断或超时丢弃。已产生副作用靠幂等/补偿。前端停 SSE，服务端标 cancelled。

#### ★ p91. 如何实现「工具结果驱动的图边」（dynamic edges）又保持可测？

**高级/架构 · Agent 开发岗** · 考察：受控分支表、白名单下一跳

#### ★ p88. MCP 的 transport（stdio / SSE / HTTP）分别适合什么部署场景？安全差异是什么？

- 坑：把远程 MCP 当「可信插件」不鉴权；或把云凭证塞进本地 stdio Server。
- 例子：公司知识库 MCP 走内网 HTTP；本机 git 工具走 stdio。

- 登记：create_order 对应 cancel_order。

### LLM 网关

#### ★ m59. 设计企业内部 LLM Gateway：必须具备哪些能力？

**高级/架构 · Agent 开发岗** · 考察：路由、限流、缓存、计量、观测、鉴权

企业内部 LLM Gateway 我把它定义成 AI 流量的控制面：统一鉴权与租户、按能力矩阵路由与 Fallback、Streaming 适配、多维限流、可选缓存、精确计量与对账、完整 trace，以及对 Agent 的工具协议归一化。没有计量与观测的「转发」撑不住 30–60k 档的平台岗面试。你还要能讲配置版本、紧急切主备、与业务 showback。和 Harness 边界：Gateway 管模型 IO；Harness 管 loop/工具/HITL。

- 企业 LLM Gateway=控制面能力集合，不是反向代理。
- 必备：鉴权、多模型路由/Fallback、流式适配、限流配额、缓存策略、token/成本计量、链路追踪、审计。

#### ★ m60. 多模型路由与 Fallback：按什么维度决策？失败如何切换不丢会话？

**中级 · Agent 开发岗** · 考察：能力矩阵、延迟、成本、协议适配

多模型路由我会用能力矩阵打分：工具调用、长上下文、多模态、合规驻地，再叠加实时健康与单价。Fallback 不是盲切：要验证工具 JSON 兼容，并可能降级「无工具纯文本」。会话中途切换要做消息规范化；关键任务建议会话级钉扎，只在硬错误时切。全链路记录 route_reason 方便复盘。上海岗常把国产+海外混部，矩阵比「哪个聪明」更重要。

- 路由看能力/质量/成本/合规；Fallback 要协议兼容。
- 决策维：是否 FC、上下文长度、延迟、价格、数据驻地。
- 失败切换保留消息中间态，必要时摘要迁移。
- 会话可钉扎模型避免中途乱跳。

#### ★ m61. Gateway 层 Streaming 统一适配要注意哪些坑？

**中级 · Agent 开发岗** · 考察：取消、心跳、半截 JSON、背压

Gateway 流式坑最多：有的厂商 chunk 语义不同、工具调用增量字段不一、代理会缓冲导致「假流式」。我会统一成内部事件（delta/tool_delta/error/done），并禁代理缓冲、定期心跳。取消：下游断开即取消上游，扣费按实际上游 usage。半截 JSON 不落执行，等完整或显式结束再校验。TS 前端状态机要容忍乱序与重连。

- Streaming 统一要处理取消、心跳、半截结构化、代理缓冲。
- 上游差异用适配器；对下游统一 SSE 事件。
- 半截 tool_call JSON 要增量解析或完成后再校验。
- 客户端断开必须取消上游。

#### ★ m62. 如何在 Gateway 做语义/精确缓存且不破坏权限与个性化？

**高级/架构 · Agent 开发岗** · 考察：缓存键含租户权限、风险类禁用

Gateway 缓存我区分精确键与语义键，但两者都必须嵌入租户与权限范围。命中后仍跑 ACL；涉及用户私有数据、价格库存、写意图的请求默认不缓存或极短 TTL。错答要有剔除与租户级隔离，避免 A 租户语义撞到 B。带 tool_calls 的对话缓存策略更保守，优先缓存检索问答。面试强调：省钱指标与错答率一起看。

- 缓存省钱但不能跳过鉴权与个性化边界。
- 键=租户+权限范围+模型+归一化请求；高风险禁用。
- 语义缓存设阈值与可剔除；命中仍过 ACL。
- Agent 带工具的请求通常只缓存无副作用答案。

#### ★ m63. token/成本计量：预估、实扣、退款与对账如何设计？

**中级 · Agent 开发岗** · 考察：usage 回调、预留、账单

成本计量：请求入口按模型单价预估做预留；上游返回 usage 后确认扣减；失败/取消退款预留。并发下用原子操作防超卖。流式场景在 done 事件结算；记录 provider request id 便于对账。业务 showback 按标签汇总。这是平台岗非常爱追问的「你怎么防止刷爆」。

- 以上游 usage 为准对账；估算仅作准入。
- 流式结束回写实际 token；失败释放预留。
- 月账单与厂商账单差异有容差流程。

#### ★ m64. 限流：用户/租户/模型/工具四维如何组合且可解释？

**高级/架构 · Agent 开发岗** · 考察：多维令牌桶、优先级、友好错误

四维限流用多层令牌桶/配额：先过用户 QPS，再租户 token 预算，再模型池并发，最后贵工具次数。批任务低优先级，可被在线抢占。触发时返回结构化错误：哪一维触顶、恢复时间、是否可降级模型。配置变更审计。结合 Agent：会话预算与 Gateway 限流要对齐，避免两边各限一次体验崩。

- 限流多维组合，错误要可解释可升级。
- 优先级：在线交互 > 批任务；核心业务白名单。
- 返回明确限额与重试建议，勿只 429。

#### ★ m65. 链路监控：一条 completion 请求要打哪些 span 与业务标签？

**中级 · Agent 开发岗** · 考察：provider、model、route、cache、cost

一条 completion 至少有：入口、路由决策、缓存查询、上游调用、用量结算。属性带齐 tenant/model/provider/cache/tokens/cost/conversation_id，才能和 Agent 轨迹拼图。贵请求与错误全量，其余采样。禁止把完整 prompt 打进明文日志。这直接对应 JD 里的「链路监控」。

- completion 级 trace 要能回答「钱花哪、慢在哪、路由为何」。
- span：鉴权、路由、缓存、上游 HTTP、后处理。

#### ★ m66. Agent 调用经 Gateway 时，tool calling 协议差异如何在网关抹平？

**中级 · 两边都考** · 考察：归一化 FC、JSON mode、重试

各厂商 tool calling 字段名、并行、流式增量不一致。Gateway 适配器把它们归一成内部 ToolCall，再交给 Harness；执行结果再映射回厂商消息格式（若需多轮）。能力不足的模型不要硬上工具，应路由到支持 FC 的，或降级无工具。用统一评测集盯工具成功率。全栈：TS 只认内部事件协议，不被厂商细节穿透。

- 网关抹平 FC 差异，Harness 仍要校验。
- 归一：tool_calls 结构、并行语义、错误回灌格式。
- 不支持 FC 的模型走受限 JSON 或禁工具路由。
- 回归集测各 provider 工具成功率。

#### ★ m67. 主供应商故障时的跨云 failover：一致性与用户感知如何处理？

**高级/架构 · Agent 开发岗** · 考察：能力降级、提示、工具兼容门禁

主供应商故障时，先健康检查与熔断，再切到能力最接近的备份；若工具协议不兼容，自动降级「只读问答」或 HITL，而不是硬切导致乱调工具。要有演练与抖动抑制（避免来回切）。合规上数据不得出镜的请求不能 failover 到海外。面试讲清 RTO 与用户感知策略。

- 跨云 failover 是能力降级，不是无感切换。
- 预演工具兼容与延迟预算；用户可感知提示可选。
- 配置一键切主备；自动切要防抖动。
- 数据驻地约束可能禁止某些 failover。

#### ★ m68. Gateway 是否该做 Prompt 注入过滤？边界在哪？

**中级 · Agent 开发岗** · 考察：分层防护、不能只靠网关

Gateway 处在所有模型流量点，适合统一做基础 jailbreak/DLP/密钥扫描，但它看不到业务 ACL 与工具副作用上下文，不能当唯一 guardrail。间接注入要在检索/工具回灌处标记 untrusted；越权在工具执行前鉴权。Gateway 过滤失败要可观测，误杀可白名单。回答体现纵深防御。

- Gateway 可做基础过滤，但不能替代应用层分层防护。
- 适合：明显越狱、密钥外泄、基础 DLP。
- 不适合单独挡间接注入与业务越权。
- 与 Harness 工具 ACL、输出过滤分工。

## RAG

先讲召回链路和权限过滤，再讲混合检索、Rerank 和索引更新。

### 检索与生成

#### ★ a3. RAG 召回差时按什么顺序排查？

**中级 · 应用开发岗** · 考察：切分、embedding、改写、重排

召回差按层排：切分/元数据 → embedding/索引 → query 改写 → 召回量 → 重排 → 生成，每层用金标定位，避免一上来改 prompt。坑：坏解析硬向量化、无引用硬答、权限只写 prompt。政策短 chunk，叙事 500–800 字+overlap，引用不齐则拒答。上海应用岗很吃这套分层排查。

#### ★ a4. 稠密/稀疏/混合检索；何时 GraphRAG？

**中级 · 应用开发岗** · 考察：专有词、多跳

专有词/货号偏稀疏或混合；语义问答稠密。多跳关系可 GraphRAG。先混合检索再上图。

#### ★ a5. 带权限的 RAG：ACL 如何进链路？

**高级/架构 · 应用开发岗** · 考察：索引/查询过滤、越权测

索引写入 ACL；查询强制过滤。端到端越权测试。勿只靠 prompt 说「不要越权」。

#### a35. chunk 大小与 overlap 怎么定？

**初中级 · 应用开发岗** · 考察：文档类型、问答粒度

按文档类型与问答粒度调：政策短段、叙事可 500–800 字；overlap 保跨段完整。用检索评测定而非拍脑袋。

- **例子**：政策短 chunk；叙事 500–800 字+overlap；对不齐引用则拒答。

#### a36. 表格、PPT、扫描件进知识库难点？

**中级 · 应用开发岗** · 考察：解析、版面、OCR

表格保结构、PPT 版面、扫描件 OCR 质量是瓶颈。分类型解析流水线，坏解析勿硬塞向量。

- **常见坑**：坏解析硬向量化、无引用硬答、权限只写 prompt。

#### a37. query 改写有哪些策略？何时会改坏？

**中级 · 应用开发岗** · 考察：多查询、HyDE、领域词典

多查询、HyDE、同义扩展、领域词典；指代不明或改偏意图会改坏。要回归原查询对照。

#### a38. 引用脚注如何保证「可点击且真引用」？

**高级/架构 · 应用开发岗** · 考察：强制 quote、字级对齐

生成强制基于检索 quote；脚注绑 chunk id。字级或句级对齐校验。点不开或对不上则降级不显示。

- **例子**：政策短 chunk；叙事 500–800 字+overlap；对不齐引用则拒答。

#### a39. 知识更新后索引延迟，用户看到旧答案怎么办？

**中级 · 应用开发岗** · 考察：版本、主动失效、说明时效

版本号/更新时间展示；主动失效缓存。

- 关键文档同步索引。旧答标注可能过时。

#### a40. 百万文档规模下的分层索引与路由？

**高级/架构 · 应用开发岗** · 考察：类目路由、级联检索

类目/租户路由→候选库→精排；热点缓存。级联避免全库暴力搜，监控路由错误率。

#### a41. 没有命中时该拒答还是靠模型知识？产品如何定？

**中级 · 应用开发岗** · 考察：领域政策、置信度

强领域政策可强制拒答；开放域可降级模型知识但须声明。产品写清置信与免责。

- **例子**：政策短 chunk；叙事 500–800 字+overlap；对不齐引用则拒答。

#### a42. embedding 模型换代如何平滑迁移？

**初中级 · 应用开发岗** · 考察：双索引、回填、评测

双索引并行、回填新向量、切流前对比召回评测，再下旧索引。

#### ★ a74. 如何做 RAG 的离线指标：Recall@k、nDCG、忠实度（faithfulness）怎么配合？

**中级 · 应用开发岗** · 考察：检索指标与生成指标分层

RAG 离线指标要分层：检索用 Recall@k、nDCG；生成用 faithfulness 与引用对齐；业务用端到端正确率。金标是 query 到相关 doc id；LLM Judge 只能辅助，不能掩盖检索失败。掉点时先分清是没召回到，还是生成胡编。常见坑是 Judge 偏爱长答，表面分数高但证据不足。上海应用岗很看你是否会分层定位。

- 检索差与生成胡编要分开量。
- 生成：答案是否被证据支持（faithfulness）；引用是否可点。

#### a75. 多模态知识库（图、表、CAD 截图）进 Agent 的架构要点？

**高级/架构 · 应用开发岗** · 考察：解析、多向量、引用模态

分模态解析与嵌入；检索可回传图文；生成注明模态来源。无解析质量就不上线硬答。多模态瓶颈在解析与引用，不在「能不能喂图」。

- 流水线：OCR/表结构/图注；图向量+文向量。
- 引用：脚注带页码/图号。
- 权限同文挡。
- 坑：整页截图当唯一 chunk 导致检索噪。

用级联与分档，不追求每问最大链路。取舍上 GraphRAG/Hybrid 按需，先证明基础召回与权限正确。例如 Hybrid + Rerank，ACL 在召回后强制过滤。

- 监控 rerank 贡献。

#### ★ m29. 权限 RAG 在车企/制造 MES 场景的特殊坑？

**高级/架构 · 应用开发岗** · 考察：组织+产线 ACL、版本

工业 ACL 维度比互联网多，面试要举维度。取舍上 GraphRAG/Hybrid 按需，先证明基础召回与权限正确。例如 Hybrid + Rerank，ACL 在召回后强制过滤。

- 越权测用真实组织树。

#### ★ m30. 换 embedding/国产模型后「掉点」第一周排查清单？

**中级 · 应用开发岗** · 考察：召回、FC、截断、温度

换 embedding 或国产模型后掉点，我第一周按层排：先冻结其它变量，用金标对比召回；再查改写、重排、截断；最后才看生成与工具调用。ACL 必须在召回后强制过滤。全程留回滚，并用同一门禁证明「修好了」。不要一上来全量怪模型，也不要没有对比就上 GraphRAG。

- 掉点分层定位，禁止直接全量怪模型。
- 这是面试高频追问。

## 评测

评的是整条轨迹能不能完成任务，不是单次回答好不好看。变更必须能回归。

### 评测方法

#### ★ p18. Agent 评测和单次 LLM 评测有何不同？

**中级 · Agent 开发岗** · 考察：轨迹、工具选择、E2E

Agent 评轨迹、工具选择、多步 E2E 成功；单次 LLM 评文本质量。两者都要，业务以 E2E 为北星。

- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。
- **例子**：E2E=任务正确完成；工具准确率作诊断面板。

#### ★ p19. prompt/模型/工具变更如何灰度与回滚？

**高级/架构 · Agent 开发岗** · 考察：影子流量、金丝雀

配置/模型/工具版本化；影子或金丝雀对比。

- 一键回滚。指标含成功率成本与安全拒答。
- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。

#### p61. 什么是 golden trajectory？如何维护它不过时？

**中级 · Agent 开发岗** · 考察：版本化、定期重跑

golden trajectory 是标注的理想工具序列与关键断言；随产品变要版本化并定期重跑，过时则修订而非删指标。

- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。
- **常见坑**：只报文采、golden 过时、离线好线上差不回流。

#### p62. 如何评测工具选择准确率 vs 最终任务成功率？两者冲突怎么办？

**高级/架构 · Agent 开发岗** · 考察：分层指标、业务优先

分层看选工具准确率与任务成功；冲突时业务成功优先，但持续错选要修描述/路由。避免只优化中间指标。

- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。
- **例子**：E2E=任务正确完成；工具准确率作诊断面板。

#### p63. 离线评测通过但线上变差，常见原因？

**中级 · Agent 开发岗** · 考察：分布漂移、延迟、并发

分布漂移、延迟导致超时换路径、并发下工具抖动、提示词线上不一致。用线上采样回流评测集。

- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。
- **常见坑**：只报文采、golden 过时、离线好线上差不回流。

#### p64. 构造评测集时如何避免「出题人偏见」？

**初中级 · Agent 开发岗** · 考察：真实日志采样、盲评

从真实日志分层抽样；多出题人。盲评与对抗集。避免全是出题人「好答」题。适合/不适合各举一例；零容错或强合规不要硬上高自主 Agent。

#### p65. 设计持续评测流水线：每次 PR 跑什么、夜间跑什么？

**高级/架构 · Agent 开发岗** · 考察：冒烟快测 vs 全量贵测

PR：冒烟+契约+小集；夜间：全量轨迹与贵模型评测。失败阻断或标风险，成本单独预算。

- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。

#### p95. 如何做工具模拟器（tool simulator）支撑大规模离线 Agent 评测？

**高级/架构 · Agent 开发岗** · 考察：状态机模拟、确定性、录制回放

按业务状态机模拟工具；关键路径确定性种子；混合录制回放与规则模拟。评估选工具与状态转移，不只是字符串。真打第三方 API 又贵又飘，要模拟器。

- 建模：订单状态等有限状态；非法操作返回真实错误码。
- 录制：线上脱敏轨迹回放；规则补齐分支。
- 断言：最终业务状态 + 关键 tool 序列。
- 坑：模拟器过宽，线上才发现鉴权错误。

北星听业务结果；模型指标作诊断。短期可牺牲文采保完成与安全。

#### ★ a79. 线上 Bad Case 如何闭环进评测集与 Prompt/工具修复？

**中级 · 应用开发岗** · 考察：采样、标注、回归、归属

按失败码采样→标注根因标签→进回归集→修工具/检索/Prompt→看回归。归属到模块 owner。没有闭环的 Bad Case 收集等于发泄。

- 标签：检索/路由/工具/生成/产品预期。
- 每周固定评审；P0 进冒烟集。
- 指标：同类 Bad Case 复发率。
- 坑：只改 Prompt 不改工具契约。

### 评测闭环

#### ★ m36. 描述一个「评测闭环」：从线上 Bad Case 到回归门禁的步骤。

**高级/架构 · 两边都考** · 考察：采样、标注、回归、发布

Bad Case 采样→标注归类→进回归→PR 冒烟/夜间全量→门禁挡发布→owner 跟到指标回升。每步有 owner 与时效。准备自己跟过的坏例表讲时间线。空谈「有评测」不如展示闭环证据。

- 闭环步骤要可执行，带 owner 与时间。

### 沙箱

#### ★ m51. 解释 Coding/Agent 执行沙箱的威胁模型：要防什么、默认拒绝什么？

**高级/架构 · Agent 开发岗** · 考察：逃逸、供应链、数据外泄、横向

Coding/Agent 沙箱的威胁模型，我先按「资产—攻击者—默认拒绝」讲。资产包括：宿主内核与同机其他租户、源码与密钥、内网服务、GPU/CPU 配额。攻击者可能是恶意依赖、被诱导的模型输出、被投毒的 Skill，或租户互相踩踏。工程上默认拒绝任意出站、禁止挂载云凭证与 Docker socket、禁特权、设 CPU/内存/墙钟上限，文件系统多为只读仓库+可写工作区。允许的出站必须走白名单代理并审计。上海 30k+ 岗常把沙箱和 Harness 一起问：你要能说清「工具在哪跑、失败如何杀干净、日志如何脱敏」。结合 TS+Python，我会强调取消信号从网关透传到沙箱 kill。

- 要防：宿主机逃逸、供应链投毒、密钥/代码外泄、横向扫内网、挖矿占资源。
- 默认拒绝：任意出站、挂载宿主机密钥、特权容器、长生命周期无审计会话。
- 与 Coding Agent 权限阶梯对齐：越低信任隔离越强。

#### ★ m52. Firecracker/微虚拟机相对 gVisor/Docker 在 Agent 工具执行场景如何选型？

**高级/架构 · Agent 开发岗** · 考察：隔离强度、冷启动、运维成本

选型我按信任级：不可信用户代码、任意 shell、第三方 Skill → 倾向 Firecracker/微VM，隔离强、攻击面小，但冷启动、镜像分发、可观测要单独做。gVisor 是折中；纯 Docker 运维成本低，适合内部可信仓库+强网络策略。成本不只是性能：还要镜像供应链、快照、与 K8s 的设备插件、故障演练。很多大厂效能岗接受「预热池」换冷启动。面试加分：说明你会按 Skill 信任标签路由到不同沙箱池，而不是一刀切。

- 按信任级与威胁选 Firecracker/gVisor/Docker，不空谈「最强」。
- gVisor：用户态内核折中；Docker：运维熟但共享内核风险更高。
- 可分层：低信任微VM，内部可信任务容器池。

#### ★ m53. 沙箱里跑 npm/pip 安装时如何防供应链投毒与任意出站？

**中级 · Agent 开发岗** · 考察：镜像白名单、无网/代理、锁文件

#### ★ m54. 如何给沙箱做「可观测但不泄密」：日志、文件系统快照、审计？

**高级/架构 · Agent 开发岗** · 考察：脱敏、只读挂载、审计事件

#### ★ m55. Agent 需要浏览器自动化时，沙箱边界与普通 API Tool 差在哪？

**中级 · 两边都考** · 考察：非结构化 UI、凭证面、截图隐私

Browser Agent 面对的是非结构化 UI 与不可信页面内容，间接注入和误操作概率远高于结构化 API。凭证面包括 Cookie、本地存储、已登录态。工程边界：独立浏览器配置档、默认无持久登录、下载与剪贴板受控、截图进脱敏存储、高危点击 HITL。优先把业务做成 API Tool，Browser 只作补缺。上海 JD 提 Computer Use 时，要主动讲「为何默认不用」。

- 浏览器自动化攻击面远大于 API Tool，默认更严。

#### ★ m56. 沙箱池化：预热、TTL、脏容器回收与租户隔离怎么做？

**中级 · Agent 开发岗** · 考察：池、驱逐、租户分池

池化是为了控 P95：按镜像/工具链预热一批微VM或容器；请求领取→执行→归还或销毁。TTL 到或检测到脏（装了不明包、异常出站）则销毁不回收。多租户：低信任「用完即毁」；同租户可复用；跨租户绝不共享可写层与网络命名空间。K8s 上用独立 RuntimeClass/节点池。面试提指标：预热命中率、销毁率、串租红队结果。

- 沙箱池用预热换延迟，用 TTL/脏标记防串租。
- 按镜像与信任级分池；租户级可硬隔离。
- 任务结束：杀进程、清可写层、可选销毁实例。
- 指标：冷启动、复用率、串租演练。

#### ★ m57. 业务方要求「能在沙箱里连生产只读库」，你如何评估与设闸门？

**中级 · 应用开发岗** · 考察：网络策略、凭证短时、审计

业务要沙箱连生产只读库时，我默认倾向否：沙箱逃逸或 SQL 注入面直接碰到生产。替代是只读副本、采样导出、或受控 Query 服务。若必须：专用只读账号+行权、短时 token、网络策略仅允许该库、语句 AST 白名单、全量审计与速率限制，并书面 risk acceptance。30k+ 回答要体现你敢拒绝不合理连通。

- 连生产只读库=扩大爆炸半径，要网络+凭证+审计三重闸。
- 只读账号、行级/库级权限、短时凭证、出口仅 DB 端口。

#### ★ m58. 超时/取消后如何保证沙箱进程与副作用真正停干净？

**高级/架构 · Agent 开发岗** · 考察：cgroup kill、网络摘除、幂等

超时/取消时，只关 SSE 不够。要把 cancel 从 Gateway→Worker→沙箱运行时，对进程组/微VM 做强制 stop，并立即摘除网络，防止「死后回连」。若工具已产生外部写，依赖幂等键去重或进入补偿；状态机标 cancelled 并写原因码。定期巡检孤儿容器。全栈角度：TS 断开订阅必须触发后端取消 API，不能只靠浏览器关页。

- 取消=控制面信号+数据面强杀+副作用幂等，三件套。
- cgroup/微VM stop；摘网络；取消令牌级联。
- 已发生写靠幂等键或补偿工单。
- 前端停流不等于后端已干净。

- 价值=相对基线的增量。
- 基线：两周人工抽检。
- A/B：同意图分布。
- 口径：人时、CSAT、差错。
- 坑：拿 Demo 准确率当价值。

#### ★ m100. 上海 30k+ 终面：如何用 3 分钟证明你能扛「Gateway+Harness+评测」而不是调包侠？

- 3 分钟结构化：子系统边界、一次事故、一组指标、明确不做。

## 通用工程问题

这些题跨岗位都会问，回答时把机制和副作用讲具体。

#### b1. token、上下文窗口、KV cache 对延迟成本的影响？

**初中级 · 两边都考** · 考察：基础

更长上下文增预填成本；生成 token 决定解码延迟。KV cache 复用降预填。Agent 多轮要控历史长度与工具回灌。

#### b2. 幻觉在 Agent 里为何更危险？

**中级 · 两边都考** · 考察：真实副作用

幻觉会触发真实工具副作用（错单、错邮、错删），不只是错文字。必须以校验、确认、权限兜底。

#### b3. Structured Output 与 Tool Calling 如何配合？

**中级 · 两边都考** · 考察：约束与重试

Structured Output 约束最终 JSON；Tool Calling 负责副作用。可先 FC 再结构化汇总。

- 失败校验重试。

#### ★ b4. 讲一个 Agent 项目：目标、架构、指标、坑、复盘。

**高级/架构 · 两边都考** · 考察：STAR+数字

讲项目用 STAR：目标与用户、架构怎么拆、上线看哪些数字、最大坑、复盘改了哪一刀，并准备一段可深挖的轨迹故事。指标至少有任务成功率、人工介入率或单位成本之一，且口径清晰。外发、改价、删除必须 HITL，不能靠 temperature=0 假装确定。能落到一次具体工具失败或注入案例，比停在架构名词更有 30k+ 说服力。

#### b5. 3 个月从 0 搭团队 Agent 能力，里程碑？

**高级/架构 · 两边都考** · 考察：落地节奏

月1：只读工具+观测评测；月2：一两个写路径+人审。月3：灰度成本优化与平台化。每周可演示增量。

#### ★ b6. Human-in-the-loop：哪些必须人确认？

**中级 · 两边都考** · 考察：外发、资损、删除

外发消息、支付/改价、删除/权限变更、不可逆生产操作必须人确认。只读可自动。

#### b7. 流式中途报错，前后端怎么处理？

**初中级 · 两边都考** · 考察：半截、重试

后端发 error 事件并结束流；前端保留半截并标记失败，支持续写/重试。勿静默吞错。

#### b8. 熔断限流舱壁如何用到 Agent？

**高级/架构 · 两边都考** · 考察：模型与工具当下游

模型与各工具当下游：独立舱壁限流熔断，失败降级规则或人。避免一工具拖垮整会话集群。

#### b9. 失败会话如何记录回放？

**中级 · 两边都考** · 考察：脱敏、mock

脱敏存轨迹；可 mock 工具重放。关联 trace。用于复盘与回归，严格访问控制。

#### b10. 如何看待自主 Agent 炒作？生产底线？

**高级/架构 · 两边都考** · 考察：风险观

炒作不等于可生产；底线是权限、可中断、可观测、人审关键写。自主程度与风险成正比。

#### b11. 解释 RAG 与微调各自适用场景。

**初中级 · 两边都考** · 考察：知识更新频率、风格

知识常变、需引用→RAG；稳定风格/格式/领域话术→微调或加示例。常组合而非二选一。

#### b12. 什么是 agentic RAG？和朴素 RAG 差在哪？

**中级 · 两边都考** · 考察：多步检索、自决定

agentic RAG 可多步检索、自决定是否够用再搜；朴素一次检索生成。难查询提升大但成本高。

#### b13. 评测里 pass@k、成功率、含时延的综合分怎么设计？

**中级 · 两边都考** · 考察：业务加权

pass@k 看多次尝试；成功率业务定义。综合分加权成功并惩罚超时超费。权重产品定。

#### b14. 你如何做技术选型答辩：自研 vs 买厂商 Agent 平台？

**高级/架构 · 两边都考** · 考察：总成本、锁定、差异化

比 TCO、锁定、差异化与合规；能买加速的买，核心权限与数据面慎交。给退出策略。

#### b15. 什么是 function calling 的 parallel / sequential？

**初中级 · 两边都考** · 考察：依赖关系

parallel 无依赖可同时调；sequential 有数据依赖必须串。编排层按依赖图调度。

#### b16. 上下文「丢包」导致工具参数缺字段，如何工程预防？

**中级 · 两边都考** · 考察：服务端补全、校验重问

服务端 schema 校验；缺字段可补默认或追问。

- 截断检测。勿把残缺 JSON 直接执行。

#### b17. 设计面试：为公司内部做 Copilot，画架构并讲风险。

**高级/架构 · 两边都考** · 考察：权限、数据、评测、成本

画入口-网关-编排-检索-工具-权限-评测-观测；风险讲数据外泄、越权、成本爆炸。给 MVP 边界。

#### b18. 开源框架升级导致行为变化，如何回归？

**中级 · 两边都考** · 考察：锁定版本、契约测

锁定版本；契约与黄金集回归。金丝雀。行为变先看 changelog 与 diff 轨迹。

#### b19. 团队只有你懂 Agent，如何降低单点风险？

**高级/架构 · 两边都考** · 考察：文档、演练、结对

文档化运行手册、结对、值班演练、录屏课。把关键决策写进 ADR，降低单点。

#### b20. 解释 temperature=0 是否绝对确定？

**初中级 · 两边都考** · 考察：仍可能非完全确定

temperature=0 仍可能因实现、并行、种子而略有差异，不能当绝对确定。关键路径靠校验。

#### b21. 什么是 guardrails？放在输入侧、工具侧还是输出侧更合适？

**中级 · 两边都考** · 考察：分层防护、不能只靠输出过滤

应分层：输入注入检测、工具前鉴权、输出 DLP/拒答。只做输出过滤挡不住副作用已发生。guardrails 是多层，不是一个正则。

- 输入：越狱/注入分类。
- 工具前：ACL 与参数消毒。
- 输出：泄密与违规。
- 坑：副作用发生后才过滤文案。

#### b22. 如何向非技术高管解释「Agent 不确定性」并拿到合理预算？

**高级/架构 · 两边都考** · 考察：风险预算、区间、对照人工

用成功率区间与人工对照；把不确定性转成风险预算与兜底成本。要预算就给指标与止损线。

- 对照：人工差错率也不是零。
- 预算：评测+人审+观测是必要成本。
- 止损：低于阈值回滚。
- 坑：用「AI 很强」忽悠预算。

#### b23. 缓存命中后是否还要跑安全与权限检查？为什么？

**中级 · 两边都考** · 考察：缓存不能跳过鉴权

必须再跑权限与租户检查；缓存键含权限范围。安全检查不可因命中而短路。缓存是性能优化，不是信任边界。键：tenant+acl 版本+query。用户升权/降权要失效。

- 坑：共享语义缓存串租。

#### b24. 解释 JSON Schema / Zod / Pydantic 在 Agent 工具链里各自角色。

**初中级 · 两边都考** · 考察：契约源、运行时校验

JSON Schema 常作跨语言契约源；Zod 护 TS 边界；Pydantic 护 Python 执行层。三者应对齐。

- 分层校验，契约单一来源。
- 生成：schema→两端模型。
- 运行：拒非法 args。
- 坑：只在前端校验。

#### b25. 当业务坚持「全自动」时，你如何谈风险接受（risk acceptance）？

**高级/架构 · 两边都考** · 考察：书面风险、限额、监控

书面列失败模式与限额；要求监控与熔断；超限自动降级人审。把 risk acceptance 留痕。

- 全自动=明确接受残余风险。
- 材料：失败模式×影响×缓解×残余。
- 工程：限额与熔断仍要做。
- 坑：口头「没事」无文档。

#### b26. Agent 中的「确定性闸门」（deterministic gate）指什么？举例。

**中级 · 两边都考** · 考察：规则校验拦截模型输出

模型输出后由规则/程序做硬校验，不通过则拒或重试。例：SQL AST、金额上限、正则工单号。

- 闸门=模型后的硬法则。
- 例：退款≤订单可退余额。
- 与 FC 配合：先 FC 再闸门。
- 坑：闸门过严误杀要可观测。

#### b27. 如何做 Prompt 注入的红队演练节奏（频率、范围、修复 SLA）？

**中级 · 两边都考** · 考察：定期红队、分级修复

月度红队+发版必跑核心集；P0 注入当日修；结果进对抗集。范围含间接注入。红队要节奏化进工程。范围：用户、检索、邮件、MCP。SLA：P0 阻断发布。

- 坑：只测中文直注不测英文/编码绕过。

#### b28. 什么是 tool-former / 模型原生工具调用与外部编排的差异？

**初中级 · 两边都考** · 考察：模型内建 vs 应用层 loop

原生 FC 由模型直接出调用；外部编排可强加状态机与策略。生产多用模型 FC + 应用层强约束。

- 能力在模型，责任在编排。
- 原生：协议简单。
- 编排：权限步数预算。
- 坑：以为有 FC 就不需要运行时。

#### b29. 多业务线共用一个 Agent 中台，如何做成本分摊与 showback？

**高级/架构 · 两边都考** · 考察：计量标签、配额、报表

按 tenant/项目打标计量 token 与工具费；月度 showback；超配额告警。推动业务为浪费买单。没有 showback 就没有治理。

- 标签：从网关强制注入。
- 报表：成本/成功率并列。
- 坑：公共 API Key 算不清。

#### b30. 解释「评测集污染」：如何发生，如何防？

**中级 · 两边都考** · 考察：训练/提示泄漏、过拟合用例

把测试题写进 Prompt/微调/长期记忆会导致虚高；隔离评测数据，定期换血与盲集。

- 污染会制造虚假安全感。
- 发生：few-shot 含测试题、日志回流未隔离。
- 防：盲集权限；用例哈希监测泄漏。
- 坑：用线上热问当唯一评测。

#### ★ m1. 上海 30k+ Agent JD 里反复出现的「Harness / Runtime」通常指什么？和「会调 LangChain」差在哪？

Harness/Runtime 指 Agent 执行控制面：loop、预算、权限、恢复、工具注册与观测；「会调 LangChain」只是库用法。上海 30k+ JD 要的是生产可控性：步数/token 墙、cancel、checkpoint、工具 ACL、可追踪。我会把做过的 SSE 协议、幂等写、评测门禁映射到这些层。坑是把用过 Dify/LangGraph 当成 Runtime 设计经验。全栈上 TS 事件协议 + Python loop 就是对外契约。

## 高频追问

短答之后常被追问——各准备约 30 秒：

1. **怎么防死循环？** → 最大步数、token/费用墙钟、tool+args 签名去重、无进展检测、写操作确认；超限转人工或固定话术。
2. **幻觉怎么办？** → Agent 有真实副作用：Schema 校验、不信任工具原文指令、写路径人审、引用对齐；不是只靠低温。
3. **要不要 Multi-Agent？** → 看可分性与接口清晰度，算额外延迟/费用；不可分就单 Agent + 工具化。
4. **只看一个指标？** → 任务成功率或人工介入率（定义清晰）；辅看成本与安全拒答；防刷分。
5. **一周上线砍什么？** → 只读 MVP + 人审写；砍 Multi-Agent 与花哨 UI；保留冒烟评测与技术债清单。
6. **TS + Python 怎么分？** → 编排/工具/校验偏 Python；SSE 与工具卡片状态机偏 TS；JSON Schema 同源生成防漂移。
7. **越权怎么测？** → 工具 ACL 执行前鉴权、检索强制 tenant_id、端到端越权用例进 CI；不靠 prompt 自觉。
8. **和 Chatbot / Workflow 差在哪？** → Agent=循环选工具+observation 改计划+副作用；强合规固定流程用 Workflow。
