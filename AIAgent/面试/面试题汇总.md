## 基础概念

先划清 Agent、Workflow、Chatbot，再讲状态、轨迹和工具调用格式。

#### 1. Agent、Workflow、Chatbot 怎么划界？什么时候用固定 DAG，什么时候让模型自己选工具？

**初中级 · Agent 开发岗** · 考察：自主决策、循环调工具、状态机边界

Chatbot 主要是多轮对话、少副作用；Workflow 是预定状态机/DAG，分支固定可审计；Agent 由模型循环选工具，并根据 observation 改计划。面试我先划边界：强合规、零容错走 Workflow；目标开放、需探索才上 Agent。也可以外层 Workflow 控合规，内层 Agent 做局部探索。上海 30k+ 更看你能否讲清何时不该用 Agent，并用前后端经验说明状态、权限与副作用如何落地。
- 先定义再划边界：自主性、副作用、可控性；强合规→Workflow，开放任务→Agent。
- **常见坑**：混用 Workflow/Agent、忽视 observation 闭环；Demo 用上帝权限，把零容错流程做成全自动 Agent。
- **例子**：退款审批走 DAG；排查异常订单走 Agent 调只读工具。低频或错一次就资损的，先人工或固定流程。

#### 2. ReAct 和 Plan-and-Execute 怎么选？最小 loop 怎么写？

**初中级 · Agent 开发岗** · 考察：延迟、可控性、复杂任务分解

ReAct 边想边做（Thought→Action→Observation），适应变化，但步数与延迟难控；Plan-and-Execute 先规划再执行，可控可并行，计划却容易过时。可分解、工具稳定的任务偏后者，探索性任务偏 ReAct。生产我常混合：短计划 + 执行中局部 ReAct，并加 max_steps、重复调用检测和费用墙。取舍本质是可控性换适应性；答到停止条件与观测指标才像工程岗。
- **常见坑**：无停止条件、只规划不校验工具结果。
- **例子**：max_steps 8–20；同签名重复≤2–3。

手写最小 loop 就这一段：`while steps < max`，调模型；有 `tool_calls` 就先做 Schema 校验再执行、把结果写回消息，否则返回最终答复。同时检查取消、重复签名和预算。停止条件要写进代码和测试，不能只写在提示词里。

#### 3. Function Calling / Tool Use 的典型请求响应格式是什么样的？

**初中级 · Agent 开发岗** · 考察：name、arguments、并行调用、错误回传

Function Calling 里，模型不会直接执行工具，而是在助手消息里返回 `tool_calls`，每项包含 `id`、`name` 和 JSON 格式的 `arguments`。服务端解析并校验后执行工具，再以 `role: tool` 消息把结果回传，并用 `tool_call_id` 对齐。模型可以一次返回多个 `tool_call` 实现并行调用，适合无依赖的读操作；有依赖就必须串行。错误应该结构化回传，包含错误码和可操作提示，让模型决定重试、改参或换工具。工程上我还会强调 Schema 同源校验和 trace 用 call_id 贯穿。

- **常见坑**：只回字符串异常、不定义并行汇合。
- **例子**：Zod+Pydantic 同源校验。

#### 4. 什么是 tool choice / forced function call？什么时候用？

**初中级 · Agent 开发岗** · 考察：强制走某工具、JSON 抽取、降低乱跑

`tool_choice` 用来控制工具选择策略：`auto` 让模型自决，`required/any` 强制至少调用一个工具，指定函数名则强制调用某个工具，`none` 则禁止调用。生产上我通常只在关键节点使用 forced——比如结构化抽取、必须查实时数据的路由——开放对话保持 auto。forced 只管「选不选工具」，不替代 Schema 校验与权限控制；写操作仍要服务端鉴权和 HITL。更稳的是入口先做意图分层：闲聊直出、明确业务进 Workflow、模糊任务再交给 Agent。

- **常见坑**：全局 forced 导致无法寒暄；以为 forced 可替代鉴权。

#### 5. 解释 observation、action、thought 在轨迹里各自是什么。

**初中级 · Agent 开发岗** · 考察：日志结构与评测对齐

thought 是推理痕迹，action 是工具名与参数，observation 是工具返回，三者构成可评测可复现的轨迹。日志按这三段对齐，才能分别看工具选择准确率与任务成功率。生产可对 thought 采样降本，但 action/observation 关键字段要完整。排障先看 action 是否选错，再看 observation 是否正确写回上下文。

- **常见坑**：只存最终回复，无法复盘工具错选。

#### 6. Agent 的「状态」通常包含哪些字段？

**初中级 · Agent 开发岗** · 考察：messages、scratchpad、tool results、budget

状态常见字段：messages、目标/scratchpad、未完成 tool 结果、步数与 token/费用预算、挂起等待点（补参/人审）。必须可序列化才能 checkpoint/resume，并带图版本。权威状态放服务端，前端只持会话 id。TS 消费状态事件、Python loop 做转移，避免双写。

- **常见坑**：前后端双写状态、恢复不校验版本。

#### 7. CoT、ToT、GoT 对 Agent 工程有什么实际价值？哪些不该上生产？

**中级 · Agent 开发岗** · 考察：成本延迟 vs 收益；生产常只要短推理

短 CoT 对难推理有性价比；ToT/GoT 搜索贵、延迟高，全量生产很少划算。Agent 工程优先工具校验与检索，推理长度设上限。是否加长推理看正确率-成本曲线；多数业务短 CoT + 工具闭环足够。推理预算也要进 Runtime 硬限制。取舍上用「查得准、校验严」替代「想得久」。

- **常见坑**：无推理预算硬限制，只靠提示词「请简短」。

#### ★ 8. Computer Use / 浏览器 Agent 和普通 API 工具差在哪？

**中级 · Agent 开发岗** · 考察：非结构化 UI、权限面更大

Computer Use/Browser Agent 操作非结构化 UI，权限面和误操作风险远大于 API Tool Agent。生产默认优先 API；上浏览器必须强沙箱、出站白名单、敏感操作人审，并限制可达域与动作集。观测要能回放关键操作序列，否则事故难追责。
- **常见坑**：无回放、无域名白名单就开放点击。

## 机器学习

这三章是机器学习、深度学习和微调。Agent 岗被追问再展开，不要把公式堆进自我介绍。温度和 KV cache 在后面的大模型基础和性能章，这里不重复。

#### 9. 机器学习按监督方式怎么分？

**初中级 · 两边都考** · 考察：标签、奖励、数据成本

按数据怎么教模型，分成四类。有监督用带标签的数据做分类或回归。无监督没有标签，靠数据自身的结构，比如按密度聚类、做降维。半监督用少量标签加大量无标签，主要为了少标注。强化学习不靠静态标签，靠和环境交互得到的奖励来改策略。面试先用这四句划开，再补一个例子：分类是有监督，用户分群是无监督，对话对齐更接近强化学习。

#### 10. 训练集、验证集、测试集各干什么？

**初中级 · 两边都考** · 考察：调参和最终评估必须分开

三份数据格式一样，用途不同。训练集最大，用来更新参数。验证集在训练过程中看损失和指标，用来选超参、决定早停，不能拿它报最终成绩。测试集只在模型和超参都定了之后用一次，衡量泛化。用验证集反复挑到的最好分数，不能当成测试集分数。

#### 11. 特征工程做什么？高维特征怎么处理？

**中级 · 两边都考** · 考察：选择、变换、构造、降维

特征工程是把原始数据变成模型更容易学的输入，四件事：选择、变换、构造、降维。选择是去掉无关和重复特征，有过滤、包裹、嵌入。变换是归一化、标准化、独热或标签编码。构造是用现有字段做出交互项、统计量、时间特征。降维是在保住主要信息的前提下减少维数，常见 PCA、LDA。

维数上去之后，距离失效、计算变贵、更容易过拟合，这就是维数灾难。处理顺序是先丢掉无关特征，再降维，再用 L1/L2 约束复杂度。树模型和带核的 SVM 对高维相对不那么脆，但不能代替清洗。

#### 12. 数据里的噪声怎么查、怎么处理？

**中级 · 两边都考** · 考察：先检测，再决定删还是平滑

噪声是会把决策边界带偏的异常点。先检测：看离均值或近邻过远的点，或者聚类后落在簇外面的点。再处理：数据量大时做分箱平滑、用回归修正极端值，或者把明确的离群点去掉。直接删会丢掉有用信息，量不大时人工看一遍更稳。不要把业务上真实的极端值一律当噪声。

#### 13. 类别不平衡怎么处理？为什么不能只看准确率？

**中级 · 两边都考** · 考察：采样、权重、评估指标

少数类太少时，模型可以靠全猜多数类拿到很高的准确率。处理从数据、损失和指标三处下手。少数类过采样或加噪声造样本，多数类下采样。训练时提高少数类权重，或用对不平衡没那么敏感的集成方法。评估改用精确率、召回率、F1，严重不平衡时看 PR 曲线下面积，而不是只看准确率或 ROC。采样之后的验证集分布要接近真实上线分布，否则指标会虚高。

#### 14. 过拟合和欠拟合怎么区分，各自怎么改？

**初中级 · 两边都考** · 考察：偏差和方差

过拟合是训练集好、测试集差，高方差：模型死记了训练样本。常见原因是模型过复杂、数据少、特征过多、训练太久。办法是加数据、降复杂度或降维、正则、交叉验证、早停。欠拟合是训练集和测试集都差，高偏差：模型容量或特征不够，或者正则太强、训练没跑够。办法是加特征、加容量、加长训练、减弱正则。目标是两边都够用，不是把训练损失压到零。

#### 15. 梯度下降在更新什么？BGD、SGD、小批量差在哪？

**中级 · 两边都考** · 考察：学习率、批量、稳定性

梯度下降沿损失下降的方向改参数。一步写成：新参数 = 旧参数 − 学习率 × 该点的梯度。学习率是步长，太大越过最优点来回跳，太小收敛慢。

差别只在梯度用多少样本估计。批量梯度用全量数据，方向稳，但每步都贵。随机梯度用一条样本，快，方向抖，可能难收敛。小批量用 32、64 这类一小批，是现在的默认：比全量便宜，比单条稳。大模型训练几乎都是小批量。

#### 16. 梯度下降常见哪些失败，怎么缓解？

**中级 · 两边都考** · 考察：量纲、鞍点、梯度幅度

特征量纲不一致时，损失曲面在某些方向很陡，收敛变慢，先做标准化或归一化。平坦的鞍点和局部极小值会让梯度接近零，动量或 Adam 这类自适应优化器比纯梯度下降更容易走出去。深层网络还会出现梯度消失或爆炸，那是反向传播乘了很多层导数，见第26题，用梯度裁剪、合适的初始化和残差，而不是只调学习率。

#### 17. 回归任务看哪些指标？

**初中级 · 两边都考** · 考察：误差形态，不是一个分数

均方误差是误差平方的平均，大误差被放得更大，适合不能容忍离谱预测的场景。平均绝对误差是误差绝对值的平均，对异常值更稳。R² 看模型解释了目标变异的多少，越接近 1 越好，接近 0 说明几乎没解释。三个一起看：MSE 盯大错，MAE 看典型误差，R² 看整体。单位不同的任务不要拿 MSE 的绝对数值互相比较。

#### 18. 分类任务的准确率、精确率、召回率、F1 各看什么？

**初中级 · 两边都考** · 考察：分母是谁

准确率是全部样本里判对的比例，类别平衡时才有意义。精确率是预测为正的里面有多少真是正，关心「报出来的准不准」。召回率是真正为正的里面找出了多少，关心「漏了多少」。F1 是两者的调和平均，一边很高另一边很低时它不高。欺诈、故障、医疗阳性通常更在意召回，搜索排序更在意精确率。先说业务更怕哪一种错，再选指标。

#### 19. ROC 和 AUC 怎么读？什么时候改看 PR 曲线？

**中级 · 两边都考** · 考察：排序能力，不是某一个阈值

ROC 的横轴是假阳性率，纵轴是真阳性率。曲线越靠近左上，越能在低误报下保持高命中。AUC 是曲线下面积：0.5 接近随机，1 是完美分离。AUC 小于 0.5 通常是正负标签反了，把预测反过来即可。AUC 对类别比例不敏感，所以类别极不平衡时它会显得乐观，这时改看精确率-召回率曲线。阈值根据业务成本另定，AUC 只说明排序能力。

## 深度学习

传统机器学习靠人工特征。深度学习用多层网络自己学特征，代价是数据和算力。

#### 20. 深度学习和传统机器学习差在哪？网络由什么组成？

**初中级 · 两边都考** · 考察：特征从哪来

传统方法要人先做出耳朵、纹理、词频这类特征。深度学习把原始图像、语音或文本送进多层网络，让隐藏层自己形成特征，输出层给出预测。它更吃数据和算力，也更擅长高维的非结构化数据。

网络三块：神经元把输入加权求和再过激活函数；层分成输入层、隐藏层、输出层；连接权重是要学的参数，决定信号传递强弱。

#### 21. 激活函数为什么必须非线性？Sigmoid、ReLU、Softmax 怎么选？

**中级 · 两边都考** · 考察：没有非线性就退回一层

如果每层都是线性变换，叠多少层仍等价于一个线性变换，学不会弯曲的决策面。激活函数提供这个非线性。

Sigmoid 把实数压到 (0, 1)，适合二分类输出，但输入绝对值大时导数接近 0，容易梯度消失，输出也不是零中心。ReLU 是 max(0, x)，正区间导数是 1，计算便宜，是隐藏层的默认选择；负区间输出恒为 0，可能出现神经元不再更新。Softmax 把一组实数变成和为 1 的概率，用于多分类输出。隐藏层用 ReLU，二分类输出用 Sigmoid，多分类输出用 Softmax。

#### 22. ReLU 在 0 处不可导，为什么还能训练？

**中级 · 两边都考** · 考察：实践里怎么取次梯度

输入恰好为 0 的概率极低，实现里这一点的梯度取 0 即可，不影响整体更新。选它是因为正区间不会把梯度乘没，计算比 Sigmoid 和 Tanh 便宜，输出为 0 的单元还带来稀疏。神经元死亡是负区间的问题，输入长期为负就不再更新，可以用较小的负斜率变体缓解，不是因为 0 点不可导。

#### 23. 分类和回归各用什么损失？

**初中级 · 两边都考** · 考察：损失是优化目标，不是评估指标

损失衡量预测和标签的差，训练就是把它变小。二分类用二元交叉熵，多分类用交叉熵。回归用均方误差或平均绝对误差；Smooth L1 在小误差处像平方、大误差处像绝对值，避免被极端值主导。不要把准确率当损失去反传，它在阈值处不可导，也给不出有用梯度。

#### 24. 反向传播在算什么？

**中级 · 两边都考** · 考察：链式法则，从前向的中间量回传

先正向算出每层输出和最终损失，并留下中间激活。再从输出层往输入层，用链式法则把损失对每一层权重的梯度乘回去。存中间量是为了不要把正向再算一遍。梯度算完才按优化器更新权重。它解决的是「高效拿到全部参数的梯度」，不保证走到全局最优。

#### 25. 早停看的是哪条曲线？

**初中级 · 两边都考** · 考察：用验证集，不是用训练集

监控验证集损失。训练集还在降、验证集连续若干轮不再降，就停止，并回到验证集最好的那一版权重。它同时减轻过拟合和浪费算力。用训练集损失来早停没有意义，那条曲线通常会一直降。耐心设太短会停在还没学完的时候。

#### 26. 梯度消失和梯度爆炸是什么，怎么处理？

**中级 · 两边都考** · 考察：梯度幅度在层间相乘

消失是梯度乘过很多小于 1 的导数后接近 0，靠近输入的层几乎不更新。Sigmoid 的饱和区和过深的网络都容易出现。爆炸是梯度越乘越大，更新把参数打飞，训练不稳定。

对应手段：隐藏层用 ReLU，让正区间导数保持 1；爆炸用梯度裁剪；初始化用和激活匹配的方法；结构上用批归一化、残差连接，序列模型用能控制信息流的门控。目标是让梯度既不没掉也不炸，不是把学习率调到某一个魔法数。

#### 27. 为什么实际训练常用 Adam？它和 L2 一起用为什么要改成 AdamW？

**中级 · 两边都考** · 考察：自适应步长，以及权重衰减被缩放

Adam 把动量和按参数自适应的学习率合在一起。更新频繁的参数步子变小，少见的参数步子相对大，所以对学习率没那么敏感，收敛通常比精调前的 SGD 快。SGD 把学习率和动量调好之后，最终泛化有时更好，但成本在调参。

直接把 L2 罚项加进损失，这项梯度会和别的梯度一起被 Adam 的二阶矩除掉，惩罚强度不再是稳定的权重收缩。AdamW 把权重衰减从梯度里拿出来，更新参数时直接减掉学习率乘以衰减系数乘以权重本身，衰减才按原意起作用。大模型微调默认 AdamW，而不是 Adam 加 L2。

#### 28. 权重为什么不能全初始化成 0？Xavier 和 He 怎么选？

**中级 · 两边都考** · 考察：打破对称，稳住前后向方差

全 0 会让同一层的神经元收到相同梯度，更新永远一样，网络学不出不同特征。初始化要让信号在前向和反向时方差不要一层层放大或缩小。Sigmoid、Tanh 用 Xavier，它按输入和输出的连接数缩放。ReLU 只通过正半轴，用 He，初始范围比 Xavier 大。选错会在很深的网络里表现为一开始就消失或爆炸。

#### 29. Dropout 在训练和测试时有什么不同？

**中级 · 两边都考** · 考察：随机失活，测试要恢复期望

训练时按概率关掉一部分神经元，迫使表示不依赖某几个单元，效果接近训练了很多个子网络再平均，用来减轻过拟合。为了让输出期望不变，保留下来的激活要按存活概率放大。测试时不再随机丢弃，所有单元都参与；若训练时做了放大，测试就用原权重，两种实现要配对，不能训练放大了、测试再缩放一次。

#### 30. 数据增强解决什么问题？图像和文本各怎么做？

**中级 · 两边都考** · 考察：扩充有效样本，不制造假标签

数据少时模型容易记住训练集。增强是对现有样本做不改变标签的变换，增加多样性。图像可以翻转、旋转、缩放、裁剪、平移、改亮度或加噪声。文本可以用同义替换、有控制的语序变化、翻译再译回。增强不能改标签含义：医学片的方向、金额字段、实体名，乱替换会把监督信号教错。它减轻过拟合，替代不了真正缺的那一类样本。

#### 31. 深度学习模型最后怎么判断「学好了」？

**初中级 · 两边都考** · 考察：任务指标加验证集，不看训练损失

分类看准确率、精确率、召回率、F1、ROC-AUC，回归看 MSE、MAE、R²，定义和第 17–19 题相同。泛化只看没参与调参的测试集，训练过程用验证集和交叉验证决定停不停。训练损失很低只能说明拟合了训练集。上线前还要看延迟、显存和坏例，不单看一个离线分数。

#### 34. 大语言模型和传统机器学习模型最大的差别是什么？

**初中级 · 两边都考** · 考察：任务泛化 vs 单任务拟合

- **常见坑**：把参数规模当成正确性保证。

#### 35. 为什么 Transformer 成为主流？Self-Attention 相对 RNN/CNN 换来了什么？

**初中级 · 两边都考** · 考察：并行、长距离依赖、代价

Transformer 用自注意力替换 RNN 的逐步递归，训练可以按序列并行，也更容易直接看远距离 token。CNN 的局部感受野要堆很多层才看得到长依赖。代价是标准注意力的计算和显存随序列长度近似平方增长，所以长上下文要靠窗口、缓存和截断，不是把窗口无限拉大。应用岗答到这里就停，不必手推 Q/K/V。

#### 36. 预训练、SFT、RLHF、DPO、GRPO 和 RAG 各解决什么？应用岗讲到哪一层？

**中级 · 两边都考** · 考察：选型边界，不是训练配方

预训练学语言和通识，知识进参数，更新贵。SFT 用指令数据把格式、术语和任务步骤拉齐。RLHF 先训奖励模型再优化策略，工程重。DPO 直接用偏好对优化，少一条显式强化学习回路，2024 之后很多对齐默认走这条。GRPO 是组内相对优势的策略优化，2026 年被问到再展开，应用岗不要主动讲成自己的主业。应用岗的结论：知识常变、要引用走 RAG；稳定格式和工具习惯才考虑 SFT 或 LoRA，二者经常一起用；偏好对齐用 DPO 类方法，不从零做 RLHF。
- **常见坑**：把微调当成知识库更新手段；把 GRPO 名词堆进应用岗自我介绍。

#### 37. Tokenizer 为什么会影响成本、切分和中文效果？

**初中级 · 应用开发岗** · 考察：计费单位不是字符

模型吃的是 token，不是汉字或单词。同一段中文在不同词表下 token 数可以差一截，上下文是否爆窗、RAG chunk 是否把实体切断、账单是否对得上，都要按**实际调用的那个模型的 tokenizer** 算。换模型时不能沿用上一家的「500 字一块」。工具参数和 JSON 结构也会吃 token，Schema 过胖会直接进成本。

- **常见坑**：用字符数估算上下文；中英混合按英文词数估。
- **例子**：切分前用目标模型的 tokenizer 看实体有没有被拆开。

#### 38. 量化、蒸馏、LoRA 分别解决什么？什么时候不该上？

**中级 · 两边都考** · 考察：部署、缩小、定制三条线

量化把权重量化到低精度，省显存和推理成本，可能掉工具调用稳定性，要拿原评测集回归。蒸馏是让小模型学大模型的行为，适合高并发、边缘或便宜路由，教师信号差就会把幻觉一起学走。LoRA 只训一小块增量参数，适合领域格式和话术，不适合当作「把新知识写进模型」的替代品，新知识仍应进索引。三条线不要混成一个「压缩」：量化不改行为目标，蒸馏改模型大小，LoRA 改行为。

- **常见坑**：量化后不回归函数调用；用 LoRA 追每天变化的制度。

## 大模型微调

全参微调更新全部权重。下面这些题是资源不够或只想改行为时的做法：并行和显存、参数高效微调、数据格式、对齐。知识经常变仍然走 RAG，见第36题。

#### 39. 大模型训练有哪些并行方式，各自切的是什么？

**高级/架构 · 两边都考** · 考察：切数据、切层、切张量、切专家

数据并行：每张卡一份完整模型，各吃不同数据，再同步梯度。实现简单，但每张卡都要放下整模。流水线并行：把层分成几段，每张卡一段，一个批次像流水线穿过各段。省显存，但段与段之间有气泡，负载要均衡。张量并行：把同一层里的矩阵乘法拆到多张卡，通信频繁，适合注意力和前馈这种计算密的层。三维并行是三者一起用。专家并行只适用于混合专家：每个专家是独立的前馈网络，分到不同卡上，由门控决定 token 找谁。没有共享权重的专家才好这样切。

#### 40. 数据并行的梯度怎么聚合？Ring AllReduce 解决什么？

**高级/架构 · 两边都考** · 考察：不要一台机器收齐再广播

每张卡先算自己这个批次的梯度，再聚合成同一份，最后各自用这份更新。若所有卡都把梯度发给某一台再广播回来，那一台的带宽会堵死。Ring AllReduce 把卡连成环：先分块传递并累加，再把累加结果传一圈，使每张卡都拿到完整梯度。通信量摊到所有卡上。计算和通信可以重叠，但同步点仍然要等最慢的那张卡。

#### 41. 流水线并行和张量并行的主要代价是什么？

**高级/架构 · 两边都考** · 考察：气泡和通信，不是「并行就更快」

流水线的代价是气泡：前一段还没算出激活时，后一段在等；微批次能把气泡摊薄，段与段的计算量差太多仍会空转。张量并行的代价是每层都要跨卡通信，机器之间的带宽不够时，通信时间会盖过计算收益。三维并行能训更大的模型，配置和排障都更重，先证明单机放不下，再上这套。

#### 42. ZeRO 三个阶段各拆走什么？Offload 换来什么、失去什么？

**高级/架构 · 两边都考** · 考察：数据并行里的重复存储

普通数据并行里，每张卡都存优化器状态、梯度和参数，大头是重复的。ZeRO-1 把优化器状态拆开，每张卡只留一份。ZeRO-2 再拆梯度。ZeRO-3 连参数也拆，用到某一层时再集中。阶段越高，单卡显存越低，通信越多。

Offload 把参数、梯度或优化器状态放到 CPU 或磁盘，用来换 GPU 显存。能在卡不够时把训练跑起来，但搬运数据会明显变慢。显存只差一点点时优先 ZeRO 和混合精度，不要先把状态卸到磁盘。

#### 43. 混合精度训练为什么又快又省？下溢怎么办？

**中级 · 两边都考** · 考察：FP16 计算，FP32 主权重

自动混合精度让矩阵乘用 FP16 或 BF16，主权重和部分累加仍用 FP32。显存和带宽大约减半，Tensor Core 上也更快。风险是半精度范围小，梯度一乘就下溢成 0，还有舍入误差。损失缩放先把损失放大再反传，更新前除回去，避免小梯度变 0。真正写回参数时用 FP32 副本，再把结果同步回半精度权重。BF16 指数位和 FP32 一样宽，比 FP16 不容易溢出，显存仍是 2 字节。

#### 44. 全参微调的显存大致由哪几块构成？

**高级/架构 · 两边都考** · 考察：参数、梯度、优化器、激活，不要只报模型大小

以混合精度、Adam 为例，参数和梯度各约 2 字节乘参数量，Adam 的一阶矩和二阶矩约 8 字节乘参数量。7B 模型这三项大约是 14GB、14GB、56GB。激活值随批次、序列长度和隐藏维度涨，往往比参数更不可控。临时缓冲另计。

省显存的对应关系：混合精度砍参数和梯度；梯度检查点用重算换激活；梯度累积让每步的微批次变小；ZeRO 按阶段拆优化器、梯度和参数；模型并行让每张卡只拿一部分层。报显存时把这五项分开说，不要说「7B 就是 14GB」。

#### 45. 什么时候用全参微调，什么时候用 PEFT？

**中级 · 两边都考** · 考察：改行为的成本

参数高效微调只更新一小部分权重，或在旁边加一小块新参数。全参更新全部权重，效果上限更高，也更吃显存、更慢，数据少时更容易过拟合，还会动到原来的通用能力。数据少、显存紧、只想改格式和话术，用 LoRA 一类方法。数据多、要尽量贴近全参效果、资源够，再用全参。PEFT 依赖底座模型本身的能力，底座不会的知识不会因为训了小矩阵就出现。新知识仍然优先进检索，见第36题和第38题。

#### 46. LoRA 训的是什么？A、B 为什么那样初始化？

**中级 · 两边都考** · 考察：低秩增量，起点必须等于原模型

原权重冻结。在要改的线性层旁边加两个小矩阵，训练只更新它们，生效时是原权重加 B 乘 A。A 用随机正态初始化，让不同的行一开始就能收到不同梯度。B 初始化为 0，这样训练起点的增量是 0，输出和原模型一致，不会一上来就把能力打乱。

原论文主要加在注意力的 Q、K、V、O 四个投影上。实践里常扩到前馈的上投影和下投影；用了带门控的激活，再加门控那一个矩阵。不是每一层的每个矩阵都必须加，加得越多越接近全参的成本和过拟合风险。

#### 47. LoRA 的秩和 alpha 怎么取？怎样避免过拟合？权重能不能合并？

**中级 · 两边都考** · 考察：容量、缩放、部署形态

秩是小矩阵的宽度。没有万能值，从小往大试，常见起点是 8 或 16。秩小则参数少、不容易过拟合，复杂任务可能不够。秩大则更接近全参，更贵，也更容易记训练集。alpha 和秩的比值决定增量相对原权重有多大，常见取 alpha 等于 2 倍秩，再用验证集比较 1 倍、2 倍、4 倍。单独背一个 alpha 没有意义。

过拟合就减小秩、加数据、加大权重衰减，或在 LoRA 层上加 dropout。

可以合并：把 B 乘 A 加进原权重，推理时没有额外矩阵，速度和显存与普通模型一样。代价是不能再热切换不同任务的适配器。一个底座要服务多个任务时，保留未合并的适配器；确定只部署一个任务时再合并。

#### 48. QLoRA 比 LoRA 多做了什么？NF4 针对什么分布？

**高级/架构 · 两边都考** · 考察：底座量化，适配器仍用较高精度训练

QLoRA 把冻结的底座权重量化到 4 bit，只训练 LoRA。再加两件事：量化常数本身再量化一次，以及优化器状态放不下时分页到 CPU，避开显存尖峰。这样消费级显卡也能微调较大的模型，训练会变慢，量化也会带来误差，要用原来的评测集看任务有没有掉。

神经网络权重大多集中在 0 附近，近似正态。均匀的 4 bit 格子会把大量刻度浪费在很少出现的极端值上。NF4 按正态分布的分位数放 16 个刻度，0 附近更密，并保留精确的 0。实现上按块算缩放系数，把归一化后的值映射到最近的刻度，存 4 bit 下标；计算前再乘回缩放系数。它不是把所有数四舍五入到等距格子。

#### 49. SFT 数据常见哪两种格式？样本从哪来？

**初中级 · 两边都考** · 考察：单轮指令和多轮对话，不要混字段

监督微调是用指令和期望回答更新模型，让它学会格式、术语和步骤。常见两种 JSON。Alpaca 风格是单轮：指令、可选输入、输出。ShareGPT 风格是多轮：一段对话里每条只有角色和内容。要函数调用时，在对应轮次加上工具调用和工具结果，不能把调用塞进普通助手文本里假装模型会了。

公开数据来自 Hugging Face、ModelScope 这一类仓库。业务数据来自内部文档、客服记录和真实工单，必须脱敏，并且不能把评测题混进训练集。多轮样本要保留真实的失败和追问，只留完美单轮会让模型不会处理中断。

#### 50. 知识蒸馏在让学生模型学什么？离策略和同策略两阶段差在哪？

**中级 · 两边都考** · 考察：学分布，不是只背最终答案

蒸馏是让小模型模仿大模型，用来缩小体积，而不是把新知识写进参数。学生要学的是教师在各个 token 上的概率，或者教师写出的推理过程，而不是只对齐一个硬标签。教师本身会胡编，学生会把这个习惯一起学走，所以蒸馏后仍要用业务集验收。

一种实用的两段做法：先让教师在「先想再答」和「直接答」两种模式下生成结果，学生用交叉熵去拟合这些文本，教师不参与学生的每一步更新，这是离策略。再让学生对同一问题自己出分布，用与教师分布的 KL 散度继续拉齐，这是同策略。只做第一段，学生会背教师的句子；加上第二段，才更接近教师的判断。

#### 51. 对齐里的 RLHF 分哪几步？在线和离线策略怎么分？

**高级/架构 · 两边都考** · 考察：SFT、奖励模型、策略优化，2026 年很多团队已改走 DPO

监督微调先让预训练模型听得懂指令。然后用人类对回答的偏好训练一个打分的奖励模型。最后用强化学习提高奖励模型的分数，同时用一项惩罚把新策略拉在原来的监督微调模型附近，避免为了刷分把话术训崩。经典算法是 PPO。

在线策略是边采样边更新，当前模型自己生成的回答立刻拿去训练，PPO 属于这一类。离线策略用事先收集好的偏好或指令数据，监督微调和 DPO 属于这一类，训练时不必再跟环境交互。2026 年应用团队若只是做偏好对齐，优先说明为什么选 DPO 而不是上 PPO：少训一个奖励模型，也少一条不稳定的在线采样。PPO 的裁剪范围通常在 0.1 到 0.3，需要单独调，不要当成默认就稳定。

#### 52. DPO 训练时两条回答的奖励一起掉，常见原因是什么？

**高级/架构 · 两边都考** · 考察：偏好数据，不是先加大学习率

DPO 不用单独的奖励模型，直接用「更好的回答」和「更差的回答」成对更新。两条的隐式奖励一起下降，多数是偏好对坏了：标注循环，例如 A 优于 B、B 优于 C、C 又优于 A；或者正例和负例差别太小、标签反了。模型无法判断该提高谁的概率，更新方向互相抵消。先查标注一致性和正负例是否真的不同，再谈学习率。DPO 省掉了 PPO 的在线采样，也因此更依赖这对数据的质量，不能利用奖励模型去给没标注过的新回答打分。

#### 53. 思维链能力靠微调和靠强化学习，差别是什么？

**中级 · 两边都考** · 考察：数据里有没有推理，奖励是否鼓励步骤

提示词可以要求模型先写步骤，那是推理时的技巧，不改变权重。要写进模型，有两条路。监督微调是在训练集里放入带步骤的回答，模型模仿这些文本。强化学习是给「答案正确」和「步骤完整」奖励：PPO 用奖励模型给展示了过程的输出加分；DPO 则让带步骤的回答作为正例、不带步骤的作为负例；GRPO 用一组采样里的相对优势，奖励可以是规则，例如答案对不对、步骤在不在。规则奖励必须真的检查步骤，只奖励最终答案，模型会学会跳过过程。应用岗讲清这三种数据形态即可，不必展开策略梯度的推导。

## 编排与恢复

运行时负责把模型包成可中断、可恢复、有预算的执行过程。先讲终止条件，再讲 checkpoint。

#### ★ 54. 设计一个 Agent 运行时：从用户消息到最终回复，画完整数据流。

**中级 · Agent 开发岗** · 考察：prompt、路由、工具、状态、人审

运行时数据流：入口鉴权 → 组 prompt（system/工具/历史/RAG）→ 模型路由 → 解析 tool_calls → 权限校验执行 → 写状态/trace → 循环或人审 → SSE 流式返回；同时画清同步路径与异步 job。机制上要有硬限制、checkpoint、cancel，以及工具副作用标记。人审节点可挂起等待，恢复后继续。结合 TS+Python：BFF 出事件，Python 跑 loop，权威状态在服务端。

#### ★ 55. Agent loop 如何做 checkpoint 和恢复？续跑和重跑怎么选？

**中级 · Agent 开发岗** · 考察：序列化、幂等、版本兼容

每步后序列化图状态与消息；工具须幂等或记执行凭证，避免续跑双写。恢复时校验图版本兼容。挂起等待用户用 wait 节点+TTL，取消用 cancel token。

checkpoint 只放续跑必需的状态：消息、目标、未完成的工具结果、步数和预算、挂起点。trace 只用于诊断，要脱敏，不拿它当恢复源。

中断之后先看副作用有没有发生。已经写成功且带幂等键，走续跑；搞不清写没写成功，先查凭证再决定，不要盲目整段重跑。用户取消之后算不算失败，要产品先定义。等用户补参用 wait 节点加 TTL，见挂起那一题。

#### ★ 56. 如何防止死循环？终止条件和无进展检测具体怎么做？

**中级 · Agent 开发岗** · 考察：步数、token、重复签名、墙钟、确认

硬限制：最大步数、token/费用墙钟、相同 tool+args 签名重复次数、无进展检测；敏感写操作强制确认。超限转人工或降级固定话术。
- **常见坑**：无步数/费用上限、resume 双写、取消只停前端。
- **例子**：max_steps 8–20；同签名重复不超过 2–3 次；费用墙钟按租户配额。

无进展不能只看步数。对规范化后的工具签名、检索 query，或订单号、金额这类目标字段做指纹；连续几步没变化就判空转，然后换工具、追问或停止。分页翻页要用目标差分，避免把正常翻页当成空转。看板上要有强制终止率和无进展触发率。

#### 57. 2026 年还问 LangChain、LangGraph、自研状态机、Temporal，怎么选？

**高级/架构 · Agent 开发岗** · 考察：可控、可观测、成本、上手

LangGraph 上手快生态好但深度定制受限；自研状态机最可控可观测成本高。
- Temporal 擅长长事务与重试，Agent 语义需自建。选看团队与 SLA。

2026 年的主答不是背 Chain 或 AgentExecutor。LangChain 是模型、提示、解析器、检索器和工具的组件层，适合固定的线性 RAG。LangGraph 把同一次任务收成可持久化的状态图：State 是共享上下文，Node 是一步，条件边按状态选下一跳，所以才能循环、暂停和恢复。YAML 或低代码适合分支事先写死的流程。

自研状态机最可控，成本也最高。Temporal 适合长事务和重试，Agent 的选工具语义仍要自己做。简单链路不必上图；上了图就要有死循环边界。LlamaIndex 适合检索原型，权限和观测要自己补，别被框架把控制面锁死。

#### 58. 什么时候上 Multi-Agent？角色、共享状态和循环讨论怎么收？

**高级/架构 · Agent 开发岗** · 考察：supervisor、辩论、流水线

先判断任务能不能切开、接口清不清楚。切不开就单 Agent 加工具，不要因为竞品在喊 Multi-Agent 就上。能切再按规划、执行、审核拆角色，共享状态用受限黑板或消息，冲突用 supervisor 或投票，汇总用摘要，避免把全轨迹塞回去。按角色拆（规划/执行/审核），共享内存用受限黑板或消息；冲突用 supervisor 或投票。

循环讨论要有轮次上限和重复论点检测，超时拉裁判或人。子 Agent 另加深度上限和子预算，只回摘要。

#### 59. 同步 loop 与事件驱动编排如何选？

**中级 · Agent 开发岗** · 考察：交互延迟 vs 长任务/多等待

低延迟对话用同步 loop；多等待外部系统、长任务用事件驱动/队列。可同步开场+异步收尾，用会话状态衔接。

#### ★ 60. 并行工具怎么调度和汇合？部分失败、依赖和子任务预算怎么处理？

**中级 · Agent 开发岗** · 考察：allSettled、短路、补偿

没有数据依赖的只读工具并行，有依赖的必须串行。调度用 allSettled 汇合，关键路径可以短路；部分失败把成功子集和错误码一起交回模型，独立工具可以单独重试。每个调用带自己的取消和超时，外面再加一个总超时。并发发起后 allSettled 汇合；关键路径可短路失败。- 部分失败返回成功子集+错误码，必要时补偿或重试独立工具。

子任务同样用 DAG 加舱壁：一个子任务有自己的预算和失败隔离，烧光不能拖垮整单，回传用摘要。

#### 61. 如何支持子 Agent 调用（delegation）且控制嵌套深度与成本？

**高级/架构 · Agent 开发岗** · 考察：深度上限、预算下发、结果摘要返回

delegation 下发子预算与深度上限，子 Agent 只回摘要不回全轨迹；父级汇总。超预算强制收束或升级人审。

#### 62. 工作流里「确定性节点」和「LLM 节点」混排，事务边界怎么定？

**高级/架构 · Agent 开发岗** · 考察：LLM 外置、业务写操作可回滚

LLM 节点不做业务事务提交；写库/支付放确定性节点且可回滚或幂等。LLM 输出经校验后再进写路径，失败补偿明确。

#### 63. Agent 中途需要用户补充信息，如何挂起等待又不丢上下文？

**中级 · Agent 开发岗** · 考察：wait 状态、回调、TTL

进入 wait 状态持久化 checkpoint，回调/下轮消息唤醒；设 TTL 与提醒。前端展示待补充槽位，服务端勿丢 messages。

#### 64. 设计支持 A/B 两套编排图同时在线的发布系统。

#### ★ 65. 用户点停止或立刻再发时，如何取消整条链路并真正停到推理和沙箱？

**高级/架构 · Agent 开发岗** · 考察：cancel token、可中断工具、一致性

请求级 cancel token 下传到工具；工具支持中断或超时丢弃。已产生副作用靠幂等/补偿。前端停 SSE，服务端标 cancelled。

取消是三层，缺一层都算没停。

前端用递增请求代号。停止后再发是作废 N、发起 N+1。界面只采纳代号等于当前值的片段，旧连接晚到的字丢掉。

服务端不能只靠连接断开。前面有反向代理时，断开常常到不了推理。按请求代号做幂等取消，传到占着 GPU 的那一层，按 token 或调度步检查，命中就移出批次并释放 KV cache。FastAPI 或 BFF 上，客户端断开要转成上游的取消令牌，截止时间从入口一路下传。

沙箱里还要把进程组或微虚拟机杀掉、摘掉网络。已经发生的外部写靠幂等或补偿，不靠「连接已经断了」。

#### ★ 66. 如何实现「工具结果驱动的图边」（dynamic edges）又保持可测？

**高级/架构 · Agent 开发岗** · 考察：受控分支表、白名单下一跳

LLM 只输出白名单内的下一跳标签；边表配置化可测；禁止任意跳转。关键业务边仍用确定性条件。动态边提灵活性，但要用白名单把状态空间收住。模型输出 next_node ∈ 允许集合；非法则重试或默认兜底节点。边表进配置中心，单测覆盖每种 observation→边。

- 业务资损边（支付）不用纯 LLM 边，用规则。
- 可观测：记录选边原因与拒绝次数。
- 坑：开放「任意节点名」导致不可复现。

#### ★ 67. 生产级 Harness 有哪些子系统？它和 Loop、Hooks 是什么关系？

**高级/架构 · Agent 开发岗** · 考察：loop、预算、工具、记忆、观测、HITL

Harness 子系统：Ingress、Prompt Assembler、Router、Tool Runtime、Memory、Policy/HITL、Telemetry、Config，不要只画模型↔工具。每个子系统讲边界与失败模式。常见落地 TS BFF + Python Tool Runtime/loop。没有预算与恢复，就不叫生产级。例如 Ingress(TS) + Tool Runtime(Python) + Policy/HITL + Telemetry。
- 按控制面清单答，不要只画「模型↔工具」两框。

Harness 是模型外面的控制面，不是又一个聊天框架。子系统至少有：入口、提示词装配、模型路由、工具运行时、记忆、策略和人审、遥测、配置。没有预算、取消和恢复，就不要叫生产级。常见落地是 TypeScript 做入口事件，Python 跑 loop 和工具。

Loop 是这个控制面里的闭环：目标、计划、工具、观察、校验，再把失败沉淀成规则或 Skill。Claude Code 一类产品的 Hooks 是把规则做成事件：工具执行前拦截危险命令，执行后跑测试和日志，会话开始时注入仓库上下文。规则只写在 system prompt 里，模型可以不遵守。

面试官如果抛出 OpenClaw、Hermes 这类产品名，先问清楚指的是编排入口，还是记忆和技能沉淀，再回到上面这三层。不要把培训营里的产品名当成行业标准背。

#### ★ 82. MCP 的 transport（stdio / SSE / HTTP）分别适合什么部署场景？安全差异是什么？

**中级 · Agent 开发岗** · 考察：本地插件 vs 远程服务、鉴权面

stdio 适合本地 IDE/桌面宿主；SSE/HTTP 适合远程 MCP Server。远程要鉴权、TLS、租户隔离；stdio 要防本地进程逃逸与恶意包。按部署形态选 transport，安全模型跟着变，不能混谈。

- stdio：进程内/本机管道，延迟低、适合 Cursor 类宿主拉起本地 Server；风险是任意代码执行、读本机文件，需签名与沙箱。
- SSE/HTTP：远程可扩缩；必须 mTLS/OAuth、网络策略、按租户凭证；防 SSRF 与开放回调。
- **取舍**：内网工具可 HTTP+网关统一审计；高敏本地能力可 stdio 但默认无外网。
- 坑：把远程 MCP 当「可信插件」不鉴权；或把云凭证塞进本地 stdio Server。
- 例子：公司知识库 MCP 走内网 HTTP；本机 git 工具走 stdio。

#### ★ 83. 工具参数改名或 Schema 演进时，如何对线上 Agent 保持兼容？

- 重命名：适配器接受新旧键一段时间。
- 版本：tools/list 带 schema_version；评测集锁版本跑回归。
- 坑：静默改必填导致大面积 tool 失败。

加字段用可选加默认；改枚举先加后弃；改名用适配器同时接受新旧键，窗口结束再删。tools 列表带 schema 版本，评测集锁版本。上游协议变了，迁移清单是：适配器、契约测试、灰度、回滚。静默把字段改成必填，会造成大面积工具失败。

## 模型路由与网关

小模型做判别，强模型做难推理。网关统一路由、流式、限流、计量和降级。

#### 110. 如何评测「路由是否选对了模型」而不只看最终成功率？

**中级 · Agent 开发岗** · 考察：代价敏感指标、反事实、阴影流量

定义难度标签与成本权重；阴影用强模型对照；统计「过度升级/欠升级」率。最终成功是北星，路由有独立诊断指标。

- 只看成功率会掩盖「杀鸡用牛刀」。
- 标一批难度；算实际模型档 vs 理想档。
- 阴影：抽样强模型结果，量质量差是否值得差价。
- 告警：简单题高频走最贵模型。
- 坑：路由模型自身不稳导致抖动——加滞回与缓存。

#### ★ 111. 企业内部 LLM Gateway 必须具备什么？和自建推理网关是不是一回事？

**高级/架构 · Agent 开发岗** · 考察：路由、限流、缓存、计量、观测、鉴权

企业内部 LLM Gateway 我把它定义成 AI 流量的控制面：统一鉴权与租户、按能力矩阵路由与 Fallback、Streaming 适配、多维限流、可选缓存、精确计量与对账、完整 trace，以及对 Agent 的工具协议归一化。没有计量与观测的「转发」撑不住 30–60k 档的平台岗面试。你还要能讲配置版本、紧急切主备、与业务 showback。和 Harness 边界：Gateway 管模型 IO；Harness 管 loop/工具/HITL。
- 企业 LLM Gateway=控制面能力集合，不是反向代理。
- 必备：鉴权、多模型路由/Fallback、流式适配、限流配额、缓存策略、token/成本计量、链路追踪、审计。

它和 Harness 的边界：Gateway 管模型 IO，Harness 管 loop、工具和人审。自建推理网关还要多管调度、KV cache 和批大小；如果只是转发云 API，不要把它讲成推理引擎。多租户网关把配额和审计放在同一层，插件市场是旁边的目录，不是网关本身。

#### ★ 112. 多模型怎么路由和降级？失败切换如何不丢会话、不乱调工具？

**中级 · Agent 开发岗** · 考察：能力矩阵、延迟、成本、协议适配

多模型路由我会用能力矩阵打分：工具调用、长上下文、多模态、合规驻地，再叠加实时健康与单价。Fallback 不是盲切：要验证工具 JSON 兼容，并可能降级「无工具纯文本」。会话中途切换要做消息规范化；关键任务建议会话级钉扎，只在硬错误时切。全链路记录 route_reason 方便复盘。上海岗常把国产+海外混部，矩阵比「哪个聪明」更重要。
- 路由看能力/质量/成本/合规；Fallback 要协议兼容。
- 决策维：是否 FC、上下文长度、延迟、价格、数据驻地。
- 失败切换保留消息中间态，必要时摘要迁移。
- 会话可钉扎模型避免中途乱跳。

简单题用小模型做意图和难度分类，要工具或置信不够再升强模型。便宜模型可以先试，失败再级联，并设费用上限。路由维度是：会不会函数调用、上下文长度、多模态、数据驻地、单价、实时健康，而不是只比谁更聪明。

Fallback 不是盲切。工具 JSON 不兼容就降级成只读问答或转人工。会话中途换模型，先把历史收成中间消息格式，再映射角色和工具结果。关键任务可以钉住模型，只在硬错误时切，并抑制来回抖动。数据不许出境的请求不能切到海外。每次路由记下原因，方便复盘「过度升级」和「欠升级」。

#### ★ 113. 网关如何统一流式和非流式？取消、心跳和半截 JSON 怎么处理？

**中级 · Agent 开发岗** · 考察：取消、心跳、半截 JSON、背压

Gateway 流式坑最多：有的厂商 chunk 语义不同、工具调用增量字段不一、代理会缓冲导致「假流式」。我会统一成内部事件（delta/tool_delta/error/done），并禁代理缓冲、定期心跳。取消：下游断开即取消上游，扣费按实际上游 usage。半截 JSON 不落执行，等完整或显式结束再校验。TS 前端状态机要容忍乱序与重连。
- Streaming 统一要处理取消、心跳、半截结构化、代理缓冲。
- 上游差异用适配器；对下游统一 SSE 事件。
- 半截 tool_call JSON 要增量解析或完成后再校验。

对下游收成一套事件：delta、tool_delta、error、done。上游不是流式时，收成单个 chunk。代理缓冲会造成假流式，要禁缓冲并打心跳。半截工具 JSON 不执行。客户端断开必须取消上游，费用按实际 usage 结算。

#### ★ 114. 语义缓存和精确缓存怎么做，才不会串租、跳过鉴权或答错？

**高级/架构 · Agent 开发岗** · 考察：缓存键含租户权限、风险类禁用

Gateway 缓存我区分精确键与语义键，但两者都必须嵌入租户与权限范围。命中后仍跑 ACL；涉及用户私有数据、价格库存、写意图的请求默认不缓存或极短 TTL。错答要有剔除与租户级隔离，避免 A 租户语义撞到 B。带 tool_calls 的对话缓存策略更保守，优先缓存检索问答。面试强调：省钱指标与错答率一起看。
- 缓存省钱但不能跳过鉴权与个性化边界。
- 键=租户+权限范围+模型+归一化请求；高风险禁用。
- 语义缓存设阈值与可剔除；命中仍过 ACL。
- Agent 带工具的请求通常只缓存无副作用答案。

精确缓存和语义缓存都要把租户、权限版本、模型写进键。命中之后仍要做 ACL，缓存不是信任边界。用户私有数据、价格库存、写意图默认不缓存或 TTL 极短。带工具的对话只缓存无副作用的答案。错答要能按条剔除。

日活上来之后，命中率和错答率一起看。省钱如果换来串租或答错，这组缓存就应该关掉。

#### ★ 115. token 和费用怎么计量、对账并分摊到业务线？会话预算如何并发扣减？

**中级 · Agent 开发岗** · 考察：usage 回调、预留、账单

成本计量：请求入口按模型单价预估做预留；上游返回 usage 后确认扣减；失败/取消退款预留。并发下用原子操作防超卖。流式场景在 done 事件结算；记录 provider request id 便于对账。业务 showback 按标签汇总。这是平台岗非常爱追问的「你怎么防止刷爆」。
- 以上游 usage 为准对账；估算仅作准入。
- 流式结束回写实际 token；失败释放预留。
- 月账单与厂商账单差异有容差流程。

入口按单价预留，上游返回 usage 之后实扣，失败和取消退预留。流式在 done 时结算，记下供应商请求号用来对账。并发扣减用预留、提交、回滚，不要先执行后扣。

showback 从网关强制打租户和项目标签，报表里成本和成功率并列。成本中心把预算、告警、自动降级放在一起：超预算先降模型或关掉贵工具，再通知业务负责人。没有分摊，业务不会在意浪费。

#### ★ 116. 限流、熔断、舱壁怎么配？用户 QPS 和 token 预算如何同时生效？

**高级/架构 · Agent 开发岗** · 考察：多维令牌桶、优先级、友好错误

四维限流用多层令牌桶/配额：先过用户 QPS，再租户 token 预算，再模型池并发，最后贵工具次数。批任务低优先级，可被在线抢占。触发时返回结构化错误：哪一维触顶、恢复时间、是否可降级模型。配置变更审计。结合 Agent：会话预算与 Gateway 限流要对齐，避免两边各限一次体验崩。
- 限流多维组合，错误要可解释可升级。
- 优先级：在线交互 > 批任务；核心业务白名单。
- 返回明确限额与重试建议，勿只 429。

先过用户 QPS，再过租户的 token 预算，再过模型池并发，最后是贵工具次数。在线高于批处理。触顶时返回哪一维满了、何时恢复、能不能降级，不要只丢一个 429。

模型和工具都当成下游：独立舱壁、超时、熔断，一个慢工具不能占满整个会话集群。会话预算和网关限流对齐，避免两层各限一次。

#### ★ 117. 多家模型的工具调用协议怎么在网关上抹平？

**中级 · 两边都考** · 考察：归一化 FC、JSON mode、重试

各厂商 tool calling 字段名、并行、流式增量不一致。Gateway 适配器把它们归一成内部 ToolCall，再交给 Harness；执行结果再映射回厂商消息格式（若需多轮）。能力不足的模型不要硬上工具，应路由到支持 FC 的，或降级无工具。用统一评测集盯工具成功率。全栈：TS 只认内部事件协议，不被厂商细节穿透。
- 网关抹平 FC 差异，Harness 仍要校验。
- 归一：tool_calls 结构、并行语义、错误回灌格式。
- 不支持 FC 的模型走受限 JSON 或禁工具路由。
- 回归集测各 provider 工具成功率。

业务只看统一的 Chat 和 Tool 接口。每家一个适配器，负责函数调用字段、并行语义、流式增量和错误回灌。能力要先探测：没有函数调用的模型不要硬上工具，改路由或降级。计费和限流按供应商拆开。国产和海外模型的差异按适配器讲，不要把某一家 2024 年的字段当成唯一标准。2026 年现场更常听到的是 DeepSeek、Qwen、Kimi、GLM、Claude、GPT；文心和旧版通义 API 只在存量系统里当差异项。

#### ★ 118. Gateway 是否该做 Prompt 注入过滤？边界在哪？

**中级 · Agent 开发岗** · 考察：分层防护、不能只靠网关

Gateway 处在所有模型流量点，适合统一做基础 jailbreak/DLP/密钥扫描，但它看不到业务 ACL 与工具副作用上下文，不能当唯一 guardrail。间接注入要在检索/工具回灌处标记 untrusted；越权在工具执行前鉴权。Gateway 过滤失败要可观测，误杀可白名单。回答体现纵深防御。

- Gateway 可做基础过滤，但不能替代应用层分层防护。
- 适合：明显越狱、密钥外泄、基础 DLP。
- 不适合单独挡间接注入与业务越权。
- 与 Harness 工具 ACL、输出过滤分工。

## RAG

先讲召回链路和权限，再讲混合检索、重排和索引版本。查询模型和索引必须成对。

#### 119. embedding、chunk、rerank、citation 各解决什么？

**初中级 · 应用开发岗** · 考察：基础概念

embedding 语义向量；chunk 切分单元。rerank 精排；citation 可追溯引用。串起 RAG 链路讲清。

- **常见坑**：概念孤立背、串不起链路。
- **例子**：一句话串完切分→嵌入→检索→重排→带 citation 生成。

#### 120. 解释 reranker 与 embedding 检索为何常常要两段式？

**初中级 · 应用开发岗** · 考察：召回广度 vs 精排精度

embedding 廉价广召回；rerank 交叉编码更准但贵。两段式平衡成本与质量。一阶段向量难又全又准。流程：取 top100→rerank top10→生成。何时可省：语料极小或延迟极敏感。

- 坑：rerank 模型与领域不匹配。

#### ★ 121. RAG 召回错了（例如问「小细胞癌」答成「细胞癌」）怎么定位并修？

**中级 · 应用开发岗** · 考察：切分、embedding、改写、重排

召回差按层排：切分/元数据 → embedding/索引 → query 改写 → 召回量 → 重排 → 生成，每层用金标定位，避免一上来改 prompt。坑：坏解析硬向量化、无引用硬答、权限只写 prompt。政策短 chunk，叙事 500–800 字+overlap，引用不齐则拒答。上海应用岗很吃这套分层排查。

先按层排，停在第一次丢信息的那一层：切分和元数据、embedding 与索引、query 改写、召回量、重排、生成。每层用同一套金标，不要一上来改提示词。

「小细胞癌」被答成「细胞癌」是粒度失配，稠密空间里核心词会吞掉限定词。排查顺序是：改写后是否还逐字含有「小细胞癌」；召回近邻是不是全成了上级概念；正确片段在不在候选里却被重排挤掉；拼进上下文时有没有被截断；最后有没有校验答案保住了完整实体。

修复也按这个顺序。改写必须逐字复制疾病名。检索加 BM25 或字符级稀疏，和稠密双路召回，含明确亚型时提高稀疏权重。重排把「是否包含完整实体」当成特征。一条候选都没有完整短语，就用原短语再检，预算用完就拒答，不用上级概念硬答。回归集里同时放「小细胞癌」「非小细胞癌」「小细胞肺癌」。

#### ★ 122. 稠密、稀疏、混合检索和 GraphRAG 怎么选？Rerank 的延迟怎么折中？

**中级 · 应用开发岗** · 考察：专有词、多跳

专有名词、货号、必须逐字命中的限定词走稀疏或混合；语义问答走稠密。GraphRAG 只用于多跳关系和实体要前后一致的问题，先证明混合检索和权限是对的，再付构图成本。指标看多跳题，不要用它掩盖召回失败。专有词/货号偏稀疏或混合；语义问答稠密。

Rerank 用级联：向量先取一批，再精排一小截，不追求每问都走最长链路。监控重排到底把答案抬升了没有。

#### ★ 123. 带权限的 RAG 如何把 ACL 做进链路？制造和车企场景多哪些维度？

**高级/架构 · 应用开发岗** · 考察：索引/查询过滤、越权测

ACL 写进索引，查询时强制过滤，再用端到端越权用例进 CI。只在提示词里写「不要越权」不算。

制造和车企还要加上组织、产线、制度版本。越权测试用真实组织树，不用扁平的用户 id。

#### 124. chunk 大小与 overlap 怎么定？

**初中级 · 应用开发岗** · 考察：文档类型、问答粒度

按文档类型与问答粒度调：政策短段、叙事可 500–800 字；overlap 保跨段完整。用检索评测定而非拍脑袋。

- **例子**：政策短 chunk；叙事 500–800 字+overlap；对不齐引用则拒答。

#### 125. 表格、PPT、扫描件进知识库难点？

**中级 · 应用开发岗** · 考察：解析、版面、OCR

表格保结构、PPT 版面、扫描件 OCR 质量是瓶颈。分类型解析流水线，坏解析勿硬塞向量。

- **常见坑**：坏解析硬向量化、无引用硬答、权限只写 prompt。

#### 126. query 改写有哪些策略？何时会改坏？

**中级 · 应用开发岗** · 考察：多查询、HyDE、领域词典

多查询、HyDE、同义扩展、领域词典；指代不明或改偏意图会改坏。要回归原查询对照。

#### 127. 引用如何保证可点击而且真的引用了？流式输出时脚注何时出现？

**高级/架构 · 应用开发岗** · 考察：强制 quote、字级对齐

生成强制基于检索 quote；脚注绑 chunk id。字级或句级对齐校验。点不开或对不上则降级不显示。

生成必须能对上检索片段，脚注绑 chunk id，做字级或句级对齐。对不上就不显示引用。流式先出正文，结束补齐并校验脚注；不要为了抢先显示一个还没对齐的角标。

#### 128. 知识更新后索引延迟，用户看到旧答案怎么办？

**中级 · 应用开发岗** · 考察：版本、主动失效、说明时效

版本号/更新时间展示；主动失效缓存。

- 关键文档同步索引。旧答标注可能过时。

#### 129. 百万文档规模下的分层索引与路由？

**高级/架构 · 应用开发岗** · 考察：类目路由、级联检索

类目/租户路由→候选库→精排；热点缓存。级联避免全库暴力搜，监控路由错误率。

#### 130. 没有命中时该拒答还是靠模型知识？产品如何定？

**中级 · 应用开发岗** · 考察：领域政策、置信度

强领域政策可强制拒答；开放域可降级模型知识但须声明。产品写清置信与免责。

#### ★ 131. 换 embedding 后答非所问，负责人又联系不上，当晚怎么止血？

**中级 · 应用开发岗** · 考察：查询向量和索引必须成对

典型原因是查询已经用新模型，库里仍是旧向量，两个空间对不上，生成只能在错文档上作答。当晚只做回切，不现场重算全库。
1. 从切换时间点圈影响面：哪些租户、哪条检索链、错答是否集中在召回而不是生成参数。
2. 回切到上一对「查询模型 + 索引」。只退查询或只退索引都会继续错。旧索引还在，就把流量指回去，这是分钟级动作。
3. 用一小套固定问题看召回是否回到切换前，再对客户说明：检索模型版本不一致，已切回稳定版本，并给出你验证过的范围。
4. 留下切换时间、版本号、回切动作和召回对比。负责人回来接手的是一份已止血的记录。
之后把查询编码器和索引做成一个版本单元：维度、归一化、模型标识不一致就拒绝启动。新模型先双索引、小流量，评测退步就不放全量。回切是改流量指针。告警打到值班通道，看检索分数、空召回和点踩，而不是只打给休假的个人。
- **常见坑**：连夜重嵌入，故障继续到天亮；回切时查询和索引不是同一版。

#### ★ 132. 如何做 RAG 的离线指标：Recall@k、nDCG、忠实度（faithfulness）怎么配合？

**中级 · 应用开发岗** · 考察：检索指标与生成指标分层

RAG 离线指标要分层：检索用 Recall@k、nDCG；生成用 faithfulness 与引用对齐；业务用端到端正确率。金标是 query 到相关 doc id；LLM Judge 只能辅助，不能掩盖检索失败。掉点时先分清是没召回到，还是生成胡编。常见坑是 Judge 偏爱长答，表面分数高但证据不足。上海应用岗很看你是否会分层定位。

- 检索差与生成胡编要分开量。
- 生成：答案是否被证据支持（faithfulness）；引用是否可点。

#### 133. 多模态知识库（图、表、CAD 截图）进 Agent 的架构要点？

**高级/架构 · 应用开发岗** · 考察：解析、多向量、引用模态

分模态解析与嵌入；检索可回传图文；生成注明模态来源。无解析质量就不上线硬答。多模态瓶颈在解析与引用，不在「能不能喂图」。

- 流水线：OCR/表结构/图注；图向量+文向量。
- 引用：脚注带页码/图号。
- 权限同文挡。
- 坑：整页截图当唯一 chunk 导致检索噪。

#### 134. 什么是 agentic RAG？和朴素 RAG 差在哪？

**中级 · 两边都考** · 考察：多步检索、自决定

agentic RAG 可多步检索、自决定是否够用再搜；朴素一次检索生成。难查询提升大但成本高。

## 评测

评的是整条轨迹能不能完成任务。变更必须能回归。

#### ★ 135. Agent 评测和单次 LLM 评测有何不同？

**中级 · Agent 开发岗** · 考察：轨迹、工具选择、E2E

Agent 评轨迹、工具选择、多步 E2E 成功；单次 LLM 评文本质量。两者都要，业务以 E2E 为北星。

- 轨迹/工具选择/E2E 分层；golden 版本化；PR 冒烟+夜全量；线上回流。

#### ★ 136. prompt、模型、工具变更如何灰度、回滚，并用回归证明没有变差？

**高级/架构 · Agent 开发岗** · 考察：影子流量、金丝雀

配置/模型/工具版本化；影子或金丝雀对比。
- 一键回滚。指标含成功率成本与安全拒答。

提示词、模型、工具变更都走同一条：版本化、评测门禁、灰度、指标对照、一键回滚。Prompt 和工具的审批流不过回归，不能进生产。开源框架升级先锁版本，跑契约和黄金轨迹，行为变了先看变更说明和轨迹 diff。证明「变好了」用同一套门禁，不靠感觉。

#### 137. 什么是 golden trajectory？如何维护它不过时？

**中级 · Agent 开发岗** · 考察：版本化、定期重跑

#### 138. 如何评测工具选择准确率 vs 最终任务成功率？两者冲突怎么办？

- 与 Coding Agent 权限阶梯对齐：越低信任隔离越强。

#### ★ 171. 不可信代码用 Firecracker、gVisor 还是 Docker？

**高级/架构 · Agent 开发岗** · 考察：隔离强度、冷启动、运维成本

选型我按信任级：不可信用户代码、任意 shell、第三方 Skill → 倾向 Firecracker/微VM，隔离强、攻击面小，但冷启动、镜像分发、可观测要单独做。gVisor 是折中；纯 Docker 运维成本低，适合内部可信仓库+强网络策略。成本不只是性能：还要镜像供应链、快照、与 K8s 的设备插件、故障演练。很多大厂效能岗接受「预热池」换冷启动。面试加分：说明你会按 Skill 信任标签路由到不同沙箱池，而不是一刀切。
- 按信任级与威胁选 Firecracker/gVisor/Docker，不空谈「最强」。
- gVisor：用户态内核折中；Docker：运维熟但共享内核风险更高。
- 可分层：低信任微VM，内部可信任务容器池。

#### ★ 172. 沙箱里跑 npm/pip 安装时如何防供应链投毒与任意出站？

**中级 · Agent 开发岗** · 考察：镜像白名单、无网/代理、锁文件

沙箱里 npm/pip 最怕供应链：恶意 postinstall、偷环境变量、回连 C2。对策是：只允许私有镜像源/代理白名单、强制 lockfile、禁脚本生命周期或仅允许审计过的包集合。更好架构是构建与执行分离：依赖在受控流水线装好并哈希固化，运行时沙箱只挂只读依赖层，禁止再装包。确需动态装的，走审批+短时有网窗口+抓包审计。这和「动态注册 Skill」同一逻辑：热加载必须降信任。

- 安装依赖=供应链攻击面，必须锁版本+无网/代理白名单。
- 用 lockfile/私有源；禁运行时随意 curl|bash。
- 异常安装审计与哈希校验。

#### ★ 173. 如何给沙箱做「可观测但不泄密」：日志、文件系统快照、审计？

**高级/架构 · Agent 开发岗** · 考察：脱敏、只读挂载、审计事件

沙箱可观测我做成「安全审计事件」而非整盘 dump：记录镜像版本、命令、资源用量、出站域名、敏感路径访问、退出原因，并挂 conversation_id。文件系统快照只保留任务工作区 diff，屏蔽 .env、密钥、家目录；日志脱敏 token/身份证。值班可看摘要，明细走权限审批。目标是既能复盘「Agent 在沙箱干了啥」，又不把客户代码当日志喷出去。

- 可观测要事件化与脱敏，不做明文全盘镜像外传。

#### ★ 174. 沙箱池化：预热、TTL、脏容器回收与租户隔离怎么做？

**中级 · Agent 开发岗** · 考察：池、驱逐、租户分池

- 沙箱池用预热换延迟，用 TTL/脏标记防串租。
- 按镜像与信任级分池；租户级可硬隔离。
- 任务结束：杀进程、清可写层、可选销毁实例。
- 指标：冷启动、复用率、串租演练。

#### ★ 175. 业务方要求「能在沙箱里连生产只读库」，你如何评估与设闸门？

**中级 · 应用开发岗** · 考察：网络策略、凭证短时、审计

## Python 与后端

#### 196. GIL 在 AI 服务里到底限制什么？线程、进程、协程怎么选？

**中级 · 两边都考** · 考察：瓶颈在 CPU 还是 I/O

CPython 的 GIL 让同一进程里同一时刻只有一个线程执行 Python 字节码，所以纯 Python 的 CPU 计算用多线程扩不动。调用模型 API、检索、数据库这些等待网络的活，线程和协程都能并发。选型：网络 I/O 优先 `asyncio`；要吃满多核的分词、解析、本地向量计算用多进程或放到独立推理服务；只有阻塞 SDK 包不住时才用线程池，并且把池子和事件循环隔开。面试要能说出「Agent 的时间主要耗在等模型和等工具」，所以 loop 用异步，CPU 重活不要堵在事件循环里。

- **常见坑**：在 async 函数里直接调同步大请求，把整个 worker 卡住。
- **例子**：解析 PDF 丢进程池；HTTP 工具走异步客户端并设超时。

#### 197. asyncio 适合 Agent 的哪一段，不适合哪一段？

**初中级 · Agent 开发岗** · 考察：并发等待 vs 计算

适合：同时召回多路检索、并行无依赖的只读工具、SSE 推送、大量空闲连接。不适合：在协程里跑 CPU 密集解析、在协程里拿着锁做同步重试、用一个事件循环既跑在线对话又跑离线批处理。取消要传到尚未完成的 await，否则用户已经断开，下游工具还在写。

- **常见坑**：`asyncio.gather` 不处理部分失败，一个工具异常把整批结果丢掉。
- **对应**：并行汇合见 `第60题`；取消透传见 `第65题` `第65题`。

#### 198. 为什么 Agent 服务常用 FastAPI？它实际启动的是什么？

**初中级 · 两边都考** · 考察：ASGI、类型、流式

FastAPI 是 ASGI 应用，本身不监听端口，通常由 Uvicorn（或 Gunicorn 管 Uvicorn worker）启动。它和 Pydantic 一起，把工具入参、会话请求和结构化输出收成可校验的类型，并带出 OpenAPI。选它是因为异步和流式顺手，不是因为「AI 必须用 FastAPI」。Django 仍然适合已有 ORM、后台和管理端的业务平台；新写的模型网关和 Agent loop 更常放 FastAPI。两边都要能讲请求生命周期：进中间件、依赖注入、路由、响应流、客户端断开。

- **常见坑**：`--reload` 进生产；一个 worker 里混跑重计算。
- **对应**：Schema 同源见 `第307题` `第307题`。

#### 199. uv、conda、容器在 AI 工程里怎么分工？

**初中级 · 两边都考** · 考察：可复现，而不是工具站队

纯 Python 的 Agent / FastAPI 服务用 uv（或等价的锁文件）锁依赖，一个项目一个环境，进镜像交付。conda 适合本机要钉 CUDA、PyTorch、系统库的实验环境，不适合当生产交付物。生产以容器镜像为版本单元：解释器、系统库、Python 依赖一起冻住。镜像里不要在启动时现装包。多项目共享一个 conda 环境能省盘，但会把升级变成全局事故。

- **例子**：服务用 uv 锁 + 多阶段镜像；训练实验单独 conda，不和线上服务混用。

#### 201. 闭包、装饰器、生成器在 Agent 工程里实际用在哪？

**初中级 · 两边都考** · 考察：能对上代码，而不是背定义

闭包是内层函数持有外层变量。装饰器就是返回闭包的语法，用来加超时、重试、鉴权和审计，而不改工具函数本体。生成器/`yield` 一次产出一块，LangGraph 的 `stream()`、SSE 分块都是这个模型：调用方拉动，生产方不把整段结果堆进内存。迭代器只能向前，流断了不能靠同一个生成器重放，续传要靠事件 id，见 `第268题`。闭包的坑是捕获了大对象或循环变量，请求结束后还占着内存；不再使用就丢掉引用。

- **常见坑**：装饰器吞掉取消异常；生成器里做了写操作，消费者中途 break 后副作用已经发生。
- **例子**：工具装饰器统一记 trace；流式输出用生成器，取消时关闭上游。

#### 202. 遇到 Python/Django + AWS 的平台岗，优先准备哪几块？

**中级 · 应用开发岗** · 考察：平台重构，不是 Agent 名词

这类 JD 的标签常常是 Python、Django、GraphQL、Docker、AWS、微服务。职责是业务 API、平台重构、Python 升级、ECS 上的容器和 Lambda 事件任务。八块都要能点名，面试时间不够时按这个顺序讲深：

1. **Django 请求链**：WSGI/ASGI → 中间件 → URL → View → ORM。ORM 讲 `select_related` / `prefetch_related`、N+1、事务边界。
2. **graphene-django**：`DjangoObjectType` 靠类属性生成 Schema；Resolver 的 N+1、分页、权限和错误形状要单独讲，REST 那套缓存不能直接照搬。
3. **ECS 与 Lambda**：短事件、可接受冷启动用 Lambda；长连接、Agent loop、要稳定 CPU 的服务用 ECS/Fargate。不要把 15 分钟以上的任务塞进 Lambda。
4. **升级与兼容**：依赖和 C 扩展先扫目标 Python 版本；API 版本化、双写或灰度、容器切运行时、CI 多版本矩阵。回滚是切镜像，不是在机器上改解释器。

安全顺口补 CSRF、注入、`ALLOWED_HOSTS`、密钥进 Secrets Manager 而不是进镜像。Linux 侧能讲端口、日志、权限和容器里怎么看进程即可。

- **常见坑**：把 Agent 项目整段搬到这个岗；GraphQL 只讲「一个端点」，讲不出 N+1。
- **例子**：升级时先锁 ABI 和 C 扩展，金丝雀切镜像，指标不过就切回旧镜像。

#### 203. 团队主体是 Java 时，Python 和 Java 怎么分工？

**中级 · 两边都考** · 考察：接入层 vs 控制面

Python 放模型实验、解析、评测脚本和需要快速改的 Agent loop。Java 放已有的网关、权限、交易和审计，如果核心链路本来就是 Java。Spring AI、LangChain4j 解决的是「在 Java 里把模型、提示词、工具和结构化输出接整齐」，不代替运行时设计。Java 调模型要单独配超时、连接池和有界队列，检索池、工具池、回调池分开，避免一个慢模型占满业务线程。流式用 SSE 或 WebClient，半包不能当成完整工具参数去执行。分工按数据边界，不按「谁更 AI」。

- **常见坑**：为了统一语言把稳定交易链路重写成 Python；线程池照 CRUD 服务的参数搬过来。
- **对应**：多语言超时取消见 `第270题` `第65题`。

#### 204. 企业知识库问答 Agent 模块如何拆？

**初中级 · 应用开发岗** · 考察：切片、检索、引用、拒答

#### 205. 如何做需求评审：这个 Agent 值不值得做？

**中级 · 应用开发岗** · 考察：频次、容错、ROI

看调用频次、容错成本、人工替代成本与数据可工具化程度。ROI 算不清或零容错则先不做 Agent。

- 用频次×容错×ROI 评审；只读→写+人审迁移；Demo 防幻觉/慢/权限。
- **常见坑**：Demo 上帝权限、零容错场景强推全自动。
- **例子**：低频或零容错→先 Workflow/人工，不做全自动 Agent。

#### ★ 206. 套壳 Chat 怎么升级成可上线的 Agent？第一个月做什么？

**中级 · 应用开发岗** · 考察：先工具只读，再写操作

先接只读工具验证价值，再灰度写操作+人审，最后扩大自动范围。保留 Chat 兜底。

第一个月先补 trace、评测和鉴权，接一两个只读工具跑通，写操作全部人审，拿出基线成功率和成本。第二个月再开一条写路径。不要第一个月上 Multi-Agent。Chat 兜底留着。每周有能演示的增量，并写明不做清单。

共性（网关、观测、权限、评测）平台化；个性 prompt/知识/工具项目配置。避免每个事业部从零造运行时。

#### 212. Text-to-SQL 如何防止危险 SQL？白名单校验看什么？

**中级 · 应用开发岗** · 考察：只读、校验、行权

- **例子**：Text-to-SQL 只读+AST 仅 SELECT；改预算双人审+限额。

## Coding Agent 与框架

2026 年加分的是控制面和你改过的层，不是组件名单。

#### ★ 245. 自研 Runtime 和基于 LangGraph/Dify 的二次开发，怎么讲才不像只会调 API？

**高级/架构 · Agent 开发岗** · 考察：可控边界、二次开发深度

加分点是你改过哪一层、为什么改、怎么回归，不是框架名字。自研可控但贵。LangGraph 或 Dify 上手快，生产上通常要补 checkpoint 存储、人审中断、流式事件、工具 ACL、租户鉴权。能讲到模块边界、一次故障和一组指标，才能和「只调了 API」分开。

低代码适合节点固定、要运营修改、要审计留痕的流程。目标开放、要动态选工具的，进 Runtime，并带预算和人审。对老板就用「确定性还是开放性」这句话，避免全部拖进画布。

#### ★ 246. 改过 Claude Code/Codex 类 harness：你会突出哪些工程点？

**高级/架构 · Agent 开发岗** · 考察：超时取消恢复、权限、轨迹、评测

若改过类 Claude Code/Codex harness，我会突出：取消与超时如何穿透、权限阶梯、会话恢复、轨迹导出给评测、与企业 SSO/配额对接。用一次真实故障说明改造价值。这正是得物风格 JD 爱听的「Agent Loop/异常恢复」。

- harness 改造故事围绕控制面：超时取消恢复、权限、轨迹、评测。
- 举证：你加的钩子、故障、指标。

类 Cursor 的编码 Agent：工具以读文件、搜码、跑测试为主，执行在沙箱；产出 diff，经人或 CI 再应用；默认只读，写入受保护分支。权限阶梯是只读探索 → 提案补丁 → 受控应用；高危操作 HITL。评测看补丁可合并率、测试通过率与回滚率，而不只是「能生成代码」。MVP 先做只读汇总与建议，写文件放二期加确认卡。答到权限与资损，才像高级系统设计。工具以读文件、搜代码、跑测试为主，执行在沙箱里。产出 diff，经人或 CI 再进受保护分支。一期只做只读汇总和建议，写文件放二期，加确认卡。成功看补丁能否合并、测试是否通过、回滚率，不看「生成了多少代码」。内部平台同样先只读加沙箱测试，人审之后才写。

#### 288. 设计企业级「会议 → 待办 → 飞书任务」闭环 Agent。

**高级/架构 · 两边都考** · 考察：ASR、抽取、确认、写入

ASR→纪要抽取→待办确认卡→写飞书；失败可编辑。权限按日历与任务应用最小化。

- **例子**：MVP 只读汇总；写任务二期加确认卡。

#### 289. 设计可插拔「技能 Skill」系统：发现、权限、执行。

**高级/架构 · 两边都考** · 考察：类似插件+策略

Skill 清单发现、权限声明、沙箱执行、版本与卸载。类似插件+策略引擎。

#### ★ 290. 企业里的 MCP 如何落地：目录、鉴权、租户 ACL、安装和升级？

**高级/架构 · 两边都考** · 考察：目录、签名、租户授权、版本

私有 MCP 目录；签名与安全扫描；租户管理员安装授权；版本钉扎与灰度升级；运行时 ACL 与审计。
- 宿主=应用商店+运行时策略。
- 发现：内部 registry。
- 安装：审批流+scopes。
- 风险：供应链与越权。
- MVP：先内置少量官方 Server。

企业 MCP 是目录加运行时，不是把公网 Server 接进来。私有 Registry 解决签名、扫描、租户授权、版本冻结和紧急吊销。发现阶段只返回该用户能用的工具；调用时再用短时令牌核对租户、scope 和参数敏感级。Server 不持有长期管理员密钥。升级钉住版本，先灰度再全量。先做几个官方 Server，再开放安装。

#### 291. 设计「客服+售后+物流」统一意图路由的超级助理（分期）。

**高级/架构 · 应用开发岗** · 考察：意图路由、专家 Agent、共享记忆

统一入口意图路由到专家；共享订单上下文；写操作分域人审。分期：先路由+只读，再各域写。

- 一期：意图+只读查询。
- 二期：售后写限权。
- 共享：订单画像服务。
- 风险：路由错误导致错域操作——要确认卡。

#### ★ 292. 设计电商内部「Agent LLM Gateway + 多渠道 Bot」一期架构。

**高级/架构 · 两边都考** · 考察：网关、适配、沙箱只读、HITL

电商内部一期架构：统一 LLM Gateway（路由计量）、多渠道 adapter、Agent Harness 只读工具+确认写、基础沙箱、trace 与小评测集。二期再沙箱升级与 Skill 市场。明确非目标防止范围膨胀。

- 非目标：全自动写、Multi-Agent、任意 MCP。
- 沙箱先容器，微VM 可二期。
- 指标：介入率、成功率、成本。

## 通用工程

这些题跨岗位都会问，把机制和副作用讲具体。

#### ★ 293. 简历和口述里，一个 Agent 项目至少要讲清哪几件事？

**高级/架构 · 两边都考** · 考察：STAR+数字

讲项目用 STAR：目标与用户、架构怎么拆、上线看哪些数字、最大坑、复盘改了哪一刀，并准备一段可深挖的轨迹故事。指标至少有任务成功率、人工介入率或单位成本之一，且口径清晰。外发、改价、删除必须 HITL，不能靠 temperature=0 假装确定。能落到一次具体工具失败或注入案例，比停在架构名词更有 30k+ 说服力。简历五要素：场景、架构、指标、风险防控、你负责的部分。口述用 STAR：目标、怎么拆、上线看哪个数、最大的坑、复盘改了哪一刀。能落到一次具体的工具失败，比停在架构名词上有用。

#### 294. 3 个月从 0 搭团队 Agent 能力，里程碑？

**高级/架构 · 两边都考** · 考察：落地节奏

月1：只读工具+观测评测；月2：一两个写路径+人审。月3：灰度成本优化与平台化。每周可演示增量。

#### ★ 295. 哪些动作必须人确认？客服里查单、退款、改地址怎么落确认点？

**中级 · 两边都考** · 考察：外发、资损、删除

外发消息、支付/改价、删除/权限变更、不可逆生产操作必须人确认。只读可自动。

外发、支付、改价、删除、改权限、不可逆的生产操作必须人确认。只读可以自动。客服里查单自动，退款和改地址展示影响后再确认，超额转人工。确认要有幂等键，例如订单、动作和请求号。写路径没有确认点，就不要上。

#### 296. 流式中途报错，前后端怎么处理？

**初中级 · 两边都考** · 考察：半截、重试

后端发 error 事件并结束流；前端保留半截并标记失败，支持续写/重试。勿静默吞错。

#### 297. 失败会话如何记录回放？

**中级 · 两边都考** · 考察：脱敏、mock

脱敏存轨迹；可 mock 工具重放。关联 trace。用于复盘与回归，严格访问控制。

#### 298. 如何看待自主 Agent 炒作？生产底线？

**高级/架构 · 两边都考** · 考察：风险观

炒作不等于可生产；底线是权限、可中断、可观测、人审关键写。自主程度与风险成正比。

#### 299. 评测里 pass@k、成功率、含时延的综合分怎么设计？

**中级 · 两边都考** · 考察：业务加权

pass@k 看多次尝试；成功率业务定义。综合分加权成功并惩罚超时超费。权重产品定。

#### 300. 你如何做技术选型答辩：自研 vs 买厂商 Agent 平台？

**高级/架构 · 两边都考** · 考察：总成本、锁定、差异化

比 TCO、锁定、差异化与合规；能买加速的买，核心权限与数据面慎交。给退出策略。

#### 301. 上下文「丢包」导致工具参数缺字段，如何工程预防？

**中级 · 两边都考** · 考察：服务端补全、校验重问

服务端 schema 校验；缺字段可补默认或追问。

- 截断检测。勿把残缺 JSON 直接执行。

#### 302. 设计面试：为公司内部做 Copilot，画架构并讲风险。

**高级/架构 · 两边都考** · 考察：权限、数据、评测、成本

画入口-网关-编排-检索-工具-权限-评测-观测；风险讲数据外泄、越权、成本爆炸。给 MVP 边界。

#### 303. 开源框架升级导致行为变化，如何回归？

**中级 · 两边都考** · 考察：锁定版本、契约测

锁定版本；契约与黄金集回归。金丝雀。行为变先看 changelog 与 diff 轨迹。

#### 304. 团队只有你懂 Agent，如何降低单点风险？

**高级/架构 · 两边都考** · 考察：文档、演练、结对

文档化运行手册、结对、值班演练、录屏课。把关键决策写进 ADR，降低单点。

#### 305. 什么是 guardrails？放在输入侧、工具侧还是输出侧更合适？

**中级 · 两边都考** · 考察：分层防护、不能只靠输出过滤

应分层：输入注入检测、工具前鉴权、输出 DLP/拒答。只做输出过滤挡不住副作用已发生。guardrails 是多层，不是一个正则。

- 输入：越狱/注入分类。
- 工具前：ACL 与参数消毒。
- 输出：泄密与违规。
- 坑：副作用发生后才过滤文案。

#### 306. 如何向非技术高管解释「Agent 不确定性」并拿到合理预算？

**高级/架构 · 两边都考** · 考察：风险预算、区间、对照人工

用成功率区间与人工对照；把不确定性转成风险预算与兜底成本。要预算就给指标与止损线。

- 对照：人工差错率也不是零。
- 预算：评测+人审+观测是必要成本。
- 止损：低于阈值回滚。
- 坑：用「AI 很强」忽悠预算。

#### ★ 307. JSON Schema、Zod、Pydantic 如何保证工具契约一致？校验失败怎样有限重试？

**初中级 · 两边都考** · 考察：契约源、运行时校验

JSON Schema 常作跨语言契约源；Zod 护 TS 边界；Pydantic 护 Python 执行层。三者应对齐。
- 分层校验，契约单一来源。
- 生成：schema→两端模型。
- 运行：拒非法 args。
- 坑：只在前端校验。三份从同一份 Schema 生成，CI 里做 diff。

类型上用可辨识联合把 tool call 和 tool result 分开，靠 type 收窄。校验失败把错误结构化写回观察，缺字段可以重试有限次数，无权限直接停。只在前端校验等于没有校验。

#### 308. 当业务坚持「全自动」时，你如何谈风险接受（risk acceptance）？

**高级/架构 · 两边都考** · 考察：书面风险、限额、监控

书面列失败模式与限额；要求监控与熔断；超限自动降级人审。把 risk acceptance 留痕。

- 全自动=明确接受残余风险。
- 材料：失败模式×影响×缓解×残余。
- 工程：限额与熔断仍要做。
- 坑：口头「没事」无文档。

#### 309. Agent 中的「确定性闸门」（deterministic gate）指什么？举例。

**中级 · 两边都考** · 考察：规则校验拦截模型输出

模型输出后由规则/程序做硬校验，不通过则拒或重试。例：SQL AST、金额上限、正则工单号。

- 闸门=模型后的硬法则。
- 例：退款≤订单可退余额。
- 与 FC 配合：先 FC 再闸门。
- 坑：闸门过严误杀要可观测。

#### 310. 如何做 Prompt 注入的红队演练节奏（频率、范围、修复 SLA）？

**中级 · 两边都考** · 考察：定期红队、分级修复

月度红队+发版必跑核心集；P0 注入当日修；结果进对抗集。范围含间接注入。红队要节奏化进工程。范围：用户、检索、邮件、MCP。SLA：P0 阻断发布。

- 坑：只测中文直注不测英文/编码绕过。

#### 311. 什么是 tool-former / 模型原生工具调用与外部编排的差异？

**初中级 · 两边都考** · 考察：模型内建 vs 应用层 loop

原生 FC 由模型直接出调用；外部编排可强加状态机与策略。生产多用模型 FC + 应用层强约束。

- 能力在模型，责任在编排。
- 原生：协议简单。
- 编排：权限步数预算。
- 坑：以为有 FC 就不需要运行时。

#### 312. 解释「评测集污染」：如何发生，如何防？

**中级 · 两边都考** · 考察：训练/提示泄漏、过拟合用例

把测试题写进 Prompt/微调/长期记忆会导致虚高；隔离评测数据，定期换血与盲集。

- 污染会制造虚假安全感。
- 发生：few-shot 含测试题、日志回流未隔离。
- 防：盲集权限；用例哈希监测泄漏。
- 坑：用线上热问当唯一评测。

## 协作、排障与行为

行为题用场景、动作、结果，并带一个能核对的数字。

#### 313. 算法要再调 prompt、产品催上线，你怎么推？

**中级 · 应用开发岗** · 考察：基线、门禁、灰度

冻基线指标；改动过门禁再灰度。产品要上线就砍范围而非跳评测。用数据对齐。

- 冻基线过门禁；砍范围不跳评测；给区间+兜底；评审含回滚。
- **例子**：书面约定：只读上线，写路径保持人审。

#### 314. 向老板解释无法 100% 稳定的口径？

**高级/架构 · 应用开发岗** · 考察：区间、兜底、评测

给成功率区间与兜底（人审/拒答）；展示评测与线上对照。

- 谈风险预算而非「绝对稳定」。
- **常见坑**：跳评测上线、向老板打包票 100%。

#### 315. 如何写 Agent 项目的技术评审材料让架构组过？

**高级/架构 · 应用开发岗** · 考察：风险、指标、回滚

写清目标指标、架构图、风险（幻觉/资损/合规）、评测与回滚。给里程碑与不做清单，方便架构组拍板。

#### 316. 产品要「更像真人客服」，算法要「更短更省」，你如何定体验指标？

**中级 · 应用开发岗** · 考察：任务成功、轮次、CSAT、成本联合

联合看板：完成率、平均轮次、CSAT、成本；设帕累托边界。文风优化不得掉完成率与安全。

- 用联合指标代替口味之争。
- 过冗长可加「简洁模式」用户可选。
- 坑：唯 CSAT 导致胡乱讨好承诺。

#### 317. 答非所问，15 分钟如何定位？

**中级 · 应用开发岗** · 考察：意图、检索、工具、生成

15 分钟：看意图路由→检索命中→是否调错工具→生成是否无视证据。对应用例日志定位。

- **常见坑**：只看最终回复不看轨迹。

#### 318. 只会「嗯嗯你好」不调工具，可能原因？

**中级 · 应用开发岗** · 考察：tool schema、prompt、模型

查 tools 是否下发、描述/枚举、模型是否支持 FC、prompt 是否禁止瞎聊、temperature。看原始响应有无 tool_calls。

#### 319. 引用张冠李戴怎么查？

**中级 · 应用开发岗** · 考察：检索片段、生成对齐

对检索 top 与生成引用 id；查是否张冠李戴或编造。强制 quote 对齐与单测。

#### 320. 同一 Prompt 在预发正常、生产偶发不调工具，如何系统性排查？

**高级/架构 · 应用开发岗** · 考察：配置漂移、流量差异、模型版本

对配置版本/模型 id/工具列表做 diff；比流量特征；查限流降级与超时。用同 request_id 级回放。先假设漂移与降级，再怀疑「模型心情」。

- 核对：tools 是否被特性开关摘掉。
- 超时：生产工具慢导致取消后模型改口。
- 录一包可复现流量。
- 坑：预发用强模型生产用小模型未声明。

#### 321. 讲一次你推动模糊需求落地的经历。

**中级 · 两边都考** · 考察：对齐指标

面对模糊需求，我先把它收成可测指标与非目标，拆 MVP，推动负责人拍板范围，再迭代上线。结果用数字和时间线说话，例如人工介入率从 x% 降到 y%、MTTR 到 z 分钟，并说清我具体推动的对齐会、评测或灰度。分歧用小流量数据或评测仲裁，而不是纯争论体验偏好——这体现落地与协作。

#### 322. 讲一次线上故障：发现、止损、复盘。

**中级 · 两边都考** · 考察：带时间线

时间线：发现告警→止损开关/回滚→影响面→根因→复盘动作。强调可观测与预案。

- **常见坑**：无数字无时间线。

#### 323. 和算法同学意见冲突怎么处理？

**高级/架构 · 两边都考** · 考察：用评测说话

拉评测集对照双方方案；小流量验证。对事不对人，用指标收敛争论。

- 时间线+数字；冲突用评测；30k+ 对标带宽与闭环交付。

#### 326. 讲一次你用数据说服业务推迟「全自动写操作」的经历。

#### 327. 跨团队（平台/业务/安全）推进 Agent 上线，你如何排优先级冲突？

**高级/架构 · 两边都考** · 考察：风险排序、里程碑、透明

#### 328. 学习 Agent 的路径你会怎么向面试官展示（30 秒）？

#### 333. 业务方要求「必须 100% 引用知识库」，技术上如何逼近？

#### ★ 334. 如果只能看一个指标判断 Agent 健康，你看哪个？

**高级/架构 · 两边都考** · 考察：任务成功或人工介入率

如果只能看一个指标，我看定义清晰的任务成功率；若成功难标，就看人工介入率（同一口径）。再辅看单位成本与安全拒答率，防止只优化一个数。口径必须稳定、可按租户/场景切片，并配人工抽检，避免刷指标。上海 30k+ 面试很吃你能不能把指标定义讲死。一周救急可以先砍到只读+人审，把介入率打下来，再逐步放开自动写。

#### 337. 模型厂商降价后，你会立刻全量切模型吗？要看哪些门禁？

**中级 · Agent 开发岗** · 考察：兼容性评测、工具成功率、成本质量

#### 338. 业务要「对标某某产品全能助理」，你如何拆解需求打回现实？

#### 339. 如果评测很好但客服组长反馈「不好用」，你怎么处理？

**中级 · 两边都考** · 考察：体验研究、分布、指标校准

先听现场：抽会话共创标签；查评测分布是否偏离真实；补体验指标（轮次、改写次数）。校准集。现场反馈是分布问题信号。方法：跟班听音+标注。可能：评测偏易、话术不合规、系统慢。

- 输出：修订北星或补集。

#### 340. 公司要自研「类 MCP 协议」，你支持还是反对？论点？

**高级/架构 · Agent 开发岗** · 考察：标准红利、锁定、成本

优先跟进开放标准获生态；自研仅当强合规/差异化且有退出适配层。反对无必要的协议分裂。协议分裂成本极高。支持自研的条件：监管强制或核心壁垒。要有适配器对接 MCP。

#### ★ 341. 若只能准备一周上海 Agent 面试，你的刷题与项目复盘优先级？

**高级/架构 · 两边都考** · 考察：深挖项目、RAG、Runtime、安全

一周备战上海 Agent 岗，我不求刷完题库，而按 JD 信号排序：先深挖项目 STAR（架构、指标、事故），再专项 Runtime 终止/恢复、RAG 掉点、权限与 HITL、全栈 SSE/契约，最后评测闭环与成本治理。每天留口述录音；编码只练最小 ReAct loop 与 Schema 校验。目标是面试官能往下挖三层。投递主攻应用开发/平台偏应用侧，少分心纯训练岗。

- 一周策略体现元认知；优先深挖而非刷完所有题。

#### ★ 346. 从 90 秒自我介绍到终面 3 分钟，怎么证明你做的是 Agent 而不是调包？

**高级/架构 · 两边都考** · 考察：闭环叙事、指标、方向

自我介绍是投递话术核心；全栈要翻译成 Agent 工程语言。rehearsed 90 秒，可打断深挖。

90 秒：你做什么场景、架构落在 Gateway、Harness、评测哪几层、一个指标、一个你负责的模块。60 秒如果被问 JD，就按 Runtime、工具、记忆、RAG、评测、人审、部署各挂一条证据，薪资只说公开带宽。

简历和口述用三个能核对的证据：上线完成率或介入率、一次资损防控、TypeScript 加 Python 的交付物。终面 3 分钟拆成 Gateway、Harness、评测，各讲一个决策或事故，并声明不做无门禁的自动写。

得物一类 JD 的故事顺序是：loop 的终止和恢复、沙箱、多渠道去重、框架改过的点、评测闭环。每段一个数字。
