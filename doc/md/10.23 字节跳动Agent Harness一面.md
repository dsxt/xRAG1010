# 10.23 字节跳动Agent Harness一面

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 面试感受

整体偏工程落地，不整虚的。Harness 不是背概念，得真懂运行时、状态、工具、沙箱那一套。问法很字节，一个知识点追到你能不能扛住生产问题。算法不难但讲究边界，别飘，把容错和可观测性讲明白就很加分。

## 一面

### 1. 自我介绍

**答题思路**

一两分钟，按「你做哪一段 → 一个能讲透的项目 → 和 Harness 岗位的关系」讲完就停。

1. 先说你实际负责的环节，例如编排、工具执行、状态恢复、检索或评测。年限用你自己的，不报职级。
2. 只留一个你能讲透的项目，点出用户要完成的事，以及你负责的那段链路。没有把握的数据不说。
3. 最后一句落到运行时：失败后从哪一步接着做，工具权限和超时放在哪里。讲完停住，把项目细节留给下一问。

### 2. 项目介绍，重点讲里面 Agent 相关的落地

**答题思路**

选一个你真正做过、而且接到过真实使用或真实评测的项目。围绕落地讲，模型调用只是其中一步。

1. 先说业务动作：谁在用，输入是什么，Agent 最后交付的结果落在哪里，这个结果能不能在业务状态里查到。
2. 再讲运行时怎么接上业务：哪些步骤由模型选择，哪些工具是你接的，状态存在哪里，进程挂了从哪一步恢复。
3. 重点放你负责的取舍，例如上下文怎么控、工具失败怎么停、怎样确认结果已经生效。别人负责的部分只说边界。
4. 效果只讲你能复述口径的部分。没有现成数字，就讲坏例怎么被发现、怎么进入回归。
5. 讲完停。对方追问循环、记忆或评测时再展开。

### 3. 你怎么理解 Agent Harness，和直接用大模型 API 有什么区别

**参考答案**

Agent Harness 是包住模型的运行时。直接调大模型 API，只是这个运行时里的一次推理。

API 按消息返回文本或结构化 tool call，这次请求结束就没有任务状态。工具有没有真正执行、做到哪一步、失败后从哪继续，都在调用方。

Harness 按检查点组装上下文，调用模型，校验参数，在沙箱里执行工具，把观察写回，再决定继续还是停止。权限、超时、幂等、取消和轨迹都在运行时。模型可以提议结束，步数、时间和取消由运行时强制执行。沙箱限制这次执行能碰的文件、网络和资源。

换模型时替换适配层。循环、工具协议、状态机和沙箱策略保持不动。提示词约束不了已经发出的写请求，也代替不了检查点。

### 4. Agent Loop 的核心流程怎么设计，什么时候停、怎么防死循环

**参考答案**

循环的一步是：读检查点，组装上下文，调用模型，解析输出。有工具调用就先校验再执行，把观察写回并落检查点，然后进入下一步。模型只提议下一步。同一轮里只要有 tool call，就先执行，伴随的正文先不当成最终答案。

停止看两类信号。模型给出无工具调用的最终回答，或调用约定好的完成工具，可以结束。步数、token、墙钟时间和费用到顶，用户取消，人工确认被拒绝，或工具进入不可恢复错误，由运行时停止。

防死循环要识别没有进展，最大步数只是最后一道闸。对「工具名 + 规范化参数 + 错误码」做指纹，同一指纹连续失败就停止或改策略。观察在变的轮询单独给次数，避免把合法轮询当成死循环。最近几步在两个调用之间来回振荡，同样停止。并行工具调用全部返回后，再进入下一轮模型请求。

单次工具超时、单步和整次任务各有预算。重试退避必须落在剩余时间里。

### 5. Harness 里状态怎么管理，短期上下文和长期记忆怎么分层

**参考答案**

状态分三层，职责不同。

短期上下文是这一轮还要用的消息、最近的工具观察和草稿，放在窗口里。任务状态是目标、计划、步骤游标、待确认动作和产物引用。窗口和任务状态一起按任务 ID 落成检查点，恢复时以这份检查点为准。

长期记忆跨任务。稳定偏好放结构化档案；需要按语义找回的事实才做检索。写入时从轨迹里抽候选，去重并处理冲突，带来源和时间，允许用户删除。读取时按当前目标取少量条目。工具输出先当不可信数据，经过校验再进入记忆。当前用户指令和安全策略优先于旧记忆。

业务真相在外部系统。记得查过订单，下一步仍要再读订单状态。检查点里的工具步骤分两段写：调用前记下步骤和幂等键，成功后再写成完成。恢复时看到回执就跳过；只有意向、没有回执，就先按幂等键查询。体积大的工具结果在上下文里留摘要和引用，原文放对象存储。

### 6. 上下文超长怎么压缩，滑动窗口和摘要各适合什么场景

**参考答案**

超长时用「钉住关键块 + 滑动窗口 + 结构化摘要」。系统提示、当前目标、未解决的报错钉住，不跟着滑出。

滑动窗口丢掉最老的原文，保留最近若干轮。适合相关性就在最近几步的对话、客服多轮和短工具链。它不改写旧内容，所以不会把历史编错。早期约束、已经读过的文件和关键 ID 会一起滑出，这些不能只靠窗口。

摘要适合步骤多的长任务，例如多文件修改和要保留早期决定的调研。token 过阈值时，把中间轨迹压成目标、约束、决定、完成步骤、产物引用和未关闭错误。最近几轮工具原文留下。ID、路径和数字放在结构化字段里，摘要散文只作索引。精确报错、代码和未完成的 diff 留原文。

大段日志先截断或改成引用，再做对话级压缩。摘要是一次额外的模型调用；失败时退回滑动窗口，主循环继续。前缀若被摘要改写，提供商的前缀缓存会失效，下一步要重新计算整段上下文。

### 7. 工具调用失败、超时、参数非法怎么容错和重试

**参考答案**

先分类，再决定是运行时重试，还是把错误交回模型改参数。两类预算分开，避免一次参数错误把传输重试也打满。

参数非法在发出请求前用 schema 拦住。字段级错误作为观察返回，让模型在有限次数内修正。同一组参数连续不合法就停止。鉴权失败、资源不存在和业务拒绝同样不重试。

超时表示结果不确定。读请求在剩余预算内退避重试，并加抖动。写请求的幂等键由任务、步骤、工具名和规范化参数组成，同一次逻辑调用的各次尝试共用这一把，不把尝试次数编进去。下游按这把键保存受理结果时，超时后先查询，确认没有受理再提交。下游做不到这件事的写工具，超时后标为结果未知，交给人对账。连接失败、429、明确可重试的 5xx 才重试，并遵守 Retry-After；等待时间超过剩余预算就结束这一步。

调用、步骤和整次任务各有重试上限，退避时间放进任务剩余时限。某个下游错误率过高就熔断。返回给模型的错误带稳定错误码和是否可重试，密钥和内部堆栈留在轨迹里。

### 8. LLM 返回的 tool call 格式不合法怎么处理

**参考答案**

校验通过之前不执行。能用提供商的结构化 tool call，就用那个通道，少靠模型在正文里手写 JSON。

不合法常见有四类：参数不是合法 JSON，必填缺失或类型不对，工具名不在本轮下发名单里，输出被最大长度截断。截断可以从结束原因和括号不配对看出来。这种调用整段丢弃，提高输出上限或要求重新发起。半截 JSON 不补全、不执行。

格式问题可以有限次交回模型：把校验错误喂回去，让它重新给出完整调用。程序不补全残缺 JSON，也不猜测业务参数。未知工具名直接拒绝，不做模糊匹配。

并行的一批先全部校验。有一条不合法，整批都不执行，把每条的校验结果交回模型。修复次数用完仍不合法，就结束这一步并留下轨迹。

### 9. ReAct 和 Plan-Execute 的区别，分别适合什么任务

**参考答案**

ReAct 是一步一观察：每一步根据上一次工具结果决定下一个动作。Plan-and-Execute 是先给出计划，再按步执行，遇到失败或观察和假设矛盾时再重规划。

ReAct 适合环境还不清楚、下一步依赖观察的任务，例如排查故障和多轮检索。方向可以随时改。代价是模型调用次数多，费用和时间都不稳定，也容易在相似工具之间打转。

Plan-and-Execute 适合步骤大体能拆开的任务，例如按清单改多处、生成一份有固定结构的报告。计划可以先给人确认，执行阶段也可以换更小的模型。计划是在看到观察之前定的，环境一变就会僵，所以失败、假设被推翻、剩余预算不够，都要触发重规划。

长任务常用粗粒度计划和步骤内的 ReAct。计划是可修订的中间状态，要进检查点。一次生成的步骤列表直接跑完，只是一条脚本。

### 10. 多工具很多时怎么选工具，Skill 和 MCP 的边界是什么

**参考答案**

工具多的时候，每轮只给模型少量候选 schema。先按业务域和风险把工具归到目录，再用工具卡片做检索。卡片写清用途、不该用的情况、关键参数和有没有副作用。置信度低就追问。执行前再对一遍本轮名单和 schema，名单外的工具不能调用。描述过于相近时，检索会把它们一起送进模型，这是选错工具的主要来源。

Skill 和 MCP 不在一层。Skill 是操作规程：什么场景启用、按什么步骤做、允许用哪些工具、做到什么算完成。它可以把一批工具收成一个按需加载的能力，模型先看到目录，选中后再展开具体说明。MCP 是连接外部系统的协议：发现工具和资源，按 schema 调用，带回结果，并处理传输和鉴权。

一个 Skill 可以规定怎么组合多个 MCP 工具。循环、记忆、停止条件和权限在 Harness。MCP 服务器提供的提示模板，代替不了 Skill 里的任务规程。

### 11. RAG 链路怎么设计，切分、召回、重排、兜底怎么做的

**参考答案**

链路按入库、召回、重排、生成、兜底拆开，每一段都能单独查。

入库保留标题结构，以及来源、版本、权限和更新时间。切分按章节和自然段，让一块还能表达一个主题；切断的句子用重叠保住。更稳的是小块入库、命中后回取所在段落。表格和代码单独成块，避免和正文黏在一起。

召回用向量加关键词。租户、权限和时间放进检索条件。先取出一批候选，再用交叉编码器重排，然后去重、按文档顺序拼进上下文，并带上可引用的来源。

要求有据的回答要能对上来源。重排分数过低或引用对不上，就说明没查到，或追问一句，或改写查询再试一次。允许常识补充时，把补充和引用分开标。分数阈值用评测集调。文档更新要让旧版本失效。权限过滤若留到生成之后，检索结果里已经带出了不该看的内容。

### 12. Agent 效果怎么评测，bad case 怎么定位和回流

**参考答案**

评测同时看终态和轨迹。终态是任务有没有达到可检查的结果；轨迹是工具选得对不对、参数对不对、有没有多余副作用。只看最终一句话，会把「工具调用错了但答案碰巧对」算成通过。

离线集用黄金任务加上线坏例，工具能回放就按保存的轨迹回放。指标分开：任务成功率、工具选择、参数正确性、步数、费用和延迟。开放式质量用写好的规则打分，并抽检人工结论。评分模型的分数不能代替轨迹上的硬条件。

定位时把模型输入输出、工具名、参数、耗时、错误码和检索片段放在同一条 trace 上。和同类成功轨迹比，看失败停在召回、选工具、填参、下游故障、上下文被截断，还是计划跑偏。再按模型版本、Skill 版本和工具版本切片。

回流时先把坏例和 trace id 放进回归集，再改对应的层：契约问题改工具，检索问题改切分或重排，稳定的规程问题改 Skill。提示词、Skill 和模型变更都过这套回归。

### 13. 长任务从 5 分钟变 20 分钟，怎么排查延迟

**参考答案**

先划定范围：某一类任务还是全部任务，从哪次发布开始，变慢的是中位数还是尾部。然后取变慢前后各一条完整轨迹，按阶段对墙钟时间。

拆成循环步数、每步模型耗时、工具耗时、排队和重试退避。步数变多，常见是检索没命中后反复搜索，或同一错误在空转。每步模型变慢，先看输入 token 是否随步数上涨。前缀缓存命中时，旧 token 不用重算；摘要或插入内容把前缀改掉，缓存失效，每一步都会重新预填整段上下文，总时间会比步数涨得更快。

工具变慢就看下游、沙箱启动和连接池等待。重试会把时间乘上去：一次超时加上退避，多步叠起来就能从几分钟拖到十几分钟。要看错误率、重试次数和单次超时，平均值会把重试风暴抹平。

对照发布记录里的模型、提示词、工具 schema、召回条数和超时。一次只改一个变量复现。排队和限流单独打点，避免算进模型耗时。

### 14. 用户中途取消任务、版本热更新时正在跑的 Agent 怎么处理

**参考答案**

取消是步骤边界上的协作式停止。任务从运行中条件更新为取消中；已经成功的任务保持成功。循环在下次调模型或调工具前检查这个标志。正在进行的读请求可以中止。写请求已经发出，就等结果或按幂等键核对，再把任务标为已取消，留下最后完成的步骤和已有产物。已经成功的写操作保留；需要撤销时走单独的补偿，取消本身不隐式回滚。随后释放沙箱和锁。锁要有租约，取消过程中崩溃也不会一直占着。

热更新不替换正在跑的那次执行。任务开始时钉住 Harness、提示词、工具 schema、Skill 和模型版本。旧实例把已接的任务跑完，新任务进新实例。紧急开关每步读取，用来阻止新的工具调用；这和中途更换 schema 是两件事。

检查点格式不兼容时，在新代码上硬恢复会读错步骤。让旧版本跑完，或做明确迁移。滚动发布时先停止接新任务，在步骤边界写出检查点再退出。

### 15. 手撕算法：实现一个带过期时间的 LRU Cache

**参考答案**

用哈希表做查找，双向链表维护使用顺序，最近使用的放在表头一侧。每个条目记录单调时钟上的到期时间。访问和写入时若已到期，就删除并视为未命中。只做这种懒删除时，没人再访问的过期键会占满容量，活数据会被提前淘汰。所以再用一个按到期时间排序的最小堆，在 get 和 put 时清掉已到期的堆顶。更新 TTL 会留下旧的堆记录，弹出时用到期时间对账，对不上就丢掉。

`get` 先清理到期项，未命中返回空，命中则移到表头。`put` 的 TTL 不大于 0 视为删除；否则更新或插入，同时刷新到期时间和链表位置，容量超出时从链表尾部淘汰。淘汰前先清到期项。

链表操作是 O(1)。每次堆操作是 O(log n)，get 和 put 摊还 O(log n)。空间是 O(capacity)，再加上尚未对账的旧堆项；堆过大时按当前活条目重建。更新键要同时刷新 LRU 和 TTL。用单调时钟，避免机器校时把缓存整体提前或延后过期。未命中和过期都返回 `None`，这样合法取值可以是 `-1`。下面的实现不是线程安全的，并发访问要在外层加锁。

```python
import heapq
import time


class _Node:
    def __init__(self, key, value, expire_at: float):
        self.key = key
        self.value = value
        self.expire_at = expire_at
        self.prev = None
        self.next = None


class LRUCache:
    def __init__(self, capacity: int):
        if capacity <= 0:
            raise ValueError("capacity must be positive")
        self.capacity = capacity
        self.map: dict = {}
        self.head = _Node(None, None, 0.0)
        self.tail = _Node(None, None, 0.0)
        self.head.next = self.tail
        self.tail.prev = self.head
        self._heap: list[tuple[float, int, object]] = []
        self._seq = 0

    def get(self, key):
        self._purge_expired()
        node = self.map.get(key)
        if node is None:
            return None
        self._unlink(node)
        self._push_mru(node)
        return node.value

    def put(self, key, value, ttl: float) -> None:
        if ttl <= 0:
            self._purge_expired()
            node = self.map.pop(key, None)
            if node is not None:
                self._unlink(node)
            return
        self._purge_expired()
        expire_at = time.monotonic() + ttl
        node = self.map.get(key)
        if node is None:
            node = _Node(key, value, expire_at)
            self.map[key] = node
        else:
            node.value = value
            node.expire_at = expire_at
            self._unlink(node)
        self._push_mru(node)
        self._seq += 1
        heapq.heappush(self._heap, (expire_at, self._seq, key))
        while len(self.map) > self.capacity:
            self._evict_lru()
        if len(self._heap) > self.capacity * 2:
            self._rebuild_heap()

    def _purge_expired(self) -> None:
        now = time.monotonic()
        while self._heap and self._heap[0][0] <= now:
            expire_at, _, key = heapq.heappop(self._heap)
            node = self.map.get(key)
            if node is None or node.expire_at != expire_at:
                continue
            self._unlink(node)
            del self.map[key]

    def _evict_lru(self) -> None:
        node = self.tail.prev
        if node is self.head:
            return
        self._unlink(node)
        del self.map[node.key]

    def _rebuild_heap(self) -> None:
        self._heap = [
            (node.expire_at, i, node.key)
            for i, node in enumerate(self.map.values())
        ]
        self._seq = len(self._heap)
        heapq.heapify(self._heap)

    def _unlink(self, node: _Node) -> None:
        node.prev.next = node.next
        node.next.prev = node.prev

    def _push_mru(self, node: _Node) -> None:
        node.prev = self.head
        node.next = self.head.next
        self.head.next.prev = node
        self.head.next = node
```
