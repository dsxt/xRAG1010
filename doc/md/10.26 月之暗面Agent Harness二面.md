# 10.26 月之暗面Agent Harness二面

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 面试感受

二面不像一面那样问你“知不知道”，是盯着你简历里 Agent 那一段往工程缝里捅。上下文压缩、checkpoint、并发改文件、死循环防护，全是生产环境真坑，答表面方案直接被追三层。面试官不装，懂就懂，不会就别绕。整体偏硬核，但聊透了挺爽，能感觉到团队是真在跑长任务 Agent，不是玩具 demo。

## 二面

### 1. 自我介绍

**答题思路**

一两分钟，按「你负责哪一段 → 一个项目 → 和 Harness 岗位的关系」讲完就停。

1. 先说你在 Agent 系统里实际负责的部分，例如编排、工具执行、上下文或评测。年限按真实情况说，不报职级。
2. 只留一个你能讲透的项目：用户要完成的事、你负责的链路、你怎样确认它已经做完。没有把握的数字不说，改讲终态或坏例。
3. 最后一句落到运行时：上下文超限怎么处理，工具失败或进程重启后从哪一步接着做。讲完停住，把全链路留给下一问。

### 2. 挑一个你最熟的 Agent 项目，讲清楚从用户输入到最终输出的全链路，每一环的输入输出是什么

**答题思路**

用同一次真实请求走完，每一环只报输入和输出。项目用你自己的，名称和规模都按事实。

1. 入口。输入是用户原话或上游事件。输出是规范化请求：任务 id、身份、权限范围、原始目标。
2. 上下文。输入是系统提示、工具定义、历史、检索片段和这份请求。输出是这一轮真正送进模型的消息，顺口说明超长时留下了什么。
3. 模型。输入是这批消息。输出要么是给用户的结论，要么是工具名加参数。有循环就指出执行完会回到这里。
4. 执行。输入是这次 tool_call。输出是结构化观察：成功结果、错误，或需要人确认。校验和沙箱点到即可。
5. 收束。输入是写回后的上下文。输出是最终结论，轨迹里留着依据和终止原因。
6. 标明哪几环是你做的。追问某一环时，能说出字段和失败后交给谁。

### 3. Harness 里 agent loop 怎么设计，终止条件除了 max_turns 还控哪些（token / 耗时 / 预算 / 重复动作）

**参考答案**

循环由 Harness 推进，停止条件在运行时计数。`max_turns` 只限制步数，挡不住单步把窗口或预算打穿，也挡不住步数内来回空转。

一步是：先检查各项上限，再组装上下文并调用模型。模型给出结论就收束；给出 tool_call 就校验并执行，按调用 id 把观察写回，然后进入下一步。

token 和预算分两本账。单次请求接近窗口时先压缩，压缩后仍放不下就停止；整段任务的累计 token 另有上限。预算按模型费用加工具费用累计，接近上限时收紧检索或换更小的模型，到顶就停并说明未完成。耗时分单次模型、单次工具和整段任务：工具超时取消这次执行，任务到点写入 checkpoint。重复动作看状态指纹，同一规范化调用配上同一结果连续出现，或两步互相抵消，就记为无进展，达到阈值后停止或强制改计划。

解析连续失败、工具连续失败和用户取消同样退出。上限写进提示词只是说明，计数和停止在循环外。

### 4. 模型返回 tool_call 后，你们怎么做参数校验、权限校验、沙箱执行和结果回灌

**参考答案**

模型返回的 tool_call 只是意图。按参数、权限、沙箱、回灌的顺序做，任何一关失败都变成结构化观察，原始异常不进上下文。

参数先对照 schema 检查必填、类型、枚举和范围，再做语义约束。路径要规范化，挡掉逃出工作区的相对路径；地址和命令对照允许列表。schema 通过仍可能是危险参数。

权限的主体是这次任务的用户和授权，工具说明里的角色不算授权。读、写、外部副作用分开，写和外部调用默认要策略允许或人工确认。

沙箱用独立进程或容器，文件系统限制在任务工作区，环境变量里不放密钥，网络走白名单，并限制 CPU、内存、超时和输出大小。超时结束整个进程组。

回灌按 `tool_call_id` 写回成功结果、错误码或待确认。同一轮有多个调用时，读可以并行，写同一资源要串行。密钥和超长正文留在轨迹里，上下文只放句柄。调用 id 对不上时，模型会把上一次的结果当成这一次。

### 5. Agent 陷入死循环或重复调用同一个工具，怎么检测和处理（状态指纹 / 去重 / 回退）

**参考答案**

死循环是动作和结果不再前进。指纹用来发现，去重用来挡住重复执行，回退用来回到还有别的选择的位置。

指纹取工具名、规范化参数、结果的错误码或内容哈希，以及当前未完成目标。参数先做键排序并去掉无关空白。连续相同，或滑动窗口里超过次数，就记为无进展；两步互相撤销同样算。哈希整段消息发现不了空转，因为上下文每步都在变长。

读工具可以回灌上一次的结果，并说明已经执行过。写工具不因为参数相同就再执行一次，已经成功的写留在记录里。模型稍后再次决定做同样的事，是新的调用 id，放不放行由这个无进展策略决定。

回退回到最近一个还有其它动作的检查点，丢掉这段重复计划。已经成功的外部写保留在状态里，需要抵消时另做补偿。把对话退回到检查点，并不会撤销已经发生的外部副作用。没有可回退点就停下来交给人，附上重复调用和最后一次观察。

### 6. 长上下文超限时，短期记忆怎么压缩，摘要丢失关键信息怎么补，跨块关联怎么保证

**参考答案**

超限时压缩已经结束的旧步骤。系统提示、当前目标、未完成计划和最近一次观察保持原文。

每一段留下做了什么、关键观察、结论、还开着的资源。数字、路径、错误码和标识符原样保留，原文留在轨迹里，摘要带块 id。水位设在窗口之下，在接口拒绝这次请求之前压缩。

关键信息用两处补回。摘要对不上时，按块 id 回读原文。必须跨步成立的事实另存结构化状态：目标、约束、已改文件、未决问题。这份状态增量更新。只在上一次摘要上继续摘要，标识符会在几次压缩后变形。

跨块靠块 id 和实体表。每块记下它依赖的前序块，后续出现「刚才那个文件」时先消解到实体，再决定回读哪一块。压缩发生在送模型之前，模型只能依据留下的状态、摘要和仍在窗口里的原文做决定。

### 7. 多 Agent 协作时，任务怎么拆分、状态怎么共享、结果冲突怎么仲裁

**参考答案**

按能单独验收的子目标拆开，共享一份显式状态，冲突用证据和单一写入者解决。

每个子任务写清输入、完成标准和可用工具。没有数据依赖才并行。后一步要读前一步的原始观察时，串行交给同一段执行，避免两边互相复述。

公共状态放目标、约束、已确认事实和产物位置。每个 Agent 只写分配给自己的字段，长观察留在自己的轨迹里，别人按引用去读。对方的整段上下文不并进自己的窗口。

事实以带来源和时间的工具观察为准，本轮观察新于旧摘要。同一文件或同一记录只有一个写入者，写入带版本。计划冲突由父节点对照用户目标和完成标准决定，材料是各子任务的结论和证据。父节点对最终结果负责。子任务失败写进状态，然后重试、改派或停止。两个 Agent 都自称完成时，要有同一份可核对的状态才能裁决。

### 8. 多个 Agent 并发改同一个文件 / 资源，怎么防冲突，锁粒度怎么定

**参考答案**

同一资源同时只有一个写入者。空间上锁到具体路径，时间上只包住提交，推理期间用版本号。

读不加锁。写记下读到的基线哈希，提交时哈希仍然一致才应用补丁；变了就把差异交回这个 Agent 重做。必须互斥时，锁的键是文件路径或记录主键，租约要短，到期释放，只有持有者能续期。锁包住写入本身，不包住模型思考，否则一次长推理会把资源占死。

粒度按整份资源，不按文件里的一小段。两个人基于同一基线改了不同位置，提交时合并或判为冲突，不能盲写覆盖。没有包含关系的文件不用同一把锁。多个路径必须一起成功时，放在这个任务自己的副本里一次提交，避免交叉持锁。会增删路径的操作按目录处理。

外部资源用幂等键和条件更新。进程内互斥锁在重启和多实例下都不起作用，冲突要能在共享存储里看出来。

### 9. Agent 执行到一半服务重启，checkpoint 存什么、放哪、怎么恢复现场

**参考答案**

检查点是进程外已经写完的任务事件。重启后先对账未决工具，再从下一步继续。

要存任务 id、目标、消息或可重建消息的事件、已完成步骤号、未完成计划、每个工具调用的 id 和状态，以及结构化任务状态。状态分已发出、成功、失败、未知。密钥只存引用。模型当轮的键值缓存不放进检查点，检查点只保留把循环继续跑下去的任务状态。

事件日志放在持久存储里，作为事实来源；快照用来加快加载，大块输出放对象存储。先把一条事件写完整，再推进步骤号。多实例共享这份存储。

恢复时加载最后一条完整事件。成功的调用把结果接上；失败的按策略重试或标失败；未知的先按幂等键查询下游，确认没有受理过再考虑重新执行。恢复过程可以重复执行。外部写做不到绝对一次，靠至少一次投递加上效果侧幂等。最容易出第二次副作用的窗口，是工具已经成功、结果还没写进检查点。

### 10. human-in-the-loop 场景，用户驳回或超时，任务怎么续跑和兜底

**参考答案**

等人时把任务挂在一个已经落盘的步骤上。驳回写成观察并换路径，有副作用的动作超时默认不执行。

挂起前写下工具名、规范化参数和理由，进程不必占着。用户的决定是下一条事件。

驳回原因回灌给模型，这条动作标成已拒绝。相同参数再次申请时，Harness 直接拒绝，不再问人。用户改了参数，就按新参数重新校验和授权，旧批准不沿用。批准绑定的是这一次的工具名和参数摘要。

超时后，有副作用的动作不执行，任务进入待人处理或安全结束，并通知用户。只读动作只有策略写明可以继续时才继续，轨迹里记下这是超时放行。等待期间按租约释放资源锁。续跑从挂起步骤之后开始，已经完成的工具不重做。同一危险动作被驳回达到次数就停，交给人收尾。

### 11. 工具返回数据过大怎么截断 / 摘要，工具失败怎么重试、熔断、保证幂等

**参考答案**

大结果截断后回灌，并留下可再读的句柄。只重试瞬时错误，熔断按工具，幂等键只复用同一次调用的重试。

超过大小上限时，回灌头部、尾部和总长度，或按字段抽成短摘要，标明已截断。错误码和关键行保留原文，全文放在对象存储里按范围再读。

参数非法、权限拒绝和业务拒绝直接回灌。连接失败、429 和明确可重试的 5xx 才做有限次退避。超时只说明结果未知，写操作先按键查询，不直接重发。

熔断按工具或下游统计连续失败和失败比例，状态跨任务共享。打开后立刻返回不可用，半开时放少量探测。

调用 id 在第一次执行前写成「进行中」，成功后记下结果。重试和恢复查到已成功就返回原结果。模型稍后再次决定做同样的事，是新的调用 id，放不放行交给死循环策略。没有幂等能力的外部写，失败后标成未知，转对账或人工。

### 12. Function Calling 和 MCP 分别解决什么问题，工具太多时怎么检索和按需加载

**参考答案**

Function Calling 解决模型如何表达一次调用，MCP 解决工具服务如何被运行时发现和执行。工具多时先检索卡片，再加载少量 schema。

Function Calling 把工具名和参数定义放进模型请求，模型返回工具名和一份参数，运行时解析、执行、把结果送回。它不负责工具从哪个进程来。

MCP 是运行时和工具服务之间的协议。服务端声明工具、输入 schema、资源和提示，客户端按统一方式列出并调用。换模型时，工具服务不用跟着改私有接口。主机把 MCP 工具映射进当前模型的 Function Calling 格式，选哪个工具仍然发生在模型这一轮。

每个工具准备名称、用途和参数摘要，按当前子目标检索出一小批，只把这批的完整 schema 放进本轮。本段轨迹已经用过的工具保持加载。模型点名一个尚未加载、但目录里存在的工具时，先补 schema，再让它重新给参数，这一次不执行。每轮只放一小批，选择更稳，上下文也更短；候选集合尽量稳定，避免前缀每次都对不上缓存。

### 13. RAG 在 Agent 里什么时机触发检索，query 改写和 rerank 怎么接

**参考答案**

检索在需要外部证据时才发生。顺序是改写查询、多路召回、rerank，再把带编号的原文放进上下文。

用户问题本身依赖文档时，第一次调模型前先检索。循环中可以由模型发出检索调用，看完观察再决定要不要继续查。计划里某一步写明依赖文档时，执行到这一步再查。计算、上下文里已经有的事实、以及准备改状态的动作，不查文档库。

改写放在召回之前：把多轮指代补成可以独立检索的句子，拆开多个意图，保留错误码和专名。改写后的查询和原句一起参加检索，避免稀有词在改写里丢掉。

关键词和向量先多取候选，再用能同时看查询和片段的模型按「能否回答这句」重排，取前几条原文。重排对象是原文块。送进模型的片段带编号和来源。最高相关度仍然很低时，明确缺证据。下一步再查时，用已经读过的块 id 去重。

### 14. Prompt 注入怎么防，危险工具调用怎么拦截，敏感数据怎么脱敏

**参考答案**

检索结果和工具输出都是数据。危险动作在执行前拦截，密钥在进模型和进日志之前换成占位符。

用户内容、网页、检索片段和工具输出放在独立的数据通道里，不拼进系统提示。系统提示要求把其中「去执行某个工具」的文字当作数据。模型仍可能照着这些文字发起调用，所以边界放在工具层。

调用必须落在本轮允许列表里，参数过 schema，再过路径、地址和命令策略。删除、对外发送、改权限、离开工作区，直接拒绝或挂起等人。批准绑定这一次的工具名和参数，参数变了就重新批。工具结果里夹带的指令，下一轮仍然是数据。沙箱使用这次任务的最小凭证。

脱敏在进模型前、写日志和检查点前、发往外部工具前各做一次。密钥、令牌、证件号和连接串替换成占位符。模型需要用密钥时只引用占位符，运行时在这次调用已经获批后，从保管处注入。给用户的输出再过滤一遍。拦截放在执行之前，输出过滤处理的是还没发出去的文本。

### 15. Agent 线上怎么评测：任务成功率、工具选错率、参数错误率、成本、耗时怎么埋点

**参考答案**

一次任务一条轨迹。成功看终态有没有达到完成条件，工具选错和参数错误分开计。

任务 id 串起模型、工具、检索和人工确认。每段记下名称、起止、状态、模型名、提示版本和工具版本，以及输入输出 token、工具错误类别和终止原因。错误类别至少分开 schema、权限、超时和业务拒绝。

终态符合预先写好的完成条件才算成功，并区分完成、失败、放弃、超时、等人。模型自称做完，还要对照这个条件。工具选错率的分母是做了工具决策的步，分子是工具与目标不符，或该用工具时直接编造。参数错误率只统计工具选对、但没过 schema 或被语义规则拒绝的调用。一次调用只归一类，选错优先。

成本按任务汇总模型费用和工具费用。耗时拆成排队、模型、每个工具和端到端，按分位看，超时单独计数。轨迹上没有提示版本和工具版本时，一次变差对不上是哪一层。

### 16. badcase 怎么归因到模型 / prompt / 检索 / 工具，怎么回流成回归集

**参考答案**

沿着这一步的输入输出，归到最先出错的那一层，再把能重放的现场放进回归集。

相同参数在固定实现上重放，结果本身就不对，归工具。完成任务需要的证据不在送进模型的片段里，归检索。证据曾经召回到、后来被裁掉，归上下文裁剪，修的是送进模型的内容。证据和工具结果都在，但工具说明或约束让模型稳定地误解，改提示就变对，归 prompt。证据、工具定义和提示都足够，输出仍然选错或编造，归模型。一次只改归到的那一层。

样本里留下用户目标、当时的消息、工具 schema、检索片段、模型原始输出、工具结果，以及判定对的动作或事实。工具用录制结果回放，回归不依赖线上接口。断言写在动作、参数约束和必须出现的事实上，自由文本不做整段比对。按失败层打标签，修完重放这一层，并看相邻用例有没有变差。说不清正确行为的样本先不进集。

### 17. 流式输出下，工具调用事件怎么往前端正向推送，断线重连怎么恢复

**参考答案**

工具事件按发生顺序推给前端，并且先写入任务日志。断线从最后序号补放，任务继续跑。

事件包括文本增量、工具调用开始、参数增量、校验通过后的执行中、工具结果和任务终态。每条带任务 id、单调序号和调用 id。参数还是碎片时只更新展示，拼成合法参数并校验通过后才执行。未校验的参数保持生成中。

日志先落盘再推给当前连接，前端按序号应用，缺号就按范围补拉。SSE 重连带上最后的事件 id，WebSocket 同样带序号。重复序号丢掉。文本按序号拼接，工具卡片按调用 id 更新。

连接断开后运行继续，取消要单独的事件。重连后补发该序号之后的事件，再接上实时流。日志已经很长时，先发一份折叠后的界面状态，再补这份状态之后的事件。任务已结束就补到终态。客户端若重试的是整次用户请求，服务端按任务 id 接到原来那次运行上，不把同一个工具再执行一遍。

### 18. 手撕算法：给一个扁平 JSON 列表（带 parent_id），恢复成树形结构并返回根节点列表

**参考答案**

先按 `id` 建索引，再按 `parent_id` 挂到父节点上。父 id 为空，或父节点不在列表中，该节点就是根。两遍都按原列表顺序走，子节点可以出现在父节点前面。每个节点只保留一份，节点上多出来的字段是 `children`，其它字段原样保留。

时间 O(N)，空间 O(N)，N 是节点数。同一 id 的类型要一致，数字 `1` 和字符串 `"1"` 对不上，子节点会变成另一个根。重复 id 直接拒绝。

挂完后从所有根做一次遍历，到不了的节点在环上，包括自己指向自己。输入若保证是森林，可以不做这步。业务若要求父引用必须存在，把「父节点不在表中」改成报错。

```python
def restore_forest(nodes: list[dict]) -> list[dict]:
    """恢复森林并返回根列表。重复 id 或环会抛出 ValueError。"""
    by_id: dict = {}
    ordered: list[dict] = []
    for raw in nodes:
        node_id = raw.get("id")
        if node_id is None or node_id in by_id:
            raise ValueError("missing or duplicate id")
        item = {**raw, "children": []}
        by_id[node_id] = item
        ordered.append(item)

    roots: list[dict] = []
    for item in ordered:
        parent = by_id.get(item.get("parent_id"))
        if parent is None:
            roots.append(item)
        else:
            parent["children"].append(item)

    seen: set = set()
    stack = [root["id"] for root in roots]
    while stack:
        current = stack.pop()
        if current in seen:
            continue
        seen.add(current)
        stack.extend(child["id"] for child in by_id[current]["children"])
    if len(seen) != len(by_id):
        raise ValueError("cycle")
    return roots
```
