# 10.27 月之暗面Agent Harness三面

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 面试感受

三面才是真刀真枪。前面还聊功能，这边直接问你“平台怎么不炸、钱怎么不烧、出事怎么查”。没做过生产级 Agent 的，到第4题成本护栏和第11题 trace 归因就开始飘。面试官不跟你绕概念，全在逼你做取舍：多 Agent 要不要拆、上下文压不压、人审放不放、灰度敢不敢放。答得明白的人，一眼就能看出来是不是踩过线上的坑。整体偏贵（考察密度高），但聊下来很爽，不像在考试，像在招一起扛系统的人。

## 三面

### 1. 自我介绍

**答题思路**

控制在一两分钟，按「方向 → 一个项目 → 和这个岗位的关系」讲完就停。

1. 一句话说明你做 Agent 工程的哪一段：编排、工具执行、评测或运行时。年限和职级按简历上的事实说，没有就不报。
2. 只展开一个你最熟的项目：用户要完成的任务、你负责的链路、结果用你拿得出来的证据。没有数字就讲评测集或坏例。
3. 收到 Harness 上：你关心模型循环外面的状态、工具约束、成本和失败后怎么停。话停在这个项目上，方便对方接着问重做。

### 2. 复盘你最熟的那个 Agent 项目：如果现在重做，架构上你会砍掉什么、保留什么、补什么

**答题思路**

用你真实做过的那一个项目，按「当时的路径 → 砍 → 留 → 补」讲。没有生产 Agent，就讲最接近的工作流或检索链路，并说明它还缺循环和工具副作用。

1. 四句话重述路径：入口、谁决定下一步、有哪些工具、怎样算结束。只讲你负责的部分。
2. 砍一个当时多出来、线上没有证明价值的设计。常见的是过早拆开的子 Agent、每一轮塞入全部历史、一个什么都能调的大工具。说清砍掉以后哪条失败路径变短。
3. 留一个你现在仍会保留的约束：幂等键、步数上限、写操作前确认，或按一次任务能查回轨迹。对上它挡住过的失败；没有线上事故，就说它针对的是你已经见过的哪类坏例。
4. 补一个当时缺的、并且能验收的能力。预算、checkpoint、工具权限或回归集，选你真的缺过的那个。
5. 框架名只在它改变了状态放在哪、失败能不能重放时才提。

### 3. Agent harness 当作一个平台能力设计时，单租户和平台化多租户在隔离、配额、审计上怎么落地

**参考答案**

单租户把隔离放在部署上：运行时、密钥、索引和日志按客户分开，配额按实例计，审计按任务回放。平台化多租户共用引擎，租户要写进每次调度和落盘的主键。

隔离：状态、checkpoint、对象存储和检索过滤都带 tenant_id，缓存键也带。工具凭证由网关按租户取用，模型参数里填写的租户名不作数。配额：并发、步数、token 和工具 QPS 在编排层记账，超限就排队或拒绝，避免一个长任务占满 worker。审计：模型调用、工具入参出参和审批带上租户、操作者、trace_id 和策略版本，保留期按合规要求定。

串租户最常见的口子是缓存和召回少了租户条件。强隔离客户可以继续独立部署。平台化省下的是运行时份数，前提是把串数据当成故障来防。

### 4. 多 Agent 系统里，成本是 Agent 数乘轮次乘上下文，你怎么从第一天就把预算护栏做进编排层

**参考答案**

预算是编排器在发起调用前就扣掉的调度约束。任务上挂 token、金额、轮次、工具次数和墙钟。子 Agent 从这笔预算里划一块，不能各自再花一遍总额。

并行分支在调用前原子地预留，预留按输入 token 和允许的最大输出 token 估价，返回后按实际用量结算。预留不足就不再发起。两路同时读到同一笔余额再各自花，预算会破。重试记在同一笔账上。

超限动作写在同一层：先压缩历史、停掉可选子 Agent，再拒绝新的模型循环，把任务标成预算耗尽并留下 checkpoint。调用前不拦截，日志告警挡不住已经发出的请求。阈值按任务类型配置。

### 5. 长任务跑飞的典型信号有哪些（无进展、重复工具、上下文膨胀），线上怎么自动降级或熔断

**参考答案**

跑飞是状态不再靠近目标。用进展、重复和体积三类信号降级；降级仍在消耗就熔断。

无进展：连续若干步之后，计划、归一化后的工具参数和已确认槽位的摘要都没变。重复工具：同一工具、同一参数指纹在窗口内反复出现，同样的成功或同样的失败都算。上下文膨胀：历史 token 或单次工具原文超过本步上限，摘要之后仍上涨。单靠超时看不到「每步都有动作、目标没有更近」。

降级只停止新的调用：摘要旧的工具输出，收窄到只读工具，停止派生子 Agent。任务允许时才换更小模型或固定脚本。熔断则停掉模型循环，标成待人工或失败，写明信号和最后的 checkpoint。再次运行要有新的输入或人的决定。已经发出且撤不回的工具，等回执写入 checkpoint，靠幂等键处理。

### 6. Agent 的「状态」该存哪些字段，checkpoint 怎么设计才能保证可回放、可审计、可人工接管

**参考答案**

状态存的是可恢复的任务事实，checkpoint 是某一时刻这份事实的不可变快照。

事实包括目标、阶段、已确认槽位、待办和完成判据。游标包括当前步骤，以及尚未回执的工具调用 id、参数摘要和幂等键。同时记下模型、prompt、工具 schema、策略和索引的版本，还有 token、轮次、费用和审批。密钥不进状态。思维链有返回时放审计日志，回放不读它。

checkpoint 按任务递增，用期望版本号做条件更新，避免两个 worker 互盖。快照带上一个 checkpoint id，以及消息和工具结果的引用；事件另存，用来补两张快照之间的过程。回放时已成功的调用用幂等键认出，副作用不自动再做。人接手时阶段改为 paused，人对槽位和放行的修改带来源，写成新事件，产生新 checkpoint 后再恢复。只留最后一条对话，中间的工具结果会丢，回放和接手都会断。

### 7. 多 Agent 共享状态时，用消息传递还是共享存储，写冲突和 stale read 怎么处理

**参考答案**

默认由父编排器单写，子 Agent 用消息交回结果。多个 Agent 必须改同一份状态时，再用带版本的共享存储。

消息方案里，子 Agent 没有全局写权限，只提交事件。父节点按当前版本检查前置条件，通过才落账。子 Agent 推理期间看到的是消息里带去的快照，过期结论会在提交时被退回。顺序和审计都在这本日志上，协调者要扛写入。

共享存储适合不同字段由不同 Agent 更新的看板。写入带上读到的版本，版本不符就重读再合并。临界区只包住这次提交，模型推理放在锁外，否则锁会持有到整次调用结束。同一轮要能读到自己刚提交的版本，任务状态读主本，不读尚未追上的副本。

贴进 prompt 或向量库的文本没有版本，发现不了写冲突，也挡不住读到旧值再覆盖。

### 8. 给一个场景：让 Agent 自动改代码仓库并提交 PR，从权限、沙箱、审批、回滚讲完整链路

**参考答案**

模型只生产补丁，合并权限在网关和人。链路是只读理解、沙箱修改、检查、人审、可回退发布。

按任务发放短期凭证，只能向指定仓库的临时分支推送。保护分支、密钥和生产环境不在凭证里，任务结束即失效。沙箱从指定 commit 起步，在隔离环境改文件、跑测试，默认不出网，依赖走内部镜像，并限制进程、时间和磁盘，不挂宿主机凭证。容器或微虚拟机都可以，边界在网络和凭证。产物是 diff，计划外路径拒绝。

机器人账号开 PR，说明里附任务、意图、测试结果和 trace。CI 通过后由人合并；鉴权、支付、迁移等目录可以要求第二人。模型没有合并权限，也没有能跳过检查的凭证。

合并使用普通提交，出问题就 revert 该提交。不再需要的沙箱分支直接删。已经发布的，回滚制品版本。Agent 改测试来换通过，是这里最常见的洞，所以可改路径要事先限定，审批材料里单列计划外文件。

### 9. Prompt 注入和检索投毒在 Agent 场景为什么特别难防，你的纵深防御分几层

**参考答案**

外部文本会进入模型的下一步，模型又会发出工具调用，所以间接提示注入和检索投毒会变成真实操作。提示里要求忽略恶意指令，挡不住这件事。

网页、邮件、工单和检索片段与用户目标待在同一上下文里，信任边界不可靠。投毒写在会被召回的文档里，问题一问就命中。被污染的结论还会传给下一个 Agent。

分四层。第一层把系统策略、用户目标和不可信内容分通道；工具调用只接受模型输出的结构化字段，不从文档里摘指令。模型仍可能照着文档发出结构合法的调用。第二层管检索：来源白名单、按权限过滤、新文档先隔离，结果带文档 id 和版本。第三层由网关按身份和参数再判，高危工具不进默认集合。第四层在写操作前等人确认，并把「要求忽略策略、外传密钥」标成中断。回归集里放注入和投毒样本，才能知道哪一层被绕过。

### 10. 工具越权调用怎么收敛，高危操作（删数据、发消息、转账类）怎么接 human-in-the-loop

**参考答案**

模型能看见的工具随阶段缩小，执行权在网关。删除、对外发消息和转账，默认等人确认后才做。

只读阶段不提供删除和转账。参数带硬边界：金额上限、收件人在允许名单内、删除必须有资源 id 和范围。网关用用户和租户的真实权限复核，调用参数里自填的角色无效。同一调用反复失败就熔断。

编排器收到高危调用后进入 paused，展示动作、参数、影响范围和 trace。确认绑定参数的规范形式；通过后用同一个幂等键执行，执行前再比对一次，金额若被改过就视为另一次操作。拒绝原因写回状态。确认有过期时间。批量操作拆开或设数量上限。人的确认只覆盖这一次授权，失败后的重试仍走幂等键，避免第二笔副作用。

### 11. Agent 可观测性怎么做：trace、span、token、工具输入输出、thinking history 怎么落盘才方便归因

**参考答案**

一次任务一条 trace，模型调用、检索、工具和人工决定各是一个 span。trace_id 从入口传到子 Agent。

模型 span 记模型名、prompt 版本、输入和输出 token、是否命中缓存，以及消息引用。工具 span 记工具名、schema 版本、参数、结果摘要、耗时、幂等键和有没有副作用。检索 span 记查询、过滤条件、命中文档 id 和分数，用来区分没召回和召回了没有用上。token 从 span 汇总到任务和子 Agent，才能看出预算是谁烧掉的。thinking 只有接口返回时才落，单独存放；归因以工具参数、命中文档和版本为准。

密钥在落盘前打码。大块输出放对象存储，span 留指针和哈希。失败和超预算的 trace 保留。按租户、任务和时间要能查到：从哪一步开始偏、当时的上下文指针、花费和版本。

### 12. 评测体系怎么搭：门禁层、端到端完成率、工具层、检索层、成本延迟横切层分别看什么指标

**参考答案**

分层是为了完成率下降时知道改哪一层。各层带上同一组模型、prompt、索引和工具 schema 版本。

门禁看必须通过的集合：注入有没有拒绝、越权工具有没有执行、高危动作有没有停在人审、输出是否符合 schema。安全项只看通过与否。

端到端看任务完成率、一次做对率、人工接手率和错误类型占比。完成由程序或业务规则判定。

工具层看该调时是否叫对、参数是否合法、不该调时是否收手、重复次数，以及超时后有没有按幂等恢复。

检索层看前 k 是否命中、引用是否指向这次返回的片段、权限过滤有没有串、空结果时是否停止编造。召回和回答分开记。

横切看 token、费用、步数、延迟分位数和超预算比例。成功任务和失败任务的费用分开，避免失败很快被看成便宜。

### 13. LLM-as-judge 有哪些偏见，怎么用人工标注校准，badcase 怎么回流成回归集

**参考答案**

模型打分会偏向先出现的答案、更长的回答，以及和裁判同一家族的文风，也容易忽略数字、否定和引用是否真实。同一份答案重判可能不一致。

校准用按任务类型抽的一小批人工双标，分歧先仲裁。按题型看裁判和人的一致程度。偏差稳定的题改裁判说明，或改成对照标准答案；安全、金额、引用退出自动分。裁判模型一换，旧校准作废，要重新对人工标签。

bad case 写成输入、上下文版本、错误层和期望行为，去重后只留能复现的，放进每次改 prompt 或模型都要跑的回归集。不再代表线上的旧题定期移出。

### 14. 模型升级或 prompt 大改时，Agent 行为可能悄悄变差，灰度发布和自动回滚怎么设计

**参考答案**

模型和 prompt 都是行为版本。一次发布绑上模型、prompt、工具 schema 和策略。离线先过门禁和回归，安全项和关键任务不能退步。

灰度用稳定哈希把会话固定到新版本，同一任务的多轮和子 Agent 用同一组。先给内部或低风险租户，再放小流量。影子流量只跑只读工具，写操作不能为了对比执行两遍。

回滚指标事先写入配置：门禁失败、完成率相对基线下降、工具误调用、人审拒绝、费用或延迟越界、用户中止。样本量达到下限再判定。触发后新流量回旧版本；已经在新版本上的任务跑完或停在 checkpoint，中途不换模型。回滚留下审计。

变差常在长尾：多一步、多一次工具、引用变少。按切片看分布。没有基线就不做自动回滚。

### 15. RAG 在 Agent 里不是独立模块，检索时机、引用溯源、上下文污染怎么和主循环解耦

**参考答案**

检索发生在主循环里面，索引细节不写进状态迁移。主循环只决定这一步要不要取证，并消费工具返回的结构。

查询词以及租户、权限、时间过滤放在调用参数里。空结果、失败和超时是返回值，循环据此重查、换工具或停止。已有槽位和工具结果够用时不查。

返回带文档 id、版本、片段和分数。回答里的引用要能对上这次结果中的 id。检索文本标成不可信数据，和系统策略分通道。每轮由单独的组装步骤挑选仍然有效的证据，旧片段不永久堆在对话里，条数和长度有上限。

换掉向量库或关掉检索，状态机和网关的契约不变，只是少了一种证据。索引版本写入 trace。

### 16. 如果让你从零设计一个月之暗面内部的 Agent 执行引擎，画得出核心模块和边界么（调度、状态机、工具网关、护栏、评测）

**参考答案**

引擎负责把任务安全跑完并留下证据。模型、业务工具和评测集在边界外接入。下面是一套可画出来的边界，不必猜内部代号。

调度决定哪个 worker 跑哪个任务，按租户配额排队。它不管业务下一步。状态机保存阶段、checkpoint 和合法迁移，是唯一写任务状态的地方。循环是读状态、组上下文、调模型、得到工具调用或结束。子 Agent 是带预算的子任务，以事件交回。

工具网关校验 schema、身份、参数和幂等，然后执行或拒绝。检索是这里的一种工具。护栏在模型和工具调用前检查步数、token、重复和策略，可以暂停、降级或熔断，原因写入状态。人审是一种暂停。

评测在请求路径外，用同一套引擎回放，比较完成、安全和成本，trace 回流成用例。调度、状态、网关和护栏若写进同一个对象，改模型适配会碰到权限代码，改一个写操作会碰到预算代码。

### 17. 你怎么看「harness 和模型是一体」这件事：同样模型换不同 harness，效果和成本能差几倍，为什么

**参考答案**

模型决定单步能力，harness 决定这些步怎么串、每步看见什么、什么时候停。费用近似是 Agent 数 × 轮次 × 每轮上下文。轮次和每轮上下文各自变一些，乘积就会到几倍。

一个 harness 每轮带上全部历史和工具原文，另一个做摘要、截断和按需检索，输入长度和证据位置都不同。无关内容把关键事实挤到长上下文中部时，模型更不容易用到它。工具面越大，误调用和额外轮次越多。没有进展检测，重复调用会把预算烧完。槽位放在模型外面，下一轮不用重新猜测已经确认的事实。无意义的重试和同时拉起的子 Agent，会把一次任务乘成多次。

比较两个模型时要锁住同一版 harness。这个倍数来自乘积，不是模型的固定属性；单轮问答里差距会小很多。模型更强时，错误的工具调用也会更坚决，权限和预算仍然放在循环外。

### 18. 最近在学什么和 Agent infra 相关的新东西，举一个你从论文或源码里抠到的底层细节

**答题思路**

只准备一个你能对着实现讲五分钟的点。阅读清单不算回答。

1. 先说对象：一份你真的读过的运行时、协议或论文。没读完就说正在追的那一段，不临时编标题和作者。
2. 用三句话讲它解决的故障，例如工具结果配错、崩溃后副作用做了两次，或关键证据被历史挤到上下文中部。
3. 落到一个数据结构或失败行为上。深度够用的粒度是：主流工具协议给每次调用一个 id，结果按这个 id 写回，而不是按返回数组的先后拼接。checkpoint 里把「已发出未回执」和「已回执」分开。字段名以你读过的那份代码为准。论文向可以讲你确读过的长上下文实验：相关段落放在中部时更容易被用漏，所以 harness 要选择证据的位置，而不是把历史均匀摊开。
4. 说这个细节会怎么改你自己的网关或 checkpoint。还没接到项目里就直接说没接。
5. 准备被问「少了这个机制会怎样」。答不上就停在你看过的那几行。

### 19. 跨团队推 Agent 落地时，算法、后端、产品目标不一致，你怎么定优先级和验收标准

**答题思路**

把三方目标收成同一条任务上的约束，再排顺序。

1. 用他们的原话复述冲突：算法关心效果和能不能换模型，后端关心稳定、权限和成本，产品关心某个场景什么时候能用、完成率怎样。
2. 把范围收成一个任务，写下一句怎样算做成、一句怎样算事故。没有这两句，顺序会变成谁声音大。
3. 排序说清楚：先保证副作用可控、任务能停，再保证任务能完成，然后才是体验和离线分数。离线分上涨但线上预算守不住，不排到前面。
4. 验收拆开认领：产品认端到端完成和接手率，算法认分层坏例有没有下降，后端认错误预算、延迟、审计和能不能回滚。门禁项不用平均分替换。
5. 准备一个你真实做过的取舍：砍了什么、留下什么证据、下次看哪个数。没有这种经历，就说你会先定一条最小闭环的验收。

### 20. 手撕算法：给定一个任务依赖关系（tasks + dependencies），输出一个拓扑排序；如果存在环，返回空并说明哪条依赖成环

**参考答案**

依赖是有向边。(u, v) 表示 v 依赖 u，u 必须先完成。用深度优先的三色标记：白是未访问，灰是正在当前路径上，黑是已完成。走到灰节点就是回边，从递归栈取出这段路径，连同这条回边，得到环上的依赖。无环时把完成顺序反转，得到一种拓扑序。

有环则顺序返回空，并列出环上的依赖，最后一条是这次发现的回边。自环只有这一条。图里有多个环时说明其中一个。已经排好的前缀也不返回，因为整个图没有拓扑序。入度算法能发现「还有点没排完」，具体是哪条边要再搜一次；这里要说明成环的依赖，所以直接用回边。

时间 O(V+E)，空间 O(V+E)。节点按名字排序只为了同一输入得到稳定结果，任何合法拓扑序都对。若题目把一对依赖定义成（任务, 前置），把边反向即可。

```python
def topological_sort(tasks, dependencies):
    """返回 (顺序, 环上的依赖)。有环时顺序为 []，环列表的最后一条是回边。"""
    graph = {task: [] for task in tasks}
    for src, dst in dependencies:
        graph.setdefault(src, []).append(dst)
        graph.setdefault(dst, [])
    for node in graph:
        graph[node] = sorted(set(graph[node]))

    white, gray, black = 0, 1, 2
    color = {node: white for node in graph}
    stack = []
    order = []

    def dfs(node):
        color[node] = gray
        stack.append(node)
        for nxt in graph[node]:
            state = color[nxt]
            if state == gray:
                start = stack.index(nxt)
                path = stack[start:]
                edges = [(path[i], path[i + 1]) for i in range(len(path) - 1)]
                edges.append((node, nxt))
                return edges
            if state == white:
                cycle = dfs(nxt)
                if cycle:
                    return cycle
        stack.pop()
        color[node] = black
        order.append(node)
        return None

    for node in sorted(graph):
        if color[node] == white:
            cycle = dfs(node)
            if cycle:
                return [], cycle
    order.reverse()
    return order, []
```

无环时，任务 A、B、C，依赖 (A, B)、(B, C)，一种合法顺序是 A、B、C。再加上 (C, B) 之后顺序为空，环上的依赖是 (B, C)、(C, B)，其中 (C, B) 是回边。
