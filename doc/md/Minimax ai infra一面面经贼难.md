## 一面

### 1. 请分享你在实习中参与的项目，着重描述你遇到的最大技术难题以及取得的优化成果

**答题思路**

按「边界 → 现象 → 定位 → 改动 → 结果」讲，两分钟左右。身份和团队用你的真实情况一句话带过，时间放在系统上。

1. 用两三句框定项目：训练还是推理，规模用你真实的卡数或参数量，你负责运行时、通信、显存、调度、数据还是平台中的哪一段。
2. 只展开一个最大的难题。先讲现象：步时变长、显存顶满、集合通信超时，还是恢复之后对不齐。
3. 讲怎么钉住原因：profiler、哪条指标、和哪一次正常 step 对比。原因归到计算、显存、通信、数据或调度中的一类。
4. 讲改了哪一个机制，以及你比较过、最后放下的做法。只讲自己做过的，例如重叠通信、改切分、重计算、改 checkpoint 的写法和提交点。
5. 成果用同一口径的前后对比：单步时间、MFU、峰值显存或恢复时间。只报自己量过的数；没打点的，就讲趋势，以及你怎么确认收益留在这个环节。
6. 收在适用边界上：换批次、换序列长度或换机间带宽之后，这个优化还成不成立。

准备好三个追问：峰值出在参数、优化器还是激活；通信在机内还是跨机；基线是改配置之前的哪一版。

### 2. DeepSpeed ZeRO 的三个阶段（Stage 1 / Stage 2 / Stage 3）各自对哪些状态进行了切分？它们在通信量和显存节省上有何递进关系？

**参考答案**

**结论**：Stage 1 切优化器状态，Stage 2 再切梯度，Stage 3 再切参数。显存逐级下降；前两个阶段的通信量与数据并行相同，Stage 3 约为 1.5 倍。

混合精度 Adam、梯度也是半精度时，每参数约 16 字节：半精度参数和梯度各 2 字节，FP32 主权重、动量、方差共 12 字节。后 12 字节是优化器状态。设参数量为 \(\Psi\)、数据并行度为 \(N\)。Stage 1 单卡约 \(4\Psi+12\Psi/N\)，\(N\) 很大时接近 4 倍节省。Stage 2 约 \(2\Psi+14\Psi/N\)，接近 8 倍。Stage 3 常驻约 \(16\Psi/N\)，随 \(N\) 线性下降。\(N\) 只计数据并行组，张量并行和流水线占掉的卡不进分母。Stage 3 计算当前层时会把该层参数暂时聚齐，峰值高于常驻公式。激活单独算，不在这三档公式里。

数据并行的 AllReduce 体积约 \(2\Psi\)，等于一次 Reduce-Scatter 加一次 All-Gather。Stage 1 和 Stage 2 都把这两半拆开：反向只把梯度规约到负责更新的那张卡（约 \(\Psi\)），各卡更新自己的参数分片，步末再 All-Gather 参数（约 \(\Psi\)），合计仍约 \(2\Psi\)。Stage 2 多做的是在规约后释放不属于自己的梯度，把梯度显存从 \(2\Psi\) 降到 \(2\Psi/N\)，通信体积保持不变。Stage 3 参数不再常驻，前向和反向各 All-Gather 一次参数，再加上梯度的 Reduce-Scatter，合计约 \(3\Psi\)。这三次按层发生，用预取和计算重叠盖住。

梯度如果先 AllReduce 出整份、再 All-Gather 一次参数，体积约为数据并行的 1.5 倍。要维持论文里 Stage 1 的同体积，梯度同步停在 Reduce-Scatter。

### 3. 训练大模型时，你使用过哪些并行方案？数据并行、张量并行和流水线并行的设计思想与适用条件分别是什么？

**参考答案**

**结论**：数据并行切批次，张量并行切层内矩阵，流水线并行切层。通信越勤，这组卡就要离得越近。回答时先说自己真实跑通的组合，再按这个顺序讲。

数据并行每卡一份模型、各算不同样本，反传后同步梯度。模型状态放得下、还要加大全局批次时用它。同步按桶做，和反向重叠；通信每步一次，可以跨机。单卡放不下优化器或梯度时，在数据并行组里再切状态，切法和通信量见上一题。

张量并行把同一层的矩阵按行或列切开。Megatron 里，QKV 和 MLP 的第一层按列切，输出投影和 MLP 第二层按行切，逐元素运算留在本地。每个 Transformer 层前向大约两次 AllReduce，反向再两次，所以放在机内高速互联上，度数一般就是这一域里的卡数，常见 2、4、8。单层或激活放不下时用它。再沿序列切 LayerNorm 和 Dropout 时，这两次 AllReduce 换成 Reduce-Scatter 加 All-Gather，体积同级，激活更小。

流水线把连续的层分成 \(P\) 个 stage，只在边界传激活，可以跨机。空泡占整段时间的比例约 \((P-1)/(M+P-1)\)，\(M\) 是 micro-batch 数。GPipe 和 1F1B 这个比例同级；1F1B 同时在飞的激活更少。每卡放 \(V\) 个不相邻的模型块时，空泡大约降到原来的 \(1/V\)。层数够切、\(M\) 明显大于 \(P\) 时才划算。嵌入和损失挂在首尾，切分时要配平计算量。

常见摆法是机内张量并行、跨机流水线、最外层数据并行。序列长到注意力放不下，再沿序列做上下文并行。

### 4. 假设需要训练一个 70B 参数量级的模型，如何粗略计算单张 GPU 所需的显存量？

**参考答案**

**结论**：单卡显存等于它实际持有的那份模型状态，加上本卡激活和通信缓冲。70B 的整份训练状态约 \(1.12\times10^{12}\) 字节；切分之前，这就是单卡要扛的模型状态。

参数量按 \(\Psi=70\times10^{9}\)。混合精度 Adam、梯度为半精度时，半精度参数和梯度各 2 字节，FP32 主权重、动量、方差共 12 字节，合计约 16 字节/参数，\(70\times10^{9}\times16=1.12\times10^{12}\) 字节。纯 FP32 的 Adam 是参数、梯度、动量、方差各 4 字节，同样约 16 字节；混合精度省的是张量核心上的计算、激活体积和梯度通信。梯度若保持 FP32，在这 16 字节上再加 2 字节/参数。只加载半精度权重做推理，才是 2 字节/参数，约 \(1.4\times10^{11}\) 字节。

切分之后用数据并行度 \(N\) 去除。Stage 1 约 \(4\Psi+12\Psi/N\)，\(N\) 很大时仍接近 \(2.8\times10^{11}\) 字节。Stage 2 接近 \(2\Psi=1.4\times10^{11}\) 字节。两者都高于 80GB 这一档的卡，所以 70B 的训练状态还要把单卡上的参数再切开：Stage 3 约 \(16\Psi/N\)，或先用张量并行、流水线减少这张卡上的 \(\Psi\)。例如 \(N=16\) 的 Stage 3，单卡模型状态约 \(7\times10^{10}\) 字节，和 80GB 卡同一量级，激活还要另留。

激活随 micro-batch、序列长度、隐藏维、层数和是否重计算增长，没有这些形状就停在正比关系。梯度累积在同一块梯度缓冲里相加，不把 16 字节乘上累积步数。集合通信的临时缓冲和分配器碎片另留一截，理论值不要填满卡。

### 5. LoRA 的核心思想是什么？为什么通过低秩矩阵分解可以大幅降低需要更新的参数数量？

**参考答案**

**结论**：冻结预训练权重 \(W\)，把要学的增量写成低秩分解 \(\Delta W=BA\)，只训练 \(A\) 和 \(B\)。

\(W\) 是 \(d\times k\) 时，全量更新有 \(dk\) 个参数。取秩 \(r\ll\min(d,k)\)，降维矩阵 \(A\) 为 \(r\times k\)，升维矩阵 \(B\) 为 \(d\times r\)，可训练参数是 \(r(d+k)\)。相对全量的比例是 \(r/d+r/k\)。例如 \(d=k=4096\)、\(r=8\) 时，一层从约 \(1.7\times10^{7}\) 个参数降到 \(6.6\times10^{4}\) 个。前向是 \(Wx+(\alpha/r)BAx\)，\(\alpha\) 是缩放系数。推理前可以把 \(BA\) 加回 \(W\)，之后计算量和原模型相同。

参数变少，是因为不必保存一块稠密的 \(d\times k\) 增量，两块细矩阵就决定了它。这样近似仍然够用，是因为适配阶段的 \(\Delta W\) 往往落在远小于 \(d、k\) 的子空间里。秩太小、或任务要改写的方向很多时，表达力不够。

冻结的 \(W\) 仍整份驻留。省下来的是可训练参数，以及只挂在 \(A、B\) 上的优化器状态。

### 6. 在 LoRA 中，降维矩阵 A 和升维矩阵 B 的初始化方式为何不同？这样设计的目的是什么？

**参考答案**

**结论**：\(A\) 用随机高斯或 Kaiming 初始化，\(B\) 初始化为 0，训练开始时 \(\Delta W=BA=0\)。

原论文对 \(A\) 用随机高斯，实现里常见 Kaiming。要点是 \(A\) 非零、\(B\) 为 0，第一步的输出与预训练模型相同，微调从原模型出发。两个都置 0 时，\(A\) 和 \(B\) 的梯度都是 0，参数停在原地。两个都随机时，\(BA\) 在第 0 步就是一块秩为 \(r\) 的噪声，输出偏离预训练模型。

梯度不对称：\(B\) 的梯度依赖 \(Ax\)，\(A\) 非零，所以 \(B\) 第一步就有梯度；\(A\) 的梯度依赖 \(B\)，此时 \(B\) 仍是 0，\(A\) 要等下一步才动。于是第一个非零增量是「已由损失更新的 \(B\)」乘上「固定的随机 \(A\)」，输出方向由损失决定。缩放 \(\alpha/r\) 不改变初始增量为 0，它让更换秩时更新的尺度更好保持。

### 7. 除了 ZeRO 系列之外，你还了解哪些用于大模型训练的优化技术？

**参考答案**

**结论**：ZeRO 切的是数据并行组里的优化器、梯度和参数副本。精度、激活和通信重叠是另外几条线。

混合精度用 BF16 或 FP16 做前向和反向。BF16 的指数位与 FP32 一样宽，预训练里通常不用为溢出去做 loss scale；FP16 的动态范围窄，要用缩放。优化器的主权重和矩估计仍用 FP32。

激活按块只留输入，反传时重算块内结果，总计算大约增加三分之一。选择性重计算只重算注意力，多花的计算和省下的激活都更少。FlashAttention 按块计算注意力，不物化 \(N\times N\) 的分数矩阵，反向从 Q、K、V 重算对应的块，显存和带宽一起降。

梯度分桶，和反向重叠，这与状态切分正交。全局批次要加大时，用梯度累积把多个 micro-batch 的梯度加进同一块缓冲，激活按 micro-batch 出现，不按累积步数叠乘。序列很长时，沿序列切分，把注意力和 LayerNorm 的激活摊到多卡。

优化器状态还有两条路：微调里常用分块 8-bit 量化动量和方差；把优化器状态放到 CPU，用主机带宽换显存，步时会卡在总线上。大规模预训练仍多用 FP32 矩估计，再配合状态切分。

### 8. 实现一个滑动窗口求最大值的算法

**参考答案**

**结论**：用单调队列。队列里存下标，对应的值从队首到队尾递减，队首就是当前窗口的最大值。

给定数组和窗口长度 \(k\)（\(1\le k\le n\)），对每个右端点 \(i\ge k-1\)，求 \(nums[i-k+1..i]\) 的最大值。输出长度是 \(n-k+1\)。

新下标入队前，从队尾丢掉所有值小于等于它的下标：那些位置更旧、值又更小，只要新元素还在窗口里，它们就不可能成为最大值。队首下标已经滑出窗口时，从队首丢掉。每个下标最多入队一次、出队一次，时间 \(O(n)\)，队列长度不超过 \(k\)，额外空间 \(O(k)\)。

```python
from collections import deque


def max_sliding_window(nums: list[int], k: int) -> list[int]:
    if k <= 0 or k > len(nums):
        raise ValueError("k 必须满足 1 <= k <= len(nums)")
    window = deque()
    answer = []
    for i, value in enumerate(nums):
        if window and window[0] <= i - k:
            window.popleft()
        while window and nums[window[-1]] <= value:
            window.pop()
        window.append(i)
        if i >= k - 1:
            answer.append(nums[window[0]])
    return answer
```

相等时用 `<=` 丢掉更旧的那个下标，队首仍然是最大值。用堆做需要懒删除已经出窗的下标，时间 \(O(n\log k)\)，实现更重。
