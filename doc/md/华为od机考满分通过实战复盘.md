### 1. 小菊和小花玩数字游戏：给定一排整数和连续个数 K，求长度为 K 的连续子数组的最大和

**题目**

小菊在纸上写了一排数字，小花需要从中选择连续 K 个数字，使这 K 个数字的和最大。小花找到最大值就算获胜。

取值范围：

- `-2147483648 <= 单个数字 <= 2147483647`
- `0 < 数组长度 <= 10^6`
- `1 <= K <= 数组长度`

示例 1：输入 `[1,3,8,6,4,10], 3`，输出 `20`。长度为 3 的窗口和依次为 12、17、18、20，最大是 `[6,4,10]` 的 20。

示例 2：输入 `[1,2,3,4,5,6,7,8,5,4,3,2,1], 4`，输出 `26`。`[5,6,7,8]` 与 `[6,7,8,5]` 的和都是 26。

方法签名（Java，类名和方法名已指定）：`public long maxSumForMilk(int[] numbers, int k)`。

**参考答案**

用**滑动窗口**，时间 O(n)，空间 O(1)。

- 暴力法对每个起点重新求 K 个数的和，复杂度 O(n·K)。n 到 10^6 时最坏接近 10^12 次操作，会超时。
- 滑动窗口的思路：先算出前 K 个数的和作为第一个窗口。之后窗口每右移一格，减去滑出的 `numbers[i-k]`，加上滑入的 `numbers[i]`，用 O(1) 得到新窗口和，同时维护最大值。
- **溢出**：单个数可到 `2^31-1`，窗口和要用 `long` 保存。最多 10^6 个 int 相加，绝对值不超过约 `2^51`，`long` 足够。累加变量、最大值变量、返回值都必须是 `long`，否则会溢出出错。
- **初值**：最大值要用第一个窗口的和初始化，不能用 0。数组全是负数时，答案是负数。

```java
public class Solution {
    public long maxSumForMilk(int[] numbers, int k) {
        // 边界保护，题目保证输入有效，这里写得稳健些
        if (numbers == null || numbers.length == 0 || k <= 0) {
            return 0;
        }

        // 1. 第一个窗口 [0, k-1] 的和，用 long 累加
        long windowSum = 0;
        for (int i = 0; i < k; i++) {
            windowSum += numbers[i];
        }
        long maxSum = windowSum;

        // 2. 从下标 k 开始滑动
        for (int i = k; i < numbers.length; i++) {
            // 减去滑出的左端元素，加上滑入的右端元素
            windowSum = windowSum - numbers[i - k] + numbers[i];
            // 3. 更新最大值
            if (windowSum > maxSum) {
                maxSum = windowSum;
            }
        }
        return maxSum;
    }
}
```

### 2. 快递驿站计费系统：按房间号统计超时费用并排序输出

**题目**

开发一个快递驿站计费系统，根据一组快递存取记录，统计每位业主需要缴纳的总费用，并按总费用从高到低输出。计费规则：

1. 免费存放 12 小时，从存件时间开始计时。存放时间 = 取件时间 - 存件时间，总存放时间 ≤ 12 小时不收费。
2. 超出免费时间的，每 12 小时收取 1 元，不足 12 小时按 12 小时计算。例如存放 25 小时，超出 13 小时，收费 2 元。
3. 同一房间号的业主可能有多条存取记录，需把所有快递的超时费用累加得到总费用。

输入：存取记录列表，每条记录是 3 个非负整数：存件时间、取件时间、业主房间号。
输出：二维列表，每条是 `[房间号, 总费用]`。按总费用从高到低排序，总费用相同按房间号从小到大排序。

数据范围：`0 <= 存件时间 < 取件时间 <= 100000`，`100 < 房间号 < 10000`，`1 <= N <= 1000`。

示例 1：输入 `[[100,110,1111],[200,210,2222],[150,165,3333],[180,190,1111]]`，输出 `[[3333,1],[1111,0],[2222,0]]`。3333 存放 15 小时，超出 3 小时，收 1 元。其余都在免费时间内，费用相同的按房间号从小到大排，所以 1111 在 2222 前面。

示例 2：输入 `[[10,30,303],[25,50,303],[40,70,201],[60,90,201],[100,130,102],[150,180,102]]`，输出 `[[102,4],[201,4],[303,3]]`。303 的两条记录存放 20、25 小时，分别收 1、2 元，合计 3 元。201 和 102 的两条记录都存放 30 小时，各收 2 元，合计 4 元。

**参考答案**

这题是**模拟 + 哈希累加 + 多关键字排序**。遍历统计一次，再排序一次，时间 O(N log N)，空间 O(N)。

1. 对每条记录算 `hours = 取件时间 - 存件时间`。
2. `hours <= 12` 时费用为 0。否则 `exceed = hours - 12`，费用为 `ceil(exceed / 12)`。整数运算里写成 `(exceed + 11) // 12`，避免用浮点数。
   - 验证：25 小时，`exceed = 13`，`(13 + 11) // 12 = 2`。
   - 验证：恰好超出 12 小时，`(12 + 11) // 12 = 1`。超出 13 小时才进入第二个 12 小时。
3. 用字典按房间号累加费用。
4. 容易漏的点：**费用为 0 的房间也要出现在结果里**，所以要对每条记录都往字典里写入，哪怕费用是 0。示例 1 的输出里就有费用为 0 的房间。
5. 排序键用 `(-总费用, 房间号)`，一次 `sort` 同时满足费用降序、房间号升序。

```python
class Solution:
    def billing_system(self, recs):
        # 房间号 -> 累计总费用
        fee_map = {}

        for store_time, pick_time, room in recs:
            hours = pick_time - store_time  # 存放时间

            if hours <= 12:
                fee = 0
            else:
                exceed = hours - 12
                # 每 12 小时 1 元，不足 12 小时按 12 小时算：向上取整
                fee = (exceed + 11) // 12

            # 即使 fee 为 0 也要登记，保证该房间出现在结果中
            fee_map[room] = fee_map.get(room, 0) + fee

        result = [[room, total] for room, total in fee_map.items()]
        # 总费用从高到低，相同则房间号从小到大
        result.sort(key=lambda x: (-x[1], x[0]))
        return result
```

### 3. 统计单词在二维字符网格中出现的路径总数

**题目**

给定一个 `m x n` 的二维字符网格 `board` 和一个字符串 `word`，计算单词 `word` 在网格中出现的总次数。单词必须按字母顺序，通过水平或垂直相邻的单元格构成，同一个单元格在一条搜索路径中不能重复使用。

输入：`board` 是大写英文字母的二维列表，`1 ≤ m, n ≤ 10`。`word` 由大写英文字母组成，`1 ≤ len(word) ≤ 100`。
输出：单词在网格中出现的路径总数。

示例 1：`[[A,B,C,E],[S,F,C,S],[A,D,E,E]]`，`"ABCCED"`，输出 `1`。
示例 2：`[[A,A]]`，`"A"`，输出 `2`。两个 `A` 各自独立构成单词，共 2 条路径。
示例 3：`[[A,B],[C,D]]`，`"ABCD"`，输出 `0`。

**参考答案**

这是**网格 DFS + 回溯**，和 LeetCode 的"单词搜索"相比，区别是要**统计路径条数**，不是判断是否存在。

- **起点**：遍历所有格子，字符等于 `word[0]` 的格子都作为起点各搜一次，结果累加。
- **搜索**：从当前格子向上下左右四个方向走，要求下一个格子字符等于 `word[idx+1]`。
- **防重复使用**：进入格子时把它临时改成 `'#'`。题目里全是大写字母，`'#'` 不会与任何字符匹配。递归返回后恢复原字符，这样同一格子能被其他路径使用。这比额外开 `visited` 集合更省空间。
- **计数**：当 `idx` 到达 `word` 最后一个字符且匹配成功时计数加 1，然后返回，不再继续扩展。
- **不能找到一条就停**：与"判断是否存在"的写法不同，这里每个分支都必须搜完，所以不能用"找到就 return True 提前终止"。
- **示例 2 的情形**：单字符单词，`idx == len-1`，直接计数。这种情况不需要标记，也不需要往下走。

复杂度：每个起点第一步有 4 个方向，之后因为不能回头，每步最多 3 个方向，所以时间上界约 O(m·n·3^(L-1))，常写成 O(m·n·4^L)，实际有字符匹配和访问标记剪枝，远小于上界。空间是递归栈 O(L)，不含 visited 集合。L 最大 100，Python 默认递归深度够用。

```python
from typing import List


class Solution:
    def count_word_occurrences(self, board: List[List[str]], word: str) -> int:
        if not board or not board[0] or not word:
            return 0

        m, n = len(board), len(board[0])
        word_len = len(word)
        count = 0
        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        def dfs(r: int, c: int, idx: int) -> None:
            nonlocal count
            # 越界，或字符不匹配（已用过的格子是 '#'，也不会匹配）
            if r < 0 or r >= m or c < 0 or c >= n or board[r][c] != word[idx]:
                return
            # 匹配到最后一个字符，找到一条完整路径
            if idx == word_len - 1:
                count += 1
                return

            temp = board[r][c]
            board[r][c] = '#'          # 标记为本路径已使用
            for dr, dc in directions:
                dfs(r + dr, c + dc, idx + 1)
            board[r][c] = temp         # 回溯，恢复原字符

        for i in range(m):
            for j in range(n):
                if board[i][j] == word[0]:
                    dfs(i, j, 0)

        return count
```
