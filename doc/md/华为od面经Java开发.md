## 机考

**现场记录**

### 1. 8 位 LED 控制器

有 8 盏灯，编号 0 到 7，一开始全灭，记成 `00000000`。指令是连续的两字符一组，长度 0 到 1000：

- `Lx`：把第 x 盏灯点亮，状态置 1
- `Dx`：把第 x 盏灯熄灭，状态置 0
- `Tx`：翻转第 x 盏灯，0 变 1，1 变 0

按顺序执行完，返回这 8 位二进制对应的整数。

`L0L1L2T1` 的过程是：`00000000` → `L0` 得 `00000001` → `L1` 得 `00000011` → `L2` 得 `00000111` → `T1` 把第 1 位从 1 翻回 0，得到 `00000101`，也就是 5。`L0` 到 `L7` 全点亮，得到 `11111111`，也就是 255。

**参考答案**

用一个整数的低 8 位保存灯的状态，初始为 0。编号 x 对应「1 左移 x 位」，0 号是最低位，所以 `L0` 的值是 1。从左到右每次取两个字符：点亮做或运算，把这一位置 1；熄灭先把掩码取反，再做与运算，把这一位清 0；切换做异或。同一盏灯可以反复操作，`L` 和 `D` 是把该位置成固定值，只有 `T` 才翻转。空指令串直接返回 0。

时间 O(n)，n 是指令串长度。空间 O(1)，只保留这一个整数。

容易漏的是位的方向：把 0 号当成最高位，`L0` 会算出 128。另一处是 `T` 和 `D` 不能互相替换，灯已经是 0 时，`D` 仍然是 0，`T` 会变成 1。

### 2. 分辨率排序

若干个 `宽x高`，空格分隔，个数小于 10。先给每个分辨率定清晰度，再从高到低输出，仍用 `宽x高`，空格分隔。

档位门槛和高低是：

- 4K：3840×2160
- 2K：2560×1440
- 1080P：1920×1080
- 720P：1280×720
- 720P < 1080P < 2K < 4K

宽和高同时大于等于某一档的门槛，才算达到该档，并且取能够达到的最高档。低于 720P 的都归进 720P。已经达到 4K 的，再大也还是 4K。宽和高按题目给出的方向判断。`2600x1400` 宽过了 2K、高只有 1400，不到 1440，所以是 1080P。`2500x3200` 宽不到 2560，是 1080P。

排序先比档位，档位相同比面积（宽乘高），面积相同比宽，三者都是大的在前。档位、面积、宽都相同的情况题面没有再规定，用稳定排序保留输入顺序即可。

`3840x2160 3840x2161 3840x1080 2560x1440 1920x1080 1x1` 的结果是 `3840x2161 3840x2160 2560x1440 3840x1080 1920x1080 1x1`。前两个都是 4K，2161 的面积更大。`3840x1080` 面积大于 `2560x1440`，但后者是 2K，仍然排在前面。`2560x1440 4000x5000 5000x4000` 的结果是 `5000x4000 4000x5000 2560x1440`：后两个都是 4K 且面积都是 20000000，宽 5000 的在前。

**参考答案**

先解析出宽和高，从 4K 往下匹配第一个宽高都达标的档；一个都不达标就归 720P。再按档位、面积、宽度做降序排序。面积用 64 位整数，避免大分辨率相乘溢出。

时间 O(n log n)，空间 O(n)。n 小于 10，排序本身很短，容易错在定档：面积不能代替档位，宽高也不能对调后再去套门槛。

### 3. WIFI 设备网络规划

办公区是不超过 50×50 的网格。`#` 是墙，不能放 AP；`.` 是空地，可以放 AP。一台 AP 的覆盖是以自己为中心的 3×3，含上下左右和对角，用切比雪夫距离来说就是距离不超过 1。出界的部分直接去掉。3×3 里的墙也属于这台 AP 的覆盖区域。任意两台 AP 的覆盖区域不能有公共格子。求盖住全部空地的最少 AP 数；做不到就返回 -1。

第一行两个整数是行数和列数，后面每行一条网格。

```text
3 3
#.#
#.#
#.#
```

输出 1。AP 放在正中间 `(1,1)`，一块 3×3 把三格空地都盖住。

```text
4 3
#.#
#.#
#.#
#.#
```

输出 2。放在第 2 行只能盖住上面三格空地，最底下那格再放就会和它重叠。改放在第 1 行和第 4 行，覆盖的是前两行和后两行，互不重叠。

**参考答案**

这是带障碍的不重叠 3×3 覆盖，要的是最少块数。每台 AP 的中心必须是空地，占住网格内距离不超过 1 的所有格子，墙也占住；真正要被盖住的只有空地。

没有空地时答案是 0。有空地时做回溯：每次选「当前还能用的中心最少」的那格未覆盖空地，只尝试这些中心。选中后把它 3×3 里的格子标成已占用，递归，再撤销。已经用掉的 AP 数不小于已知最优解时剪掉；还可以用「剩下的空地除以 9」做下界。某个空地已经没有任何不冲突的中心，这条分支失败。全部方案都失败就返回 -1。

` .#. ` 这种一行三格、两边是空地、中间是墙的布局就是无解：两台 AP 都会占到中间的墙，又没有任何一个合法中心能同时盖住两边。这是按题意推出来的边界，原帖没有这个样例。

最坏时间是指数级。不重叠和「最少候选优先」能剪掉很多分支，但不能写成多项式。空间 O(nm)，用来记占用状态和每个空地的候选中心。

### 3. 实现订单系统的下单、发货、查询三个函数

**参考答案**

原帖只要求这三个函数，没有给参数、字段和失败时的返回约定。下面是一套能在 30 分钟内写完并讲清的内存实现，用来复习状态怎么走。

订单只有两种状态：已下单、已发货。下单生成唯一订单号并进入已下单；发货只允许已下单的订单，成功后变成已发货；查询按订单号返回状态。订单号用自增整数，放在 HashMap 里。单次下单、发货、查询平均都是 O(1)，n 笔订单的空间是 O(n)。

三个函数容易写漏的是失败分支：用户标识为空不能下单；订单不存在，发货和查询都要有明确结果；已发货不能再发货，状态也不能退回已下单。原帖没提并发，先把单线程状态机写对。如果面试官追问多线程，再把 Map 换成并发 Map，发货时对单笔订单做原子的状态切换。

```java
public class OrderSystem {
    enum Status { CREATED, SHIPPED }

    static final class Order {
        final long id;
        final String userId;
        Status status;

        Order(long id, String userId) {
            this.id = id;
            this.userId = userId;
            this.status = Status.CREATED;
        }
    }

    private final java.util.Map<Long, Order> orders = new java.util.HashMap<>();
    private long nextId = 1L;

    public long placeOrder(String userId) {
        if (userId == null || userId.isEmpty()) {
            throw new IllegalArgumentException("userId required");
        }
        long id = nextId++;
        orders.put(id, new Order(id, userId));
        return id;
    }

    public boolean ship(long orderId) {
        Order order = orders.get(orderId);
        if (order == null || order.status != Status.CREATED) {
            return false;
        }
        order.status = Status.SHIPPED;
        return true;
    }

    public String query(long orderId) {
        Order order = orders.get(orderId);
        return order == null ? null : order.status.name();
    }
}
```text

### 2. 无重复字符的最长子串

力扣第 3 题。原帖写的是「无重复字符的最大子串」，指的就是这道原题：给定字符串 `s`，求不含重复字符的最长子串的长度。`s` 的长度可以从 0 到 5×10^4，字符是英文字母、数字、符号和空格。

`abcabcbb` 的答案是 3，对应 `abc`。`bbbbb` 的答案是 1。`pwwkew` 的答案是 3，对应 `wke`。空串是 0。

**参考答案**

用滑动窗口。右端点从左扫到右，窗口里始终没有重复字符。用数组记下每个字符上一次出现的下标，初始为 -1。右端点的字符如果上次出现的位置还在窗口里，就把左端点移到那个位置的右边。然后更新这个字符的最新下标，并用 `右 - 左 + 1` 刷新最大长度。左端点只往右走。

暴力枚举所有子串是 O(n²)。滑动窗口每个下标最多进出一次，时间 O(n)。空间 O(字符集大小)；按这道题的字符范围，长度 128 的数组就够。字符如果会超出 ASCII，把数组换成哈希表，空间变成 O(min(n, 字符集大小))。

力扣要的是长度。面试官如果要子串本身，在刷新最大值时记下左右端点，最后再截取，复杂度不变。

```java
public int lengthOfLongestSubstring(String s) {
    int[] last = new int[128];
    java.util.Arrays.fill(last, -1);
    int left = 0;
    int best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (last[c] >= left) {
            left = last[c] + 1;
        }
        last[c] = right;
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

### 4. AOP 是什么

**参考答案**

AOP 是面向切面编程，把日志、鉴权、事务、监控这类横切逻辑从业务方法里抽出来，在调用进入目标方法时织入。Spring 用切点匹配哪些方法，用前置、后置、异常和环绕通知规定织入时机。类有接口时常用 JDK 动态代理，没有接口时用 CGLIB 生成子类。增强只发生在经过代理对象的调用上。

同一个类里用 `this` 调用自己的方法，走的是原对象，方法上的事务或日志注解不会生效。切面加在外部进来的 public 方法上。代理和目标不是同一个对象，注解没生效时先确认注入的是不是代理。

### 5. 面向过程、面向对象、面向接口三种编程思想是什么

**参考答案**

面向过程把程序看成按顺序执行的步骤，数据和函数分开，适合步骤固定、分支少的小问题。面向对象把数据和行为收进对象，用封装藏内部状态，用继承复用共同部分，用多态让同一次调用落到不同实现，适合规则会变的业务。面向接口再约束依赖方向：调用方只依赖方法契约，不依赖具体类。Spring 里注入接口而不是实现类，就是为了换实现时不用改调用方。

三者是一层层收束。方法内部仍是过程，对象之间通过接口协作。面向接口解决的是依赖落在谁身上；多写一个 interface、调用方却仍然 new 具体类，依赖方向没有变。它和 AOP 不是同一件事，AOP 解决的是横切逻辑放在哪里。

### 6. MySQL 建立联合索引的原则和注意事项

**参考答案**

联合索引是一棵 B+ 树，键按建索引时的列顺序拼在一起。查询要能用上从最左列开始的连续前缀，跳过左边的列，右边的列就不能用来缩小查找范围。列顺序按真实 SQL 定：等值过滤里区分度高、又经常一起出现的列放左边，范围条件放后面。`a = ? AND b > ? AND c = ?` 这种条件，`(a, b, c)` 里的 `c` 不能再缩小索引范围。

建的时候对着 WHERE、JOIN、ORDER BY 看，不要按感觉排列。对列做函数或发生隐式类型转换，这一列以及它右边的列会退出查找。查询的列都能从索引取出时，可以避免回表，这是覆盖索引。同一组列不要再建一个顺序相反、查询却用不上的索引。每多一个联合索引，写入都要维护，列不加没有对应 SQL 的长度。

## 综面

**现场记录**

大约 30 分钟。一直在问项目和毕业设计：先介绍内容，再问难点和解决办法，然后追细节。中间夹了下面这些常规问题。原帖的感受是压力很大，问题会不断延伸。

### 1. 介绍项目的内容、难点和解决办法，并回答细节追问

**答题思路**

综面不要求展开框架和源码，但会顺着一句内容往下问。准备一条能连问四五次的线。

1. 内容按「背景、你做的部分、做成什么样」讲，两分钟内。名称和一面保持一致。
2. 难点讲一个，解决办法按时间顺序，每一步都能被追问「当时为什么这么做」。
3. 细节预先想好四件：边界在哪、和谁配合、失败了用户看到什么、你怎么确认做好了。问到哪件答哪件。
4. 被问到没做过的细节，说清你知道到哪一层，再补你实际核过的部分。不要为了接话现编模块。

### 2. 介绍毕业设计的内容、难点和解决办法，并回答细节追问

**答题思路**

和项目分开讲，避免两段经历合成一个故事。简历没写，更要能从题目讲到你自己的工作。

1. 题目、要解决的问题、你的工作量，三句说完。
2. 难点选导师也可能知道的那个，这样追问时事实对得上。
3. 解决过程里如果有导师的建议，说明建议是什么、你采纳后改了什么。不要把指导说成自己独立完成，也不要把自己的工作说成导师做的。
4. 准备进度：开题、中期、当前结果各一句话。问「现在能不能演示」时，按真实情况答。

### 3. 大学期间遇到的最困难的事，或者最让你骄傲的事

**答题思路**

HR 如果已经听过一件，这里换另一件。两件都按同一个骨架，临时换故事容易前后矛盾。

1. 开头一句点明是困难还是骄傲，并给出时间，例如大四上学期。
2. 中间三步：当时的限制、你的行动、可核对的结果。
3. 困难题收到「我学到了哪条以后还会用的做法」。骄傲题收到「这件事哪部分不能换成别人来做」。
4. 不评价同学或老师。综面会把这句话追到毕设和多任务那些题上。

### 4. 怎么学习 Java 的

**答题思路**

用真实时间线，和「大四才开始、没有实习」保持一致。

1. 按阶段讲：语言和集合，然后 Web 和数据库，然后一个能跑起来的项目，最后用项目里的问题回头补基础。
2. 每个阶段说你怎么判断自己会了：能写出来，能讲给别人听，能自己改掉一个 bug。
3. 书和教程只报真用过的。没读完就说读到哪一章、它帮你解决了项目里的哪个问题。
4. 主动说出缺口：缺少实习，所以用项目和毕设补「从需求到能运行」这一段。

### 5. 最近在看什么书，在学什么技术

**答题思路**

只准备最近一段，能接受追问「看到哪里了」。

1. 一本书加一项技术就够。书名必须是你真的在看的。
2. 三句结构：为什么看，目前看到哪，它改变了你哪一种写法。
3. 最近没有看书，就讲一个你正在补的点，并举项目或练习里的一个例子。
4. 不要报一本只听过名字的书。综面会马上问目录或某一个概念。

### 6. 有没有感受到毕业设计导师的不公平对待

**答题思路**

这题看你怎么处理人际关系。结论要基于事实。

1. 没有这样的经历，就直接说没有。可以补一句导师要求严，但任务和评价标准说得清楚。
2. 如果真有，只讲一件能核对的事：任务分配、评分标准或沟通方式。说你怎么确认、怎么沟通、毕设后来怎么完成。
3. 话停在做法上：把预期写成节点，有分歧就问清标准。不评价导师的为人，也不扩散到其他同学。
4. 没有事实时不要编冲突。这轮会追问细节。

### 7. 手头已经有好几个任务，还不断被派发新任务，怎么办

**答题思路**

讲排序和反馈，不讲「我会熬夜全部做完」。

1. 先把已有任务和新任务的目标、截止时间列出来，确认冲突是真实存在的。
2. 按影响和期限排序，说出先交付哪一个最小结果，哪一个可以后移。
3. 做不到的部分当场说明：延期、加人，还是缩小范围，并给出你建议的方案。
4. 例子用课程、毕设和求职准备这类你真实同时遇到过的事。没有同时爆过，就只讲这个排序办法，不编一次项目事故。

### 8. 压力非常大的时候怎么排解

**答题思路**

结合学生阶段的真实压力，例如毕设、课业和找工作叠在一起。办法要是你用过的。

1. 先分开压力从哪来：不会做、时间不够，还是标准不清楚。三种处理不一样。
2. 当天只留一块能做完的。卡住时写下已知和未知，找同学或导师对齐，不一直耗在同一处。
3. 恢复方式说一个你真实在用的，例如固定睡眠、运动，或做完一块就离开屏幕。说清它帮你恢复到能继续工作。
4. 收尾回到交付：压力在，节点还是要可见。不说硬扛，也不把情绪交给别人处理。
