# 吉利汽车 ai agent技术面一轮过

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 面试感受

这面真不水，不是背八股那种。面试官明显是自己踩过 Agent 坑的人，问到 Harness、Codex、图+向量混合检索就知道了，不是来听你吹 LangChain 的。答得出来就是能打，答不出来马上往深里刨。不考算法反而更累，因为全在考你有没有真把 Agent 跑进生产。

整体下来我觉得自己项目讲得还行，RAG 和意图识别没虚，多 Agent 状态隔离也接住了；图数据库那块被追了两层，算是有点狠。但一轮过就说明对方要的是能落地的 Java + Agent 工程仔，不是调 API 的。

## 一面

### 1. 自我介绍

**答题思路**

控制在一两分钟，按「方向 → 一个项目 → 和岗位的关系」讲完就停。

1. 一句话说你在 Agent 工程里写的是哪一层：Java 服务、编排、检索、工具执行或运行时。年限用你的真实情况，职级和薪资不用提。
2. 只展开一个你负责过的项目：用户要完成的任务、你写的那段链路、结果用评测集、失败分类或人工接管的变化来证明。没有把握的数字就不说。
3. 收到这场面的问法上：后面会追意图怎么分流、检索和图怎么配合、多 Agent 状态怎么隔开。介绍停在你亲自做的那个取舍上，把追问让出来。

### 2. 讲一个你做过的最复杂的 Agent 或 AI 应用项目

**答题思路**

按「约束 → 职责 → 三个取舍 → 一个坏例」讲。不报公司、项目代号和团队规模。

1. 先说任务为什么复杂：目标清楚，但路径事先写不全，中间有记忆、多步工具和写操作。步骤固定的流水线不要拿来充这个项目。
2. 职责只圈你写的部分，例如意图短路、离线入库、工具网关或状态隔离。框架名一句带过。
3. 准备三个会被追问的取舍：规则和模型怎么分工、为什么向量之外还要图、Worker 为什么只能看见完成本步所需的上下文。每个都说备选方案，以及你放弃它的原因。
4. 主动交一个线上坏例：哪类问题答错过，你改的是切分、过滤、幂等还是确认，改完用同一批问题复查。图如果被追，先讲存的关系，再讲这些关系怎样限制向量候选集。

### 3. Java 侧怎么支撑 Agent 服务的高并发工具调用，线程池和异步编排怎么设计

**参考答案**

工具调用是慢 IO，还可能有副作用。入口线程只做鉴权、限流和建 trace，然后把这一轮交给编排。

模型 HTTP、向量检索、外部工具分成独立的有界舱壁，解析、校验和融合打分留在小的计算池。某一类下游变慢，只堵住自己的池。阻塞 IO 用虚拟线程或非阻塞客户端承载，容量看连接池、信号量和对方配额。虚拟线程进了本地方法，或在较旧 JDK 的 `synchronized` 里停留，仍会占住载体线程。

无依赖的只读工具并行，写操作按依赖串行。每个工具的超时短于整轮截止时间，取消要传到 HTTP 调用。队列有界，满了就拒绝并降级，避免 `CallerRuns` 把阻塞送回入口。trace 跨过异步边界传下去。写超时视为结果未知，先按幂等键查询再决定重试。

### 4. Agent 和 AI 工作流到底有什么区别，什么场景不该上 Agent

**参考答案**

工作流的路径由人预先定好，分支、重试和停止条件由编排器执行，模型只在节点里做分类、抽取或生成。Agent 由模型选择下一个工具、参数和停止时机，运行时负责循环、预算和约束。

路径可以画全、步骤要可审计、延迟和费用要稳定的任务用工作流，例如审批、计费、固定质检和控车。下一步取决于刚查到的内容、分支事先写不全的任务，才适合有步数和费用预算的 Agent。

开放任务里的下单、外发或控车，收回到确认节点。外层用工作流划分阶段，只在开放子任务里跑 Agent。

### 5. 意图识别在你项目里是规则、分类模型还是 LLM 路由，各自边界在哪

**参考答案**

三层按确定性从高到低短路。面试时先讲你线上真实的短路顺序，再讲边界。

规则负责可枚举、要稳定的说法：明确车控、固定口令、安全词、能抽全的槽位。命中明确模式就可以执行只读动作，或进入确认。一句里有多个动作时，单条规则不能把整句吞掉。规则挡不住改写和长尾。

分类模型负责标签集稳定、要低延迟的中频意图，输出意图和粗槽位。新意图要重新标注，多意图、指代和「上次那家」这类说法很弱。分数低于阈值就继续往下，不要硬分一个类。

LLM 路由负责模糊、多意图、必须结合记忆才能判断的句子。输出用 schema 约束，低置信或必填槽缺失就澄清。它慢、贵、不稳定，路由结果只是候选，写操作仍要过权限。每一层命中都记下来，反复落到 LLM 的模式再沉成规则或训练样本。

### 6. 模糊意图比如“下班接娃再去上次那家川菜馆”怎么拆任务、补槽位、调记忆

**参考答案**

先拆成有依赖的子任务，再逐个补槽。记忆只提供候选，写操作等关键槽确认后再执行。

「下班」查日历或通勤设置得到出发时间。「接娃」要补孩子、地点和时间窗，缺了就停下问。「川菜馆」带指代，要和接娃地点、到达时间一起算路线。接娃地点不确定时，不订座，也不开始导航。

槽位按本轮原话、当前行程、长期记忆、主动澄清的顺序补。必填是接娃地点、时间窗、餐厅和人数。路线偏好可以沿用历史。订座有副作用，即使用过也要确认。

家庭成员、学校和常去地点放在画像或图里。上次用餐用「川菜、本人、近期」过滤后再召回。两家都像时列出候选。确认后的结果写回记忆，下一次「上次」才有依据。指代要落成显式槽位，整句原话不能直接当工具参数。

### 7. AI 工作流里的节点失败、超时、补偿、人工介入怎么落地

**参考答案**

每个节点做成可重放的幂等步骤，状态机持久化。失败分成可重试、要补偿、必须人工三类。

节点超时短于整条流程的截止时间。读超时按退避重试；参数错误直接失败。写操作超时表示结果未知，先用幂等键查询下游，确认没有成功再重试。只对网络错误、429、5xx 重试，并限制次数。

有副作用的节点成功后登记补偿。订座成功但后续支付失败，就发取消订座。补偿同样要幂等、可重试；补偿再失败就进死信并告警，不能无限打下游。

人工介入是一个持久化的等待状态：冻结输入、已完成节点的输出和失败原因。人补槽或改决策后从断点继续。谁改了哪个字段要审计，等待超时要升级。进程重启后靠检查点恢复。至少一次执行加上幂等，才能安全重放。

### 8. RAG 离线链路怎么设计：解析、清洗、切分、元数据、向量化、索引

**参考答案**

离线链路要把文档变成可过滤、可追溯、粒度适合回答的切片。手册和制度文档里，解析质量决定上限。

解析按版式走，保留标题层级、页码和表格，扫描件单独 OCR。清洗去掉页眉页脚、重复目录和乱码，表格保留表头。切分优先沿标题、步骤和表格边界，每片带上标题路径。

元数据至少有文档 id、版本、生效时间、车型或配置、章节、权限和语言。查询和文档使用同一嵌入模型，切片里带上标题路径，减少「这段离开章节就看不懂」。按内容哈希增量嵌入，未改的片跳过。

向量索引和标量过滤一起建，需要精确词时另建 BM25。文档改版用版本过滤或别名切换，避免新旧切片同时被召回。写入成功后，用一批真实问题看该中的片在不在前排。

### 9. 长文档切分用固定长度、语义切分还是结构感知切分，重叠区怎么定

**参考答案**

有标题、步骤、列表或表格时用结构感知切分。没有结构的长叙述再用语义切分。固定长度只做兜底，并作为单片上限。

结构感知沿标题和自然段切开，表格、代码和连续步骤保持完整，标题路径写进每片。语义切分比较相邻句子的相似度，在话题转折处切开，同时设最大长度。固定长度实现简单，但会把条件和步骤切散。叙述文本常见是几百 token 一片，用真实问题的命中情况来调。

重叠只为接住被边界切断的那一两句，常见留大约一成到两成，或者重叠相邻的一两句。已经切在自然边界上时，重叠可以很小，章节信息放进元数据。重叠过大，召回结果会反复占用上下文。

切片太小会丢掉「仅限某配置」这类条件，太大又把关键句淹没。小片负责命中、回带父段负责生成，是常见补救。效果看答案所在的片有没有进前排。

### 10. 向量数据库选过 Milvus、Qdrant 还是 PgVector，写入、召回、扩容、过滤怎么权衡

**参考答案**

三者都能做近似近邻。先看事务、规模和运维，再选引擎。

pgvector 适合中等规模、业务条件已经在 PostgreSQL 里的场景。车型、权限、版本可以和向量一起提交。过滤很严时，先近似召回再过滤会把结果滤空，要让过滤参加索引扫描，或先按结构化条件缩小范围。量上来以后主要靠分区和垂直扩容，索引构建要单独压测。

Milvus 适合更大规模和多副本检索。按车型或业务线分区，用切片 id 幂等 upsert，标量字段参与过滤。刚写入能否被搜到取决于一致性级别。组件多，运维更重。

Qdrant 适合过滤条件复杂的场景，payload 过滤可以和向量搜索一起做。按 point id upsert，分片键避开热点。

三家写入都走批量、可重跑。车型、权限、有效期在召回时过滤。量化能省内存，开不开用业务集的召回结果决定。

### 11. 图数据库在 Agent 里用来存什么，车辆功能关系、用户偏好、知识图谱怎么和向量检索打通

**参考答案**

图存关系和约束，向量存语义相近的原文。Agent 先用图圈定合法范围，再用向量找说法接近的证据。

车辆功能图存车型、配置、功能、可执行动作和前提，用来判断这台车能不能做，以及工具参数是否合法。用户偏好图存家庭成员、常去地点和历史选择，并带时间，用来补槽。知识图谱存现象、原因、排查步骤和手册章节，用来做有条件的多跳。

打通分四步。原话先链接到图上的车型、功能或故障码，词典和实体向量一起用。沿允许的边类型做有限跳，并带上车型版本，得到文档、章节或功能 id，作为向量检索的过滤条件。向量命中一个零件或步骤后，再取图上的相邻步骤补充上下文。路径距离和关系类型作为重排特征。

边要有版本和生效条件，新旧车型不能走同一套关系。跳数和边类型要限制，无关邻居不能整包塞进提示词。

### 12. 混合检索里向量、BM25、图检索三方结果怎么归一化和重排

**参考答案**

三路原始分不能直接加权。余弦、BM25 和图上的路径权重不是一个量纲。各路先取比最终条数更宽的候选，权限、车型和版本在召回时就过滤掉。

合并用倒数排名融合：一条结果在某一路排第 r 名，就贡献 `1/(k+r)`，多路命中相加。常数 k 常用 60，只用名次，避开分数不可比。同一切片多路命中要去重并保留来源，融合分自然提高。候选集很小时，对原始分做 min-max 会夸大差距。

融合后的前几十条再交给交叉编码器重排，并加上车型是否精确命中、时效、图前提是否满足。型号和故障码让词法一路参加融合，改写和口语更依赖向量；权重加在排名项上，用评测集确定。图负责关系约束，路径特征参与重排。

### 13. 多 Agent 里 Orchestrator 和 Worker 怎么分工，上下文和状态怎么隔离

**参考答案**

Orchestrator 负责拆解、选择 Worker、检查子结果和汇总，不直接执行高危工具。Worker 按单一职责工作，例如检索、行程或只读车况，只拥有该角色的工具白名单。

共享上下文只有用户目标、已确认槽位、全局约束和预算，例如车型、权限和截止时间。Worker 的工具原文、中间推理和其他 Worker 的失败细节留在本地，回传结构化结果：结论、证据 id、置信度和缺的槽。这样既隔离信息，也避免把用户目标弄丢。

状态放在会话存储里，按会话和 Agent 分区。Worker 写自己的草稿，提交时才由 Orchestrator 合并。两个 Worker 改同一槽位时按优先级合并，不能后写覆盖已确认的值。子 Agent 的深度、步数和工具次数有预算。记忆和工具结果按当前用户过滤，一个 Worker 不能看见另一个用户的数据。

### 14. Agent 调工具时参数校验、权限、幂等、超时、降级、审计怎么做

**参考答案**

模型只提议调用。校验、授权、幂等、超时、降级和审计都在执行前的网关里完成。

参数按 JSON Schema 校验类型、枚举、范围和必填，失败就把结构化错误还给模型，不执行半截参数。模型多传的字段丢掉。用户、车型和租户由服务端注入。

工具白名单按人、角色和车辆配置计算。控车、下单、外发再过策略，需要时在可信界面上确认。资源 id 在 API 和检索层再鉴权一次。

写操作的幂等键由会话、工具名、规范化参数和步骤号算出，下游按键去重。单工具超时短于整轮截止时间；写超时视为结果未知，先查询再重试。

工具不可用时返回明确失败和替代路径，例如澄清或转人工。降级不能改调权限更高的工具。审计记录提议参数、网关实际下发的参数、结果码和 trace，敏感字段脱敏。

### 15. Harness 工程里消息循环、工具注册、上下文拼装、沙箱、观测各自负责什么

**参考答案**

Harness 是模型外面的运行时。模型只产生下一条消息，循环、工具、上下文、隔离和记录由代码强制执行。

消息循环读取模型输出，遇到工具调用就执行并把结果送回，直到给出最终回答，或步数、token、时间预算耗尽。它负责停止，包括拦住重复的同一调用。

工具注册保存名称、schema、权限、超时和是否有副作用。当前角色只能看见自己的工具清单。上下文拼装按预算组装系统约束、已确认状态、检索证据和近期对话，旧的工具结果改成摘要。密钥和身份不放进可由模型决定的文本里。

沙箱执行命令和代码：文件路径白名单、网络默认拒绝、资源有限额，工作目录可以丢弃。观测把每一步的工具入参和出参、token、耗时、停止原因串进同一条 trace，用来区分模型选错和工具失败。停止条件、权限和沙箱写在运行时里。

### 16. Codex 或 Coding Agent 实战里，你是怎么让它读代码、改代码、跑测试、防它乱删文件的

**参考答案**

给它一个可丢弃的工作副本。先只读定位，改动限制在任务路径内，测试命令和删除由运行时控制。

读代码靠目录、符号和检索定位，再按行范围打开相关文件。密钥文件默认不可读。

改动以补丁提交，限制在声明过的路径里。路径要规范化，挡住写到工作目录外面。

测试在沙箱里跑。命令由 Harness 固定，或从仓库已有的测试脚本里选，网络默认关闭，日志截断后回给模型。以进程退出码为准，步数用完就停。

删除默认拒绝。工作目录用单独的 git worktree 或副本。删除换一种写法就能绕过黑名单，所以命令走白名单，并且只能落在任务路径里。diff 里删除量异常就中止，交给人确认。是否完成看退出码和 diff。

### 17. Prompt 注入和工具越权在车机或企业内部场景里怎么防

**参考答案**

用户原文、检索片段、地点名和工具返回都当成不可信数据。权限按服务端身份计算，模型的话不能把权限扩大。

检索内容放进明确的数据区，其中出现的指令不执行，也不因此触发控车、外发或改配置。关键词扫描只能做辅助，挡不住改写后的间接注入。高危动作是否执行，由网关策略和人在可信界面上的确认决定，确认动作不交给模型。

工具按最小权限拆开：只读车况、手册检索、导航、控车、企业知识库互不借用身份。每次调用带服务端注入的用户、车辆和租户，检索过滤也带这些条件。模型传来的资源 id 要再鉴权。记忆按用户隔离，日志里不串别的用户内容。

检索之后立刻外发、或连续碰高危工具，按异常组合告警，并可以切断该会话的写工具。能挡住越权的是网关、数据过滤和可信界面上的确认。

### 18. Agent 线上出问题，trace、日志、token 成本、失败率、人工接管率怎么看

**参考答案**

一次用户任务串成一条 trace：会话、每一轮模型、每次检索和工具。卡在意图、召回还是工具，看跨度和停止原因，并记下模型名。

日志用结构化字段记工具名、错误码和下游请求 id。提示词和用户内容脱敏、采样，不全量当普通日志留存。

token 成本按会话、意图和模型拆开输入与输出。重点看重试有没有把一次任务放大成多次生成。单会话有预算，超预算改为澄清或转人工。

失败率按原因拆开：模型没有给出可执行结果、工具超时、校验拒绝、用户放弃。工具超时和参数不合法的处理不同，一个总失败率不够。

人工接管率的分子是转入人工处理的任务，分母是进入该意图的任务，和自动解决率一起看。升高时先分清是缺槽没问清，还是工具失败。平均值会掩盖某个车型或某个工具，线上坏例要能回放。
