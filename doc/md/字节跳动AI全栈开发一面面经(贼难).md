# 字节跳动AI全栈开发一面面经(贼难)

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 一面

### 1. 实习拷打

**答题思路**

这一项没有单独题干，意思是面试官顺着实习往下追。只讲一条你真正做过的链路，讲完就停。

1. 先划清边界：你负责哪一个模块，导师或正式员工已经定好的部分是什么。没上线、没接真实用户，第一句就说清楚。
2. 用一次请求把路径走完：入口、你改过的代码、状态存在哪、失败时你亲眼看到的现象。
3. 只留一个你自己做的决定：备选方案是什么，为什么放弃，用什么验证。验证要能对上测试或日志。
4. 数字只用你自己量过的。记不清就说记不清，不要把课程作业说成大规模上线。
5. 后面如果追到检索、幻觉或耗时，沿着同一条链路答，不要中途换成另一个项目。

公司、职级和项目名称用简历上的原词，不要临时编一套。

### 2. 项目里你遇到最大的难点是什么？怎么解决的？

**答题思路**

只讲一个难点。现象、失败的第一版、改动、验证，按这个顺序，控制在两三分钟。

1. 现象要具体：哪一类请求会错，错成什么样。例如召回了字面相关但答非所问的片段，或下一步用了上一步编出来的实体。用你项目里真实发生过的那一种。
2. 说明第一反应为什么不够。例如只改提示词、只把 top-k 加大、只让模型自己检查。
3. 改动讲机制：你改的是判定、状态、工具契约，还是评测。说出你因此放弃了什么，例如少了自由发挥，多了一次追问。
4. 结果用你能量到的口径：同一批坏例里还剩多少、延迟变了没有。说不出口径，就不要报百分比。
5. 收在「如果重做会改哪里」。这个难点要和你后面讲的检索或 Agent 是同一件事，避免前后两个系统对不上。

### 3. RAG 针对模糊提问做精准检索：如何识别用户问题的模糊度？完整处理流程是什么？

**参考答案**

模糊度要同时看缺不缺槽、检索有没有把握，不能只让模型打一个分。缺了会改变检索目标的槽，就追问；只是说法和文档对不上，才改写后再检索。

识别分三层。规则先看过短、没有时间或地点或对象、指代落空、一句话里有两个意图。再用约束输出列出缺失槽和两种可能解释，这一步不许它直接作答。第一次召回之后看分布：最高分很低、前两名几乎一样高、或者结果落在互相矛盾的主题里，都算没有把握。这些阈值要用标注过的问题标定，没有通用常数。

流程是：先做查询规范化，再做上面的判定。缺校区、缺上课时间这种槽，本轮只问一个问题，不检索。意图清楚、只是用词不同，就生成两三条更具体的改写，分路召回、融合、重排。重排之后分数仍然拉不开，就拒答或再追问，不要把弱相关片段交给生成。生成时只能引用重排留下的片段。

凡事都追问，体验会很差；凡事都改写，会把另一种意思检索进来。容易漏的是只相信模型的「我听懂了」。缺约束时它经常很确定，检索分差才是必要的第二信号。

### 4. 关键词检索存在关键词漂移问题，如何平衡向量匹配和关键词匹配？

**参考答案**

关键词漂移指用户的词和文档的词对不上，或者查询扩展把原意带偏。词法检索会咬住表面词，向量检索又会放过必须精确命中的编号和专名。两边不要合成一个固定权重。

词法分和向量分的量纲不同，不能直接相加。各自取回一批候选，用名次融合，或先把分数归一化再加权。查询本身要分类：错误码、教室号、很少见的专名，提高词法权重，甚至把原词做成硬过滤；口语和同义说法，提高向量权重。扩展词只加少量有把握的同义词，原词仍要参与匹配，避免越扩越偏。

融合之后用交叉编码器重排，让模型同时看到两路候选，比手调一个全局比例更稳。校区、时间这类约束用元数据过滤，放在融合之前，不要指望向量自己过滤。

容易漏的是把向量权重调到极大。精确条件一旦被「语义相近」冲掉，错文档会更稳定地排在前面。词法保底和硬过滤要留下。

### 5. 混合检索 RRF 的加权参数 k，你是怎么调的？业务上有没有自定义调整？

**答题思路**

先把参数说准，再说你真实做过的调法。没有网格搜索，就说用的是实现里的默认值，不要编一个「最优 k」。

1. 写出融合公式：文档得分是各路 `权重 / (k + 名次)` 之和，名次从 1 开始。k 不是向量和关键词谁更重要，它只决定名次拉开的幅度。
2. 说明候选从哪来：每一路先取固定条数，再融合。这一步的条数是 top-k，和 RRF 的 k 不是同一个参数。
3. 调参过程按你的实际情况讲：有标注问题就扫一组 k，看的是 Recall 或 nDCG，并且把精确查找和口语查找分开看。只在实习环境里离线跑过，就不要说成线上 A/B。
4. 业务上的自定义，优先讲这三件里你真的做了的：某一路的权重、按查询类型切换权重、用校区或时间做硬过滤。没做就说没做。
5. 如果面试官问「为什么不直接加原始分」，回答是两路分数不可比，名次融合不用先校准分数。

论文和不少检索实现把 60 当作 k 的起点，它不是你的业务最优值。

### 6. 向量检索更准时，k 值应该调大还是调小？

**参考答案**

共享的 RRF 常数 k 应该调小，但只调 k 并不会让融合偏向向量。向量更准确时，还要单独提高向量这一路的权重。

得分是 `1 / (k + 名次)`。k 变小，前列和后列的分差变大，各路的头部更说了算。k 为 10 时，第 1 名大约是第 20 名的 2.7 倍；k 为 60 时大约只有 1.3 倍。向量如果经常把对的文档排进前几名，小 k 能保住这个优势，不让长尾把名次抹平。k 变大时，低名次的影响力上升，融合更接近「谁在更多路里出现过」。

k 对每一路一视同仁。关键词漂移造成的错误第 1 名，在小 k 下会被同样放大。要偏向向量，使用加权形式 `权重 / (k + 名次)`，提高向量路的权重，或者在口语查询上降低词法路的权重。

```python
def rrf(rankings, k=60, weights=None):
    scores = {}
    for i, ranked_ids in enumerate(rankings):
        weight = 1.0 if weights is None else weights[i]
        for rank, doc_id in enumerate(ranked_ids, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + weight / (k + rank)
    return sorted(scores, key=scores.get, reverse=True)
```

这里的 k 只是名次平滑项，常见实现用 60 做起点。它不是每一路召回多少条。召回条数加大，进融合的噪声也会变多。

### 7. 查空教室并推荐火锅时，多轮推理和任务调度是怎么做的？

**参考答案**

这种任务应该用带类型的状态图来调度，而不是让一个 Agent 自由决定何时调用工具。教室编号只能源自教室接口，火锅查询只读已经校验过的状态。

状态里保留约束、已校验教室、火锅候选和还缺的槽。每一轮先补槽：时间、校区、人数缺了，就追问并结束本轮，不调用工具。槽齐了再查教室，结果做结构校验后写入状态。火锅要「离这间教室近」时，必须等教室坐标；用户已经指定了商圈，两路可以并行。查无教室是正常业务结果，不重试；超时和服务端错误才按次数退避。同一组参数在本轮内做幂等缓存。

跨轮保存这份状态。「换一家火锅」只重跑火锅节点，不从历史对话里重新猜教室。步数、单次工具超时和总预算要写死。

难点是依赖和失败边界。模型容易把两件事并成一次自由工具循环，没有教室时仍去推荐「那附近」的火锅。图比自由推理僵硬，但这两个工具的依赖是清楚的，僵硬正好用来截断幻觉。措辞可以交给模型，店名和教室号从状态拷贝。按你真实实现讲；没有依赖切断，就不要说成已经做过。

### 8. 前序 Agent 编造了不存在的教室（幻觉），下一步仍直接做火锅推荐。幻觉的链式积累怎么处理？

**参考答案**

下一跳只能消费工具返回里校验过的字段。编造的教室不能进入火锅查询。

自由文本是链式幻觉的载体。前一步说「已经找到 A301」，后一步会把它当成事实。交给下游的状态应该是结构化的：教室编号、坐标、工具调用编号、是否已校验。已校验的条件是编号出现在这次工具的 JSON 里，并且满足时间和校区过滤。对不上就清空教室，走「没有教室」的分支，禁止用这段话去调用火锅接口。

回复也尽量不要让模型改写编号，实体从状态填进模板，模型只组织语言。校验失败就停，不要先推荐再说不确定。被拒绝的编造编号记进评测集。

容易漏的是只在最终回答上做引用检查。中间步骤已经用假教室查过火锅，副作用已经发生。

### 9. 如果检测 Agent 自身也会幻觉、误判，工程上怎么解决？如何保证检测 Agent 可靠？

**参考答案**

能用代码判定的事实不要交给检测 Agent。检测模型只处理代码判不了的残余，失败、超时或解析不了都按不通过，后续有副作用的节点不执行。

教室号是否来自工具、时间是否落在请求范围内、坐标是否是接口字段，都是包含关系和结构校验，写成函数就能单测。检测模型若和执行模型同一族、看同一段上下文，会重复同一种编造；再投票也消不掉这种相关错误。它说「我核对过了」也不算核对。

仍然需要模型的部分，例如措辞是否答非所问，输入收成「工具原文加待核对的说法」，要求指出原文位置，指不出就判失败。温度取 0 只能减少随机性，不能制造事实。不给检测模型工具，输出必须是结构化的通过或不通过。

可靠性来自评测：准备「工具结果里真有的教室」和「模型常编的教室」两组回归用例。线上如果模型和校验函数不一致，以代码为准，并把这个样本加回评测集。

### 10. 项目基于 GPT-5.4，有没有真实用户大规模上线使用？

**答题思路**

第一句就回答范围：公开上线、只在内部或同学里用过，还是离线演示。没有真实用户，就不要把演示说成大规模。

1. 有线上用户时，只讲你能对上的口径：谁在用、用了多久、你看过的请求量或失败量。说不出统计窗口就不要报 DAU 或 QPS。
2. 模型版本单独说：调用的是哪一家的哪个接口，有没有固定版本。版本新，不能证明服务已经能承载真实流量。
3. 没上线时，主动补三件还缺的事：身份和配额、内容安全、离线评测有没有覆盖坏例。这三件用你项目的真实缺口，不要临时编一套已上线架构。
4. 准备被追问费用、超时和供应商故障时你怎么降级。没做降级就说没做。
5. 和简历里的耗时、检索效果使用同一套环境，避免线下数字和线上范围混在一起。

### 11. 简历写测试服务耗时缩短 40%，是线上数据还是个人自测？

**答题思路**

第一句说明 40% 的来源：线上对比、同一环境改造前后，还是自己的本地测试。是本地测试就明确说是本地测试。

1. 定义耗时：哪一个服务、哪一段路径、看的是平均值还是尾延迟，数据量是否相同，缓存是冷是热。
2. 本地测试要能复述方法：同一台机器、改动只有一处、跑了多少次。次数很少或波动很大，就不要把 40% 说成稳定收益。
3. 原因只讲一个主因，例如少了一次远程调用、批次变大、或避开了重复检索。不要把所有优化叠在这一个百分比上。
4. 现在复现不了，就当面收回这个数字，改讲你仍然确定的现象。守不住的简历数字比慢更减分。
5. 如果还有后续优化，说明它没算进这 40%，避免和别的项目成果重复计算。

### 12. ToC 上线有没有考虑敏感词和违规内容的安全过滤？

**参考答案**

要考虑，而且不能只在提示词里写「不要输出违规内容」。先说自己做到了哪一层；只做了关键词，就不要说成已经有分类模型和人工审核。

用户原文先做规范化，去掉零宽字符、统一全半角和同形字，再走多模式匹配。明确违规的词可以直接拦截；误伤高的词只做标记，交给分类器。分类按辱骂、色情、暴恐、违法、自残、隐私等分开设阈值，高风险类别宁可不回答。

模型生成之后再查一次。流式输出按句或一个小窗口缓冲，命中就截断并换成拒答，避免半句已经发到客户端。检索词和对外工具参数也要过同一套检查。知识库在入库时过滤，否则违规文档会借检索进入上下文。

日志记类别和请求编号，原文按合规要求脱敏。用一组固定坏例做回归。关键词挡不住谐音和改写，所以不能只有词表；分类器也会误伤，所以要能按类别调节，而不是全站一个分数。

### 13. 开发过程有没有使用 AI 辅助开发（vibe coding）？完整工作流程是什么？

**答题思路**

先回答用没用。如果只有行内补全，就不要说自己有完整的 AI 开发流程。用过的话，按你真实的工具和下面的闭环讲。

1. 生成之前写出验收标准、接口和不能改的文件。标准要能变成测试。
2. 一次只交给模型一个函数，或一个已经失败的测试，不把「把项目做完」当成一条提示。
3. 上下文只放相关文件、接口和报错。整个仓库贴进去，改动会扩散到无关模块。
4. 断言由你来定或逐条核对，再在本地跑。没跑过的测试不算数。
5. 自己读 diff。无关的重排、改名、吞掉的错误处理，都退回。
6. 通过后再提交，保证能回到上一个正确版本。
7. 工具名按你用过的说。没有评审和测试的生成，流程还没有完成。

### 14. AI 长任务开发出现上下文丢失、忘记需求、乱改代码，如何优化解决？

**参考答案**

需求和不变条件写在仓库里，对话只执行一小步。上下文被压缩之后，以文件和测试为准，不以模型记得什么为准。

长对话丢需求，是因为窗口被代码占满后，摘要把约束删掉了。开始时把验收点、禁止修改的模块和接口约定写成短文档，每条有编号。每一步只引用编号、相关文件和当前失败的测试，并写明可以改哪些路径。

出现无关改动就丢掉这份 diff，不要在脏改动上继续聊。每个通过测试的小步单独提交，这样不必依赖已经被总结坏的历史。新开一段对话时重新读文档和测试。测试是需求的可执行副本：模型忘了「不能使用未校验的教室」时，对应测试会失败。

如果运行环境还会做摘要，把文档路径留在摘要里，不要把约束压成「继续优化」。容易漏的是只加大窗口。窗口变大仍然会丢掉早期约束，而且乱改的范围更宽。

### 15. 本科学习中你认为最重要的基础技能是什么？为此做了哪些努力？

**答题思路**

只选一项你真的下过功夫、也经得起追问的基础，不要报一串课程名。这场面试问到了协议、索引、运行时和检索，优先选你能讲到机制的那一项。

1. 先说技能，再说它为什么决定你能不能把系统做对。例如网络基础决定你能不能判断超时发生在哪一层，数据结构决定你能不能解释索引和近邻查找。
2. 努力按「课内来源、一次自己做的实现或实验、一次靠它定位的问题」讲。实现可以很小，例如写过倒排、B+ 树的插入，或把一次抓包和协议对上。
3. 问题用你自己的：现象、你查到的那一层、改了什么。没有实习故事就用实验或课程作业，不要借一个没参加过的项目。
4. 准备一个追问。选了网络，就要能对比不同 HTTP 版本；选了数据结构，就要能说出 B+ 树和近邻图的差别。
5. 说完这一项就停。第二项等面试官问，避免哪一项都讲不深。

### 16. HTTP/1.1、HTTP/2、HTTP/3 的核心区别是什么？

**参考答案**

三者的差别在连接如何复用、队头阻塞发生在哪一层，不在 GET、POST 这些语义。

HTTP/1.1 是文本报文。一个连接上，前一个响应没处理完，后面的请求就受阻。协议里有流水线，但中间设备和浏览器基本不用。页面并发靠多条连接，重复的头部每次都完整发送。

HTTP/2 改成二进制帧。一个 TCP 连接上可以有多条流，每条流有自己的流量控制，HPACK 压缩重复头部。它去掉了应用层的队头阻塞，但丢一个 TCP 包，这条连接上的所有流都要等这个包重传。

HTTP/3 把同样的流放到 QUIC 上，QUIC 跑在 UDP 上。丢包只堵住对应的流。连接由连接 ID 标识，地址变化时不必重新握手。首次建连通常是 1-RTT，恢复已有会话可以 0-RTT，而 0-RTT 有重放风险。头部压缩换成 QPACK，避免为了压缩去依赖 TCP 的严格顺序。

容易漏的是把 HTTP/2 说成没有队头阻塞。它只是把阻塞从 HTTP 层换到了 TCP 层。

### 17. HTTP/3 性能更好，为什么内网微服务依然多用 HTTP/2？HTTP/2 的内网优势是什么？

**参考答案**

HTTP/3 的优势主要在丢包高、往返时间长的网络。内网丢包低、延迟小，连接又是长期复用的，这个优势基本用不上，CPU 和现有设施的成本更明显。

内网里一次握手的时间可以忽略，0-RTT 省不下多少。QUIC 在用户态做可靠传输和加密，高 QPS 时通常比内核里的 TCP 更吃 CPU。它也不能像 HTTP/2 那样在可信网段使用明文的 h2c。服务网格、gRPC 和四层负载均衡都按 TCP 上的 HTTP/2 来做；QUIC 的连接 ID 和地址迁移对固定的服务地址没有收益，反而让只认识五元组的负载均衡更难做。抓包和排障也更麻烦，因为 QUIC 始终加密。

HTTP/2 在内网的优势，是一条长连接上并发很多 RPC，并用每流的流量控制避免慢调用拖死连接。HPACK 能压掉反复出现的鉴权头和追踪头。代理可以在连接上做超时、重试和负载均衡，内核 TCP 也已经有成熟的分段和拥塞控制。主流 gRPC 就定义在 HTTP/2 上。

所以不是 HTTP/3 在所有链路上都更快，而是它解决的那个阻塞，在内网很少成为瓶颈。

### 18. V8 引擎的垃圾回收机制是什么？

**参考答案**

V8 按分代回收。大多数对象活不久：新生代用拷贝式的 Scavenge，老年代用可并发标记的标记-清除，碎片多时再整理。

小对象分配在新生代。新生代分成 from 和 to 两半。Minor GC 会短暂停顿，从根和跨代指针出发，把活对象拷到 to 空间；to 空间放不下，或对象已经活过若干次 Minor GC，就晋升到老年代。然后两半对调，死对象整块丢弃，不必逐个清除。老年代不会被整段扫描，写屏障把「老对象指向新对象」记进 remembered set，Minor GC 只扫这些位置。

老年代的标记可以和业务并发进行，写屏障记下并发期间新出现的指针；收尾仍有一次短停顿。清除可以并发，压缩用并行线程消除碎片。过大的对象放在单独空间，避免每次 Minor GC 都拷贝。

容易漏两点。Minor GC 的停顿还在，只是短。跨代指针如果没记下来，活着的新生代对象会被当成垃圾。晋升太猛，则会把本该很快死去的对象送进老年代，后续的大回收更频繁。

### 19. MySQL 索引原理是什么？B+ 树是怎样的结构？

**参考答案**

InnoDB 的索引是 B+ 树。整行和非叶节点分开：非叶节点只有键和子页指针，所有记录都在叶子，叶子之间按键顺序链接。等值查找和范围查找因此走同一棵树。

节点按页组织，默认一页 16KB。非叶节点不放整行，一页能放很多键，树通常很矮。缓冲池命中时，非叶页常常在内存里，不稳定的开销主要是叶子页的随机读。叶子有序，范围查询沿着页之间的链接走，不用回到根节点。

主键索引是聚簇索引，叶子就是整行。二级索引的叶子存的是主键的值，不是一条行地址。查询没有被二级索引覆盖时，还要用这个主键再查一次聚簇索引，这就是回表。联合索引只能从最左列开始连续使用；中间遇到范围条件，后面的列就不再用于缩小范围。

二叉树太高，也不能按页读取。哈希不能做范围、排序和前缀匹配，所以不能当这种磁盘索引的结构。InnoDB 可以在内存里对热点页建自适应哈希，那只是等值查找的附加加速，不替代 B+ 树。主键一改，所有二级索引里保存的主键值都要跟着改。

### 20. 向量检索引擎里 IVF 和 HNSW 的核心区别是什么？

**参考答案**

IVF 先把空间分成簇，查询时只在少数簇里比对。HNSW 在一张多层近邻图上，从稀疏的上层走到稠密的下层。前者用多探测几个簇换召回，后者用边的度数和搜索宽度换召回。

IVF 先训练粗质心，常见做法是 k-means，每个向量挂到最近的倒排链上。查询只扫描 nprobe 个簇，还可以用乘积量化把原向量压成短码，省内存、损失精度。它适合大批量、可以重新训练的库。真近邻如果落在没被探测的簇里，就一定找不到。数据分布变了，质心会过时，新数据通常先追加，再定期重训。

HNSW 不训练质心。每个点按几何分布进入若干层，上层点少、边跨得远，最底层包含全部点，每个点的邻居数由 M 一类参数限制。查询自顶向下贪心前进，efSearch 越宽，候选越多，也越慢。内存里要同时放下原向量和图上的边。删除大多只打标记，图的质量会变差，适合放得进内存、又需要陆续插入的集合。

带过滤条件时两边都会漏：符合条件的点可能在没探的簇里，也可能在图上已经不连通。不能只把无过滤的 top 结果事后筛一遍。也没有「IVF 一定更快、HNSW 一定更准」这回事，两条召回-延迟曲线都能调，差别在内存、要不要训练、以及怎么更新。

### 21. Java 接口和抽象类的区别是什么？

**参考答案**

接口描述一个类能做什么，抽象类保存一段还没完成的实现。一个类可以实现多个接口，但只能继承一个类。

接口不能有实例字段，也不能有构造方法；里面的字段只能是公开的静态常量。没有方法体的方法默认是公开的抽象方法。Java 8 起可以写 default 和 static 方法，Java 9 起可以用 private 方法给 default 方法共用代码。实现类必须完成那些还没有方法体的方法，否则自己也必须是抽象的。static 方法通过接口名调用，不会变成实现类的实例方法。

抽象类可以有构造方法、实例字段，以及任何访问级别的具体方法。它可以一个抽象方法都没有，但仍然不能被实例化。适合把子类共享的数据和受保护的步骤放在父类里。

选择时看要不要共享状态，以及要不要允许多个类型同时具备这种能力。接口表达能力；抽象类还可以规定数据放在哪、哪些步骤子类不能改。

### 22. Java 8 接口支持 default 方法之后，抽象类还有存在意义吗？接口无法替代抽象类的点是什么？

**参考答案**

有。default 方法解决的是行为上的多继承，替代不了抽象类的状态、构造方法和访问控制。

default 方法必须是 public，不能声明实例字段，也没有构造方法。它没法在父类型里保存子类共享的计数器、连接或已经校验过的配置。抽象类可以用构造方法先把不变式立住，用 protected 方法把可扩展的步骤留给子类，用 final 方法把不能改的步骤封住。这些可见性，接口都提供不了。

继承关系也不一样。子类已经继承了一个带状态的基类之后，剩下的能力只能再实现接口，不能再继承第二个抽象类。反过来，一组只带 default 方法的接口也拼不出一份共享的可变状态。

冲突时的规则也说明二者不同：两个接口的 default 方法签名一样，实现类必须自己重写；父类里的具体方法优先于接口的 default 方法。要不要抽象类，看子类是否需要共享实例状态和受控的扩展点，不是看接口能不能写方法体。

### 23. AI Coding：编写一个函数

**答题思路**

原帖只写到「编写一个函数」，没有函数签名、输入输出、约束和样例，所以这里没有唯一的标准解。现场按这个顺序写，不要凭印象补一套题。

1. 先复述函数：输入、输出、数据范围、重复和空输入怎么处理。有歧义先问，再写代码。
2. 用一句话给出朴素做法和目标复杂度，确认再落笔。时间、额外空间和瓶颈各说一句。
3. 函数保持短小。边界放进你自己写的断言里，至少覆盖空输入、单个元素和题目里的一个普通例子。
4. 允许用代码生成时，生成完自己读 diff，在本地跑这些断言。它改了题目以外的文件，就退回。
5. 交卷前检查溢出、下标和是否修改了不该修改的入参。说不清复杂度，就还没写完。

可以练和这场面试相邻的小函数：融合多路名次、判断时间段是否重叠、检查一个编号是否出现在工具返回里。这些只是练习方向，不是这道题的题面。
