### 3. 解释一下什么是向量数据库，它与传统关系型数据库的核心区别是什么？

**参考答案**

**结论：** 向量库按近似最近邻取出和查询向量最接近的 k 条；关系库按谓词精确找出满足条件的行，并支持连接和事务。

向量库存嵌入。查询是距离或内积，常见索引是 HNSW、IVF，结果不保证和暴力扫描一致。关系库用 B+ 树这类结构做等值、范围和连接，结果是精确的。差别在访问方式。关系库也可以放向量列（例如 pgvector），过滤和事务更顺手，数据量和召回要单独看。

嵌入表达的是相似度，机型、版本要作为元数据过滤。过滤很严时，先在全库做近似搜索再过滤，候选里可能没有符合条件的近邻。先把子集切出来再做近似搜索，索引若不是按这个过滤条件建的，也会漏。子集很小就对子集暴力扫描。召回用标注集看。两边向量都做了 L2 归一化时，内积最大、余弦最大和欧氏距离最近是同一顺序；只归一化一边，就不能把检索换成点积。入库前确认字段存的是相似度还是距离，两者排序相反。

### 4. 在 RAG 流程中，如果检索到的文档相关性不高，导致生成答案质量差，可能有哪些原因？如何优化？

**参考答案**

**结论：** 先分开「没检索对」和「检索对了但模型没照证据说」。先在标注集上看召回，再决定要不要改提示词。

常见原因：

- 问句有指代（「它怎么充电」），或用词和文档不一致。
- 切块太大把主题冲淡，太小把步骤和警告拆开，块上丢失章节路径；表格被从中间切断。
- 嵌入模型和语种、领域不匹配，距离度量用错，近似搜索的候选太少。
- 语料过期、重复，或混进了别的机型。
- 证据里已经有答案，生成时仍被模型换掉。这是生成问题。

优化按这个顺序：准备一批「答案就在某一段」的题，看召回。然后做指代消解和查询改写；按标题、步骤切块，小块用来检索、大块用来生成，块上带标题路径。机型名、错误码同时走关键词检索，再和向量结果一起重排。过滤条件限定机型、版本。证据不够就明确说没找到。用假设文档去检索可能把查询向量带偏，要单独评测。

### 5. 谈一谈你对 ReAct 框架的理解。它的核心思想是什么，如何帮助 Agent 进行推理和行动？

**参考答案**

**结论：** ReAct 把「想一步」和「做一步」放进同一个循环：根据当前状态产生下一步，调用一个工具，读入观察，再决定继续还是回答。

核心是用外部观察修正下一步。计划一次写完再执行，适合步骤事先看得清的任务；工具结果经常推翻计划时，交错进行更合适。原工作把痕迹写成 Thought、Action、Observation。现在很多系统用函数调用实现同一个循环，模型不必输出这些标签。

它把成功、空结果或报错写回上下文，下一步必须面对这些观察，轨迹也可以复查。想法文本本身没有被验证，模型仍可能不理会观察。步数上限、超时，以及答案是否引用观察，要由程序检查。

### 6. 在 AI Agent 中，记忆（Memory）通常分为哪几种类型？简要说明它们的作用

**参考答案**

**结论：** 先按生命周期分成短期工作记忆和长期记忆。长期记忆再按内容分成情景、语义和程序。

工作记忆是这一轮的目标、对话、计划和工具观察，放在上下文里，用来把当前任务做完。会话结束后不再默认保留。当前这一帧感知也进工作记忆。

长期记忆跨会话：

- 情景记忆是具体经历，例如上次任务停在哪。
- 语义记忆是稳定事实和偏好。
- 程序记忆是技能怎么调用，通常是工具、代码和规程。

缓冲、摘要、向量库是存放方式。向量检索解决不了「某个偏好的当前值」，那要语义记忆里的结构化字段。

### 7. 实现一个简单的多轮对话状态管理，你会考虑哪些关键要素？

**参考答案**

**结论：** 状态要分开存「说过的话」和「已经确认的任务进度」。只追加消息列表，槽位确认、改口和并发都会丢。

1. 身份和版本：用户、会话、轮次，加上状态版本号。同一会话的并发请求用版本或锁，避免后写的旧状态覆盖新状态。
2. 任务状态：已确认槽位和待确认槽位分开；当前目标、步骤、挂起的工具调用和它的幂等键。
3. 历史：全量落库。送进模型的是滚动摘要加最近几轮，有 token 预算。
4. 改口：用户改一个槽位时，清掉依赖它的后续槽位和已经过时的工具结果。
5. 生命周期：空闲超时、主动结束、失败后留下现场以便恢复。
6. 隐私：证件号、密钥不写进长期摘要。

上下文组装是独立的一步：系统说明、摘要、最近轮次、检索证据，超预算就截证据和更老的轮次，已确认槽位保留。

### 8. 如何评估一个 AI Agent 的好坏？除了准确率，还可以关注哪些指标？

**参考答案**

**结论：** 终态对了才算成功：该查的查到了，该改的只改了一次，该停的停下了。回复和标准句子的字面重合只能作旁证。

除此之外看：

- 工具是否选对，参数和单位是否正确。
- 步数、端到端时延、token 和费用。
- 工具失败后能否换路或如实说明，而不是编一个成功结果。
- 回答是否被检索片段或工具观察支持。
- 危险或越权动作有没有被拦住。
- 同一意图换种说法，结果是否稳定。
- 为了补齐信息，用户被追问了几轮。

轨迹和终态一起看。用模型当裁判时要有细则，并抽一部分和人的判断对齐，避免裁判和代理犯同一种错。

### 9. 了解 LangChain 或 LlamaIndex 这类框架吗？谈谈它们解决了什么问题，以及可能的局限性

**参考答案**

**结论：** 这两个框架解决的是胶水代码。LangChain 统一模型、提示、解析和工具调用；LlamaIndex 的长处是数据接入、索引和检索。

有了它们，换模型和接一个新的文档源会快一些。多步任务里，分支、暂停和恢复需要显式的状态图，LangGraph 就是干这个的。线性的默认循环表达不了这些。

局限也明确：抽象改过好几轮，出错时要看到实际发出的提示和工具参数。文档质量、召回评测、工具幂等和权限都不在框架里。步骤固定、工具少的时候，自己写一个循环更好查。检索准不准，仍由切块、嵌入和评测决定。

### 10. 在开发 Agent 时，如何设计提示词（Prompt）来提升其任务执行的稳定性和准确性？

**参考答案**

**结论：** 稳定性来自约束写死，并且同一批题反复跑。提示词负责把目标、工具和停机条件说清。

提示里分开写目标、允许的工具、何时停止、输出格式。每个工具写清参数、单位、副作用，以及什么时候不要用它。检索文本和网页放在单独的资料区。下一步若要被程序执行，就用函数调用或固定 schema，少让模型自由写格式。例子少而硬：该调工具、该追问、该停，各留一个。

温度调低可以减少抽样抖动。有的推理服务即使温度为 0 也不保证逐字稳定，回归集仍要跑。提示词要有版本。越权动作由程序里的允许列表拦住，提示词只是说明。

### 11. 如果 Agent 在调用一个外部工具 API 时失败了，从系统设计角度，应该有哪些容错或降级策略？

**参考答案**

**结论：** 按错误类型决定是否重试，把失败原样写回观察，写操作和身体动作禁止无幂等的自动重试。

超时、429 和 5xx 可以有限次重试，用退避加抖动，并且受整轮时间预算限制。参数错误和业务拒绝直接返回，不重试。写操作带上幂等键，同一次意图只会生效一次。某个工具连续失败就熔断，避免把时间预算耗光。

观察里写明错误码和是否可重试。模型只能在换工具、使用只读缓存、向用户说明之间选择。机器人动作失败后停在安全状态，同样的运动指令不自动再发。整段调用进入轨迹，方便事后看是超时还是参数错。

### 12. 手写算法：实现一个函数，计算两个向量的余弦相似度

**参考答案**

**结论：** 余弦相似度是夹角的余弦，等于点积除以两个模长的乘积，范围在 -1 到 1。任一向量模长为 0 时无定义。

两边都做了 L2 归一化时，余弦等于点积，检索可以只做内积。只归一化一边则必须把模长除回去。时间 O(d)，额外空间 O(1)，d 是维度。

```python
import math


def cosine_similarity(a: list[float], b: list[float]) -> float:
    if len(a) != len(b) or len(a) == 0:
        raise ValueError("vectors must be non-empty and the same length")
    dot = na = nb = 0.0
    for x, y in zip(a, b):
        dot += x * y
        na += x * x
        nb += y * y
    if na == 0.0 or nb == 0.0:
        raise ValueError("cosine similarity is undefined for a zero vector")
    return dot / (math.sqrt(na) * math.sqrt(nb))
```

`(1, 0)` 与自身为 1，与 `(0, 1)` 为 0，与 `(-1, 0)` 为 -1。维度不同要报错。有的库返回的是余弦距离 `1 - cos`，排序方向相反。

### 3. 在你项目的 RAG 实现中，文本分块（Chunking）策略是如何设计的？遇到过哪些问题，如何调整的？

**答题思路**

按「单位 → 一次失败 → 怎么改 → 怎么验证」讲真实实现。

1. 切分单位是标题、步骤、句子，还是固定窗口。块大小按 token 还是字符，和嵌入模型、问题长度什么关系。重叠有没有做。
2. 讲一次失败：表格被切开，操作步骤和警告分离，或者块里看不出它属于哪一节，检索字面相关但答非所问。
3. 你的调整：按结构切、小块检索大块生成、块上带标题路径。固定字数如果就是当时的做法，照实说。
4. 用一组你知道答案在哪一段的题看召回。不要只说看起来顺了。

### 4. 如何为你的 Agent 设计长期记忆和短期记忆？例如，如何存储和检索跨会话的用户偏好？

**参考答案**

**结论：** 短期记忆保证这一轮任务不断；长期偏好写成带时间的字段，检索时直接读档案。旧对话的向量用来回忆经历，不用来决定偏好的当前值。

短期记忆放在会话里：原始轮次、滚动摘要、已确认槽位、当前计划和未完成的工具调用。落库之后刷新还在。送进模型的只有预算内的摘要和最近几轮。会话有空闲超时。

长期偏好一条记录包含：谁、哪一项、取值、何时确认、来源。更新时写下新值并保留时间，读的时候取这项的当前值。随口一句话先进入候选，确认后再变成档案；用户能改、能删。和安全有关的事实，例如不能进入的区域，变更要再次确认。

「上次把东西放在哪」这类情景按事件存储，需要时用向量召回，并带上时间。程序记忆是工具和规程，随版本发布，不从闲聊里自动改写。

### 5. 在 ReAct 循环中，Agent 有时会陷入无效的“思考-行动”循环。你如何设计机制来检测并跳出这种循环？

**参考答案**

**结论：** 循环检测做在程序里。签名用工具名和规范化之后的参数；想法句子每次都会换措辞，不拿它当签名。

规范化包括参数键排序，浮点数用稳定的小数位。同一签名连续出现，或这次观察和上次相同，就说明没有新信息，停止原样再调。同一错误重复出现则熔断该工具。整轮还有步数上限和墙钟时间。

停下来之后三选一：返回已经完成的部分，向用户要缺失信息，或换成先列计划再执行。提示里可以写「不要重复同一调用」，停不停仍由循环代码决定。

### 6. 多 Agent 协作系统有什么了解？如果要设计一个多 Agent 系统来完成复杂任务，你会考虑哪些架构问题？

**参考答案**

**结论：** 线性流水线用一个有状态的图就够。多个决策者只在任务能并行，或权限必须拆开时才引入。

常见可用的形状是一个调度者把子任务交给工具更少的专职代理，每个代理有类型化的输入输出。要先定这些事：

- 一份状态只有一个写入者。
- 有副作用的工具，尤其是运动和写入，只留给一个代理。
- 子代理超时后，部分结果如何回到调度者。结束与否由调度者判断。
- 传下游的是摘要和产物，不是所有代理的全部历史。
- 整条任务共用一个轨迹 id。

多个代理互相聊天会放大延迟、费用和重复动作。检查者可以只有读权限，用来核对证据是否支持结论。

### 7. 如何保证 AI Agent 生成内容的安全性（Safety）和可控性（Alignment）？在工程上可以采取哪些措施？

**参考答案**

**结论：** 安全是不造成人身、隐私和财产伤害。对齐是行为符合用户这次的意图和产品规范。可控是每一步都能限制、打断和追查。三件套要分开做。

工具按会话授权，用最小权限。检索文本和网页当资料，高风险工具的开关在程序里。动作分成只读、写入和身体动作。身体动作和不可逆写入走独立策略，必要时先让人确认。

限速、可活动空间、碰撞和急停放在控制侧。急停在计算挂死时仍然有效，不依赖模型调用一个工具。训练阶段的对齐解决不了一次错误的工具参数，所以上线后的允许列表和确认要单独存在。

日志记下工具参数、结果和是谁授权的。回归集里放提示注入、含糊的破坏性指令，以及不该调用的工具。

### 8. 如果用户的问题非常模糊或存在歧义，你的 Agent 如何与用户进行澄清性对话？

**参考答案**

**结论：** 缺了必填槽位、有多个指代、证据不足或约束互相矛盾时，先澄清再调用有副作用的工具。

一次问一个决定性的问题，选项来自当前场景，例如「客厅的灯还是卧室的灯」。答案写回对应槽位，同一槽位不重复问。低风险事项可以说出假设再继续。加热、离开住所、接触人和动物，假设不能代替确认。

澄清设次数上限，超过就交给人。高风险技能在槽位补齐前不要调用。已经确认的内容留在任务状态里，不靠模型下次还记得。

### 12. 手写算法：模拟一个简单的文本分块函数，给定文本和最大块大小，按句子边界进行分块，避免截断句子

**参考答案**

**结论：** 先按句末标点切开，再从左到右装箱。当前块放得下整句就放入；放不下就封块。单句已经长于 `max_size` 时不拦腰截断，整句单独成块。

这里的大小按字符计。生产里的块大小通常按 token，二者不要混用。时间 O(n)，额外空间 O(n)。这个函数不重叠；检索里让相邻块共享一两句，是另一条召回策略。

英文句点后的缩写和编号可能被切开，例如 `Dr. Smith`。小数点因为后面紧挨数字，不会被切开。更严的分句可以再换，这道题先保证句子不被拦腰截断，并且所有块拼回去等于原文。

`啊。呀。哦。` 在 `max_size = 4` 时得到 `啊。呀。` 和 `哦。`。

```python
import re

_SENT_END = re.compile(r"[。！？!?]|\.(?=\s|$)")


def chunk_by_sentence(text: str, max_size: int) -> list[str]:
    if max_size <= 0:
        raise ValueError("max_size must be positive")
    if text == "":
        return []

    sentences: list[str] = []
    start = 0
    for match in _SENT_END.finditer(text):
        sentences.append(text[start:match.end()])
        start = match.end()
    if start < len(text):
        sentences.append(text[start:])

    chunks: list[str] = []
    buf = ""
    for sent in sentences:
        if len(buf) + len(sent) <= max_size:
            buf += sent
            continue
        if buf:
            chunks.append(buf)
            buf = ""
        if len(sent) <= max_size:
            buf = sent
        else:
            chunks.append(sent)
    if buf:
        chunks.append(buf)
    return chunks
```

### 2. 抛开现有项目，如果让你从零设计一个用于家庭服务机器人的 AI Agent 大脑，你的技术架构蓝图是怎样的？

**参考答案**

**结论：** 大脑分成两条时钟。高频运动控制负责站稳和避开碰撞；慢速任务代理负责听懂人话并选择下一个技能。对话模型不进入平衡所在的控制周期。

1. **安全壳**：限速、可活动空间、碰撞、急停。急停在计算挂死时仍然有效。技能目标越界就被拒绝。
2. **运动控制**：行走和平衡按控制周期运行。它可以是传统控制，也可以是专门的运动策略，但不等一次大模型推理才迈步。

4. **世界状态**：地图、人和物体的位置、手是否占用，由感知模块维护，都带时间。指代先落到这里的对象上。
5. **任务代理**：输入是用户的话、世界状态摘要和相关记忆。输出是下一个技能或一个澄清问题。观察失败就按当前世界状态重规划，并有步数上限。
6. **记忆**：户型、禁区和偏好用结构化字段。过去的具体事件再走检索。
7. **交互**：语音进出。加热、离开住所、接触人和动物，先向人确认。

难点是把话落到当前场景的对象上，以及技能做到一半失败时从世界状态恢复。难的规划可以在有网时放到云端；断网时端侧只开放有限技能。

### 12. 手写算法：设计一个简单的缓存结构，用于存储和检索向量相似度查询的结果（考虑缓存大小和淘汰策略）

**参考答案**

**结论：** 缓存的键是一次检索的范围加上查询向量，值是那次的近邻结果。范围里必须有索引版本、度量、top-k 和过滤条件。容量用 LRU 淘汰。阈值设为 1 时只接受同一向量；小于 1 时在同一范围内取余弦最高且达到阈值的一条。

查询向量先按 `float` 规范化。非有限值和零向量直接拒绝，余弦对它们无定义。相同向量再次写入只更新结果并刷新为最近使用，不增加条目。`get` 命中后也刷新，失败的查找不刷新。

近似命中只说明查询方向接近，两次 Top-K 仍可能不同。不能容忍错结果时把阈值设为 1。索引有增删就要换版本，旧版本自然不会命中，但还会占容量直到被淘汰。这份结构不是线程安全的，多请求共享时加锁。条目不多时线性扫描就够；扫描本身成为延迟之后，再为缓存单独建近似索引，那个索引也会找错邻居。

`get` 时间 O(n·d)，`put` 时间 O(n)，空间 O(n·d) 再加结果本身。n 是条目数，d 是维度。

```python
import math
from collections import OrderedDict


def cosine_similarity(a: list[float], b: list[float]) -> float:
    if len(a) != len(b) or len(a) == 0:
        raise ValueError("vectors must be non-empty and the same length")
    dot = na = nb = 0.0
    for x, y in zip(a, b):
        dot += x * y
        na += x * x
        nb += y * y
    if na == 0.0 or nb == 0.0:
        raise ValueError("cosine similarity is undefined for a zero vector")
    return dot / (math.sqrt(na) * math.sqrt(nb))


class VectorQueryCache:
    def __init__(self, capacity: int, threshold: float):
        if capacity < 1:
            raise ValueError("capacity must be >= 1")
        if not 0.0 <= threshold <= 1.0:
            raise ValueError("threshold must be in [0, 1]")
        self.capacity = capacity
        self.threshold = threshold
        self._items: OrderedDict[int, tuple] = OrderedDict()
        self._seq = 0

    def get(self, index_version, metric, top_k, filter_key, query):
        scope = (index_version, metric, top_k, filter_key)
        q = self._as_vec(query)
        if self.threshold >= 1.0:
            found = None
            result = None
            for eid, (sc, vec, item) in self._items.items():
                if sc == scope and vec == q:
                    found = eid
                    result = item
                    break
            if found is None:
                return None
            self._items.move_to_end(found)
            return result

        best_id = None
        best_sim = self.threshold
        best_result = None
        for eid, (sc, vec, result) in self._items.items():
            if sc != scope or len(vec) != len(q):
                continue
            sim = 1.0 if vec == q else cosine_similarity(q, vec)
            if sim >= best_sim:
                best_sim = sim
                best_id = eid
                best_result = result
        if best_id is None:
            return None
        self._items.move_to_end(best_id)
        return best_result

    def put(self, index_version, metric, top_k, filter_key, query, result) -> None:
        scope = (index_version, metric, top_k, filter_key)
        q = self._as_vec(query)
        found = None
        for eid, (sc, vec, _) in self._items.items():
            if sc == scope and vec == q:
                found = eid
                break
        if found is not None:
            self._items[found] = (scope, q, result)
            self._items.move_to_end(found)
            return
        self._seq += 1
        self._items[self._seq] = (scope, q, result)
        while len(self._items) > self.capacity:
            self._items.popitem(last=False)

    def _as_vec(self, query) -> tuple[float, ...]:
        if not query:
            raise ValueError("query must be non-empty")
        out = []
        norm = 0.0
        for x in query:
            value = float(x)
            if not math.isfinite(value):
                raise ValueError("vector contains a non-finite value")
            norm += value * value
            out.append(value)
        if norm == 0.0:
            raise ValueError("query vector must be non-zero")
        return tuple(out)
```

### 1. 请做一个简单的自我介绍

**答题思路**

45 到 60 秒，少用术语。现在做什么，一件你负责的事和结果，为什么想来做会行动的机器人。结果用你自己的数。技术细节等对方问。

### 2. 为什么选择宇树科技？对我们公司或业务有什么了解？

**答题思路**

先说明你了解它是做四足和人形机器人的公司，智能要接到真实环境里的行动上。只展开一个你真看过的公开产品或演示，不背公司简介。

再把你的经历接上：工具调用、检索或端侧，你做过哪一块，希望面对安全约束和断网。看机会的原因用一句话，不评价现雇主。没核实过的融资、销量和型号不要讲。

### 3. 你过往经历中压力最大的一次挑战是什么？如何应对的？

**答题思路**

选一件时间紧或出了故障、行动主体是你的事。情境一句，你做的两件事，结果一句，之后你改了什么工作方式一句。数字用你记得住的。不要把责任推给同事，也不要编一个悲情故事。

### 4. 你更喜欢什么样的团队氛围和工作方式？

**答题思路**

说你做事的方式：目标写清楚，技术意见当面对，决定和假设留在文档里，自己的接口跟到上线。再补一句你如何配合，例如会早说风险、评测和回退一起交。用你现在团队里真实的做法举一个很小的例子。

### 5. 当你与上级或同事意见不一致时，通常会怎么处理？

**答题思路**

先确认双方要的结果是不是同一件。能用小范围事实解决的，约时间做对比。对用户和安全没有实质影响的，接受负责人的决定并执行。涉及安全或不可逆后果时，把证据写下来升级。事后按决定做，不在私下反复翻。例子用真实的一次，比抽象表态有用。

### 6. 你如何看待加班问题？

**答题思路**

把发布、现场试验和故障这些真实窗口，和日常把加班当排期手段分开。前一种你会在；后一种你会提出来调整范围。给一个你能长期保持的节奏。机器人试验要卡硬件和场地，这个约束可以主动说你理解。

### 7. 你目前的薪资构成和期望薪资是多少？

**答题思路**

先问清职级和结构：底薪、奖金、股票或期权、发放周期。现有包用你自己的数，按年折成总现金。期望给一个区间，对应这次是否独立负责一条链路、是否值班。区间基于你了解到的市场和你现在的总包。

这里不写示例数字。对方要一个数时，说明你需要知道级别再落点，避免先报一个和职级对不上的数。

### 8. 你还有什么问题想问我的吗？

**答题思路**

问和岗位相关的三件：这个角色前半年要交付的机器人能力是什么；团队现在卡在模型、技能还是评测；现场试验和值班怎么排。流程上可以问下一轮和定级。工作节奏放在最后问一个。先问假期，信息量小。
