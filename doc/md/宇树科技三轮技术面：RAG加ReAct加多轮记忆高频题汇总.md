# 宇树科技三轮技术面：RAG加ReAct加多轮记忆高频题汇总

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 面试感受

一面别背概念。幻觉、RAG、ReAct、向量库这些如果只说名词，会直接挂。二面看工程：harness 不只是会调框架，要能讲循环防护、工具校验和机器人安全拦截，不然就是玩具 Agent。三面别空谈多 Agent，具身场景必须落到仿真、真机、评测和回滚。谁只说大模型能搞定一切，会被当场顶回去。

## 一面

### 1. 自我介绍

**答题思路**

控制在 1 到 2 分钟，按「我是谁 → 做过什么 → 为什么和这个岗位有关」讲。

1. 一句话说明年限和方向：你写 Agent 的哪一层，模型调用、检索、编排还是业务系统。
2. 只展开一个你真正做过的 Agent 或检索项目：用户的一句话最后变成什么结果，你负责哪一段。
3. 主动落到这次会深挖的点：幻觉怎么约束、知识从哪来、工具调用有没有副作用。数字只用你自己有的。
4. 收到一个具体技术点上停住，把追问留给面试官。

### 2. 讲一个你做过的 AI Agent 项目，说清楚角色、整体链路和线上指标

**答题思路**

用真实项目套。没做上线就说清楚当时停在哪一层，缺的指标不要编。

1. 角色：你写编排、检索、工具还是评测，谁对线上结果负责。
2. 链路按一次请求讲：输入和会话 → 意图或目标 → 检索或工具 → 校验 → 回复或动作 → 记录。只读和会改状态的调用分开。
3. 指标先定义再报数：任务是否真的完成、工具参数是否合法、用户是否接管、时延和成本。完成与否看状态或人工判定，不看模型自己说完成了没有。
4. 准备一个线上问题：现象、你怎么定位到检索、提示词、工具还是模型，改了什么，用哪组案例确认。
5. 结尾留三个可追问的点：状态存在哪、失败怎么停、哪一类请求你拒绝自动化。

### 3. 大语言模型为什么会产生幻觉，Agent 场景下幻觉会比纯对话更严重的原因是什么

**参考答案**

结论：模型在预测下一个 token，没有单独的事实核对。Agent 里幻觉会写进工具参数和后续观察，所以比闲聊严重。

训练目标是像语料，知识被压进参数，不全也会过时，相近概念会混在一起。解码只要句子通顺就能继续；对齐又鼓励把话说满、顺着用户，不确定时模型仍会给出具体数字。

闲聊里的幻觉大多是一句错话。Agent 会在三处放大：速度、点位、故障码可以编得完全符合 JSON；工具有副作用，机器人会真的动；调用失败时模型还可能补写一段没发生的观察，下一步把这段话当测量结果。步数一多，测到的和说出来的就混在同一条上下文里。

回答时把知识幻觉、参数幻觉、观察幻觉分开。提示词约束的是怎么说，已经发出去的动作要靠外层校验拦住。

### 4. RAG 完整链路怎么设计，从文档入库、切分、向量化、检索、重排到生成分别要关注什么

**参考答案**

结论：每一段都要能用「带标准答案的问句」单独验收。生成提示词补不了入库时丢掉的型号、版本和警告。

入库先解析正文，保留标题、步骤、表格和警告，去掉页眉页脚和重复页。每块带上机器人型号、手册版本、章节路径、生效时间。原文放在文档库，向量库里留文本、向量和这些元数据，换嵌入模型时按同一编号整库重建。

切分按操作或章节边界，保证一块里的事实是完整的。向量化用同一模型和同一种归一化，查询和文档的前缀按该模型的要求加。检索先按型号和版本过滤，再取候选；故障码这类精确词同时走关键词检索，两路结果按名次融合。重排只处理前若干个候选，用来读细粒度匹配，候选集里没有的片段重排找不回来。

生成时只根据给出的片段和工具结果作答，关键句带出处。检索为空或片段互相矛盾时，回答「不确定」并指出缺哪一本手册。上线后按型号切片看召回和引用是否真被答案用到。

### 5. 机器人操作手册类知识做 RAG，文本分块按固定字数切还是按语义/章节切，为什么；模糊指令相关片段如何避免被切散

**参考答案**

结论：操作手册按章节和步骤切。固定字数会把前提、警告、参数表和动作拆开，检索命中半句时，模型会把另一半补上。

一块尽量等于一个可执行步骤组：标题、适用条件、警告、动作、参数在一起。超过上下文预算时，拆成父块和子块。子块保存自己的步骤，同时记下父块编号和标题路径；命中子块后把父块里的警告和参数一并送进生成。表格和「注意」不从对应步骤上撕下来。块之间可以留一小段重叠，重叠只补边界上的半句话。

「走稳一点」这类说法往往对应步态章节里的现象描述加一张参数表。按字数切，现象和参数会落进不同块，召回只能看见其中一块。除了按章节聚在一起，再为口语说法建一条指向该章节的别名或问答，否则切得再完整，查询词对不上标题也回不来。

### 6. 向量数据库和关系型数据库核心区别是什么；Milvus、Qdrant、FAISS 各自适合什么规模和能力诉求

**参考答案**

结论：关系库回答「等值、范围、事务和关联」，向量库回答「哪几条在语义上接近」。手册原文、任务状态以关系库或对象存储为准，向量库是检索索引。

关系库走 B+ 树这类精确索引，约束和事务完整。向量库存高维浮点，用 HNSW、IVF 等近似近邻索引返回 top-k，结果是近似的，召回率要单独测。过滤条件很多时，先过滤再搜索还是搜索后再过滤，会影响延迟和召回，不能假设和 SQL 的 WHERE 一样便宜。

FAISS 是进程内的算法库，适合实验和单机索引，GPU 索引也在库里；持久化、多租户和按型号过滤要自己做。Qdrant 这类库把向量和 payload 过滤放在一起，单机到中小集群、过滤条件多的在线检索比较合适，运维比分布式系统轻。Milvus 面向需要分片、多集合、单独扩容的大规模检索，组件和运维更重。规模没到那一步时，先把评测和过滤做对，不必先上分布式。

### 7. Embedding 模型怎么选型，句向量维度、领域适配、多语言、更新频率分别怎么考虑

**参考答案**

结论：用你们自己的手册问句集选模型。维度、语种和领域都看召回，不看榜单上的一个总分。

维度升高通常更细，内存、带宽和延迟也上去。常见模型从几百维到几千维都有，没有通用默认值。支持截断维度的模型可以先缩短，再用同一套问句看召回掉多少，然后按存储拍板。

通用嵌入会把步态、关节限位、故障码混进日常语义里。有标注时，用真实问句和对应章节做对比学习，负例挑同型号的相邻章节。暂时不能训练，就让故障码、型号走关键词检索，和向量结果融合。

中文手册夹英文型号和故障码时，用多语言模型，并用中英混合问句评测。只在英文上训练的模型，中文步骤会整段漂掉。双塔模型常常要求查询和文档使用不同前缀，前缀用反了，召回会整体变差，以该模型的说明为准。

换嵌入模型等于换了一套向量空间，旧向量不能和新向量放在一个集合里比距离。做法是新建索引、影子查询、再切换。手册改了几页，只对变更块用同一个模型重嵌入。模型版本写进每条向量的元数据。

### 8. 检索召回不相关时，从 query 改写、分块、向量模型、索引、重排逐层怎么排查

**参考答案**

结论：先看标准片段在不在库里、在不在候选集里，再改模型和提示词。重排只能重排已经召回的候选。

1. 改写：对照原句和改写句。改写可能补错型号、丢掉「不要」，或把口语改成另一个部件。错误实体会让后面每一层都朝着错文档走。
2. 分块：直接打开标准片段。片段里没有完整步骤、警告或参数，问题在切分，调索引没有用。
3. 向量模型：用暴力扫描看标准片段的距离。它和正确问句仍然很远，就是模型和领域或前缀不匹配。关键词能命中、向量不能，多半是故障码、型号这类精确词没被语义覆盖。
4. 索引：暴力结果里有、近似结果里没有，查搜索宽度、过滤时机，以及度量和归一化是否一致。没做归一化时，内积不等于余弦。手册更新后索引没重建，也会表现为召回正常但内容是旧的。
5. 重排：标准片段进入了候选、重排后掉出窗口，再查重排模型、输入截断和领域。候选里没有，就回到上面四层。

每一层都先确认过滤条件。型号或手册版本过滤错了，现象和「模型不行」一样。

### 9. Prompt 怎么写能降低幻觉；系统提示、任务约束、引用要求、拒绝回答规则分别怎么设计

**参考答案**

结论：提示词规定「没有依据就停」。参数是否真能执行，由 schema 和动作闸门判定，不由模型自我保证。

系统提示写清角色和优先级：这台机器人的操作助手，安全规格优先于用户的催促。写明速度、力矩、限位以给定片段和配置为准，不用闲聊记忆填空。

任务约束把输出收成固定结构，并限制步数。动作只能通过工具字段给出，正文里多出来的数字不能被执行器读取。

引用要求每条事实带片段编号或工具结果编号。没有编号的数值留在草稿里，到不了下发接口。片段冲突时并列两个出处，并指出版本，不合成一个折中数。

拒绝规则覆盖四类：检索为空、相关度不够、工具失败、指令含糊且涉及移动或接触。回复说明缺的是型号、目标还是位置。降低温度能减少乱选词，会把记错的参数说得更稳定，所以温度不是依据。

### 10. 上下文窗口有限，多轮机器人任务对话怎么做压缩、摘要、关键信息抽取和滑动保留

**参考答案**

结论：窗口里放结构化任务状态和最近几轮原话。更早的内容先抽出槽位，再摘要；工具原文留在窗口外面。

滑动保留最近若干轮用户原话、澄清，以及刚下发的动作和回执。这些句子短、容易被改写弄错，原样留下。

关键信息单独成槽：目标、机器人、地点、否定句、速度上限、未完成子任务、待确认项。摘要可以重写过程，槽位只能由新的用户原话或工具结果修改。

摘要按增量更新，压的是已经被槽位吸收的旧过程。每轮把全部历史重新摘要一次，既贵又容易漂。

压缩针对工具报文和旧检索。上下文只留工具名、状态和编号，大报文放对象存储；检索片段按当前子目标临时取。预算先扣掉系统提示、工具 schema 和生成，剩下的再分给历史。否定句和数字只放在槽位里，避免摘要把「不要上楼梯」收成「去楼梯」。

### 11. ReAct 的思考、行动、观察闭环讲一遍；在机器人指令场景里如何避免无限循环

**参考答案**

结论：ReAct 是「想一步、做一个动作、读回结果」，下一步只能使用读回来的结果。循环上限和停止条件写在外层运行时里。

思考根据当前目标和已有观察决定下一步，行动是一次带名称和参数的工具调用，观察是工具的真实返回。例如先定位「那个杯子」，读到物体编号和位置，再决定导航或抓取。最终回答出现，或者步数用尽，循环结束。思考文本不是观察，不能把「应该已经抓到」写进状态。

机器人场景里用四条规则截断循环。步数、墙钟时间和 token 有预算。同一工具加同一组规范化参数重复出现，记一次重复。任务状态的摘要连续几轮不变，视为没有进展。触发后先要求更换工具或向用户澄清；预算用尽就停止，并给控制器发已定义的安全停止，不再追加移动指令。

模型自己输出「结束」只是一种正常收尾。相同调用和无进展由运行时计数，不靠提示词约定模型自觉停。

### 12. 多轮对话状态怎么管理，用户偏好、当前任务、已调用工具结果、未完成任务分别存哪里

**参考答案**

结论：四类状态生命周期不同，分成长期资料、会话状态、调用记录和待办。都放进一条聊天记录里，过期和并发会缠在一起。

用户偏好按用户和机器人编号存在长期存储里，带更新时间和来源。新会话开始时读出来，放进槽位。偏好是软约束，安全上限仍然用规格里的值。

当前任务放会话状态：目标、阶段、槽位、机器人编号。热数据可以放 Redis，能恢复任务的检查点同时落库。键用会话编号，不和别的机器人共用。

工具结果按调用编号存储完整报文，设置较短的保留时间。会话状态和提示词里只留工具名、状态、业务编号。需要审计的调用再追加到任务流水。

未完成任务是会话状态里的待办列表，每一项有前置条件和状态。断线后要接着做的，待办必须在检查点里，只存在模型上下文中会随窗口滑掉。

并发时一个会话只有一个写入方。两个工人同时覆盖整份 JSON，后写的会丢掉先完成的工具结果。

### 13. 具身场景里用户说「走稳一点」「把那个拿过来」这种模糊指令，Agent 怎么澄清并转成可执行目标

**参考答案**

结论：先把模糊说法落成带编号和约束的目标，再允许动作。缺了对象、终点或幅度，就补一次具体选项，用规格里的默认值直接开跑会把相对指令做成危险动作。

「把那个拿过来」缺对象和终点。用当前场景图、对话里刚提到的物体和指向信息列候选。场上只有一个明显对象时，把假设说出来并执行低风险查询；有杯子和遥控器两件，就问「哪一个」，问句里带上看到的名字，不同时抛出三个以上问题。

「走稳一点」是相对当前步态的修改。先读当前速度和步态，再映射到白名单里的稳定模式，或一个不超过安全幅度的变化量。用户没给数字，数字就来自这份白名单，不来自模型现场估一个速度。

可执行目标至少包括动作、对象或目的地、约束（速度上限、步态名）和机器人编号，通过 schema 后才进规划。涉及接触、进入新区域或超过当前安全包络时，先把具体参数给用户确认。澄清一轮后仍缺关键槽位，就保持原地，只回复缺什么。

### 14. 用 Redis 存会话上下文和工具结果缓存怎么做，键设计、过期策略、并发读写要注意什么

**参考答案**

结论：Redis 放热状态和幂等读的短缓存。任务真相和审计在数据库；步态、导航、抓取的结果不进缓存。

键按会话拆开：`sess:{id}:state` 放槽位，`sess:{id}:turns` 放最近原话，`sess:{id}:lock` 放写入锁。工具缓存用 `tool:{id}:{tool}:{args_hash}`，哈希里包含工具 schema 版本。大报文改存对象存储，Redis 里留编号。一个巨大的字符串既不好并发更新，也会把无关字段一起淘汰。

会话键使用同一段空闲过期时间，有新消息时一起续期，避免原话还在、槽位已经没了。工具缓存更短，只覆盖幂等读。运动指令每条都要真正下发，缓存命中会把上一次的成功回执当成这一次的执行。

同一会话用 `SET key token NX PX` 串行化写。释放锁时用 Lua 比较 token 再删除，避免删掉别人刚拿到的锁。锁的过期时间要盖住临界区，进程死掉后锁能自己释放。两个工人写工具结果时按调用编号写入，合并进状态，覆盖整份 JSON 会丢更新。Redis 重启或内存淘汰后，从数据库检查点恢复任务，不根据半截缓存继续移动。

### 15. 手撕算法：实现两个向量的余弦相似度，要求处理零向量、维度不一致和批量输入

**参考答案**

结论：余弦相似度是点积除以两个范数的乘积，范围在 -1 到 1。任一向量范数为 0 时没有定义；两边维度必须相同。批量是「一条对多条」或「等长逐对」，时间是 O(配对条数 × 维度)，输出占用 O(配对条数) 额外空间。

入库时如果已经做了 L2 归一化，余弦等于点积，但零向量不能先归一化。这里遇到零向量或维度不一致就报错，调用方决定是丢弃这条还是改查询。若改成返回 0，零向量会在排序里混在正常分数中间，调用方看不出是无定义。

```python
        return [_pair(row, rows_b[0]) for row in rows_a]
    if len(rows_a) != len(rows_b):
        raise ValueError(f"批量条数不一致: {len(rows_a)} 和 {len(rows_b)}")
    return [_pair(u, v) for u, v in zip(rows_a, rows_b)]


def _rows(data, name):
    if isinstance(data, (str, bytes)) or not isinstance(data, (list, tuple)) or len(data) == 0:
        raise ValueError(f"{name} 必须是非空向量或向量列表")
    if isinstance(data[0], (list, tuple)):
        width = None
        rows = []
        for i, row in enumerate(data):
            if not isinstance(row, (list, tuple)) or len(row) == 0:
                raise ValueError(f"{name}[{i}] 不是非空向量")
            if width is None:
                width = len(row)
            elif len(row) != width:
                raise ValueError(f"{name} 内部维度不一致")
            rows.append([float(x) for x in row])
        return rows
    return [[float(x) for x in data]]


def _pair(u, v):
    dot = norm_u = norm_v = 0.0
    for x, y in zip(u, v):
        dot += x * y
        norm_u += x * x
        norm_v += y * y
    if norm_u == 0.0 or norm_v == 0.0:
        raise ValueError("零向量的余弦相似度没有定义")
    return dot / (math.sqrt(norm_u) * math.sqrt(norm_v))
```

### 1. 自我介绍

**答题思路**

这一轮面试官要听运行时和线上约束，概念定义一句带过。

1. 用一句话定位你维护的是模型外面的哪一层：工具校验、循环控制、任务状态或动作下发。
2. 讲一个已经接过真实工具的项目，按「请求怎么进来、动作怎么出去、失败怎么停」说，不超过四句。
3. 补一个你处理过的工程问题：重复调用、超时重试或误下发，说明你怎么发现、怎么收口。
4. 数字只用真实的。没有完整线上系统，就讲你在哪一层做过校验和停止条件。

### 2. 讲最近一个 Agent 项目，重点说 harness 怎么编排思考、工具调用、重试、回滚和终止

**答题思路**

harness 就是包住模型的执行运行时。按一次任务的控制流讲，少讲业务故事。

1. 思考：每一步模型看到的状态是什么，哪些字段是运行时放进去的，哪些原文不会给它。
2. 工具调用：schema 校验在调用前，危险动作经过哪道闸门，校验失败是否允许模型改一次参数。
3. 重试：只重试超时和明确可重试的错误；重试有次数和间隔。运动类要先查询是否已经生效。
4. 回滚：说清楚哪些步骤能补偿，哪些世界变化不能撤销，状态如何回到可继续的检查点。
5. 终止：正常完成、用户取消、步数或时间用尽、安全拒绝，四种出口分别把机器人和任务状态置于哪里。
6. 准备追问：幂等键放哪、谁和模型抢写会话、停掉之后用户看到什么。

### 3. Agent 工具调用 schema 怎么设计，参数类型、必填项、默认值、枚举约束、错误码如何规范

**参考答案**

结论：schema 是运行时的合同。模型可以提议参数，缺字段、类型不对或越出枚举时，调用不会发生。

每个工具有稳定名称、用途，以及明确写清何时不要用它。参数使用 JSON Schema：`type` 固定为 object，字段写明 `string`、`number`、`integer`、`boolean`，坐标和速度带单位。封闭选项用 `enum`，例如步态名，不用自由字符串。`required` 只放没有它就无法安全执行的字段，`additionalProperties` 设为 false，避免模型多塞一个未定义的速度。

默认值只给无副作用的可选项，例如返回条数。速度、力度、目标点不设静默默认；确实要有业务默认时，默认来自配置白名单，并由闸门再校验一次，同时写进日志。

工具统一返回 `ok`、`code`、`message`、`retryable` 和 `data`。参数错误、无权限、超出范围、超时、安全拒绝、下游冲突分成不同码。只有超时和明确的下游拥塞可重试。schema 失败允许模型根据错误码修正一次，第二次仍失败就停止这条工具路径，把错误交回规划，而不是让模型自由改字段重试。

### 4. 机器人控制类工具，比如下发步态、导航、机械臂抓取，接入 Agent 时如何做权限、范围、实时性和安全校验

**参考答案**

结论：Agent 下发目标点和模式，控制器按自己的频率跟踪。权限、范围和安全在动作网关上完成，模型选中了工具只表示「提出申请」。

权限按角色和机器人归属划分。读状态、下发步态、导航、抓取是不同工具，危险工具要有独立许可，不因为用户能聊天就自动拥有。每次调用带操作者和机器人编号，网关做鉴权。

范围用规格和地图，包括关节限位、最大速度和加速度、工作空间、禁区和抓取力度。参数越界就拒绝。枚举步态要映射成配置里的具体数值，再做一次数值校验，防止枚举背后的配置被改宽。

实时性上，语言模型不进伺服内环。指令带序号和幂等键，等待回执；超时后的状态是未知，先查机器人实际模式，再决定能否重发。重复的序号返回上一次的受理结果，避免超时重试打出两次导航。

安全校验读取急停、定位、电量和周围障碍。任一前提不满足就拒绝，并把拒绝码返回给 harness。控制器自己还有限位和看门狗：指令流中断后进入该机型定义的安全状态，例如受控停止或抱闸，丢弃过期的速度指令。

### 5. ReAct 出现重复调用同一工具或思考行动无进展，harness 怎么检测循环、做退避、换策略或硬停止

**参考答案**

结论：先区分「下游抖了一下」和「决策在原地打转」。退避只用于前者；同一参数反复出现用换策略或硬停止。

检测用规范化后的记录。工具名、参数键序、浮点精度先收成一个字符串，再比较。同一组合连续出现，或间隔出现并形成周期，记为重复。另外对目标、阶段和观察摘要做哈希，连续若干步哈希不变，就是思考在更新、任务没有进展。只比较思考文本会漏掉「换了说法、工具完全一样」的情况。

退避是指数拉开可重试错误的间隔，并设次数上限，用来对付超时和拥塞。逻辑循环如果也退避，只是把同一个错误动作放慢。

换策略时，把「该参数组合已经失败」写进观察，让模型改工具、改子目标或向用户问一个缺的槽位。换策略只有一次到两次机会。

硬停止看步数、重复次数、墙钟和 token 预算。到达后任务标为失败，机器人进入安全状态，检查点留下最后一次真实观察。瞬态重试次数和 ReAct 步数分两个计数器，避免一次超时把规划步数吃光，也避免规划循环借用重试预算一直跑。

### 6. 短期记忆、会话记忆、长期记忆、空间记忆在具身机器人上分别存什么；跨任务保留用户操控偏好怎么落地

**参考答案**

结论：四类记忆的键和过期不同。操控偏好是长期记忆里的一条软约束，写入要有确认，读取时不能超过安全规格。

短期记忆是当前这一步的草稿：最近的思考、本步工具观察、尚未提交的子目标。它随任务推进被覆盖，放在运行时状态里。

会话记忆是这一次交互：原话、澄清、待办、已经确认的目标。按会话编号放在热存储和检查点里，会话结束后只保留需要审计的部分。

长期记忆跨会话：用户稳定偏好、被要求记住的称呼、反复确认过的常用目的地。按用户编号存在关系库，并用向量做同义召回。物体此刻在哪，不属于长期记忆。

空间记忆按场地和机器人：语义地图、禁区、最近看到的物体位置。它由感知更新，带观测时间，过期很快，因为杯子会被拿走。多个会话可以读同一份场地地图，写入以传感器时间为准。

跨任务保留偏好时，单独记一条 `{用户, 机器人, 键, 值, 来源, 更新时间}`。一次「慢一点」先改当前任务槽位；用户确认或多次稳定出现，再写入长期表。新会话加载后，网关仍用规格上限截断。用户能查看和删除。玩笑和单次抱怨不直接进长期表。

### 7. 多轮对话中历史消息哪些必须留、哪些可摘要、哪些应转长期记忆；不同会话并发如何隔离，避免记忆串扰

**参考答案**

结论：原话保留「现在还生效的约束」，摘要只压缩过程，长期记忆只收已经确认、下次仍适用的事实。隔离键是租户、用户、会话和机器人。

必须原样留下的有：当前目标、最新更正、否定句和安全约束、尚未收到回执的动作、等待用户确认的那个问题。这些一旦被摘要改写，机器人会执行反方向。

可以摘要的有：寒暄、已经被新计划替代的旧步骤、思考过程、已经写进任务状态的成功结果。摘要里留一句结果即可。

转到长期记忆的有：用户明确说「以后都这样」，或多次确认的偏好和常用地点。工具报错、临时物体位置和这次任务的中间失败留在会话或空间记忆里，并带过期时间。

并发时每个会话一份检查点和工作记忆，提示词只拼接这一份。长期记忆的检索条件里必须有用户编号，共享的只有场地级空间记忆。两个会话同时改同一条偏好时，用版本号做比较更新，后写覆盖前写要能被发现。串扰的常见原因是缓存键少了用户或机器人，把别人的速度偏好读进了这次提示词。

### 8. RAG 在 Agent 里是每次先检索还是按需检索；结合机器人故障手册、场地地图、任务规则怎么设计混合检索

**参考答案**

结论：按需检索。每轮先查一遍，会把无关手册塞进上下文，规划更容易引用错误片段。问候、继续当前动作、槽位已经齐全的确认，都不检索。

触发条件写成工具或路由：出现故障码、问「怎么处理」、涉及场地规则或任务前提时再查。检索内容和当前子目标绑定，查抓取时不把整本维护手册放进去。

三条知识用不同索引。故障手册用向量加关键词，关键词负责故障码和型号，元数据先按机器人和手册版本过滤，再对候选重排。场地地图以地图服务为主，房间名和别名可以走向量，几何关系、路径和禁区走空间查询；「去会议室」先链接到地图节点，再交给导航。任务规则量通常不大，但有安全含义，按场地和任务类型精确查找，返回结构化条款。安全条款不靠语义 top-1 碰运气。

三路结果分成标明来源的块交给模型。手册是操作说明，地图是位置，规则是允许与否，三种命中不能揉成一段「参考资料」。

### 9. 工具返回脏数据或超时，如何做校验、降级、人工确认；危险动作下发前如何用规则引擎二次拦截

**参考答案**

结论：工具返回先过 schema，超时记为未知。危险动作在离开 harness 之前，还要经过与模型无关的规则引擎。

校验看类型、必填、数值是否为 NaN、位姿是否在量程内、时间戳是否过旧。不合规则丢弃这次观察，把错误码交回规划。模型不能把残缺 JSON 里的某个数挑出来用。

超时后先查实际状态。幂等的读可以按预算重试；导航和抓取只有在确认机器人没有接受该序号时才能重发，同序号使用同一个幂等键。重试间隔后退，次数用尽就停。

降级按动作级别。感知脏了，可以请用户确认，或在时间戳仍新鲜时使用上一帧；过期就停止移动。手册没查到，就拒绝给出限位数字。讲解可以缺省，位移和接触没有缺省动作。

人工确认用于低置信度、接触、不可逆和规则点名的动作。确认界面展示即将下发的参数，用户同意的是这条指令，不是一句「可以，你看着办」。

规则引擎的输入是提案、机器人状态和地图，输出允许、改写到上限以内或拒绝。急停、禁区、超速、电量、工作空间有人，都在这里裁决。拒绝会结束这个动作，规划可以在规则内换一条路径，不能改提示词绕过。

### 10. Kafka 或 RocketMQ 在 Agent 系统里传感知事件、任务指令、执行回执怎么设计 topic、顺序性和消费幂等

**参考答案**

结论：感知、指令、回执分 topic，按机器人编号分区，消费端按指令编号做幂等。消息队列传的是任务级事件，伺服内环仍在机器人控制器上。

topic 拆开是为了避免感知流量堵住回执。感知用语义事件，原始高频传感器不进这条总线，保留时间可以更短。指令是 Agent 到执行器的任务，回执是执行器到 Agent 的结果。失败消息进死信，用来排查，不自动重放成第二次动作。

顺序只保证同一机器人在同一 topic 的分区内有序。分区键用机器人编号。跨 topic 没有总顺序，状态合并以事件上的机器人和序号为准。Kafka 用分区键，RocketMQ 用同一队列选择键，两者都适用；需要事务消息或延迟消息时再按现有集群的能力选，不因为名字换设计。

投递按至少一次设计。指令和数据库里的任务状态用发件箱放在同一事务：任务行提交成功，消息一定能发出。消费端把 `command_id` 做成唯一约束，重复消息直接确认。回执带序号或版本，只有更新的版本能覆盖任务状态。端到端的恰好一次要靠这层唯一约束，不是生产者参数单独能给出的。

### 11. 模糊指令拆解成子任务后，如何做依赖编排；某个子任务失败，整体重规划还是局部恢复

**参考答案**

结论：子任务排成有向无环图，没有前置的先执行。失败先分类，再决定局部恢复还是重规划剩余部分。

节点是可验证的子目标，边表示前置，例如先看见物体，再导航，再抓取，再放置。入度为 0 的可以执行；同一只手臂、同一个底盘同时只能占一个动作，所以拓扑上能并行的，还要过资源锁。每完成一步就写检查点。

失败后的处理：

- 超时且回执证明没生效：按幂等键局部重试。
- 物体位姿过期或抓取参数不合适：重新感知，只改这一节点。
- 物体消失、路被长期堵住、用户改了目标：保留已经发生的位移，对剩余节点重规划。
- 安全规则拒绝：全部停止，不换一种说法再下发同一动作。

已经走到桌边，重规划的起点就是当前位姿，而不是任务开始时的充电桩。局部重试抓空的物体没有意义；每次失败都从头规划，会重复已经完成的移动。

### 12. Agent 线上评测怎么做，任务完成率、工具调用准确率、幻觉率、时延、token 成本、人工满意度分别怎么统计

**参考答案**

结论：六个数都要有分母和判定来源。模型说完成了，只记成一种输出，不记成完成。

任务完成率的分子是目标条件真的达到，依据是机器人状态、业务单号或人工判定。分母要写明是全部任务，还是排除了用户取消和本身不可行的任务。按任务类型和机器人型号分开看，总平均值会掩盖抓取失败。

工具调用准确率拆成三层：schema 是否合法、工具是否选对、参数或执行结果是否正确。非法调用和合法但错误的调用分开计数，否则一次改 schema 会看起来像模型变好了。

幻觉率用抽检。事实句在检索片段和工具结果里找不到依据，或口头说成功但状态对不上，各计一次。只用模型给自己打分，会把幻觉评成没有幻觉。

时延报端到端的 p50 和 p95，并拆开排队、模型、检索和工具。平均时延盖不住尾部那一次卡住的导航。

token 成本按每次任务的输入和输出计算，重试、循环和失败任务都算进去，再除以成功任务数。只统计成功那次调用，成本会被低估。

人工满意度同时看显式评分和接管、急停、立刻改口。样本要包含失败任务。线上指标按天看切片，发版用固定评测集做回归，两套都留。

### 13. MySQL 存任务流水、记忆元数据、人工反馈时表结构怎么设计，慢查询和批量写入如何优化

**参考答案**

结论：MySQL 存任务、记忆元数据和反馈的可过滤字段。大报文和向量放外部，用同一个编号关联。流水表以追加为主。

任务表放用户、机器人、会话、目标、状态和时间。步骤表放 `task_id`、步骤号、工具名、状态、错误码，以及参数和结果的外部引用。记忆表放归属、类型、文本、来源任务、生效和失效时间，向量库使用同一个 `memory_id`。反馈表放任务、评分、原因码和短评语。

索引服务于真实查询：任务用 `(user_id, created_at)` 和 `(robot_id, status, created_at)`，步骤用 `(task_id, step_no)` 唯一约束，记忆用 `(owner_id, mem_type, valid_to)`。正文和原始 JSON 不建普通二级索引。低基数的状态不单独建索引。

慢查询先看具体 SQL。列表避免 `SELECT *`，深分页改成上一页的 `(created_at, id)`。时间条件写成范围，不在索引列上套函数。历史步骤按时间归档，避免一张步骤表无限长。

批量写入用多行插入，单事务行数设上限。步骤追加，任务状态只更新窄表上的状态字段。发消息和任务入库放在同一事务的发件箱里。二级索引只留查询真正用到的，写放量后先减索引，再考虑拆库。

### 14. 手撕算法：给定一个字符串数组表示的工具调用历史，判断是否存在重复参数组合的死循环，返回首次进入循环的起始位置和周期

**参考答案**

结论：把每条调用收成规范字符串后，死循环是「从下标 start 一直重复到历史末尾」的周期 p，并且这段周期至少完整出现两轮。返回最早的 `(start, p)`。中途重复过、最后已经跳出的，不算仍在循环里。

调用方先把工具名和参数收成稳定字符串：键排序，浮点按约定精度四舍五入。否则同样的参数因为键序不同对不上。

从左到右枚举进入点，再从短到长枚举周期。若从 start 起每个位置都等于 p 步之前的调用，就找到了。时间最坏 O(n³)，额外空间 O(1)。n 是单次任务的调用次数，通常远小于语料规模。若要更快，对每个后缀用前缀函数求最小周期，总时间 O(n²)。

```python
from typing import Optional


def find_tool_loop(history: list[str]) -> Optional[tuple[int, int]]:
    """返回 (起始下标, 周期)。历史末尾仍在重复才算死循环。"""
    n = len(history)
    for start in range(n):
        max_period = (n - start) // 2
        for period in range(1, max_period + 1):
            if all(
                history[i] == history[i - period]
                for i in range(start + period, n)
            ):
                return start, period
    return None
```

例如 `["A","B","C","D","C","D"]` 返回 `(2, 2)`，`["A","B","A"]` 返回 `None`，因为第二轮并不完整。`["A","A"]` 返回 `(0, 1)`。

### 3. 自研 Agent 框架和 LangChain、LangGraph、AutoGen 等方案怎么取舍；宇树这类具身场景为什么可能要自研部分编排层

**参考答案**

结论：框架用来加速模型调用、状态图和轨迹记录。动作网关、安全规则、仿真与真机的同一套接口，由自己掌握。自研指这一层边界，不是重写一个提示词库。

LangChain 适合把检索、模型和工具快速串起来，原型快。抽象升级频繁，复杂分支和安全截断散落在回调里时难审查。

LangGraph 把流程写成显式状态图，带检查点、暂停和人工插入，适合任务阶段清楚的规划。它仍是通用运行时，不知道步态、急停和控制器回执的语义。

AutoGen 的典型模式是多个代理互相发消息，适合软件任务里的分工讨论。连续控制需要的是带截止时间和拒绝语义的动作提案，对话轮次会把延迟和责任都变模糊。

具身场景要自研编排边界，是因为规划频率和伺服频率必须分开，同一动作 API 要能打到仿真和真机，安全拒绝必须在图的外面且可审计。规划图可以用 LangGraph 这类状态机来表达，下发前的那一次裁决保留在自己的网关里。这样升级框架时，安全行为不跟着框架的默认回调变化。

### 4. 多 Agent 协作怎么做，感知、规划、控制、校验、记忆各自职责，消息协议、状态共享和冲突消解怎么设计

**参考答案**

结论：按职责拆模块。规划和必要的语言理解使用语言模型，其余模块输出带时间戳的结构化结果。

感知维护场景图和物体轨迹，输出带时间戳的结构化观察。规划把用户目标拆成子目标。控制把单个子目标映射成控制器已经支持的模式或目标点，不接受自由文本速度。校验对照规则、状态和地图，给出允许或拒绝。记忆按用户、会话、场地分别读写，不在模块之间传递整段聊天。

消息用类型区分：观察、计划、动作提案、裁决、记忆写入。每条带机器人编号、关联编号和截止时间。共享状态放在带版本的黑板里，动作通道只有一个写入方。

冲突按优先级处理：急停高于校验，校验高于已经确认的计划。新感知先写入黑板，由校验决定继续、收紧还是取消。底盘和手臂用资源锁，同一执行器同时只执行一个动作。校验拒绝后，规划在规则内重做或问人。已经进入执行的动作走取消协议，感知模块不直接改力矩。

### 5. MCP、A2A、Function Calling 的关系和边界；企业内多机器人、多业务系统接入工具如何统一注册和治理

**参考答案**

结论：三者叠在一条链上。Function Calling 是模型吐出结构化调用的能力，MCP 是宿主访问工具和资源的接口，A2A 是代理之间委托任务的协议。

Function Calling 解决「这一步调用哪个函数、参数是什么」，合同是本次请求里带上的 JSON Schema。它不负责工具发现、权限和跨系统治理。

MCP 把工具、资源和提示词以服务器的形式暴露给宿主，传输可以用标准输入输出或 HTTP。宿主再把 MCP 工具转成模型看到的函数定义。手册和地图适合作为资源来读，移动和抓取只作为受控工具暴露。

A2A 解决另一个代理如何发现你、委托任务并跟踪状态，通常用代理名片声明能力，并用任务状态交流。传递的内容是任务。接受委托的机器人代理仍然走本地动作网关，关节指令留在网关内。

企业里用统一注册表记录名称、schema、负责人、版本、风险级别和适用机器人。模型看到的函数列表由注册表生成，避免提示词里的参数和网关不一致。按工具做身份认证和授权，schema 变更进兼容性检查。原始电机接口不进公共总线。高风险工具有紧急下线开关。A2A 只用于真正需要互派任务的系统之间，例如派一条维护单；对方不能绕过安全网关直接驱动机器人。

### 6. 具身 Agent 安全体系怎么建，提示词层、harness 层、工具层、硬件急停层分别做什么；危险指令如何多层拦截

**参考答案**

结论：四层都能拒绝，任意一层拒绝，动作就不会执行。提示词层最容易被绕过，只负责少提出危险意图。硬件和工具网关不接受提示词改写。

提示词层要求含糊指令先澄清，危险请求直接拒绝，并规定没有依据就不填物理参数。这一层会被越狱和错误上下文影响，所以它的拒绝是提前收口，通过与否都不算安全证明。

harness 层做工具白名单、schema、步数和重复检测、人工确认。模型输出的是提案。确认没完成、预算用尽或校验失败，提案不会离开这一层。

工具层是动作网关：身份、限位、禁区、速度和力度、电量和定位前提、幂等键和回执超时。它把枚举模式展开成数值再判一次。超时视为未知，先查真实状态。

硬件和固件层保留限位、独立急停和看门狗。指令流中断或校验失败时，进入该机型预先定义的安全状态，并丢弃过期速度指令。足式和人形机器人的安全状态写在机型策略里，可以是受控停止或抱闸。直接卸力可能导致摔倒。

危险指令要同时通过四层。硬件一旦拒绝，用户和模型都不能覆盖。每一层的拒绝带层名和原因写进审计，用来区分是提示词提前收口，还是网关或固件拦住的。

### 7. 仿真到实机怎么闭环，域随机化、系统辨识、真实数据回流、VLA 微调、灰度发布和回滚分别怎么落地

**参考答案**

结论：仿真负责大量试错和回归，真机负责发现仿真里没有的差距。新策略先影子对照，再小范围执行，指标破了就切回上一版。

域随机化在仿真里改变光照、纹理、质量、摩擦和延迟，让策略少记死某一台仿真器。随机范围过宽时任务本身会变不可能，所以从当前误差出发逐步加宽。

系统辨识用真机轨迹估计延迟、摩擦和负载，先把仿真参数对齐。随机化覆盖剩下的、测不准的部分。

真实数据回流收集失败、人工接管和真机轨迹，按质量和安全筛过之后，补到暴露差距的那一类数据上，例如某种地面的步态或某种光照的检测。全量回灌不区分原因，评测会看不出哪一项变好。

VLA 把图像、语言指令映射成动作，适合技能层。微调数据来自仿真和真机，并留出没见过的场景做验证。任务层仍由规划和规则决定能不能做，技能模型的输出也要过动作网关。

灰度时先影子运行：新策略只记录会发什么，旧策略继续执行。再放到少量机器人、收紧的速度上限里。看接管率、跌倒或异常停止、任务完成。版本和配置按机器人钉死。回滚是切回已经加载的上一版制品和配置，阈值破了自动切，不在故障当场重新训练。

### 8. 世界模型、仿真器、RAG 外部知识在具身决策里分别承担什么角色，如何避免模型凭空生成物理参数

**参考答案**

结论：仿真器提供可重复的物理推演，世界模型提供数据里学到的短时预测，RAG 提供人写过的规格和流程。限位和额定参数只来自版本化规格。

仿真器用物理引擎和已知参数做训练、回归和假设实验。参数能通过系统辨识对齐，误差范围相对清楚。它不是真机本身。

世界模型根据观测预测接下来的状态或图像，用来比较几个短时动作的可能后果。它在数据分布外会编出不合理的接触和滑动，所以预测只作为候选排序，不作为「这个关节允许转到这里」的证明。

RAG 检索操作步骤、故障码含义、场地规则和规格表。它不积分物理，也不替换地图的几何查询。检索到的是某版本文档里的句子，生成时要保留版本。

避免凭空数值的做法是：速度、力矩、关节范围、电量阈值按机器人型号到配置或规格表里精确查找；查不到就拒绝这一动作。世界模型滚出来的数标成预测，并被规格区间截断。schema 在下发前再验一次范围和单位。模型把检索到的 0.3 改写成 0.5，也算一次凭空生成，所以关键数值以查表结果为准，生成文本只负责解释。

### 9. 长期记忆用向量库加图或关系存储做用户、环境、技能画像，怎么解决召回噪声、时效性和一致性

**参考答案**

结论：关系库或图保存可核对的实体和关系，向量库是按原文检索的派生索引。过期和归属在写入时就定好，读取时先过滤再做近邻搜索。

用户画像存确认过的偏好，环境画像存场地、禁区和带时间的物体位置，技能画像存某个动作的前提、成功条件和适用机器人。多跳关系，例如某用户在某房间常用的速度，用图或关系表更稳；说法不同但指同一偏好时，用向量召回候选编号，再回表取结构化记录。

噪声靠少写和严读。不是每轮对话都入库，要有确认、重复次数或明确的「请记住」。检索先按用户、机器人、记忆类型过滤，再设相似度阈值和重排。低于阈值就当没想起，让规划去问用户。新事实和旧事实矛盾时，保留更新的一条，旧条失效。

时效按类型给有效期：物体位置以分钟或小时计，偏好可以长得多。排序里加上新鲜度。空间事实到期后不再注入提示词。

一致性以关系记录为准。修改偏好先写关系行，再更新向量；向量写失败就由补偿任务补索引，检索不到至少不会读到一条没有主键的记忆。向量里的编号必须能回表。删除和过期在数据库查询里生效，再同步删向量，提示词里加一句「请忽略过期记忆」留不住已经拼进去的旧速度。

### 10. 大上下文模型普及后，RAG 还有没有必要；什么场景必须检索，什么场景可用长上下文替代

**参考答案**

结论：长上下文用来读已经选中的材料，RAG 用来在大语料里选择、鉴权和保持新鲜。窗口变长，手册并不会自动变新。

必须检索的情况：全部手册、全部场地和历史版本放不进窗口，或者放得进但每轮都塞的 token 成本和延迟不可接受。不同场地的资料有权限，不能为了省检索把别的场地拼进同一次提示。故障码、限位表要精确命中并留下出处。文档今天改了版本，检索索引可以更新，已经塞进某次长提示里的旧副本不会自己变。

可以用长上下文替代切块检索的情况：材料本来就是一份放得下的规程、一张工单或一段当前会话，整份放进窗口能避免步骤被切散。此时仍然要先选对那一份文档，只是不必再切成很小的块。

实用做法是检索出少量片段或整篇短文档，和任务槽位一起放进窗口。窗口里无关文本一多，中间的那条限位仍然可能被忽略，所以「放得下」不等于「会被用到」。规格数字继续走精确查表，查表结果再放进上下文解释给用户。

### 11. Agent bad case 闭环怎么建，线上失败样本如何标注、归因到 prompt、retrieval、model、tool 哪一层，如何自动回归

**参考答案**

结论：每条失败留下完整轨迹，归因到最早那个改掉就能避免后续错误的层，然后冻结进回归集。只改一句提示词、不加入测试集，同一失败会在下次发版回来。

样本来自未完成、急停、人工接管、用户立刻改口和工具错误，同时保留一小部分成功轨迹做对照。轨迹里要有提示词、检索片段和分数、工具参数与原始回执、模型输出、机器人状态和最终标签。敏感字段按场地脱敏。

标注先标现象：理解错、工具选错、参数越界、循环、口头成功但状态不符。归因看证据。工具超时、回执脏或网关放行了越界参数，归 tool。标准片段不在候选集，归 retrieval。片段和回执都在上下文里，决策仍然错，归 model。约束根本没写进指令或工具说明，归 prompt。后面的胡言常常是前面缺依据引起的，根因记最早的那一层，其余记成下游现象。

回归时把输入、语料版本和期望行为钉死，提示词、索引、模型或 schema 变更都跑这组用例。安全类失败是发布门槛。通过离线集之后用影子流量看一段时间，再放开执行。新修的案例当天就进集，避免只存在某个人的笔记里。

### 12. 高并发 Agent 服务用 Redis 做限流和缓存、Kafka 做异步任务、ES 做日志和 trace 检索，整体容量和降级方案怎么设计

**参考答案**

结论：接纳请求和执行规划分开扩容。容量看模型并发、单台机器人的动作并发和队列堆积，不看 API 进程的 CPU。ES 慢不能挡住急停和状态查询。

Redis 用一段 Lua 做令牌桶，按用户、机器人和全局预算限流，避免固定窗口在边界上放进两倍流量。缓存放会话热状态和幂等读，任务是否受理以数据库为准。内存要设上限，并明确淘汰策略；限流组件不可用时，拒绝受理新的动作任务；状态查询可以按单独策略继续。

Kafka 按机器人编号分区，消费者数量和分区对齐，堆积超过阈值就停止接受新的长任务。重试有上限，失败不要立刻无间隔重回队列，否则下游一慢就会被重试打满。回执消费者和感知消费者分开，避免感知流量拖住任务状态。

ES 存日志和 trace，按天滚动。在线放行动作不查询 ES。写入异步，ES 变慢只影响排查，不影响网关。

降级按层丢掉工作：先关重排、额外检索和长摘要；队列或模型超过预算后拒绝新的规划，仍接受停止和状态查询；模型供应商不可用时不改用「凭经验生成一个动作」，机器人保持该机型的安全状态，规则系统继续回答是否处于急停。每层的触发条件用延迟、堆积和错误率，事先写好，故障时不再临时选择。

### 13. 新技术选型时，自研大模型、开源模型、云服务、规则系统怎么组合；稳定性、成本、延迟、可解释性如何权衡

**参考答案**

结论：规则系统守住动作边界，语言模型做开放指令的理解和下一步提案。自研大模型指自己训练模型，和自研编排不是一件事。

规则系统负责限位、禁区、急停逻辑、故障码到处置的确定映射。它稳定、延迟低、每次判决都能解释，覆盖不了开放说法。

云端大模型语言能力强、接入快，适合任务级规划。数据是否出内网、尾延迟和版本是否突然变化，都受服务条款影响，费用随 token 和重试上涨。

开源模型部署在内网时，版本和数据边界由自己钉死，延迟可以规划。GPU、评测和值班要自己承担，效果取决于选型和你们的数据，不取决于「开源」这两个字。

从零训练通用大模型，只在数据、人员和现有模型的差距都证明必要时才做。机器人团队更常见的是微调技能策略或较小的规划模型，基座继续用云或开源。

稳定性上，规则和钉死版本的自建服务高于会随供应商升级的云模型。成本上，规则几乎不随调用增长；调用量小的时候自建 GPU 可能比云更贵。延迟上，伺服和安全在机旁或内网，任务级语言可以在预算内走云。可解释性来自结构化参数、规则判决和检索出处；模型写出一段通顺理由，不能代替网关的拒绝码。

### 15. 手撕算法：给定一个自然语言子目标列表和依赖关系，构建执行 DAG，输出满足依赖的拓扑执行顺序；若存在环返回冲突子目标

**参考答案**

结论：依赖是「前置必须先于后续」的有向边。用 Kahn 算法每次取出入度为 0 的节点；全部取完就是拓扑序。取不完就存在环，此时不返回执行顺序，只返回环上的子目标。

被环挡住、本身不在环上的后续节点不算冲突。例如 A 完成后 B 与 C 互为前置，D 等着 C，冲突是 B 和 C。同一层有多个可执行节点时，用小根堆按名字弹出，得到字典序最小的拓扑序，同一输入回放顺序稳定。时间 O(V+E)，使用堆时是 O((V+E) log V)，空间 O(V+E)。

拓扑序只表达逻辑前置。两步都没有前置、却要同一只手臂时，还要加资源锁，这一层算法不知道执行器有几只。

```python
import heapq
from collections import defaultdict


def execution_plan(goals: list[str], deps: list[tuple[str, str]]) -> dict:
    """deps 的 (前置, 后续) 表示前置先完成。有环时 order 为空。"""
    nodes = set(goals)
    for pre, post in deps:
        nodes.add(pre)
        nodes.add(post)

    graph = defaultdict(list)
    indeg = {name: 0 for name in nodes}
    seen = set()
    for pre, post in deps:
        if (pre, post) in seen:
            continue
        seen.add((pre, post))
        graph[pre].append(post)
        indeg[post] += 1

    ready = [name for name in nodes if indeg[name] == 0]
    heapq.heapify(ready)
    order = []
    while ready:
        current = heapq.heappop(ready)
        order.append(current)
        for nxt in graph[current]:
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                heapq.heappush(ready, nxt)

    if len(order) == len(nodes):
        return {"order": order, "conflicts": []}
    remaining = [name for name in nodes if indeg[name] > 0]
    return {"order": [], "conflicts": _cycle_nodes(remaining, graph)}


def _cycle_nodes(remaining: list[str], graph: dict) -> list[str]:
    rem = set(remaining)
    adj = {name: [nxt for nxt in graph[name] if nxt in rem] for name in rem}
    index = 0
    stack = []
    onstack = set()
    indices = {}
    low = {}
    conflicts = []

    def strong(node: str) -> None:
        nonlocal index
        indices[node] = low[node] = index
        index += 1
        stack.append(node)
        onstack.add(node)
        for nxt in adj[node]:
            if nxt not in indices:
                strong(nxt)
                low[node] = min(low[node], low[nxt])
            elif nxt in onstack:
                low[node] = min(low[node], indices[nxt])
        if low[node] == indices[node]:
            comp = []
            while True:
                item = stack.pop()
                onstack.remove(item)
                comp.append(item)
                if item == node:
                    break
            if len(comp) > 1 or node in adj[node]:
                conflicts.extend(comp)

    for name in sorted(rem):
        if name not in indices:
            strong(name)
    return sorted(set(conflicts))
```
