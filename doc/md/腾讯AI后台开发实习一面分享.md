## 一面

### 1. 力扣原题：最小路径和

**参考答案**

力扣 64。一个 m 行 n 列的网格，从左上角走到右下角，每步只能向右或向下，求沿途数字之和的最小值。题目给出的格子是非负的。只能向右或向下，路径图没有环，直接递推即可。

设 `dp[i][j]` 为走到第 i 行第 j 列的最小和。这一格只能从上方或左方进来：

`dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`

第一行只能从左边累加，第一列只能从上面累加。每个格子算一次，时间 O(mn)。结果可以写回原网格，额外空间 O(1)。面试要求不改原数组时，用长度为 n 的一维数组保存上一行的结果，空间 O(n)。

原地写的时候，左边那一格必须已经是更新后的值，上面那一格还留着上一行的结果，所以先完成上一行，再从左到右改当前行。

```java
public int minPathSum(int[][] grid) {
    int m = grid.length;
    int n = grid[0].length;
    for (int j = 1; j < n; j++) {
        grid[0][j] += grid[0][j - 1];
    }
    for (int i = 1; i < m; i++) {
        grid[i][0] += grid[i - 1][0];
        for (int j = 1; j < n; j++) {
            grid[i][j] += Math.min(grid[i - 1][j], grid[i][j - 1]);
        }
    }
    return grid[m - 1][n - 1];
}
```

### 2. Java 中的接口和抽象类有什么区别

**参考答案**

接口定的是契约，一个类可以实现多个接口。抽象类可以带字段和半成品实现，一个类只能继承一个类。

接口的字段只能是 `public static final`，没有构造方法，也没有实例字段。Java 8 起可以写 `default` 和 `static` 方法，Java 9 起可以用 `private` 方法给默认方法复用。默认方法仍然读不到实现类自己的实例字段。两个接口的默认方法签名冲突时，实现类必须覆盖。

抽象类可以有构造方法、实例字段，以及 `protected` 的具体方法。子类通过 `super` 初始化父类里的公共状态，父类可以把固定流程留在自己这边，把变化的步骤做成抽象方法。

需要一份共享状态或一段受保护的模板流程时，用抽象类。需要一个类同时具备几种能力时，用接口。默认方法只是减少了“为了带一行实现就去占继承位”的情况，它替代不了抽象类的字段。

### 3. 在 Java 中循环拼接字符串几万次，用 String、StringBuilder 还是 StringBuffer

**参考答案**

单线程循环里拼几万次，用 `StringBuilder`，并且按预计长度分配容量。`String` 会反复拷贝，`StringBuffer` 的锁在这个循环里没有收益。

`String` 不可变。`s = s + piece` 每一轮都要把已经拼好的内容拷进一个新字符串，总代价接近平方。编译器会把一条表达式里连续的几个 `+` 合成一次拼接，循环的每一轮仍然是一次独立拼接，几万次照样一轮一轮拷贝。

`StringBuilder` 用可变数组承接追加，容量不够时才分配更大的数组并拷贝旧内容。能估计最终长度时写成 `new StringBuilder(expected)`，把扩容次数压下去。它的方法不加锁，只给一个线程写。

`StringBuffer` 的 `append` 是同步方法，多线程共用同一个 buffer 时，单次 `append` 的字符不会写乱。这个循环若在一个线程里跑，每次加锁只增加开销。多个线程即使共用 `StringBuffer`，两次 `append` 之间锁也会放开，由好几段组成的一条记录仍可能交错。每个线程用自己的 `StringBuilder`，最后再按顺序拼起来，边界更清楚。

```java
StringBuilder sb = new StringBuilder(expectedChars);
for (String piece : parts) {
    sb.append(piece);
}
String result = sb.toString();
```

### 4. Java 里面如何实现线程安全

**参考答案**

先看共享的是不是可变状态，再看要保的是原子性、可见性，还是有序性。手段按临界区来选。

读改写要互斥时，用 `synchronized` 或 `ReentrantLock` 把这一段包起来。只需要一个字段的原子加减、比较交换时，用 `AtomicInteger` 这一类 CAS 类型，避免自己写锁。`volatile` 保证单个变量的写对其他线程可见，并约束它周围普通读写的重排序；`count++` 这种复合操作它保不住。

容器优先用 JDK 已经写好的并发类，例如 `ConcurrentHashMap`。几个线程安全的调用拼在一起，中间的判断仍可能交错，`putIfAbsent`、`compute` 才是一次完成的复合操作。

不共享就没有竞态：局部变量、不可变对象，或者每个线程只碰自己的那份数据。`ThreadLocal` 是线程封闭，线程池里用完要 `remove`，否则下一次任务会读到上一个任务留下的值。

### 5. synchronized 可以修饰变量吗

**参考答案**

不可以。`synchronized` 能修饰实例方法、静态方法和代码块，不能写在字段声明上。

要让一个字段的读写互斥，把读写放进同步方法或同步块。实例方法锁的是 `this`，静态方法锁的是这个类的 `Class` 对象，同步块锁的是括号里那个对象。字段声明上该用的是 `volatile`，它只管可见性和有序性。

同步块括号里的对象必须是所有线程共用的同一把锁。在方法里 `new` 一个对象再锁住它，每次进来都是一把新锁，起不到互斥。拿 `String`、装箱后的 `Integer` 当锁，可能和别的代码锁到同一份缓存对象上。

```java
private final Object lock = new Object();
private int count;

public void add() {
    synchronized (lock) {
        count++;
    }
}
```

### 6. Java 中哪些注解可以实现依赖注入

**参考答案**

把一个 Bean 装配进另一个 Bean，常见的是 `@Autowired`、`@Resource` 和 `@Inject`。`@Value` 注入的是配置值，对象是另一个 Bean 时不靠它。

`@Autowired` 是 Spring 的注解，默认按类型匹配，`required` 默认为 true，找不到就启动失败。同一类型有多个 Bean 时，用 `@Qualifier` 或 `@Primary` 指定。它可以标在构造器、setter 和字段上。类只有一个构造器时，Spring 4.3 起可以不写这个注解，仍然会按构造器注入。字段注入发生在构造方法之后，构造过程里还用不到被注进来的字段。

`@Resource` 来自 JSR-250。Spring 处理它时，写了 `name` 就按这个名字找；没写就先用字段名找，找不到再按类型。`@Inject` 来自 JSR-330，按类型注入，多个候选时用 `@Named` 区分，运行时需要 classpath 里有对应的 API。Spring 6 里这两个注解的包名在 `jakarta` 下，老项目还在 `javax` 下。

`@Component`、`@Service` 负责把类注册成 Bean，本身不把依赖装进来。必需的依赖优先放在构造器参数上，测试时可以直接 `new`。

### 7. HashMap 如何扩容，扩容机制是怎样的

**参考答案**

JDK 8 的扩容把数组建成旧长度的 2 倍，再按 hash 里旧容量对应的那一位把原桶拆成两条，节点之间原来的相对顺序保持不变。

`resize` 分配新的 `Node` 数组。容量始终是 2 的幂，下标用扰动后的 hash 和 `容量 - 1` 做与运算。扰动是把 `hashCode` 的高 16 位异或进低位，避免只使用低几位时堆积。`null` key 的 hash 按 0 处理。

桶里只有一个节点时，新下标就是 `hash & (newCap - 1)`。桶里是链表时，看 `(hash & oldCap)` 是否为 0：为 0 留在原下标，不为 0 则新下标是原下标加上旧容量。`oldCap` 正好是新掩码多出来的那一位，所以不用重新调用 `hashCode`。hash 完全相同的节点这一位也相同，扩容后仍在同一个桶。红黑树也按这一位拆开，某一侧节点数不超过 6 时退回链表。

迁移期间新旧两个数组都在，内存会短时间上去。扩容后的阈值按新容量乘加载因子得到，容量和阈值通常一起翻倍。JDK 8 的拆链避开了 JDK 7 头插法在并发扩容时成环的问题。`HashMap` 仍然不允许并发写，两个线程同时 `put` 会丢更新。

```java
// oldCap 是旧数组长度。这一位为 0 则下标不变，否则下标加上旧容量
int newIndex = (e.hash & oldCap) == 0 ? oldIndex : oldIndex + oldCap;
```

### 8. HashMap 什么情况下会进行扩容

**参考答案**

有两条路径会把 `HashMap` 的数组变大：元素个数超过阈值，或者某个桶已经有 8 个节点再插入、数组长度却还小于 64。

默认构造出来时表是空的，第一次 `put` 走 `resize` 建成容量 16 的数组，阈值是 `16 × 0.75 = 12`。之后每次新增一对键值使 `size` 大于 `threshold`，就再扩容。`threshold` 等于容量乘加载因子，加载因子默认 0.75。构造时如果指定了初始容量，会先向上取到不小于它的 2 的幂，表真正创建之后再按加载因子算阈值。替换已有 key 的 value 不增加 `size`，不会因此扩容。

另一条路径在树化判断里。`TREEIFY_THRESHOLD` 是 8，指的是桶里已经有 8 个节点。再插入第 9 个时才调用 `treeifyBin`，链表刚到 8 个还不会转。调用时如果数组长度小于 64，这次只扩容，让低位相同、更高一位不同的 hash 分开，不在这一次里变成红黑树。数组长度已经不小于 64，才把这条链转成树。所以扩容可以发生在 `size` 还没超过阈值的时候。

容量上限是 `1 << 30`。已经到顶后不再加长数组，阈值被设成 `Integer.MAX_VALUE`，后面只增加元素。空表 `putAll` 会按待写入数量预先把容量抬到能装下的 2 的幂。表已经建好时，开头最多先翻一倍，仍装不下就在后面的 `put` 里继续扩。

### 9. MyBatis 中如何防止 SQL 注入

**参考答案**

用 `#{}` 做预编译参数绑定。`${}` 是语句发出前的字符串替换，用户输入进了 `${}` 就可以改掉 SQL 结构。

`#{}` 在解析后变成 JDBC 的 `?`，值由 `PreparedStatement` 绑定。输入里的引号、注释和分号都只是参数值的内容，不会变成新的子句。这是防注入的机制，靠的是语句结构和数据分开，不是把 `select`、`drop` 这类词过滤掉。

`${}` 会直接拼进 SQL，一般用在表名、列名、`ORDER BY` 这种不能放占位符的位置。这些位置只接受一份白名单里的标识符，请求参数不能原样代进去。`ORDER BY ${column}` 是常见口子。`IN` 列表用 `<foreach>` 生成多个 `#{}`，不要拼成一条 `${ids}`。

`LIKE` 的百分号写在参数值上，仍然用 `#{}`：`concat('%', #{kw}, '%')`。为了拼通配符改用 `${}`，注入就回来了。`#{}` 防的是语句被改写；用户传入的 `%` 仍可能扩大匹配范围，那是业务过滤，要单独处理。

### 10. 微服务的熔断和降级

**参考答案**

熔断决定还要不要继续调用下游，降级决定主路径走不通时返回什么。两件事经常接在一起，触发条件和返回给上游的内容要分开设计。

熔断看的是下游这一段时间的健康情况。关闭时正常放行并统计；慢调用或异常超过阈值就打开，打开期间直接失败，不再把请求打过去；冷却后进入半开，放进少量探测请求，成功就关闭，失败就继续打开。它停掉的是后续调用，给调用方的线程和下游的恢复留时间。单次超时只结束这一次调用，后面的请求仍会打到下游。

降级是替代结果：熔断打开、调用超时，或者大促时主动关掉某个功能，就返回缓存、默认值，或跳过推荐、积分这类非核心步骤。没有准备替代结果时，熔断只能快速失败。也可以不装熔断器，靠开关提前降级。

实现可以用 Sentinel 或 Resilience4j。慢调用比例、异常比例、异常数按这个接口自己的耗时和错误分布来定。限流限制的是进入的量，下游正常时超额请求也会被拒绝；熔断看的是下游已经在失败。降级得到的兜底值要让上游认得出，不能当成真实成功写进账务。

### 11. 了解过哪些限流方法

**参考答案**

先定限的是 QPS 还是同时处理的请求数，限在单机还是整集群，再选算法。被限流的请求要快速失败或走降级，不要在入口无限排队。

固定窗口按一段时间做计数，实现短。窗口交界处两边各放行将近一整窗，瞬时流量可以接近配额的两倍。滑动窗口把这段时间切成小格，过期的格子丢掉，边界比固定窗口稳。

漏桶按固定速率往外放，突发进来的请求排队或者被丢掉，出口是平的。令牌桶按固定速率往桶里放令牌，桶有上限，请求拿走令牌才通过，所以允许用掉已经存下的那一段突发。网关侧两种都常见；进程里还可以用信号量限制同时执行的线程数，这和每秒请求数是两个量。

集群限流把计数放到共享存储，一般用 Redis 加一段 Lua，让判断和扣减同一次执行。Redis 不可用时是拒绝还是放行，按这个接口能不能承受超额流量事先定好。单机限流挡不住从其他实例进来的总量，入口总量要用集群计数或者网关统一限。

### 12. Kafka 如何保持高流量、高可用

**参考答案**

高流量靠分区并行、批量顺序写和消费时的零拷贝。高可用靠多副本和 ISR。写入要等副本确认时，吞吐会下降，两个目标要一起说清取舍。

主题分成多个分区，生产者按 key 选择分区，同一个 key 落在同一个分区，分区内顺序才有意义。消费者组里一个分区同时只分给一个消费者，消费者数量超过分区数不会再提高并行度。热点 key 会把流量打进一个分区，只加分区摊不平。

生产者把短时间里的多条记录攒成一批再压缩发送。`linger.ms` 默认是 0，同一次已经进入缓冲区的记录仍会合成一批；流量高时把它略调高，用一点延迟换更大的批次。Broker 把日志顺序追加到磁盘，数据留在页缓存里。消费者来拉时，Broker 用 sendfile 把页缓存送到网卡。消费速度跟不上时，堆积会留在分区上，扩容消费者的上限仍是分区数。

生产上常见的写法是副本因子 3、`min.insync.replicas` 为 2、生产者 `acks=all`。`acks=all` 等的是当前 ISR 里的副本，落后的副本不在这次等待范围内。这样坏掉一台仍能写入；再坏到 ISR 人数不够，就拒绝写入。未同步的副本不要选成 Leader，已确认的消息才不会因为领导权落到落后副本上而丢失。

生产者重试可能写出重复。幂等生产者覆盖的是同一次生产会话里的重试；消费者处理完、偏移量还没提交就崩溃，重启后仍会再消费。业务侧按主键去重。副本和 `acks=all` 换的是不丢已确认的消息，同时会拉低写入吞吐。

### 13. MySQL 出现慢查询如何优化

**参考答案**

先分清时间花在扫描行上，还是花在等锁上，再改索引和写法。一条语句变慢时，先把它的访问路径改清楚。

慢日志里的 `Query_time` 含等待锁的时间，`Lock_time` 要单独看。锁等待长，就去查谁占着锁、事务是否没提交，给过滤列加索引解决不了长事务。MySQL 8.0 可以用 `EXPLAIN ANALYZE` 看实际每一步的耗时；更早的版本看 `EXPLAIN` 的 `type`、`key` 和估计行数。`type` 为 `ALL`，或者 `Extra` 里出现 `Using filesort`、`Using temporary`，就是这条语句的优化对象。

索引按最左匹配来接：等值列在前，范围列和排序列在后。列上套函数、比较时发生类型转换、`LIKE` 以通配符开头，都会让这列上的索引用不上。多个 `OR` 可能走 index merge，也可能退成全表扫描，以 `EXPLAIN` 为准。只查需要的列，列表所用的列都在索引里就可以不回表。很深的分页不要用大偏移，按上一页最后的排序键接着查：

```sql
SELECT id, created_at
FROM orders
WHERE user_id = ?
  AND (created_at, id) < (?, ?)
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

排序列有重复时要把主键带进比较，否则会漏行或重复。统计信息过旧时优化器会选错索引，可以重新分析这张表。读写分离把读分到副本，这条语句的执行计划不变。索引和写法改完仍然不够，再考虑缓存或拆表。

### 14. 用 EasyExcel 解析一万行 Excel，解析到第 5000 行出错如何处理

**参考答案**

先决定这一万行是整批一起成功，还是允许前面的行先落库。EasyExcel 按行回调，默认在 `onException` 里把异常继续抛出，读取停在出错的行。如果每几百行就已经提交，停在第 5000 行时前几批还在库里，用户整份重传会插重。

转换失败会进入 `onException`，`invoke` 里抛出的业务异常也会进来。要跳过坏行并把文件读完，就在这里记下表格行号和原因，方法正常返回。`readRowHolder().getRowIndex()` 从 0 计，而且包含表头；返回给用户的行号要按表格上看到的那一行换算，避免指错格子。从某一行起整列都对不上时，先看表头和合并单元格，EasyExcel 默认不会把合并单元格的值填满整块区域。

整批成功：解析时只收集合法行和错误行，有任何一行失败就不写入。一万行普通数据放得进内存，全部合法后再开一个事务插入，失败则整批回滚。

允许部分成功：按固定批量提交，坏行不进入当前批。已经提交的行要能按业务唯一键重放，用户修好第 5000 行后通常会把整份文件再传一次。任务结束时返回成功数，并把失败行和原因导出。读到一半抛出未处理异常时，把任务标成失败，不要标成成功。

单元格格式、空值和数据库约束失败分开记录，用户才能改文件，而不是把前 4999 行再跑一遍。

```java
@Override
public void onException(Exception exception, AnalysisContext context) {
    int rowIndex = context.readRowHolder().getRowIndex();
    errors.add(new RowError(rowIndex, exception.getMessage()));
}
```

### 15. 项目里是否用了大模型，接入的是哪个

**答题思路**

先如实说有没有接，再讲你真正调用的那一个。没有用过就直接说没有，停在这里。

1. 第一句只回答接了还是没接。接了就说出配置或客户端里写的模型名称。只调过对话接口，就讲到这次调用为止。
2. 放回链路：哪个服务在调、用户是同步等结果还是稍后拿结果、失败时接口返回什么。
3. 说清输入和输出：你传了哪些业务字段，结果写回哪张表或哪个字段。提示词若是你写的，说明它放在代码、配置还是模板里。
4. 小版本记不清，就说以线上配置为准，现场不猜一个模型号。
5. 向量检索、工具调用、微调、离线评测，没做的就说明没做，等面试官决定要不要往下问。

### 16. 大模型的数据存放在哪里

**答题思路**

先把“数据”拆开，再只讲你这个系统里真实存在的那几类，以及每一类放在哪。

1. 模型权重。走厂商接口时，权重在对方那里，你这边没有模型文件。只有自己部署，才说明权重文件在哪台机器或哪个存储上。
2. 业务数据。本来就在你的库里的那些表，模型只是在一次请求里读到你查出来的字段。说清查的是哪类数据、结果写回哪里。
3. 检索数据。做了检索增强，才有原文、切片和向量索引，分别说存放位置，以及原文改了以后索引怎么更新。没做就说明请求里没有额外的知识库。
4. 调用记录。提示词、输出和 trace 若落了日志，说清落在哪、保留多久、用户隐私有没有打进去。没落就说没落。

按这个顺序讲：先点明四类里你有哪几类，再讲存放位置和谁负责更新。厂商侧的权重不要说成存在自己的业务库里。

### 17. 大模型准确率大概能有多少

**答题思路**

没有量过就不要报百分比。先定义这个项目里的“准”指哪一件事，再讲你怎么数的。

1. 说明任务是抽取、分类、生成还是检索。生成结果用什么叫一条可用，例如字段齐全、人工能直接采用，还是必须和标准答案逐字相同。
2. 做过评测，就讲样本从哪来、多少条、谁标注、分子分母各是什么。这个数必须是你自己统计过的。
3. 没做过评测，就直接说现在没有这个数。补上你准备怎么量：固定一小批标注样本，把模型答错、检索没召回、源数据本身有错分开计。
4. 接着讲你见过的失败，以及当时的处理：限死输出格式、对不上就拒绝、交给人工复核。公开榜单上的分数不能拿来当作这个项目的结果。
5. 面试官继续要一个大概区间时，仍然回到口径和坏例。没有样本就没有区间。
