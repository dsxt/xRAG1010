# 虾皮agent开发一面面经面试官水得一批

> 根据面试截图整理。题干来自原帖，参考答案用于复习，不是候选人当时的口述。

## 一面

### 1. 500 条基于 500 条真实用户咨询的标注是人工标的还是自动的？

**答题思路**

先把「500 条咨询」和「标注」分开。咨询来自真实会话，只说明样本来源；意图、标准片段、答复对错是另一层标签。

1. 直接回答金标是谁打的。报准确率用的集合，应由人按书面规范标注。模型或规则打出来的标签只能当初筛，不能再用来证明同一个模型的准确率。
2. 讲清规范里的三件事：一条咨询允许多个意图还是只留一个；什么叫标对；两人冲突时谁裁定。做过双人标注，就说不一致如何裁定；没做过就说明这是当时的缺口。
3. 若检索标签和答案标签不是同一路，分开说。命中哪篇文档可以靠规则核对，答复是否越出证据通常要人看。
4. 记不清人数或抽检比例就不要补。面试官要听的是：这 88% 的分母是不是人工金标。

### 2. 88% 准确率，剩下 12% 是什么情况？哪一类问题准确率最低？

**答题思路**

先说清 88% 的判定，再谈那约 12% 的错误。判定若是 hit@3，就不要把它说成用户第一次就得到正确结果的比例。

1. 错误按原因分桶，用你复盘过的坏例。没有分桶数据就直说当时只留了总体准确率，下面是你补拆的方式，不要现场编占比。
2. 桶按链路切：库里没有对应文档；标准片段没进生成窗口；片段在，但答复改了条件或金额；多意图、指代或跨轮丢槽位；金标本身有争议；该调工具时参数错了。
3. 「哪一类最低」按意图或业务类型切片，例如规则经常改的政策、要查多份文档的问题。点出你看到的那一类，并说明失败主要在召回还是生成。
4. 事先说死拒答算不算错、标答不唯一时算不算对。这两条会直接改变那 12% 的组成。

### 3. 如何限制 RAG 幻觉

**参考答案**

幻觉要卡在「证据里没有的事实仍然被说出来」。把温度调低，只是让同一句错话更稳定。

检索为空、片段互相矛盾或对不上问题时，回答不确定并追问，不补政策条款。金额、时效和适用条件只从召回片段抄出，并标上片段编号。知识库按版本和业务线过滤，过期文档下线。两条冲突政策同时命中时，并列出处，不合成一个折中结论。

生成后再核对数字和实体是否出现在证据里，对不上就重试或转人工。评测把「标准片段没召回到」和「召回到了但说超了证据」分开，后者才是幻觉。

### 4. 新文档如何处理？会纳入知识库吗？

**参考答案**

新文档要先解析、切分、嵌入，并标成生效，线上检索才会用到它。文件刚上传，还不在可检索集合里。

处理按同一条链路：解析时保留标题、表格、来源和生效时间；用和旧库相同的切分方式与同一个嵌入模型写进向量库和原文库。元数据至少有文档编号、版本、权限和状态。换了嵌入模型，新旧向量不能放在同一集合里比距离。

纳入看状态。解析失败、仍是草稿或调用方没有权限的文档保持不可检索。审核或规则通过后改为生效。替换旧版时沿用同一文档编号，下线旧块，避免新旧条文一起被召回。上线前用只出现在新文档里的问题做一次召回验收。

会改口径的规章适合有一道生效门禁。公告类可以自动入库，仍然要带版本，并能整篇下线。

### 5. 意图识别准确率为什么统计 hit@3 而不是 hit@1

**参考答案**

hit@k 表示正确意图在不在前 k 个候选里。只有系统真会使用前三名时，hit@3 才对得上线上效果。

一句话常有多个诉求，细粒度标签也容易标到相邻类。前三名若用来澄清或交给下游路由，hit@3 量的是候选里有没有正确项。直接执行分数最高的那一个，对应 hit@1；单标签时它就是准确率。

只报 hit@3 会把第二、第三名算进命中。要说明前三名是展示、澄清还是丢弃，并给出 hit@1。说不清去向，这个口径就是把判定放宽了。

### 6. 多轮对话任务完成率如何统计？有什么方法区分对话是完成、半完成还是未完成？

**参考答案**

任务完成率只统计已经结束的任务，看终点有没有达到。轮数、用户说「谢谢」、模型自称完成，都不算完成。

一次会话里两件独立的事要拆开。结束包括最终答复、用户离开、超时和移交。还在等用户补充的会话先不进分母，超时后再打标签。终点在打分前写死。

完成：结束前终点已出现。槽位已齐且关键工具成功，或问答结论能被引用片段支持、没有遗留子诉求。半完成：结束时只达成一部分子目标，例如两个诉求只处理了一个，或槽位没收齐就超时。未完成：结束时没有有效进展，包括用户放弃、工具失败后没有恢复、答非所问，以及尚无有效进展就被接管。移交前终点已达到的仍记完成。人工后来解决的，不回填成机器人完成。

主判定用槽位、工具返回、引用和结束原因。模型只按同一份书面标准做辅助，再抽一部分人工复核。工具返回成功但用户目标没达到，仍不是完成。

### 7. 父子文档混合分块是解决什么问题？父子文档怎么关联？子文档是否包含比父文档更多的信息？

**参考答案**

混合分块解决的是检索和生成要的粒度不同。小块用来命中具体句子，大块用来把前提、例外和步骤一起交给模型。

只索引大块时，短问句的相似度会被整段稀释，正确段落进不了前几名。只把小块交给模型时，警告和相邻步骤会丢掉。做法是子块嵌入后参与召回，命中再取对应的父块送去生成。

关联用编号。每个子块记下父块编号、标题路径和自己在父块中的位置，父块记下子块列表。原文库按父块编号取回正文。两边不要再靠向量距离临时配对。

子块是父块的切片，信息更少、更集中。父块才有前后文和例外。把父标题拼进子块，只是补了路径，不是让子块比父块更全。子块里出现父块没有的句子，就是切分或回填写错了。

### 8. 文档转 Markdown 有用自动化工具吗？

**答题思路**

先回答用了，以及用在解析这一段。自动转换不负责决定这篇文档能不能生效。

1. 按你真实处理过的格式说。版式整齐的 PDF、网页用解析器抽出标题、列表和表格；扫描件才需要 OCR；本来就是 Markdown 或纯文本，就不要再转一次。工具名以你跑过的为准，记不清就说能力。
2. 说清自动结果哪里会坏：页眉页脚、多栏、合并单元格。你的验收是抽页核对标题层级和表格，或用答案只存在于表格中的问题做召回。
3. 人工留在解析失败和版式异常的样本上。被问到是不是全自动，把「转成 Markdown」和「内容是否准入」分成两步。

### 9. recall@20 有问题，最终用的是多少？（原帖注明简历已修正为 recall@5）

**答题思路**

recall@k 是标准片段有没有出现在前 k 条里。生成若只读前几条，用 20 做对外指标，会把模型没看见的命中也算进效果。

1. 承认口径差异。初召可以比生成窗口大，用来给重排准备候选；写在简历上的数要和送进模型的 k 一致。原帖已把简历改为 recall@5，回答时就说明 5 是不是这个窗口，不要再把初召的 @20 说成最终效果。
2. 记不清当时的条数，就说以生成阶段的截断为准，不另编一个 k。库很小、20 已经接近全库时，recall@20 同样会虚高，这一点可以主动说。
3. 补一个排查：标准片段在前 20 里、不在前 5 里，是排序或重排问题；前 20 里都没有，是切块、嵌入或过滤问题。@20 可以留作内部诊断，不作为用户侧结果。

### 10. 告警 Agent 如何控制风险，人工在哪一步介入？

**参考答案**

有副作用的动作默认停在执行之前。风险控制靠工具权限和确认闸门，不靠提示词里写「请谨慎」。

只读诊断可以自动做：拉告警、指标、日志和最近变更，这一步不改生产。模型给出的修复参数必须来自工具结果或预案，服务名、环境要和告警标签一致。工具按白名单分成查询和变更。查询自动调用；重启、改配置、扩缩容、回滚进入待确认。删除数据、切流量这类高危动作直接拒绝，或只生成步骤。

人工加在「建议」变成「下发」的那一步。人看到依据、命令和影响面，确认后由系统调用工具，执行结果再写回上下文。失败或超时就停止，不再换一个更重的命令重试。

每个事件限制变更次数。确认疲劳时，人会习惯性点通过，所以可自动的范围写在白名单和参数约束里。提示词拦不住已经发出的请求。

### 11. 生成修复指令具体是什么指令？

**答题思路**

把指令定义成一次结构化工具调用。先说你当时有没有真正下发，还是只生成建议、由人执行。没有下发就不要说成已经自动改了生产。

1. 只列你接过的类别：回滚到上一版本、切换已有开关、按预案执行现成脚本。模型新造的 shell 不在清单里。每类补四个点：作用对象、参数从告警还是从预案来、期望看到什么恢复、失败后停在哪里。
2. 用一条真实调用的形状回答，服务名和版本用当时的对象；记不清就用占位符，并说明字段。例如回滚要有服务、环境、当前版本和目标版本，目标版本来自发布记录，不由模型编。
3. 参数过 schema：环境枚举、版本必须存在、变更幅度有上限。校验失败就没有指令，只有一条缺口说明。

### 12. 工具有撤销的能力吗？

**参考答案**

大多数生产工具没有通用撤销。能撤回的，只是事先做成补偿动作的那几类。

查询没有副作用，不需要撤销。配置下发如果在执行前保存了旧值，可以再写回上一版；旧值来自记录，不来自模型回忆。重启、扩容和流量切换没有事务回滚，反向操作要单独做成工具，并再次经过确认。已经发出的通知或数据修复常常不可逆，补偿失败就停止并交人。

每次变更记下参数和幂等键。超时后的重试可能把一次扩容做成两次，重试本身不是撤销。让模型现写一条反向命令，也不构成撤销能力。

### 13. Agent 操作的是多个服务还是一个服务？

**答题思路**

按你真实接过的权限回答。一条告警的调用链上经常有多个服务，写权限不必跟着放大。

1. 诊断侧：只读可以跨服务，看下游指标、日志和变更。这些调用的身份只有查询权限。
2. 修复侧：写收在告警所属的服务，或收在预案点名的那一个对象。你没做过跨服务变更，就明确说写是单服务。
3. 约束怎么落地：工具按服务鉴权，参数里的服务名必须等于告警标签。模型换成「看起来相关」的另一个服务时，校验直接失败。
4. 多服务场景把难点放在归因。现象在入口服务、原因在下游时，说明你如何避免先重启入口。读可以多，写保持单一。

### 14. 诊断的整体流程怎么做？

**参考答案**

诊断先收集证据、再缩小假设，最后才产生修复建议。第一步就下发重启，说明这条链路没有在诊断。

从告警取出服务、环境、时间窗和错误码，后面的工具都用这些条件过滤。接着取这一窗里的指标、错误日志和最近变更。变更时间和指标拐点对得上，就优先核对这次变更。

模型只保留少数几个和证据相容的假设，每个假设对应一次还缺的观测。新观测和假设矛盾，就丢掉该假设。假设稳定后，才匹配预案，生成待确认动作。证据不足时停在「还缺哪一项观测」，不进入执行队列。

日志先按错误码和时间过滤再交给模型。全程留下看过什么、排除了什么，并设步数上限。有副作用的动作仍停在人工确认之前。

### 15. 讲一个真实处理告警的案例

**答题思路**

用你真正跟过的一条告警。只参与了其中一段，就讲那一段；没有的环节说没有，不补服务名、损失和时长。

1. 按这个顺序：告警现象，先看的证据，排除了什么，结论，动作是建议还是已执行，谁确认的，事后靠哪个指标或人工结论判断恢复。
2. 案例里放一个 Agent 会犯错的点，例如把相关服务当成根因，或证据不够时建议重启。接着说你靠白名单、确认或观测拦住它。
3. 用这个案例把前面的设计说实：人在执行前介入；这个动作可补偿，或你接受它不可撤销，所以必须先确认。
4. 记不清的 QPS、持续分钟数不要写进故事。现象和证据链比数字重要。

### 16. 笔试：验证二叉搜索树

**参考答案**

空树是合法二叉搜索树。非空时，左子树的全部节点都小于根，右子树的全部节点都大于根，两棵子树自身也要满足。只比较当前节点和左右孩子会漏掉祖先约束：右子树里出现一个比祖先更小的值，它仍可能小于自己的父节点。相等值在这道题里非法，中序遍历必须严格递增。

用深度优先，给每个节点传开区间 `(low, high)`。根没有边界。进入左子树时把上界改成当前值，进入右子树时把下界改成当前值。当前值碰到任一边界就失败。边界用空值表示，避免节点值刚好等于整数极值时被误判。

时间复杂度 O(n)，每个节点访问一次。空间复杂度 O(h)，h 为树高，由递归栈决定；平衡时约 O(log n)，退化为链时为 O(n)。

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def is_valid_bst(root: TreeNode | None) -> bool:
    def dfs(node: TreeNode | None, low: int | None, high: int | None) -> bool:
        if node is None:
            return True
        if low is not None and node.val <= low:
            return False
        if high is not None and node.val >= high:
            return False
        return dfs(node.left, low, node.val) and dfs(node.right, node.val, high)

    return dfs(root, None, None)
```
